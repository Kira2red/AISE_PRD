## 一、背景与收益

**需求简介**：为运营后台提供学员账号的合并与删除能力，配套回收站兜底误操作。仅后台可操作，学员端不提供任何入口。

**业务诉求**：

- 同一学员重复注册产生多个账号（如先在小鹿等渠道用手机号注册、又在官网用同一手机号注册），报名与考试成绩分散在两个账号，需要合并归拢。
- 无用账号（空账号、测试账号、重复注册后弃用的账号）需要删除，减少无效数据。
- 删除/合并属高危操作，需要回收站兜底，误操作可恢复。

**收益**：

- 运营可自助处理重复账号，不再依赖技术老师在数据库层面手工操作，处理时效从天级降到分钟级。
- 学员的所有报名与考试记录归拢到单一账号，成绩查询、证书发放、报告查看不再因账号分散而遗漏。
- 回收站保证误操作 90 天内可恢复，高危操作有兜底。

**关联决策（2026-10-16 需求组讨论拍板）**：

- 删除账号风险高，必须可恢复 → 采用回收站模式。
- 合并/删除的账号信息存入回收站，可恢复，并可设自动清理时长。
- 删除后同手机号重新注册：不提示恢复旧数据，直接注册新账号。
- 先做两两合并，三个及以上账号通过多次两两合并实现。
- 报名信息全部保留；个人信息、渠道以哪个账号为准由运营逐字段选定。
- 本需求替代《9月考务需求（第二批）》中搁置的源表 #22「删除/合并考生ID」。

## 二、业务流程简述

**合并**：运营在「账号合并」页分别搜索选择 2 个账号 → 系统生成字段对比表 → 运营逐字段点选保留 A 或 B 的值（选后可修改）、勾选保留哪些子账号、选定保留哪个登录手机号 → 二次确认弹窗核对摘要 → 执行合并 → 原账号 B 禁用并移入回收站。

**删除**：运营在学员管理列表定位账号，点击行内「删除」操作 → 弹窗展示账号数据概况（报名/考试记录、子账号、在途业务） → 有在途业务的账号不允许删除 → 无在途业务的账号进入强确认弹窗，输入「我确认」后执行 → 账号禁用并移入回收站，列表中不再展示。

**恢复**：运营在「账号回收站」列表定位记录 → 点击恢复并确认 → 删除恢复＝解除禁用；合并恢复＝拆回两个账号并按快照还原。超过 90 天自动清理，清理后不可恢复。

## 三、详细功能说明

### 3.1 账号合并

**位置**：管理后台 → 考务与用户 → 账号合并（一级独立菜单页）

**目标**：将两个重复注册的学员账号合并为一个，报名与考试记录全部保留归拢。

**交互逻辑**：

1. **步骤一·选择账号**
   - 页面分左右两栏：「主账号 A（保留候选）」「主账号 B（合并来源）」。
   - 每栏提供搜索框，支持姓名 / 手机号 / 身份证号模糊搜索，下拉展示候选（姓名 + ID + 手机号）。
   - 选中后展示账号概要卡片：姓名、ID、登录手机号、注册渠道、注册时间、子账号数、记录数；可点「重选」更换。
   - 两个账号都已选中且不为同一账号时，「开始比对」按钮才可点击；A、B 选择了同一账号时按钮置灰并提示「两个位置不能选同一个账号」。
2. **步骤二·比对与确认**，包含四个区块：
   - **个人信息逐字段确认表**：列出姓名、性别、身份证号、联系电话、电子邮箱、所在省市、详细寄送地址、监护人姓名、监护人电话、注册渠道。每个字段并排展示 A、B 两方的值（值不一致的标「不一致」角标），点选其一自动带入「合并后」输入框；「合并后」输入框可直接修改为任意值。默认全部预选 A 的值。
   - **登录手机号**：单选卡片二选一（A 的手机号 / B 的手机号）。未被保留的手机号合并后失效，无法再登录；卡片下方明确提示失效后果。默认选中 A 的手机号。
   - **子账号**：列表展示两个账号名下全部子账号（姓名、身份证号、归属账号 A 或 B、报名记录数），每行带勾选框，默认全部勾选保留。主账号与子账号均由运营逐个勾选决定保留或遗弃，遗弃规则如下：
     - 无报名与考试记录的子账号：可直接取消勾选遗弃。
     - 有报名与考试记录的子账号：取消勾选时**不允许直接遗弃**，弹窗提示「该子账号有 N 条报名与考试记录，须先转移记录」；运营在弹窗中选择记录的接收方（合并后保留的其他子账号，下拉二选一或多选）→ 点击「转移并遗弃」→ 记录全部转移至接收子账号名下 → 该子账号记录清零、变为灰色划线遗弃态。转移在点击「确认合并」时随合并一并生效。
     - **同场测评冲突处理**：转移记录时，若接收子账号与遗弃子账号报了同一场测评活动，弹窗强提示「两个子账号存在同一场测评，合并后仅保留接收方的记录，遗弃子账号的同场记录将作废」，并要求点击「确认转移」二次确认后方可继续；确认后以接收方的记录为准，遗弃子账号的同场记录标记作废（不展示、不参与成绩与证书计算，作废记录保留在库以支撑合并恢复回退）。
     - 记录转移完成后，遗弃子账号身份不再保留（姓名、身份证号不并入任何账号）；报名与考试记录始终挂在子账号（孩子）名下，不并入主账号。
     - 转移弹窗中接收方下拉仅列出姓名不重复的保留子账号；同姓名的接收方追加归属账号后缀区分（如「张小虎（账号 A）」）。
     - 特殊场景：同姓名同身份证号的孩子在两个账号下重复（如家长先后两次注册各建了一次），遗弃其中一个前须将记录转移给另一个，转移后两个身份自然归并为一个，系统不自动归并。
   - **报名与考试记录**：只读展示两账号各自的记录明细；全部自动合并保留，无需逐条确认。记录的归属子账号因遗弃发生转移的，在明细中标示「由 X 转移至 Y」。
3. **步骤三·确认与执行**
   - 「确认合并」弹窗展示摘要：字段取值确认情况、保留的登录手机号、保留/遗弃子账号数（含记录转移情况，如「遗弃 1 个，其中 1 个记录已转移至张小凤」）、将失效的手机号。
   - 弹窗提示「合并后原账号 B 将被禁用并移入回收站，可在回收站恢复」。
   - 点击「确认合并」执行；成功后展示结果页（合并后账号 ID、保留手机号、合并记录数、保留子账号数），并可继续合并下一组。
4. **步骤条**：页面顶部展示「选择账号 → 比对与确认 → 完成」三步进度，已完成步骤打勾。

**状态与边界**：

- 账号存在在途业务时，该账号不可作为「合并来源（B）」，选择时置灰并提示「该账号存在在途业务，请先处理完再合并」；作为保留候选（A）不受限。
- **在途业务范围**：自报名创建起即算在途，包含：待支付、审核中、退款中的报名，候考中、模拟考中、进行中的测评。上述状态全部结束后账号方可删除或作为合并来源。
- 两个账号的身份证号不一致时，字段表该行标红提示「身份证号不一致，请人工核实是否同一学员」，不阻断操作，由运营自行判断。
- 合并执行失败（网络异常/系统错误）时弹窗提示失败原因，数据不变更，可重试。
- 合并过程中的重复提交：执行期间「确认合并」按钮置灰，防止双击重复提交。

### 3.2 账号删除（学员管理页行操作）

**位置**：管理后台 → 考务与用户 → 学员管理（12_学员管理）列表行操作列，新增「删除」图标按钮（与重置密码同款形态）

**目标**：安全删除无用学员账号；删除为逻辑禁用，数据全部保留。

**交互逻辑**：

1. 学员管理列表每行操作列提供「删除账号」图标按钮，点击弹出**删除确认弹窗**。
2. 弹窗展示**数据概况卡片**：报名/考试记录数、子账号数、在途业务数，以及明细提示。
3. 按账号数据状况分三种处理：
   - **有在途业务**（存在待支付、审核中、退款中的报名，或候考中、模拟考中、进行中的测评）：**不允许删除**。卡片下方红色警示「存在在途业务，不允许删除」，并提示先处理完在途业务（完成审核流转、取消报名或退款等）后再删除；强确认输入区与删除按钮不展示。
   - **有过往数据**（有报名/考试记录、证书或子账号，但无在途业务）：弹窗展示账号信息与过往数据明细，要求在输入框中**手动输入「我确认」**，输入完全匹配后「确认删除并禁用」按钮才可点击；输入不匹配时按钮置灰并显示红色错误提示。
   - **无任何数据**：同样弹强确认弹窗（流程一致，统一防误操作），弹窗中过往数据栏显示「无报名与考试记录」。
4. 确认执行后：账号立即禁用（无法登录），全部数据移入回收站，轻提示「账号已删除并移入回收站，可在账号回收站恢复」。

**状态与边界**：

- **已禁用账号不在学员管理列表中展示**（含列表默认视图与状态筛选），防止重复删除；账号数据在回收站保留期内可恢复，恢复后重新出现在列表。
- 删除后该账号的登录手机号立即释放。同手机号重新注册时**不提示恢复旧数据，直接注册新账号**（已拍板）。
- 删除执行失败时数据不变更，可重试。
- 删除操作与合并操作均记录操作审计：操作人、操作时间、操作类型、操作摘要。

### 3.3 账号回收站

**位置**：管理后台 → 考务与用户 → 账号回收站（一级独立菜单页）

**目标**：兜底合并与删除两类高危操作，误操作可在保留期内一键恢复。

**交互逻辑**：

1. **列表**：展示回收站内全部记录，列：账号信息（姓名 + ID + 手机号）、操作类型（账号合并/账号删除，标签色区分）、操作摘要（合并去向或删除时数据概况）、操作人、进入回收站时间、剩余保留期（保留期不足 10 天的红色加粗提醒）。
2. **筛选**：支持按姓名/手机号/ID 搜索、按操作类型筛选。
3. **恢复**：
   - 点击「恢复」弹确认弹窗，按操作类型展示恢复后果说明：
     - **删除恢复**＝账号解除禁用，立即恢复登录，数据完整还原；若该手机号在删除期间已被新注册占用，**暂不允许恢复**，提示「此手机号已被占用，请提醒用户使用新的手机号重新注册」，处理完成前该记录保留在回收站。
     - **合并恢复**＝拆回合并前两个独立账号：个人信息与子账号按合并前快照还原，报名与考试记录拆回各自原账号；因遗弃而转移过记录的子账号，其被转移的记录按快照回退至原子账号名下，同场测评冲突中作废的记录同步解除作废；若拆回后手机号已被占用，同上暂不允许恢复并提示处理。
   - 确认后执行恢复，列表移除该记录，轻提示恢复结果。
4. **自动清理**：记录保留 **90 天**（可配置），到期自动清理；清理后数据彻底删除，不可恢复。剩余保留期在列表中实时展示。
   - **清理范围**：该学员名下全部明细数据彻底删除，包括：账号与子账号信息、报名与考试记录、成绩、证书、报告、支付订单，以及爱测评侧对应虚拟账号下的作答等数据（随清理一并删除）。
   - **不回溯项**：基于该学员历史明细产生的统计汇总计数不做回溯修改；账号合并与删除的审计日志保留，不随清理删除。

**状态与边界**：

- 回收站为空时展示空状态「回收站为空，暂无待恢复的账号」。
- 恢复操作同样记录审计日志。
- 合并恢复的前提是保留账号此后未被再次合并或删除；若保留账号已不在（被再次删除/合并），恢复时提示「原合并目标账号已变更，请联系技术核查后恢复」。

## 四、系统关联与依赖

| 关联模块 | 关系 |
|----------|------|
| 学员管理（12_学员管理） | 删除功能落点页：列表行操作列新增「删除」按钮；被删除账号立即从列表移除（含状态筛选），恢复后重新出现 |
| 报名管理 / 测评管理 | 在途业务判断来源：待支付/审核中/退款中报名、候考中/模拟考中/进行中测评的账号不可删除、不可作为合并来源 |
| 登录认证 | 删除/合并失效的手机号立即失去登录能力；同手机号重新注册走全新注册流程，不关联旧数据 |
| 证书 / 报告 | 记录随账号合并自动归拢到保留账号名下，证书编号与报告不重新生成 |
| 爱测评 | 合并时，遗弃子账号在爱测评侧对应虚拟账号的数据（报名、作答等）同步合并至接收子账号对应的虚拟账号，合并后爱测评侧不再保留被遗弃子账号的数据；回收站恢复时按快照同步回退；90 天到期清理时爱测评侧对应数据一并删除。两端数据同步机制与失败处理由研发评估实现 |

## 五、验收标准

| # | 场景 | 前置条件 | 操作 | 期望结果 |
|---|------|----------|------|----------|
| 1 | 合并主流程 | 两个同身份证号账号 | 完成三步合并 | 记录归拢、B 账号禁用进回收站、A 可正常登录 |
| 2 | 合并同账号校验 | — | A、B 选同一账号 | 开始比对按钮不可点击并提示 |
| 3 | 合并在途账号 | 账号有审核中报名 | 选其为合并来源 B | 置灰并提示先处理在途业务 |
| 4 | 删除强确认 | 有过往数据的账号 | 输入「确认」「我确认 」等非精确内容 | 按钮不可点击；仅精确输入「我确认」可执行 |
| 5 | 在途业务拦截 | 有审核中报名的账号 | 尝试删除 | 不允许删除并提示处理在途业务 |
| 6 | 遗弃有记录子账号 | 子账号有报名记录 | 取消其勾选 | 弹窗提示须先转移记录，不允许直接遗弃 |
| 7 | 记录转移后遗弃 | 已选记录接收方 | 点击「转移并遗弃」并确认合并 | 记录全部转入接收子账号名下，原子账号遗弃且记录清零 |
| 8 | 删除后重新注册 | 账号已删除 | 同手机号重新注册 | 直接注册新账号，不提示恢复 |
| 9 | 回收站恢复删除 | 回收站有删除记录 | 恢复 | 账号解除禁用可登录，数据完整 |
| 10 | 回收站恢复合并 | 回收站有合并记录 | 恢复 | 拆回两个账号，字段与记录按快照还原（含转移记录回退、作废记录解除作废） |
| 11 | 保留期到期 | 记录超过 90 天 | 自动清理 | 学员名下全部明细数据（含爱测评侧数据）彻底删除且不可恢复；审计日志保留，统计汇总计数不回溯 |
| 12 | 审计日志 | 执行任一合并/删除/恢复 | 查操作日志 | 有操作人/时间/类型/摘要记录 |
