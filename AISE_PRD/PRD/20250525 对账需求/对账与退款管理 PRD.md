## 1. 产品概述

### 1.1 模块定位

AISE 管理后台当前缺少统一的支付对账与退款管理能力，各类查询依赖开发介入，效率低下。本方案在管理后台新增「对账管理」一级分类，并增强现有「报名管理」的退款能力，构建覆盖支付全链路的查询、退款、对账闭环。

核心架构决策：

- **订单系统独立于报名表**。从现有报名管理中拆出通用订单系统，通过关联字段与报名解耦（R-OS-01 / R-OS-02）。当前订单主要来自报名场景，但架构预留会员、增值服务等其他订单类型的扩展能力。
- **交易流水是数据底座**。汇总所有支付场景的交易数据，提供统一查询视图。当前数据主要来自报名订单，但设计上不限于报名。
- **报名管理是唯一退款写入口**。退款操作仅在报名管理页面发起，交易流水为只读镜像。

### 1.2 用户角色

| 角色 | 说明 | 涉及页面 |
|------|------|----------|
| 最高管理员 | 现有最高权限管理员角色，负责退款操作、对账数据查看、数据导出 | 全部 |
| 运营人员 | 日常查看交易数据、导出报表、核对差异 | 交易流水、交易数据统计 |
| 财务人员 | （暂不独立创建角色）对账核对、差异追踪 | 交易流水 |

> 当前不细分财务管理员角色，统一由最高管理员权限覆盖（R-RB-01）。

### 1.3 核心价值

- **不再依赖开发查询**：运营/财务可自主查询交易流水、导出对账数据
- **统一退款入口**：后台一键退款，联动撤销考试资格和电子证书
- **数据底座**：独立订单系统支撑报名以外的支付场景扩展

### 1.4 适用范围

本 PRD 覆盖以下两个页面的设计与改动：

1. **交易流水（29_交易流水.html）** — 新增页面，对账管理一级分类下
2. **报名管理（11_报名管理.html）** — 已有页面增强（退款流程、抽屉重构、状态体系变更）

「交易数据统计」页面不在本 PRD 范围内，另起文档。

## 5. 报名管理 — 详细设计

### 5.1 退款流程

#### 完整步骤

```
管理员打开订单抽屉
       │
       ▼
  查看订单详情（状态=支付成功）
       │
       ├── 当前时间 ≥ 考试开始时间？
       │     ├── 是 → 退款按钮置灰，tooltip「考试已开始，不可退款」
       │     └── 否（且支付金额 > 0）→ 显示「退款」按钮
       │
       ▼
  点击「退款」按钮
       │
       ▼
  打开「退款确认」弹窗
  · 展示退款信息摘要
  · 联动操作勾选（撤销考试资格 / 撤销电子证书）
  · 备注（选填）
       │
       ├── 点击「取消」→ 关闭弹窗，订单状态不变
       │
       └── 点击「确认退款」
             │
             ▼
          关闭弹窗
          订单状态 → 退款处理中
          记录操作日志
          调用支付渠道退款 API（原路退回）
             │
             ├── 退款成功
             │     │
             │     ├── 订单状态 → 已退款
             │     ├── 记录退款金额、时间、操作人
             │     ├── 若勾选「撤销考试资格」→ 移除该考生考试资格
             │     ├── 若勾选「撤销电子证书」→ 使已签发证书失效
             │     └── 刷新抽屉内容
             │
             └── 退款失败（含竞态失败）
                   ├── 支付渠道回调失败 → 退款失败
                   ├── 退款完成时考试已开始（竞态）→ 退款失败
                   ├── 订单状态 → 退款失败
                   ├── 失败原因记录到操作日志
                   ├── 抽屉显示失败状态 +「重试退款」按钮
                   └── 联动操作不执行（仅在退款成功后触发）
```

#### 关键规则

| 规则 | 说明 |
|------|------|
| 无 C 端退款入口 | 所有退款均由后台管理员发起，C 端不提供退款按钮 |
| 无审核流程 | 管理员点击「确认退款」后直接执行，无中间审核环节 |
| 全额原路退回 | 仅支持全额退款，金额不可修改。退款路径 = 原支付渠道 |
| 阶段判定 | 考试开始时间前 → 可退款；考试开始时间后 → 不可退款（按钮置灰） |
| 退款金额为零 | 后台直接开通（金额 ¥0.00）的订单显示退款按钮但置灰不可点击 |
| 竞态判定 | 退款以完成时间为判定节点：退款完成时若考试已开始 → 退款失败（非退款发起时间） |

│                                     │

│  ┌─────────────────────────────┐    │

#### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 退款金额 | 只读 | — | 大字展示，font-mono 红色，金额 = 订单实付金额 |
| 订单编号 | 只读 | — | 来源订单 |
| 支付方式 | 只读 | — | 微信支付 / 支付宝 |

| 测评名称 | 只读 | — | 完整测评名称 |
| 撤销考试资格 | checkbox | 否 | 默认不勾选；勾选后退款成功时联动执行 |
| 撤销电子证书 | checkbox | 否 | 默认不勾选；勾选后退款成功时联动执行 |

#### 交互规则

- 「确认退款」按钮点击后立即关闭弹窗，订单状态同步变更为「退款处理中」
- API 调用在后台异步执行，前端通过轮询或 WebSocket 更新状态
- 「退款处理中」→「已退款」或「退款失败」后，抽屉内容自动刷新

### 5.3 订单状态流转图

订单从创建到可能的退款，状态按以下路径流转：

```
订单创建
    │
    ▼
┌──────────┐    支付超时/取消    ┌──────────┐
│  待支付   │ ───────────────→ │  已关闭   │
└────┬─────┘                   └──────────┘
     │  支付成功（微信/支付宝回调 或 后台直接开通）
     ▼
┌──────────┐
│ 支付成功  │
└────┬─────┘
     │
     │  管理员点击退款（需满足：考试未开始 + 金额 > 0）
     ▼
┌──────────────┐
│ 退款处理中    │  ← 调用支付渠道退款 API
└──┬───────┬───┘
   │       │
   │ 成功  │ 失败
   ▼       ▼
┌──────────┐ ┌──────────┐
│  已退款   │ │ 退款失败  │
└──────────┘ └────┬─────┘
                  │
                  │ 管理员点击「重试退款」
                  ▼
            ┌──────────────┐
            │ 退款处理中    │  （回到退款处理中状态）
            └──────────────┘
```

#### 状态定义

| 状态 | 含义 | 触发条件 | 颜色/样式 |
|------|------|----------|-----------|
| 待支付 | 订单已创建，用户尚未完成支付 | 用户提交报名、发起支付但未完成 | 琥珀色（amber） |
| 支付成功 | 用户已完成支付或后台直接开通 | 微信/支付宝回调 / 管理员后台开通 | 绿色（green） |
| 已关闭 | 订单超时未支付或自动取消 | 支付超时 / 系统自动取消 | 灰色（slate） |
| 退款处理中 | 退款已提交，支付渠道处理中 | 管理员确认退款 | 蓝色（blue） |
| 已退款 | 退款已执行，费用已原路退回 | 支付渠道退款回调成功 | 灰色（slate / 带删除线） |
| 退款失败 | 退款执行失败 | 支付渠道退款回调失败 | 红色（red） |

> ⚠️ 与早期业务需求文档相比，撤销了「退款申请中」和「退款驳回」两个状态（决策：无审核流程、无 C 端退款）。

- 若无值（如待支付状态）：展示「—」
- 商户交易编号的来源由订单系统生成，当前若为待支付状态暂不生成，待确认生成时机

- 「重试退款」行为同退款：调用退款 API，状态重新进入「退款处理中」

### 5.5 退款后联动操作规则

| 联动操作 | 触发条件 | 执行逻辑 | 可逆性 |
|----------|----------|----------|--------|
| 撤销考试资格 | 退款确认时勾选 | 将该考生从对应考试场次中移除，释放名额 | 不可逆（需重新报名） |
| 撤销电子证书 | 退款确认时勾选 | 将已签发的电子证书标记为失效/作废状态 | 不可逆 |

- 联动操作在退款 API 回调成功后执行
- 若联动操作执行失败（如证书服务异常），不影响退款本身的完成状态，联动操作记录失败日志供运营排查

### 5.6 筛选区改动

| 支付方式 | 微信支付 / 支付宝 / 后台直接开通 | **保持不变**（HTML demo 已对齐） | — |
