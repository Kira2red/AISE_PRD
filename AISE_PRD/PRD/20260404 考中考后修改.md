# 20260404 考中考后修改

## 功能一：监考页面考生卡片状态与操作联动优化

### 1. 项目背景
- **需求简介**：在监考详情页，新增对考生设备状态（摄像头、录屏）和检录状态的实时反馈联动。当考生处于未检录、未开摄像头或未开录屏的异常状态时，将其卡片对应的操作按钮显示为置灰不可点击状态。
- **业务诉求**：方便监考老师在通过顶部筛选器定位异常考生后，利用视觉焦点（置灰按钮）快速辨识具体的异常项，从而提升监考核查效率。

### 2. 业务流程简述
监考人员进入监考界面 -> 浏览考生卡片或通过筛选器检索 -> 系统根据实时获取的设备与检录数据，对相关状态异常的考生底层交互按钮进行禁用（置灰）处理 -> 监考人员快速判别异常并介入。

### 3. 详细功能说明

#### 3.1 考生卡片操作区状态流转
- **位置**：监考页面 -> 考生卡片底部操作按钮组。
- **关联数据源**：页面需动态提取并判断考生的三项核心状态：`摄像头状态`、`录屏状态`、`检录状态`。
- **禁用（置灰）规则**：
  - 当 `检录状态 = 未检录` 时，依赖检录数据的按钮（如“查看检录”）需呈现禁用态。
  - 当 `摄像头状态 = 关闭/异常` 时，“查看摄像头”按钮需呈现禁用态。
  - 当 `录屏状态 = 关闭/异常` 时，“查看录屏”按钮需呈现禁用态。
- **禁用态交互规范**：
  - 视觉表现：按钮呈灰度显示，鼠标悬浮（Hover）时无高亮反馈。
  - 指针表现：鼠标悬停时显示禁用标志（Not-allowed）。
  - 动作反馈：点击失效，不触发任何提示或页面跳转。
- **状态恢复**：若监考期间学生恢复设备开启或完成检录，系统刷新获取到正常数据后，对应的按钮自动解除禁用，恢复正常交互状态。

## 功能二：测评详情视频查看及全屏播放优化

### 1. 项目背景
- **需求简介**：在现有的考后监控（录屏/摄像头）视频列表中，保留原有的网格图文框架，新增单视频的全局全屏试听与控制功能。
- **业务诉求**：原有列表播放视窗较小且操作控制基础。通过新增支持倍速、拖放进度的沉浸式全屏弹窗，大幅降低监考与阅卷人员排查异常片段的时间成本。

### 2. 业务流程简述
用户进入测评详情下的视频查看模块 -> 浏览视频缩略图卡片 -> 点击任意卡片封面 -> 系统唤起全局全屏播放弹窗并自动加载视频源 -> 用户使用底部控制栏进行倍速或进度拖拽操作 -> 操作完毕点击关闭，返回原视频列表页。

### 3. 详细功能说明

#### 3.1 视频数据网格视图
- **页面布局**：采用适配屏幕宽度的自适应网格布局排列视频卡片。
- **卡片元素构成**：
  - 缩略图封面：提取视频关键帧作为封面。
  - 基础信息：左下角显示【视频序号、格式分类、生成时间】（例：`1、录屏视频-2026-01-24 14:02:45`）。
- **交互规范**：鼠标悬停在封面上时，浮现半透明暗色遮罩及中心播放图标，点击该区域即可唤起全屏播放器。

#### 3.2 沉浸式播放弹窗
- **展现机制**：弹出全局弹窗层，配备深黑色遮罩以聚焦用户视线。
- **弹窗控制与操作组件**：
  - **关闭逻辑**：提供显性的关闭按钮（右上角），同时支持点击外部深色遮罩或按下键盘 ESC 键快捷关闭进程。
  - **播放中控组件**：
    - 基础控制：播放/暂停切换。
    - 进度滑动条：支持自由拖拽与精准点击，实现快速时间轴定位。
    - 倍速调节菜单：提供 `1.0x, 1.25x, 1.5x, 2.0x` 等常规倍数档位配置。
    - 全屏展示：支持画面最大化铺满整个显示器。

## 功能三：用户信息审核管理（后台管理侧应用）

### 1. 项目背景
- **需求简介**：在 AISE 运营后台考务体系下新增“用户信息审核”模块，集中处理爱测评（iceping）用户端提交的核心身份信息变更审批工作。
- **业务诉求**：为保证考生基础身份信息的严肃性与准确性，考生在用户侧发起的敏感信息变更需经由运营后台人工流转审批，形成安全风控闭环。

### 2. 业务流程简述
运营人员进入 AISE 平台后台“用户信息审核”菜单 -> 查阅待处理的用户申请报表 -> 点击单条记录の“审核”操作 -> 进入审核详情页比对身份信息 -> 决策点击“通过审核”或“不通过审核” -> 系统执行变更状态，并将审核结果流转反馈至爱测评（iceping）用户端。

### 3. 详细功能说明

#### 3.1 审查汇总清单列表
- **页面框架**：统一复用 AISE 平台当前考务管理的列表规范组件。
- **展示字段要求**：包含 `考生姓名`、`证件类型`、`证件号`、`手机号`、`监护人姓名`、`监护人手机号`、`提交时间`。
- **记录操作项**：右侧常驻操作列提供“审核”指令，点击后路由至审批详情专页。

#### 3.2 审核详单与人工审批操作
- **信息展示面板**：复用常规考生详情页的信息展示矩阵，进行只读排版。
- **审批决策组件**：
  - 页面移除原有默认的“修改/保存”能力组件。
  - 替换为两个强意图的决策按钮：
    1. **不通过审核（驳回）**：判定变更不合规，终止变更流程，状态变更为拒绝。
    2. **通过审核（许可）**：确认变更有效，系统正式将修改后的数据落库并覆盖旧档案信息。
- **完成回调反馈**：审批决策下发并经系统确认后，提示操作成功，并自动返回待办列表页，当前工单状态完结移出待办队列。

#### 3.3 爱测评（iceping）用户端状态联动展示
- **入口**：爱测评（iceping）前台 -> 个人中心 -> 个人信息页。
- **审批锁定机制**：
  - 用户修改信息并提交后，系统进入审核前状态。本地信息不立即生效。
  - **展示效果**：“保存修改”按钮即刻转为禁用状态避免重复提交。并在该操作区附近增加显性提示：**“正在审核中”**。审核期间，表单保持用户修改后的最新值为只读展示视图。
- **审批结果解散策略**：
  - **审核通过**：“正在审核中”状态消除，页面恢复可用状态，新数据结构正式生效。
  - **审核不通过**：状态提示消除，个人信息回滚为本次修改动作发起前的原始旧数据，页面恢复可用状态。

#### 3.4 边界防范与空窗风控
- 相关申请拦截：若考生的账号存在一笔锁定推进中的待审记录，限制在爱测评（iceping）前台发起任何重复的资料修改申请。
- **信息判定隔离**：在信息核实审批空档期间，考生参与考试签到或报名核准时，全系统一律调取该考生的**未修改前的合法历史快照数据**进行校验，防范利用审核机制空窗伪造资料入场的合规缺漏。

## 功能四：监考卡片操作日志管理与离线溯源支持

### 1. 项目背景
- **需求简介**：在测评详情的考生监控卡片底部新增“查看日志”的操作通道，利用弹窗内数据表格形式结构化展示考生的系统级行为和业务交互记录，并支持一键提取保存。
- **业务诉求**：当场次发生断考、防作弊误判或网络交卷中断诉求时，监考与巡考人员能获得直白的行为溯源线索进行前置判定，并将完整报文导出转移给研发团队进行深层复查。

### 2. 业务流程简述
监考人员在详情页某考生的业务操作区点击“查看日志” -> 系统弹出专项日志浮层 -> 按业务时间节点序列化阅读行为简报 -> 如需下载查证，点击“导出日志”提取报表文件 -> 关闭弹窗返回主视口。

### 3. 详细功能说明

#### 3.1 唤起入口控制
- **交互定位**：位于某考生的详情卡片底部功能面板末端。
- **可用性判定**：如果被考评者的当前考试进度仍为“未开始”，其对应的“查看日志”应当处于置灰锁定状态，防范无效空查询。

#### 3.2 考试行为时序流面板
- **弹窗展示规范**：采用中心模态弹窗排版。
- **核心数据列表**：
  1. **发生时间**：记录关键节点的精确发生时间（例如 `2026-01-04 18:53:36`）。
  2. **业务转述摘要**：系统使用产品视角的非技术说明还原现场。如：“学员完成程序登录”、“检测到终端非法切屏”、“点击正式交卷操作”等。
  3. **完整报文折叠视区**：面向技术排障维度的操作报文支撑。鉴于报文字符冗长，对该列采用收纳拦截（折叠）处理，仅鼠标交互反馈时提示原信息内容，避免影响视觉查验。

#### 3.3 本地离线流转能力
- **文件导出执行**：点击“导出日志”后触发标准的数据下载行为。
- **文档输出属性**：生成通用数据表格（如 `.csv` 电子表格文件），默认按照 `日志文件_{特定考场号}_{考生姓名}_{日期时间}.csv` 的规范命名表单档案。

## 功能五：实践题批改效率优化 - 在线阅卷预览支持

### 1. 项目背景
- **需求简介**：在人工批改实践题附件场景中，改变传统的强制下载方式。针对常态化富媒体资源与特定文稿增加“预览”通道功能支持。
- **业务诉求**：节约主观多附件型试题的来回下载、寻找应用程式开启、分屏查分所造成的人员工作链路损耗。打造流畅直观的连贯阅卷体验通道。

### 2. 业务流程简述
阅卷方到达指定考生的试题给分区域 -> 展开审阅其交卷附件文档列表 -> 系统动态识别评估是否属展示能力的常规资源 -> 在原“下载”项附近渲染“预览”操作按键 -> 人员点击即可通过平台前端窗口即时查阅并开展资料查验工作 -> 查核无误后直接执行评分与提交流程。

### 3. 详细功能说明

#### 3.1 可视化预览过滤与显性触发
- **触发定位**：作为附件条目操作队列，紧随【下载】功能项并列露出展现。
- **内部白名单识别管控策略**：
  - **支持在线查阅范畴**：系统底层支持展现的主流文件格式（含静态/动效图片、音视频文件媒体库、PDF档案文本及多数直读无码化的代码内容后缀等格式内容），予以正常显示出【预览】按钮键。
  - **规避隔离处理类型**：涉及特定压缩格式及可执行文档范畴由于欠缺平台内查验支撑与安全验证支持，页面则保持原状，仅提供【下载】通道用于线外下落工作机排查使用。

#### 3.2 大画幅内容装载容器组件
- **展现形式**：引入内嵌居中的全局大弹窗预览阅览工具组件。
- **功能体验要素**：
  - 首栏部分附带当前待查文档名的清晰身份标识标语；匹配配置醒目的快捷关闭路径退出按钮；可并行布置一份便利快速存档原始文档的安全提取交互按钮。
  - 中心展示交互区由系统依附底层相应的视图检视器或阅读流媒介插件将具体考点信息完美内嵌置中。同时保有相应的滚动拖拉和大小微观操控支持。

#### 3.3 流程链路剥离设计原则
- 整个内嵌文档窗口展示操作闭环将严格限于自身模块展示内，完全不影响或挪动原有最下半部用于记录与敲定核心评定结果功能逻辑。保证教师阅改判定核心作业习惯不会被破坏干涉影响。

## 功能六：多教师阅卷流转控制（并判冲突防御拦截）

### 1. 项目背景
- **需求简介**：对“批改数据管理模块”执行的“手动批改”打分发起动作构建系统级的状态锁定检测以及异常接管机制。
- **业务诉求**：避免多名审核人员由于同时抢占对同一张答卷展开重复批改操作导致的时间资源沉网、或是因意外覆盖导致评分结论失效的教学事故。以事前检测配合可接管越级逻辑彻底防范审阅分配乱序。

### 2. 业务流程简述
评审账号用户对成绩名录下的既定考卷下达【手动批改】接指指令 -> 平台端核验该单试卷后台状态标识 -> 若闲置未被锁定且并未结单生成记录 -> 则进入常态化批改进度；**当发生异常判定（此单当前在锁且处于审批态、亦或之前已通过审批）** -> 阻断进程页面并利用正向拦截警示框悬停意向并发出抉择对话请求 -> 审批人员此时可点击响应并撤止或是决断选取最高权限将流程盖面接管夺权覆核。

### 3. 详细功能说明

#### 3.1 跨端前置碰撞校验机制
- **执行点位**：测评管理端查询明细列表进入学生判分项发生成绩批断点接指令前的时机触发阻挡干预检测防线。
- **碰撞报警门槛**：
  - **进行期占坑冲突**：内部探测体系发现卷子处理被锁进且已派生占领活跃判定标志不为空缺。
  - **确权覆盖冲突**：内部确认单据归类判定标识中包含评卷完成与下放给结果落地的终极成绩完结标志存在。
  - 任意一项触发预警红线拦截体系即中断常规进程向 3.2 下达干涉控制权提示。

#### 3.2 并判防覆交互干预提醒窗口
- **阻绝反馈呈现部署**：页面生成阻扰指令前行的明显信息对话组件悬停并阻拦底页操作环境影响。
- **文案组织体系建立**：提供明确的阻燃提醒口令语：`【有人正在处理此考卷/此考卷已被评估完毕。确认仍要开展评分核实复查接入吗？】`。（具体执行字眼遵循全局统一步调规范统一输出兜底合用句子提示为主方案导向）。
- **流程结果处置权限与功能键归属机制说明**：
  - 界面限制操控者必需做出决策且只留两条闭口结局供其干涉反馈点单挑选处置后续去往哪里：
  - **【取消 / 放弃动作】反馈**：退出操作阻断体系环境，消除刚刚因操作动作发出的警告痕迹返回最先初试总报表继续浏览挑选其他对象工作进行。
  - **【接管指令：强行确认批改】下发效维结果说明**：处理人员未正常清理状态或因特定核覆修正场景启用之特殊高阶通道。指令生效产生越权替换控制后：直接剪断前期相关账户对这份资料一切旧约束归属属性羁绊并消除封锁凭证占位以及推翻既有归档案记录打分效果，把完整进入评价界面的全新操控凭据过继交给实施本次覆盖强行的教师操作者管理拥有。当该次最新分数经填入落盘提呈并确证时；代表新成绩接驳入库盖覆，宣告处理终期全业务彻底结束。
