# 渠道选择 — PRD

## 1. 背景

### 1.1 问题

AISE 支持多个 B 端渠道合作（如 AISE 官网、作业帮、学而思等），不同渠道有独立的用户体系，各自完成注册流程。但所有渠道用户共享 AISE 官网的统一登录入口。

当同一个自然人在多个渠道分别注册时，会形成多套独立账号。这些账号可能使用相同的用户名和密码，但彼此不互通。现有登录流程不区分渠道，当一组凭证对应多个渠道账号时，系统无法确定用户意图，存在登录到错误渠道账号的风险。

### 1.2 目标

在登录流程中插入渠道检测环节，确保用户在存在多渠道账号时可以自主选择目标身份，消除登录歧义。

## 2. 范围

### 2.1 涉及页面

| 页面 | 类型 | 说明 |
|------|------|------|
| 用户端登录页 | 修改 | 登录按钮点击后增加渠道检测逻辑 + 渠道选择弹窗 |

### 2.2 不涉及

- 渠道注册流程的修改
- 后台管理端的渠道管理
- 渠道之间的数据打通
- 用户端其他页面的渠道感知

## 3. 用户故事

**作为** AISE 的用户，
**当** 我的同一组账号密码在多个渠道都注册过，
**我希望能** 在登录时选择以哪个渠道身份进入系统，
**以便** 访问对应渠道的历史数据和学习记录。

## 4. 交互流程

### 4.0 核心匹配规则

渠道检测以「用户名 + 密码」组合为依据，而非仅凭用户名：

- 系统查询：该用户名下，哪些渠道的密码与用户输入的密码匹配
- 只有密码匹配的渠道才进入候选列表
- 同一个用户名在不同渠道可能设置相同密码，也可能设置不同密码

示例：

| 用户名 | 渠道 | 密码 | 输入密码 a 时 | 输入密码 c 时 |
|--------|------|------|---------------|---------------|
| user1 | AISE 官网 | a | 候选 | — |
| user1 | 作业帮 | a | 候选 | — |
| user1 | 学而思 | c | — | 候选 |

- 输入密码 a → 匹配 2 个渠道（AISE 官网 + 作业帮）→ 弹窗选择
- 输入密码 c → 匹配 1 个渠道（学而思）→ 不弹窗，直接登录

### 4.1 单渠道流程（密码只匹配 1 个渠道账号）

1. 用户在登录页输入账号、密码、验证码
2. 点击「立即登录」
3. 按钮变为「检测中...」，禁用
4. 系统以「用户名 + 密码」组合查询，仅匹配到 1 个渠道账号
5. 直接登录成功，跳转回触发登录的前置页面

此流程与现有登录行为一致，零用户感知。

### 4.2 多渠道流程（密码匹配 2 个及以上渠道账号）

1. 用户在登录页输入账号、密码、验证码
2. 点击「立即登录」
3. 按钮变为「检测中...」，禁用
4. 系统以「用户名 + 密码」组合查询，匹配到 2 个及以上渠道账号
5. 弹出渠道选择弹窗（见 4.3），弹窗仅列出密码匹配的渠道
6. 用户点击某个渠道账号卡片 → 卡片进入选中态，底部按钮激活
7. 用户点击「以该身份登录」
8. 弹窗关闭，以所选渠道身份登录，跳转回前置页面

### 4.3 渠道选择弹窗

#### 遮罩层

- 全屏覆盖，半透明深色背景（rgba(15,23,42,0.6)）
- 模糊效果（backdrop-filter: blur(4px)）
- 点击遮罩关闭弹窗（等同于取消），回到登录页
- 弹窗出现/消失有 0.25s 淡入淡出动画

#### 弹窗主体

- 居中白色卡片，16px 圆角
- 宽 440px，最大 90vw；高不超过 80vh
- 阴影：0 25px 50px -12px rgba(0,0,0,0.25)

#### 弹窗头部

- 标题：「检测到多个关联账号」（18px 加粗）
- 副标题：「请选择您要登录的渠道身份」（13px 灰色）

#### 渠道账号卡片列表

- 可滚动区域，上下 12px 内边距
- 每张卡片展示：

| 元素 | 位置 | 说明 |
|------|------|------|
| 头像 | 左侧 44×44px 圆形 | 有头像图时显示图片，无图时显示用户姓名首字（灰底白字） |
| 用户姓名 | 中间上方 | 15px 加粗 |
| 渠道名称 | 中间下方 | 12px 灰色 |
| 首次注册时间 | 右侧上方 | 11px，格式：首次注册 YYYY-MM-DD HH:MM |
| 最近登录时间 | 右侧下方 | 11px，格式：最近登录 YYYY-MM-DD HH:MM |

- 默认状态：灰边框（#e2e8f0）
- hover 状态：浅蓝边框（#93c5fd）
- 选中状态：蓝边框（#2563eb）+ 浅蓝底色（#eff6ff）

#### 弹窗底部

- 取消按钮（白底灰字描边，flex:1）→ 关闭弹窗，回到登录页
- 确认按钮（flex:2）
  - 未选中任何渠道时：灰底灰字，不可点击（cursor: not-allowed）
  - 选中渠道后：深色渐变背景白字，可点击（cursor: pointer）

### 4.4 取消 / 关闭弹窗

- 点击取消按钮、点击遮罩层 → 关闭弹窗
- 关闭后回到登录页，不清空已填写的账号、密码、验证码
- 用户可以再次点击登录重新触发检测

### 4.5 登录后跳转

- 登录成功后的跳转目标不由此功能定义
- 由触发登录的前置页面决定（如首页、报名流程等）
- 保持现有跳转逻辑不变

## 5. 非功能说明

### 5.1 检测延迟

- 渠道检测为异步操作，预计耗时不超过 3 秒
- 前端显示「检测中...」状态，按钮禁用防重复提交
- 超时处理：超过 5 秒未返回结果，按钮恢复，提示「检测超时，请重试」

### 5.2 无渠道账号

- 检测结果为 0 时按现有逻辑处理：「账号或密码错误」

### 5.3 渠道数量

- 弹窗卡片列表支持任意数量的渠道账号
- 超过弹窗可视高度时出现纵向滚动条
- 卡片列表使用页面级滚动条样式（custom-scroll）

## 6. 数据

### 6.1 渠道账号数据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| channelId | string | 渠道唯一标识 |
| channelName | string | 渠道显示名称（如「AISE 官网」「作业帮」） |
| userName | string | 该渠道账号的用户姓名 |
| avatar | string / null | 头像 URL，null 时使用首字母头像 |
| firstRegisterTime | datetime | 该渠道账号的首次注册时间 |
| lastLoginTime | datetime | 该渠道账号的最近一次登录时间 |

### 6.2 接口定义（供后端参考）

```
POST /api/auth/login
Request: { account, password, captcha }
// 后端以 account + password 组合匹配渠道账号，
// 而非仅按 account 查询全部渠道。
// 只有密码匹配的渠道才进入 channels 列表。
Response: {
  code: 0,
  data: {
    needChannelSelect: boolean,
    channels: [                     // 仅包含密码匹配的渠道
      {
        channelId: string,
        channelName: string,
        userName: string,
        avatar: string | null,
        firstRegisterTime: string,  // ISO 8601
        lastLoginTime: string       // ISO 8601
      }
    ],
    token: string | null            // 单渠道时直接返回 token
  }
}
```

## 7. 边界与异常

| 场景 | 处理 |
|------|------|
| 用户名+密码匹配 1 个渠道 | 不弹弹窗，直接以该渠道登录 |
| 用户名+密码匹配 2+ 个渠道 | 弹出弹窗，仅列出密码匹配的渠道供选择 |
| 用户名下存在多个渠道，但当前密码只匹配其中一部分 | 弹窗仅显示密码匹配的渠道；密码不匹配的渠道不出现在弹窗中 |
| 用户名下存在多个渠道，但当前密码一个都不匹配 | 等同于「账号或密码错误」 |
| 弹窗中未选择直接关掉 | 回到登录页，表单数据保留 |
| 弹窗中切换选择 | 上一个卡片取消选中，新卡片选中，确认按钮保持激活 |
| 检测接口超时 | 提示用户重试 |
| 检测接口返回异常 | 提示用户重试 |

## 8. 视觉

- 延续现有登录页设计语言：Inter 字体、slate 灰 + brand blue 色系、12px 圆角
- 弹窗卡片使用与页面一致的阴影和过渡效果
- 头像默认态：灰色圆形底（#e2e8f0）+ 白色首字母文字
