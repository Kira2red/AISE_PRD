# 场景锚点：测评多考场

## 产品定位

AISE 标准测评报名流程升级：将现有的「一个测评活动 = 一个固定时间段」模型改为「一个测评活动 = 多个考场（时间段）」，用户报名时自主选择考场。

## 现有系统基线

### 当前模型

- 测评活动有唯一开始时间和结束时间（datetime-local 输入）
- 用户报名流程：协议同意 → 填写信息（机构/项目/个人信息）→ 确认 → 支付
- 支付成功即报名完成，自动进入该测评的唯一考场
- admin 端没有独立的「考场」概念，时间属于测评活动属性

### 当前配置字段（admin/05_新建测评活动.html）

| 字段 | 类型 | 说明 |
|------|------|------|
| 测评名称 | 文本 | - |
| 开始时间 | datetime-local | 单个时间 |
| 结束时间 | datetime-local | 单个时间 |
| 测评时长 | 数字（分钟） | 考试时长 |
| 交卷时间限制 | 数字（分钟） | 开考后禁止提前交卷时间 |
| 标签配置 | 多选标签 | - |
| 模拟考配置 | 开关+子配置 | 可选 |

### 当前报名流程（user/08_考试报名_主页.html）

1. 报名须知 → 2. 填写信息 → 3. 确认 → 4. 支付

填写信息步骤中：
- 渠道识别码（选填）
- 所属机构/学校（下拉）
- 报名测评项目（下拉，依赖机构）
- 考生姓名、身份证号、性别、邮箱
- 照片上传
- 监护人信息、地址

**没有考场选择步骤。**

## 目标模型

### 新增「考场」实体

一个测评活动下可配置多个考场，每个考场有：
- 考场名称（如「上午场 9:00-10:30」）
- 开始时间
- 结束时间
- 容量上限（人数）
- 所属级别标签（用于用户端分组展示）

### 用户报名流程变更

报名流程变更为：
1. 报名须知
2. 选级别（如该测评有多个级别分组）
3. 选考场（展示该级别下可选时间段，含剩余名额）
4. 填写信息 → 5. 确认 → 6. 支付

### 关键约束

- 一个考场时间到了自动截止报名（或提前满员截止）
- 考场满员后在前端标记为「已满」，不可选
- 已报名的考场不允许删除/修改时间
- admin 端可查看每个考场的报名人数/剩余容量

## 涉众

- **运营方（admin）**：配置测评活动的多个考场，查看报名情况
- **C 端用户**：报名时选择考场
- **合作方（org_admin）**：查看渠道下的考场报名情况
- **爱测评底层**：考场数据需同步到考试引擎

## 涉及页面

### admin 端（修改）
- `03_测评活动列表`：列表中可能需体现考场数
- `04_测评活动详情`：新增考场管理区域
- `05_新建测评活动`：新建流程中配置考场，或新建后独立管理考场
- `11_报名管理`：报名记录需显示所属考场

### user 端（修改 + 新增）
- `08_考试报名_主页`：插入「选级别→选考场」步骤
- `09_考试报名_填写信息`：可能不受影响（考场选择在前序步骤）
- `16_我的考试`：考试列表需显示考场信息
- `26_我的报名`：报名记录需显示所选考场

### org_admin 端（修改）
- `04_报名列表`：需显示考场维度
- `08_项目详情`：场次管理需支持多考场

## 业务规模

- 当前：每级别 6 个考场（上午 2 + 下午 4）
- 十月预计：4~6 个级别 = 24~36 个考场
- 单个测评活动的考场数可能达到 36 个
