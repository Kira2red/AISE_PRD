# 方案概要：测评多考场

> 版本：V2.1 | 日期：2026-07-10 | 作者：产品大师（审查整合）
>
> ⚠️ V2.1 变更：整合 Reviewer 审查发现（5🔴+12🟡+6🟢），主要补充切换自动创建考场、遗漏页面清单、停用通知处理、级别选择逻辑。

---

## 1. 概述

### 1.1 背景

AISE 当前测评模型为「一个测评活动 = 一个固定时间段」。随着考试规模增长（合作方「小鹿」每级别 6 个时间段，十月预计 4-6 个级别共 24-36 个考场），需要将测评从单考场升级为多考场。

### 1.2 两种模式

| | 单考场模式（现有） | 多考场模式（新增） |
|------|------|------|
| 测评配置 | 开始时间、结束时间、时长、交卷限制、标签、模拟考 | 仅开始时间、结束时间（作为边界约束） |
| 考场配置 | 无独立考场概念 | 每个考场独立配：名称、时间、时长、交卷限制、标签、模拟考、容量、级别标签 |
| 用户报名 | 选机构→选项目→填信息→支付 | 选机构→选级别→选考场→填信息→支付 |
| 切换方式 | 默认模式 | 运营手动切换，不可逆 |

## 2. 数据模型

### 2.1 测评活动（Activity）新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 考场模式 | 枚举 | `single`（默认）/ `multi`，从 single 切到 multi 不可逆 |

切换后：测评级的时长、交卷限制、标签、模拟考配置**保留不删**（仅供历史参考），实际考试不再使用。

### 2.2 新增：考场（ExamRoom）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 考场 ID | - | - | 主键 |
| 所属测评活动 ID | 外键 | ✅ | |
| 考场名称 | 文本 | ✅ | 如「上午场 9:00-10:30」 |
| 开始时间 | datetime | ✅ | 必须 ≥ 测评开始时间 |
| 结束时间 | datetime | ✅ | 必须 ≤ 测评结束时间 |
| 测评时长 | int（分钟） | ✅ | |
| 交卷时间限制 | int（分钟） | ✅ | 必须 ≤ 测评时长 |
| 标签配置 | 多选标签 | 否 | 从标签体系中选择 |
| 模拟考配置 | JSON | 否 | 子字段：开关、模拟卷来源、模拟考起止时间、次数限制 |
| 容量上限 | int | ✅ | ≥0，0=不限。修改时不能低于已报名人数 |
| 已报名人数 | int（计算列） | - | |
| 级别标签 | 枚举 | 否 | 从标签体系预定义中选择，用于用户端分组 |
| 报名截止时间 | datetime | 否 | 默认=开始时间前30分钟。必须 ≤ 开始时间且 ≥ 创建时间 |
| 排序 | int | ✅ | |
| 状态 | 枚举 | ✅ | `active` / `inactive` |
| 创建时间 | datetime | - | |
| 更新时间 | datetime | - | |

### 2.3 报名记录（Registration）

新增字段：`考场 ID`（外键）。

## 3. 单考场→多考场切换

### 3.1 切换确认弹窗

弹窗内容：
> 切换为多考场模式后：
> ① 当前测评的时长、交卷限制、标签、模拟考配置仅供历史参考，不再对考试生效
> ② 系统将自动创建一个默认考场，继承当前测评的时间配置
> ③ 此操作不可撤销
>
> 确认切换？

运营确认后，系统自动：
1. 将测评的考场模式改为 `multi`
2. 创建 1 个默认考场：名称「{测评名称} - 默认考场」，时间/时长/交卷限制/标签/模拟考均继承测评级当前值，容量不限
3. 批量回填存量报名记录的考场 ID 为该默认考场 ID

### 3.2 切换后

- 测评编辑区域仅保留开始时间、结束时间（可编辑）
- 测评级时长/交卷限制/标签/模拟考保留展示但标注「仅供历史参考」，置灰不可编辑
- 下方展示「考场管理」区域

## 4. admin 端改动

### 4.1 测评活动列表（03_测评活动列表）

- 新增「考场模式」列（单考场/多考场）
- 多考场显示考场数量

### 4.2 测评活动详情页（04_测评活动详情）

**单考场模式下**：现有编辑区域不变。

**多考场模式下**：

顶部统计卡片：考场总数、总容量、已报名总数、剩余总容量。

考场管理区域：

- **考场列表表格**：名称 / 时间 / 时长 / 交卷限制 / 标签数 / 模拟考 / 容量(已报名/上限) / 级别 / 排序 / 状态 / 操作
- **新建考场** → 弹出编辑弹窗
- **编辑考场**：已有报名的考场禁止修改开始/结束时间
- **删除考场**：已有报名（含已退款）禁止删除；无报名可删除，需二次确认
- **停用考场**：弹窗提示「该考场已有 N 人报名，停用后他们仍可正常参加考试」，确认后考场状态变为 inactive，前端不再展示
- **排序**：表格内拖拽排序或上移/下移按钮
- **考场克隆**：每行增加「复制」操作，快速克隆考场（仅复制配置不复制报名数据），克隆后自动命名为「{原名称} - 副本」

### 4.3 考场编辑弹窗

| 字段 | 必填 | 校验规则 |
|------|------|---------|
| 考场名称 | ✅ | |
| 开始时间 | ✅ | ≥ 测评开始时间 |
| 结束时间 | ✅ | ≤ 测评结束时间 |
| 测评时长（分钟） | ✅ | |
| 交卷时间限制（分钟） | ✅ | ≤ 测评时长 |
| 标签配置 | 否 | 多选下拉 |
| 模拟考配置 | 否 | 开关展开子配置 |
| 容量上限 | ✅ | ≥0，修改时不能 < 已报名人数 |
| 级别标签 | 否 | 枚举下拉 |
| 报名截止时间 | 否 | 默认=开始前30分钟，必须 ≤ 开始时间 |
| 排序 | ✅ | 数字 |
| 状态 | ✅ | 开关（active/inactive） |

### 4.4 测评时间修改联动校验

编辑测评的开始/结束时间时，校验是否导致考场时间越界。如有考场开始时间 < 新测评开始时间 或 结束时间 > 新测评结束时间，**阻止保存**并提示「有 N 个考场的时间超出新的测评时间范围，请先调整考场时间」。不允许静默保存。

### 4.5 报名管理（11_报名管理）

- 新增「考场」列
- 筛选区新增「考场」下拉
- 导出含考场信息

## 5. user 端改动

### 5.1 报名流程

**单考场测评**：沿用现有 4 步，无变化。

**多考场测评**：动态步骤：
```
协议同意 → [选级别] → [选考场] → 填写信息 → 确认 → 支付
```
（[] = 条件跳过）

### 5.2 分支逻辑

| 条件 | 行为 |
|------|------|
| 可用考场的级别标签去重后 ≤ 1（含全部为空） | 跳过「选级别」，按 1 个默认分组展示考场 |
| 当前级别下可用考场数 = 1 | 自动选中该考场，仍展示确认界面 |
| 当前级别下可用考场数 = 0 | 该级别在选级别页置灰标注「已满/已截止」 |

「可用」定义：`状态=active + 未满员（已报名 < 容量或容量=0）+ 未过报名截止时间`。

### 5.3 选考场

- 考场卡片：名称、时间、时间段、剩余名额（如「15/50」）、满员置灰
- 名额≤5 时红色提示
- 名额 15 秒轮询刷新

### 5.4 填写信息

- 顶部固定已选考场信息
- 报名测评项目字段根据考场反查，自动带入不可修改

### 5.5 已填信息回退

用户从填写信息退回选考场或选级别时，已填的个人信息保留不清空。只有当用户选择不同考场并重新进入填写信息页时才刷新项目字段。

---

## 6. 边界条件

| 场景 | 处理 |
|------|------|
| 容量缩小 < 已报名人数 | 阻止保存，提示「当前已报名 N 人，容量不能低于 N」 |
| 报名截止时间 ≥ 开始时间 | 阻止保存 |
| 考场时间超测评范围 | 前端+后端双重校验阻止 |
| 测评时间收缩导致考场越界 | 阻止保存，提示需先调整考场 |
| 已报名考场修改时间 | 禁止 |
| 已报名考场删除 | 禁止（含已退款报名） |
| 考场停用 | 二次确认弹窗说明影响人数；已报名用户仍可参加考试，前台不再展示 |
| 考场满员 | 前端置灰，支付前最终校验 |
| 并发超报 | 行级锁 + 支付前校验，失败提示「该考场名额已被抢完」 |
| 全部考场不可用 | 选级别页该级别显示「已满/已截止」 |
| 用户退回修改级别/考场 | 已填信息保留，项目字段随新考场刷新 |

## 8. 设计决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 单/多考场模式 | 二分，不可逆 | 存量兼容简单，避免混用混乱 |
| 切换时自动创建考场 | 是，1 个默认考场 | 避免切换后无考场导致无法报名 |
| 考场配置 | 完全独立，从零配 | 不同考场可不同时长/标签/模拟考 |
| 测评时间 | 边界约束，收缩时校验 | 保证所有考场时间合法 |
| 考场克隆 | 提供 | 36 个考场逐个配太繁琐 |
| 容量修改 | 不能低于已报名人数 | 防止数据不一致 |
| 考场时间重叠 | 允许，不阻止 | 业务场景可能同时开多个考场 |
