# 证书模板迁移与实例选择 · 产品方案 V1

> 需求名：证书模板迁移与创建测评时选择证书实例
> 日期：2026-09-21 ｜ 状态：阶段一方案已确认（Q1-Q5 已拍板），进入阶段二 demo
> 需求提出：张二红（方案口径已确认）＋ Micheal 考务反馈（2026-09-21 群聊）

## 1. 背景与目标

AISE 电子证书存在新旧两套并存的生成逻辑：
- 旧逻辑：测评打「证书模板」标签（运营自建属性，3 个标签值），证书按标签生成——无 PRD 定义，3 套证书写死在代码里
- 新逻辑：20260512 上线的三层模型（证书模板 → 证书实例 → 用户证书），实例按测评逐场手动绑定——正式测从未使用，测试环境所有测评「电子证书」均为未配置

痛点：正式测每场考后需手动建实例（10 月测评 17 个考场要重复 17 次），运营负担重且无人执行。

目标（一句话）：把 3 套写死证书迁入「证书模板管理」，创建测评时直接选证书实例，考后自动出电子证书，运营零重复操作。

## 2. 用户故事

- 作为考务运营，我在新建测评时选好证书实例，考试结束后电子证书自动生成，不再逐场手动配置（价值依据：D，Micheal 2026-09-21 反馈 17 场重复操作）
- 作为运营，我能在证书模板管理里维护 3 套证书的内容字段（年份、参测模块等），模板改了以后新生成的证书自动用新内容（价值依据：D，历史证书内容与标签脱节）
- 作为运营，我仍然能在 14_测评证书管理看到每场测评的电子证书配置状态，漏配的能补配（价值依据：D，20260512 已定义但未用起来的入口）

## 4. 核心流程（新）

```
创建测评/批量创建 → 选证书实例（选一次，多考场继承）
    → 考试结束 → 批改 → 待复核环节按实例自动出电子证书
    → 14_测评证书管理 电子证书列显示「已配置」
未选实例的测评 → 电子证书列「未配置」→ 考务可在 14 点「配置电子证书」补绑（兜底）
```

预备测路径不变：仍按渠道维度在 28 一次性配置。

## 5. 边界与异常场景

| # | 场景 | 处理方案（建议） |
|---|---|---|
| B1 | 创建测评时未选实例 | 允许留空（兼容存量习惯），电子证书列显示未配置，考后可补绑；表单加引导文案 |
| B2 | 实例被禁用但有测评引用 | 拦截并提示「有 N 场测评正在引用」，提供批量换绑或先解绑再禁用 |
| B3 | 实例绑定的模板被修改 | 沿用 20260512 原则：只影响之后新生成的证书，已签发不变 |
| B4 | 存量测评打了标签但已出过证书 | 不动已出证书；仅补「电子证书配置状态」显示，不重新生成 |
| B5 | 一场测评同时有标签和实例 | 以实例为准，忽略标签；迁移完成后标签仅存档 |
| B6 | 批量创建时部分考场想用不同实例 | 批量选一次为基础，生成后可在 33 活动详情对单个测评行内改选（走行内编辑） |
| B7 | 模板必填字段（如参测等级）在测评无对应数据 | 签发时该字段留空并记录告警，不阻断整场签发 |
| B8 | 3 套证书迁入后样式与线上现有证书不一致 | 迁移时以线上现行证书为样式基准做底图，完成后测试环境比对验收 |
| B9 | 弹窗勾选的实例与测评数据不匹配（模板必填字段无对应数据） | 保存时校验并提示具体不匹配字段，不阻断其他测评配置 |

## 6. 成功度量

- 10 月测评正式测电子证书「已配置」比例 100%（来源：14_测评证书管理筛选统计，目标值）
- 考后手动建实例操作次数：从每场 1 次 → 0 次（来源：28 实例管理操作日志）
- 首个考期后回访考务确认无重复操作痛点（来源：考务反馈，定性）

## 7. 风险与依赖

- 依赖 28_证书实例管理模型调整（配置/运行数据分离），是本需求最大研发工作量（F3）
- 3 套写死证书的底图与样式需要开发从代码中导出（F1 前置条件）
- 存量补绑（F5）需先盘点测试/正式环境打了「证书模板」标签的测评清单
- 旧标签退役（F6）放 P2，避免一次性改动过多
