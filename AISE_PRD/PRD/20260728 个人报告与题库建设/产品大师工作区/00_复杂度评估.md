## 2. 复杂度评估

### 2.1 维度评分（按 lead-pm-prompt 维度表）

| 维度 | 评分 | 说明 |
|------|------|------|
| 功能范围 | ⚠️ 偏复杂 | 多模块：报告详情页（新增）+ user/15、user/20 入口改造 + 服务端生成链路 |
| 硬件依赖 | ✅ 简单 | 纯软件，无硬件依赖 |
| 用户场景 | ✅ 简单 | 单角色（考生/家长），查看报告 + PDF 下载为主 |
| 竞品参考 | ⚠️ 部分参考 | 无外部成熟竞品；但有内部权威样式依据（PDF 内嵌图 + 像素级提取规格，C 级依据） |
| 数据要求 | ✅ 简单 | 等级映射/掌握率公式/文案表已在底稿明确定义，无外部行业数据需求 |
| 交互复杂度 | ⚠️ 偏复杂 | 单页面渲染为主，但含跨页面流转（user/15、user/20 → 详情页）与两入口按钮并存矩阵 |

### 2.2 总复杂度：🟡 中等（建议轮次上限 10 轮/子任务）

判定理由：3 个维度偏复杂（功能范围、竞品参考、交互），未达「复杂」档（无多角色协作、无跨系统硬件交互）；权威样式规格已像素级提取，数据要求低。

### 2.3 Controller 微调意见

接受 Lead PM 评估（🟡 中等）。S4（demo HTML）评估为 🟢 简单（5 轮）：单页面纯前端重写、样式数据已精确提取、无交互逻辑；若执行中样式还原争议超预期（如小提琴图 SVG 形态核验），Controller 可升档至 🟡 并扩轮次。期望各子任务 2-3 轮收敛，不空耗上限。

## 4. 关键风险与执行注意

1. **样式冲突（T1）是最大风险点**：S2 与 S4 必须全程以 page2_img1设计规格.md 为基准，PRD 样式章节显式登记新旧冲突与采纳口径，防止 Reviewer 以旧色板（业务需求 2.3 引用）判 demo 不符。
2. **证据驱动**：所有 PRD 结论附出处（业务需求章节号 / 设计规格段号 / 色值提取来源），禁止臆造；用户价值判断按 A-E 级标注依据（内部权威样式 = C 级）。
3. **demo 自验**：S4 完成后浏览器打开核对 390px 视口下 11 段布局、胶囊色值（绿 #33CD52/#E6F4E8、橙 #F27915/#F5EFE8、靛 #4E35CF/#553ECC）、代码块 #0F1A36；「无视觉模型」环境下以像素提取数据为唯一事实源。
4. **跨 PRD 边界**：生成链路依赖证书签发 PRD（20260512）的队列机制，S3 只引用不重造；题库知识点字段依赖题目录入侧独立 PRD。
5. **轮次耗尽预案**：任一子任务 3 轮内出现死锁（连续 3 轮立场无变化）即提交用户 A/B/C 裁决，不空耗上限。
