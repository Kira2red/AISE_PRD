## 2. 方案正文

### 2.1 背景与目标

- **目标产品**：AISE 考级平台 user 端「个人考级报告」，纯软件功能（评估 1.1；业务需求 需求总览）。
- **目标**：成绩发布后自动生成五模块报告（标题栏 / 考级结果概览 / 知识点掌握情况 / 考级具体表现 / 下一阶段建议），内容字段、判定逻辑、文案全部有据可依；demo 数据口径与 PRD 数据契约一致（T5）。
- **核心用户**：考生 / 家长，单角色查看场景（评估 1.1，用户场景评分「简单」）。
- **范围边界**：本规格只定义**内容逻辑**（字段、规则、文案、排序、边界）；样式还原归 S2；生成时机/入口/异常归 S3；demo HTML 归 S4；PDF 服务端生成归服务端链路（T6）。
- **已锁定决策遵守登记**（逐条落实，供 Reviewer 核验）：

### 2.4 核心内容逻辑规格（五模块字段级）

**数据契约（所有模块的数据来源，先行声明）**

| 数据项 | 来源/规则 | 出处 |
|--------|----------|------|
| 正式总分 score | 考试系统正式发布总分；**不取整、不四舍五入、不重新汇总** | 业务需求 1.3.1 |
| 题目「知识点」字段 | 每道题带一级/二级/三级知识点；三级入库、前端不展示；题目标签≠知识点，不可替代 | 业务需求 补充说明#1 |
| 题型（客观题/编程题） | 两套画像取题依赖题型判定；数据源=题目录入侧（独立 PRD） | 业务需求 1.5.1 + 待确认 W8 |
| 学生作答原文 | 客观题选项 + 编程题代码，用于展示与点评 | 业务需求 1.5.1 |
| 级别（一级~八级） | 考试报名级别，标题栏与建议模块共用 | 业务需求 1.2/1.6 |
| demo 数据 | 全部为示例值，统一标注「示例数据，字段口径以 PRD 数据契约为准」 | 评估 T5 |

#### 2.4.2 模块二 考级结果概览（对应设计规格第 4-7 段，评估 T4）

**a. 等级映射表（唯一事实源，不允许二次计算）** — 业务需求 1.3.1

| 正式总分 score | 通过状态 | 报告等级 | 所处成长区间 |
|---------------|---------|---------|------------|
| 0 ≤ score < 30 | 未通过 | 待提升 | 初步形成 |
| 30 ≤ score < 60 | 未通过 | 待提升 | 稳步接近 |
| 60 ≤ score < 70 | 通过 | 合格 | 目标达成 |
| 70 ≤ score < 80 | 通过 | 良好 | 熟练掌握 |
| 80 ≤ score ≤ 100 | 通过 | 优秀 | 高阶表现 |

- 边界精度：分数可为小数（不取整），判定用左闭右开区间；score=100 唯一闭区间。单测覆盖点：0、29.99、30、59.99、60、69.99、70、79.99、80、100（见 2.6-M1）。
- 使用正式发布总分，禁止前端/服务端重新汇总（1.3.1）。

**b. 成长区间小提琴图规则** — 业务需求 1.3.2

| 规则项 | 内容 |
|--------|------|
| 轴线类型 | **类别轴**，非连续分数轴 |
| 五段宽度 | 30% / 30% / 20% / 10% / 10%（左→右） |
| 五阶段（左→右） | 初步形成、稳步接近、目标达成、熟练掌握、高阶表现 |
| 标记位置 | 固定于对应阶段中心，不随阶段内具体分数移动；五中心=15% / 45% / 70% / 85% / 95% |
| 满分特例 | score=100 时标记取 100% |
| 图形含义 | 仅表示五个阶段，**不代表人数或真实样本分布** |

**c. 一句话总结文案表**（按报告等级匹配，非按区间） — 业务需求 1.3.3

| 报告等级 | 文案（原文，不得改写） |
|---------|----------------------|
| 待提升 | 综合本次考级表现，本级基础正在逐步形成，建议继续巩固核心任务。 |
| 合格 | 综合本次考级表现，已达到本级基本要求，可继续巩固并拓展。 |
| 良好 | 综合本次考级表现，已较稳定达到本级要求，可进一步提升综合应用。 |
| 优秀 | 综合本次考级表现，已高质量完成本级主要任务，可继续挑战更复杂的综合任务。 |

**d. 等级胶囊 = 通过状态视觉化** — 评估 T4：报告等级以「本次等级」绿胶囊呈现（demo 值「良好」），未通过时等级=「待提升」；胶囊色值/形态归 S2（绿 #33CD52/#E6F4E8 系，评估 4.3）。

**e. 「同级参照」橙胶囊** — 评估 T4/T5：结果概览固定展示元素（demo 值「熟练掌握」=成长区间，橙 #F27915/#F5EFE8 系）；其完整文案/语义以设计规格 4-7 段为准，由 S2 还原，S1 仅登记存在性与 demo 口径。

#### 2.4.3 模块三 知识点掌握情况（对应设计规格第 8 段，对齐点）

| 规格项 | 内容 | 出处 |
|--------|------|------|
| 知识树结构 | 一级知识模块 → 二级知识点；三级标签入库、前端不展示 | 业务需求 1.4.1 + 补充说明#1 |
| 各级别知识树 | 各级别有独立知识树；完整清单人工补充 | 业务需求 待确认#2（已闭环：人工补充） |
| 掌握度公式 | **该知识点关联题目的得分之和 ÷ 该知识点关联题目的满分值之和** | 业务需求 1.4.2 |
| 掌握状态阈值 | 作答数据 < 60% → 重点提升；≥ 60% → 稳定掌握 | 业务需求 1.4.2 |
| 展示排序 | 一级模块按知识树顺序；一级下二级标签按状态升序：**先「重点提升」、再「稳定掌握」**；同状态内按知识树顺序 | 业务需求 1.4.3 |
| 数据依赖 | 题目「知识点」字段（题目标签不可替代），实现归题目录入侧独立 PRD | 业务需求 补充说明#1 |
| demo 示例 | 四级（PL1）知识树表 12 行（Python运算/流程控制/常用标准库/编程基础），标注「示例数据」 | 业务需求 1.4.1 + 评估 T5 |

- 未定义项（需登记，见 W2/W3）：一题可挂知识点数量与得分计入规则；知识点无关联题目（分母=0）时的展示降级。

#### 2.4.4 模块四 考级具体表现（对应设计规格第 9-10 段，对齐点）

**两套展示逻辑**（触发条件按总分，满分画像=总分 100，非满分画像=总分 < 100）— 业务需求 1.5.1

| 规则项 | 满分画像（score = 100） | 非满分画像（score < 100） | 出处 |
|--------|----------------------|--------------------------|------|
| 展示题目数 | 1 道 | 2 道 | 1.5.1 |
| 题目选取 | **首道满分的编程题** | **首道错误的客观题 + 首道扣分的编程题** | 1.5.1 |
| 排序 | / | 按题号展示，客观题先于编程题；**如客观题全对则仅展示编程题** | 1.5.1 |
| 展示答案 | 只展示学生作答，**不展示正确答案** | 展示学生作答与正确答案 | 1.5.1 |
| 作答点评 | 固定文案「本题目作答达到要求，完整完成任务。太棒了！」 | 「建议重点提升【题目二级标签知识点】。」 | 1.5.1 |

**口径锁定**（对照运营口头规则，采用 PRD 原文，防止实现漂移）— 业务需求 1.5.3

| 维度 | 采用口径 | 不采用（口头旧规则） |
|------|---------|---------------------|
| 满分取题 | 首道满分的编程题 | 首道错题 |
| 非满分取题 | 首道错误客观题 + 首道扣分编程题 | 首道编程题 |
| 满分展示答案 | 只展示学生作答 | 展示正确答案 |
| 满分点评 | 固定文案 | 结合二级标签重点提升 |
| 非满分点评 | 结合二级标签 | 统一一句话文案 |

**编程题截断规则** — 业务需求 1.5.2：学生作答代码行数较多时，**统一保留前 5 行后截断**（≤5 行不截断；截断后无展开交互，V1 假设，W7）。

- 未定义项（需登记，见 W4/W5）：满分画像但试卷无编程题；非满分画像无客观题或无编程题。
