# 2. 第一部分：报告生成时机与用户端入口

## 2.1 背景与目标

- **目标产品/平台**：AISE 考级平台 user 端（考生/家长侧）+ 服务端异步生成链路。纯软件，无硬件依赖（00_复杂度评估.md 2.1：硬件依赖 ✅ 简单）。
- **核心用户画像**：
  - 考生（编程考级学员，一级～八级）与家长（代查代看报告）——登录态用户，走 user/15 我的活动；
  - 公开查询用户（姓名+手机号，可不登录）——走 user/20 成绩与证书独立页（业务需求梳理.md 2.2.2；证书 PRD 3.9/3.10 改造范围「查询条件新增证书编号」）。
- **业务目标**：考试成绩发布后，为每位有正式总分的考生自动生成个人考级报告，考生/家长在 user 端查看并可下载为 PDF；报告覆盖含未通过考生在内的全部考生，补齐未通过考生的服务闭环（业务需求梳理.md 需求总览 2、2.1）。
- **用户价值依据**：报告使考生从「看分数」升级为「看路径」（等级/成长区间/知识点/表现/建议五模块），为内部需求底稿明确诉求，标注为内部权威依据（C 级：内部需求文档）；「未通过考生无成果物」缺口为业务需求 2.1 明示（C 级）。

## 2.4 核心流程

### 2.4.1 生成时机

| 项 | 内容 | 出处 |
|----|------|------|
| 触发时机 | 与电子证书签发同一时机，**成绩发布后自动触发** | 业务需求 2.1 |
| 触发条件 | 考试批改完成且正式总分已发布 | 业务需求 2.1 |
| 触发方式 | 系统自动，无需人工操作 | 业务需求 2.1 |
| 逻辑校验 | 证书状态链路「等待成绩 → 生成中 → 待签发 → 已签发」，证书在成绩发布后进入生成队列（证书 PRD 3.9.2 结果卡片状态表）；报告依赖的三类数据（正式总分、题目知识点字段、学生作答）在批改完成、成绩发布后全部齐备 → 共用触发点可行 | 业务需求 2.1（逻辑校验）；证书 PRD 3.9.2 |
| 与证书差异 | 报告生成不依赖电子签章环节，生成完成即可查看；证书需签发完成（生成 PDF → 第三方签章 → 已签发）才可查看/下载。两者共用触发点、各自独立异步流水线 | 业务需求 2.1；证书 PRD 2.3/3.9.2（逻辑校验） |

### 2.4.2 覆盖范围

- **报告**：所有已批改且有正式总分的考生均生成（**含未通过**，呈现「待提升」等级）——业务需求 2.1。
- **证书**：仅覆盖成绩达标考生——证书 PRD 3.9.2「成绩未达标 → 未获得证书」（逻辑校验）。
- 两者同一时机触发、覆盖范围不同，为业务需求 2.1 明示；「未通过但有报告」是 user/20 按钮并存矩阵的独立差异行（§2.4.6 矩阵第 9 行）。

### 2.4.3 生成方式（引用证书队列机制，不重造）

- 异步任务生成：每个考生的报告为一条异步任务，经**消息队列**消费（参考证书 PRD 2.3「每个用户证书的签发为一条异步任务，通过消息队列消费；签发中心提供全局启停开关控制所有签发任务」——**只引用不重造**，00_复杂度评估.md 关键风险 4）。
- 失败重试与导出文件管理：建议复用 admin 消息中心能力（PRD_2red规范版 4.1 依赖模块表；索引文档 admin「系统支撑：消息中心」）。
- 全局启停开关：参考签发中心全局开关（证书 PRD 2.3、3.5.6「全局签发启停」），报告侧建议提供等价开关（§3.5 B4-1）。
- 架构选型：异步队列为**建议架构**，最终选型待技术评审确认（A20）。
- **入口约束**：生成完成后考试卡片才展示「查看报告」入口；成绩未发布或生成中的卡片不展示（业务需求 2.1、2.2.1）。

### 2.4.4 报告状态机

| 状态 | 触发条件 | 用户端表现 | 对应证书状态（逻辑校验） |
|------|---------|-----------|------------------------|
| 未生成 | 成绩未发布 | 不展示「查看报告」按钮 | 等待成绩（证书 PRD 3.9.2） |
| 生成中 | 成绩已发布、异步任务生成中 | 不展示「查看报告」按钮 | 生成中（证书 PRD 3.9.2） |
| 已生成 | 异步生成完成 | 展示「查看报告」按钮，可进入详情页 | 待签发 / 已签发（证书 PRD 3.9.2） |
| 生成失败（服务端任务态，不新增用户端状态） | 重试耗尽/超时置失败（建议：指数退避 + 重试上限 3 次 + 单任务超时 30 分钟，A19） | 等同「未生成」：不展示按钮；失败原因与手动重试仅 admin 端可见 | 证书侧失败走自身重试链路（证书 PRD 2.3/3.5.6 重签） |

- 用户端可见状态仅三态（未生成/生成中/已生成），生成链路失败、重试中等服务端任务状态不新增用户端可见状态（PRD_2red规范版 5.3.2 口径）。
- 状态流转图见 PRD_2red规范版 6.1（引用参考结构，S5 整合时收编）。

### 2.4.9 数据流（主链路）

```
考试系统（批改完成、正式总分发布）

    → 异步生成任务（消息队列消费，按考生批量）

            → 新页面打开详情页 → 五模块渲染 → （可选）PDF 下载
```

# 3. 第二部分：边界与异常场景穷举

## 3.1 处理策略总原则

- 处理策略优先级：**拦截 > 降级 > 重试 > 提示**；同一场景可组合使用（PRD_2red规范版 5.3.3）。
- 所有「建议」值（重试次数、超时时长、保留期、文案）为默认建议，最终以需求确认/技术评审结论为准。
- 编号体系：B1-x 数据异常 / B2-x 生成链路 / B3-x 用户端 / B4-x 容量；对应 PRD_2red规范版 5.3.3 的 S4-1-x/S4-2-x/S4-3-x/S4-4-x（S5 整合时映射）。

## 3.2 数据异常类

| 编号 | 异常场景 | 触发条件 | 处理方案 | 出处 |
