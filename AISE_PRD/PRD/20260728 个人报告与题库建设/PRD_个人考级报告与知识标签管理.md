# 一、需求背景

AISE 考级平台目前缺失两项能力：一是考生完成测评后没有完整的考级报告，无法看到等级评定、知识点分析、错题回顾和学习建议；二是后台缺少知识标签体系，题库标注当前依赖活动级标签（参测模块、参测等级），无法支持"一级知识模块→二级知识点→三级题库标签"的精细化管理。

本需求新增用户端考级报告页面，以及 admin 端知识标签管理模块。两模块通过三级标签衔接：后台录入的知识标签用于标注题库题目，前端报告根据考生作答情况生成知识点掌握分析。

本需求不改动已有 html demo 页面的功能和结构。新增页面遵循 AISE 现有设计风格。

**范围说明**：「题库建设」相关的录题界面改造（级别下拉、题目字段、题目筛选、Python 参考答案上传等）本期不在本需求范围内，由后续需求单独覆盖。本期仅完成知识标签体系搭建（为题库标注提供数据基础）和考级报告展示。报告页 §4 的错题详情依赖题库侧已录入的题目与作答数据，联调时需确认该上游数据已就绪。

# 二、用户端：考级报告

## 2.1 概述

新增 user 端页面 `29_考级报告.html`。考生完成测评后，从「我的活动」进入考级报告。报告为移动端竖屏展示，最大宽度 480px 居中，纯展示无交互输入。

报告支持两种测评类型：
- **考级**：正式考级测评，有通过/未通过判定，显示获得级别，含完整下阶段建议
- **模考**：模拟测评，无通过/未通过判定，不显示获得级别，建议文案为模考专属

报告覆盖考级八个级别（程序设计一至八级），通过顶部按钮切换查看各级别结果详情。

## 2.2 页面结构

页面自上而下五个区块（命名第一至第五章），全部不可折叠，一页到底滚动。

### §1 顶部信息区

展示考生基本信息与本次测评结果摘要。

- 考试信息行：级别名称、测评类型（考级/模考）、考试日期（年月）
- 考生姓名
- 通过/未通过/模考徽章（三选一）：
  - 考级通过：绿色徽章「✓ 通过」
  - 考级未通过：红色徽章「✗ 未通过」
  - 模考：灰色徽章「模考」
- 三列信息：报考级别、获得级别、得分
  - 考级通过时：获得级别显示为「{级别名}（{优秀/良好/合格}）」
  - 考级未通过时：获得级别显示为「最高通过：{历史最高通过级别}」
  - 模考时：获得级别列隐藏
  - 得分：0-100 整数

### §2 结果预览

展示考生成长区间定位（小提琴图）和定性总结。

**成长区间定位**：
- 五档水平，从左到右宽度比 30%/30%/20%/10%/10%，中心位置分别在 15%、45%、70%、85%、95% 处
- 五档名称：初步形成、稳步接近、目标达成、熟练掌握、高阶表现
- 红色虚线+三角箭头标记考生位置，箭头所在档以蓝色高亮填充
- 定位规则：得分<30→初步形成，30-59→稳步接近，60-69→目标达成，70-79→熟练掌握，80-100→高阶表现

**等级判定映射表**（分数→等级→区间→定性总结）：

| 分数区间 | 报告等级 | 成长区间 | 定性总结 |
|----------|----------|----------|----------|
| 80-100 | 优秀 | 高阶表现 | 已高质量完成本级主要任务，可继续挑战更复杂的综合任务 |
| 70-79 | 良好 | 熟练掌握 | 已较稳定达到本级要求，可进一步提升综合应用 |
| 60-69 | 合格 | 目标达成 | 已达到本级基本要求，可继续巩固并拓展 |
| 30-59 | 待提升 | 稳步接近 | 本级基础正在逐步形成，建议继续巩固核心任务 |
| 0-29 | 待提升 | 初步形成 | 本级基础正在逐步形成，建议继续巩固核心任务 |
| 模考 | — | 按得分对应区间 | 本次为模拟测评，结果供参考 |

通过线：60 分。得分 ≥ 60 为通过。任一模块未通过时，获得级别显示最高通过模块对应等级。

**边界情况**：
- 所有模块均未通过（满分和为 0）时，不生成报告。入口处「查看报告」按钮不显示。
- 模考无通过/未通过判定，始终生成报告。
- 客观题全对、仅编程题有错时，§4 错题回顾仅展示编程题（不强制展示客观题）。
- 编程题作答超过 5 行时，报告仅显示前 5 行并标注「…（共 N 行）」。

**定性总结**（蓝色提示框内文案）：
- 80-100分：综合本次考级表现，已高质量完成本级主要任务，可继续挑战更复杂的综合任务。
- 70-79分：综合本次考级表现，已较稳定达到本级要求，可进一步提升综合应用。
- 60-69分：综合本次考级表现，已达到本级基本要求，可继续巩固并拓展。
- 30-59分：综合本次考级表现，本级基础正在逐步形成，建议继续巩固核心任务。
- 模考：本次为模拟测评，结果供参考。建议根据知识点掌握情况针对性提升。

### §3 知识点掌握情况

按一级模块分组，每组下列出二级知识点，每个知识点标注掌握率、掌握状态。

- 一级模块名称（加粗小标题）
- 每个二级知识点一行：知识点名称、状态标签、正确/总题数
- 掌握率 = 正确数/总题数 × 100%
- 掌握率 ≥ 60%：「稳定掌握」绿色标签
- 掌握率 < 60%：「重点提升」红色标签
- 数据来源：题库题目标注的知识标签聚合计算

### §4 考级具体表现

根据得分是否满分，展示不同内容。

**满分（得分=100）**：
- 标题：「高光时刻」
- 金色渐变卡片，展示首道满分编程题
- 显示题目编号、题干、考生完整作答代码
- 附表扬性评语：「本题目作答达到要求，完整完成任务。太棒了！」

**非满分（得分<100）**：
- 标题：「重点错题回顾」
- 红色系卡片，展示最多 2 道典型错题（客观题和编程题各至少一道，不足时全部展示）
- 每题显示：题目编号、题型标签、题目题干
- 左右对比列：你的作答（红色背景）vs 正确答案（绿色背景）
- 每题附提升建议，指向对应知识标签

**模考**：
- 标题改为：「作答表现」
- 其余展示逻辑与「重点错题回顾」相同

### §5 下阶段学习建议

根据测评类型、当前级别、是否通过，给出差异化的学习建议。

**考级通过**：
- 考级衔接建议：根据当前级别给出升级衔接建议
  - 一至七级：建议学习下一级的核心知识点，衔接文案逐级不同
  - 八级：建议衔接 C++ 与高阶算法
- 课程学习建议：给出该级别的课程推荐方向

**考级未通过**：
- 考级衔接建议：建议先巩固当前级别，再学习相关知识点
- 课程学习建议：不展示

**模考**：
- 学习建议：通用文案，建议针对「重点提升」知识点加强练习

各级别衔接文案对照：
- 一级→二级：建议学习变量、循环和条件判断，尝试编写较复杂的逻辑程序
- 二级→三/四：建议学习数据类型及顺序、分支和循环结构，逐步过渡到代码编程
- 四级→五级：建议学习列表、字典及循环分支嵌套，构建更复杂的程序逻辑
- 五级→六级：建议学习函数定义与整除取余，尝试用程序解决数学问题
- 六级→七级：建议学习核心算法与数据分析，使用枚举、模拟等方法解决实际问题
- 七级→八级：建议学习经典高阶算法，尝试用算法解决综合项目问题
- 八级→进阶：已完成当前等级序列，可衔接 C++ 与高阶算法

## 2.3 页面交互

### 测评类型切换

顶部「考级/模考」分段控件，点击切换类型。切换后所有章节数据联动更新：§1 徽章变化、§2 文案变化、§3 数据不变（同一份作答）、§4 标题变化、§5 建议文案变化。

### 级别切换

八个级别按钮（一级至八级），分两行每行四个排列。点击后所有章节数据联动更新为对应级别。

### 返回

左上角「← 返回」按钮，调用浏览器返回上一页。

# 三、Admin 端：知识标签管理

## 3.1 概述

新增 admin 端页面 `31_知识标签管理.html`。运营人员维护三级知识标签体系，用于题库标注。标签体系完全独立于活动标签（13_标签配置），不交叉污染。

## 3.2 标签层级

| 层级 | 命名 | 说明 | 示例 |
|------|------|------|------|
| 第一级 | 级别 | 对应考级级别，由系统预置 | 程序设计四级 |
| 第二级 | 一级知识模块 | 级别的知识大类 | Python运算、流程控制 |
| 第三级 | 二级知识点 | 模块下的细分知识点 | 比较运算、布尔值 |
| 末端 | 三级标签 | 知识点下的具体标签，关联题库 | `>`、`<`、`==` |

四级标签关系中，级别预置（由系统维护），运营人员管理模块、知识点、三级标签。

## 3.3 页面布局

左侧树形面板 + 右侧详情面板，标准 admin 布局。

### 左侧：树形面板

- 搜索框：实时过滤树内节点（级别、模块、知识点名称匹配）
- 三层树形结构，节点展开/折叠箭头控制
- 级别节点：加粗显示，显示「X个模块」
- 模块节点：常规字重，显示「X个知识点」
- 知识点节点：浅色字重，显示「X个标签」
- 选中知识点节点后右侧显示该知识点的三级标签列表
- 每行末尾「+」按钮：在该节点下新增子项

### 右侧：详情面板

- 顶部操作栏：面包屑路径（级别 > 模块）、「+ 新增三级标签」按钮
- 标签表格：序号、标签名称、预览样式、操作（编辑/删除）
- 未选中知识点时：显示空状态引导提示「请从左侧选择一个知识点」

## 3.4 操作功能

### 新增操作

| 操作 | 触发方式 | 弹窗字段 | 说明 |
|------|----------|----------|------|
| 新增级别 | 页面顶部按钮 | 级别名称 | 新增后加入左侧树 |
| 新增模块 | 页面顶部按钮 | 所属级别（下拉）、模块名称 | 新增到选定级别下 |
| 新增知识点 | 模块行「+」 | 模块名称（不可编辑）、知识点名称 | 新增到选定模块下 |
| 新增三级标签 | 知识点行「+」或右侧「+ 新增三级标签」 | 知识点名称（不可编辑）、标签名称 | 新增到选定知识点下 |

所有弹窗提交前校验：名称不能为空，三级标签名称全局唯一（跨知识点）。

### 编辑操作

| 操作 | 触发方式 | 弹窗字段 |
|------|----------|----------|
| 编辑级别 | 级别行编辑图标 | 级别名称 |
| 编辑模块 | 模块行编辑图标 | 所属级别（下拉）、模块名称 |
| 编辑知识点 | 知识点行编辑图标 | 所属模块（下拉）、知识点名称 |
| 编辑标签 | 表格行「编辑」 | 标签名称 |

### 删除操作

- 所有层级支持删除
- 删除含子节点的项目时，弹窗警告「该{项目}下还有 X 个{子项}，删除后将一并移除，确定删除？」
- 删除后前端即时移除，数据提交后端

## 3.5 数据依赖

知识标签配置存储为独立数据表，与活动标签（13_标签配置）隔离。
