## 1.1 报告五模块骨架

报告从上到下依次渲染五个模块（出处：业务需求梳理.md 1.1）：

| 顺序 | 模块 | 内容说明 | 规则小节 |
|------|------|---------|---------|
| 1 | 标题栏 | 级别、学生姓名、考试年月、通过/未通过状态 | 1.2 |
| 2 | 考级结果概览 | 报告等级 + 成长区间 + 一句话总结 + 小提琴图 | 1.3 |
| 3 | 知识点掌握情况 | 按一级、二级知识标签展示掌握状态 | 1.4 |

实现规格：
- 模块顺序固定为 1→5，自上而下渲染，不允许重排或省略（业务需求梳理.md 1.1）。
- 本报告依赖的数据（正式总分、题目知识点标签、学生作答）在批改完成、成绩发布后齐备；生成时机与数据就绪条件见 S3，本章假设数据已就绪。

## 1.3 考级结果概览

概览区包含三部分：等级总览映射（1.3.1）、成长区间定位图（1.3.2）、一句话总结（1.3.3）。

### 1.3.1 等级总览映射表

数据来源：直接使用考试系统正式发布总分，不取整、不四舍五入、不重新汇总（出处：业务需求梳理.md 1.3.1）。

| 正式总分 score | score 边界（含等号） | 通过状态 | 报告等级 | 所处成长区间 |
|---------------|-------------------|---------|---------|------------|
| 0 ≤ score < 30 | [0, 30) | 未通过 | 待提升 | 初步形成 |
| 30 ≤ score < 60 | [30, 60) | 未通过 | 待提升 | 稳步接近 |
| 60 ≤ score < 70 | [60, 70) | 通过 | 合格 | 目标达成 |
| 70 ≤ score < 80 | [70, 80) | 通过 | 良好 | 熟练掌握 |
| 80 ≤ score ≤ 100 | [80, 100] | 通过 | 优秀 | 高阶表现 |

实现规格（区间推导自 1.3.1 映射表）：
- score 类型：float，区间判断按浮点值直接比较，不做任何取整/四舍五入（业务需求梳理.md 1.3.1）。
- 边界含等号示例：score = 30.0 → [30,60) → 未通过/稳步接近；score = 59.999 → 未通过；score = 60.0 → 通过/合格；score = 70.0 → 通过/良好；score = 80.0 → 通过/优秀；score = 100.0 → 通过/优秀。
- 报告等级共 4 档（待提升/合格/良好/优秀），其中「待提升」覆盖两个分数区间、均为未通过（业务需求梳理.md 1.3.1）。
- 异常数据：score 超出 [0, 100] 视为异常数据，走数据校验（原文未定义处理流程，需另行确认，本章不编造规则）。

（出处：业务需求梳理.md 1.3.2）

### 1.4.2 掌握度判定

（出处：业务需求梳理.md 1.4.2）

| 知识点作答掌握率 | 掌握状态 |
|----------------|---------|
| < 60% | 重点提升 |
| ≥ 60% | 稳定掌握 |

- 掌握率公式：**该知识点关联题目的得分之和 ÷ 该知识点关联题目的满分值之和**（业务需求梳理.md 1.4.2）。
- 实现规格（推导自 1.4.2）：
  - **聚合粒度取二级知识点（推导依据）**：知识树结构为「一级知识模块 → 二级知识点 → 三级标签」，其中三级标签「需入库，前端不展示」（业务需求梳理.md 1.4.1 补充说明 #1）；报告展示粒度为一/二级（业务需求梳理.md 1.1 模块 3「按一级、二级知识标签展示掌握状态」），故取二级为聚合与展示的公共粒度。
  - 按题目「知识点」字段的**二级**知识点聚合题目；掌握率 = sum(关联题目得分) / sum(关联题目满分值)。
  - **分母口径**：掌握率分母（满分值之和）仅统计**带「知识点」字段**的题目；题目无「知识点」字段时不进入分子/分母（不拉低掌握率）。该降级处理见 **S4-1-2**（交叉引用）。
  - 以浮点计算、不做取整/四舍五入（与 1.3.1 总分口径一致），再与 0.6（60%）比较。
  - 边界含等号：掌握率 = 60%（0.6）时判定为「稳定掌握」。
  - 若某二级知识点下无关联题目（满分值之和为 0，除数为 0），掌握率未定义；原文未定义该边界，需另行确认（本章不编造规则；处理建议见 **S4-1-3**，交叉引用）。
  - **UI 展示映射**：「稳定掌握」→ 状态标签展示「稳定」；「重点提升」→ 展示「重点提升」（出处：样式参考.md 5.3 组件样式要点，见 S2.4 M3；标签语义与色值待 Q8/Q9 采样核验，见 S2.6）。

### 1.4.3 展示排序

（出处：业务需求梳理.md 1.4.3）

| 层级 | 排序规则 |
|------|---------|
| 一级知识模块 | 按知识树顺序展示 |
| 二级知识点（一级模块内） | 先展示「重点提升」，再展示「稳定掌握」（升序） |
| 同状态内 | 按知识树顺序展示 |

实现规格（推导自 1.4.3）：排序为稳定排序，优先级为「一级按知识树顺序 → 二级按状态（重点提升 < 稳定掌握）→ 同状态内按知识树顺序」；知识树顺序以各级别知识树清单为准（1.4.1）。

## 1.5 考级具体表现

### 1.5.1 两套展示逻辑

（出处：业务需求梳理.md 1.5.1）

| 规则项 | 满分画像（总分 = 100） | 非满分画像（总分 < 100） |
|--------|---------------------|----------------------|
| 触发条件 | 总分等于 100 | 总分小于 100 |
| 展示题目数 | 1 道 | 2 道 |
| 题目选取 | 首道满分的编程题 | 首道错误的客观题 + 首道扣分的编程题 |
| 排序 | / | 按题号展示，客观题先于编程题；如客观题全对，则仅展示编程题 |
| 展示答案 | 只展示学生作答，不展示正确答案 | 展示学生作答与正确答案 |
| 作答点评 | 本题目作答达到要求，完整完成任务。太棒了！ | 建议重点提升【题目二级标签知识点】。 |

实现规格（推导自 1.5.1 + 1.5.3）：
- 触发条件与 1.3.1 共用同一正式总分 score（float 比较）：score == 100 → 满分画像；score < 100 → 非满分画像。
- 名词定义：「满分编程题」= 该题得分 = 该题满分值的编程题；「扣分的编程题」= 该题得分 < 该题满分值的编程题；「错误的客观题」= 该题得分未达满分（含 0 分）的客观题。「首道」按题号升序取题号最小者（排序口径推导自 1.5.1「按题号展示」）。
- 非满分排序：两题均存在时客观题在前、编程题在后；客观题全对（不存在错误客观题）时仅展示编程题（业务需求梳理.md 1.5.1）。
- 非满分点评文案中【】内填充该题目的**二级知识点**名称（1.5.1 + 1.5.3）。
- 边界（原文未定义，需另行确认，本章不编造规则）：① 非满分画像中若不存在「首道扣分的编程题」（编程题全部满分），展示内容未定义；② 满分画像中若不存在「满分的编程题」，展示内容未定义。实现时以上述原文规则为准，并预留降级策略的确认点。
