## 1.1 报告五模块骨架

报告从上到下依次渲染五个模块（出处：业务需求梳理.md 1.1；S1 2.4）：

| 顺序 | 模块 | 内容说明 | 规则小节 |
|------|------|---------|---------|
| 1 | 标题栏 | 级别、学生姓名、考试年月、通过/未通过状态（+学号/学校/头像，T3 增量） | 1.3 |
| 2 | 考级结果概览 | 报告等级 + 成长区间 + 一句话总结 + 小提琴图 + 同级参照 | 1.4 |

| 4 | 考级具体表现 | 满分高光 / 非满分重点错题，两套展示逻辑 | 1.6 |
| 5 | 下一阶段建议 | 考级衔接 + 课程学习建议，按级别 × 状态交叉 | 1.7 |

- 报告依赖的数据（正式总分、题目知识点字段、学生作答）在批改完成、成绩发布后齐备；生成时机与数据就绪条件见第三章，本章假设数据已就绪（S1 2.1）。

## 1.4 模块二 考级结果概览（对应设计规格第 4-7 段，评估 T4）

### 1.4.1 a. 等级映射表（唯一事实源，不允许二次计算）— 业务需求 1.3.1

| 正式总分 score | 通过状态 | 报告等级 | 所处成长区间 |
|---------------|---------|---------|------------|
| 0 ≤ score < 30 | 未通过 | 待提升 | 初步形成 |
| 30 ≤ score < 60 | 未通过 | 待提升 | 稳步接近 |
| 60 ≤ score < 70 | 通过 | 合格 | 目标达成 |
| 70 ≤ score < 80 | 通过 | 良好 | 熟练掌握 |
| 80 ≤ score ≤ 100 | 通过 | 优秀 | 高阶表现 |

- 边界精度：分数可为小数（不取整），判定用左闭右开区间；score=100 唯一闭区间；定义域上界=100（「满分=100」假设，见 1.2 数据契约）。单测覆盖点：0、29.99、30、59.99、60、69.99、70、79.99、80、100，及越界防御 -1、101（见 1.10-M1）。
- 使用正式发布总分，禁止前端/服务端重新汇总（业务需求 1.3.1）。

### 1.4.2 b. 成长区间小提琴图规则 — 业务需求 1.3.2

| 规则项 | 内容 |
|--------|------|
| 轴线类型 | **类别轴**，非连续分数轴 |
| 五段宽度 | 30% / 30% / 20% / 10% / 10%（左→右） |
| 五阶段（左→右） | 初步形成、稳步接近、目标达成、熟练掌握、高阶表现 |
| 标记位置 | 固定于对应阶段中心，不随阶段内具体分数移动；五中心=15% / 45% / 70% / 85% / 95% |

### 1.4.3 c. 一句话总结文案表（按报告等级匹配，非按区间）— 业务需求 1.3.3

## 3.4 核心流程

### 3.4.1 生成时机

| 项 | 内容 | 出处 |
|----|------|------|
| 触发时机 | 与电子证书签发同一时机，**成绩发布后自动触发** | 业务需求 2.1 |
| 触发条件 | 考试批改完成且正式总分已发布 | 业务需求 2.1 |
| 触发方式 | 系统自动，无需人工操作 | 业务需求 2.1 |
| 逻辑校验 | 证书状态链路「等待成绩 → 生成中 → 待签发 → 已签发」，证书在成绩发布后进入生成队列（证书 PRD 3.9.2）；报告依赖的三类数据（正式总分、题目知识点字段、学生作答）在批改完成、成绩发布后全部齐备 → 共用触发点可行 | 业务需求 2.1；证书 PRD 3.9.2 |
| 与证书差异 | 报告生成不依赖电子签章环节，生成完成即可查看；证书需签发完成（生成 PDF → 第三方签章 → 已签发）才可查看/下载。两者共用触发点、各自独立异步流水线 | 业务需求 2.1；证书 PRD 2.3/3.9.2 |

### 3.4.2 覆盖范围

- **报告**：所有已批改且有正式总分的考生均生成（**含未通过**，呈现「待提升」等级）——业务需求 2.1。
- **证书**：仅覆盖成绩达标考生——证书 PRD 3.9.2「成绩未达标 → 未获得证书」。
- 两者同一时机触发、覆盖范围不同，为业务需求 2.1 明示；「未通过但有报告」是 user/20 按钮并存矩阵的独立差异行（3.6 矩阵第 11 行）。

### 3.4.3 生成方式（引用证书队列机制，不重造）

- 异步任务生成：每个考生的报告为一条异步任务，经**消息队列**消费（参考证书 PRD 2.3「每个用户证书的签发为一条异步任务，通过消息队列消费；签发中心提供全局启停开关控制所有签发任务」——**只引用不重造**，00_复杂度评估.md 关键风险 4）。
- 失败重试与导出文件管理：建议复用 admin 消息中心能力（PRD_2red规范版 4.1 依赖模块表）。
- 全局启停开关：参考签发中心全局开关（证书 PRD 2.3、3.5.6），报告侧建议提供等价开关（第四章 B4-1）。
- 架构选型：异步队列为**建议架构**，最终选型待技术评审确认（A20）。
- **入口约束**：生成完成后考试卡片才展示「查看报告」入口；成绩未发布或生成中的卡片不展示（业务需求 2.1、2.2.1）。

### 3.4.4 报告状态机

| 状态 | 触发条件 | 用户端表现 | 对应证书状态（逻辑校验） |
|------|---------|-----------|------------------------|
| 未生成 | 成绩未发布 | 不展示「查看报告」按钮 | 等待成绩（证书 PRD 3.9.2） |
| 生成中 | 成绩已发布、异步任务生成中 | 不展示「查看报告」按钮 | 生成中；**等待成绩（瞬时组合）**——证书任务延迟入队/状态未更新时仍为等待成绩，见 3.6 矩阵 |
| 已生成 | 异步生成完成 | 展示「查看报告」按钮，可进入详情页 | 待签发 / 已签发 / **成绩未达标**（未通过考生「有报告无证书」，矩阵第 11 行）/ **等待成绩（瞬时组合）** |
| 生成失败（服务端任务态，不新增用户端状态） | 重试耗尽/超时置失败（建议：指数退避 + 重试上限 3 次 + 单任务超时 30 分钟，A19） | 等同「未生成」：不展示按钮；失败原因与手动重试仅 admin 端可见 | 证书侧失败走自身重试链路（证书 PRD 2.3/3.5.6 重签） |

- 用户端可见状态仅三态（未生成/生成中/已生成），生成链路失败、重试中等服务端任务状态不新增用户端可见状态（PRD_2red规范版 5.3.2 口径）。
- **状态口径映射登记**：PRD_2red规范版 4.3 报告状态查询接口返回**四态**（未生成/生成中/已生成/生成失败，原文），与用户端渲染三态不冲突——「生成失败」为服务端任务态，由服务端按「未生成」口径下发或前端按未生成处理，失败原因/手动重试仅 admin 端可见。
- 对应证书状态仅为逻辑校验参考，证书实际状态以其自身查询为准；「等待成绩」瞬时组合源于报告与证书为两条独立异步流水线，状态更新存在异步窗口（推导自证书 PRD 2.3 队列机制）。
- 状态流转图参考 PRD_2red规范版 6.1（已收编结构，Mermaid 图保留于 V2.0 文档备查）。
