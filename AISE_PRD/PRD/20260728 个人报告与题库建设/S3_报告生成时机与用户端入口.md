## S3.1 报告生成时机

### S3.1.1 触发时机与触发条件

| 项 | 内容 | 出处 |
|---|---|---|
| 触发时机 | 与电子证书签发同一时机，**成绩发布后**自动触发生成 | 业务需求梳理.md 2.1 |
| 触发条件 | 考试批改完成且正式总分已发布 | 业务需求梳理.md 2.1（逻辑校验见 S3.1.2） |
| 触发方式 | 系统自动触发，无需人工操作 | 业务需求梳理.md 2.1 |

**触发链路（建议）**：

```
成绩发布（批改完成）
  → 触发「个人报告生成」事件（与电子证书签发共用同一触发点）
    → 按考生批量生成异步任务入队（消息队列）①
      → 消费者生成报告 → 报告状态置为「已生成」
        → 用户端考试卡片展示「查看报告」入口

> ① 消息队列为**建议架构**（参考证书签发 PRD 2.3 消息队列机制，逻辑校验），与 S3.4 体例一致——最终架构选型**待技术评审确认**（20260806 第 1 轮 Reviewer 反馈标注）。
```

### S3.1.2 触发点校验（逻辑校验）

| 校验项 | 结论 | 依据 |
|---|---|---|
| 证书状态链路 | 电子证书状态链路为「等待成绩 → 生成中 → 待签发 → 已签发」，证书在成绩发布后进入生成队列 | **逻辑校验**，引用 [20260512 证书签发流程 PRD](<../20260512 5 月需求/20260512 证书签发流程 prd.md>) 3.9.2 结果卡片状态定义（等待成绩/证书生成中/待签发/已签发）；业务需求梳理.md 2.1 已确认该链路 |
| 报告依赖数据齐备性 | 报告依赖的三类数据——正式总分、题目知识点标签、学生作答——在批改完成、成绩发布后全部齐备 | 业务需求梳理.md 2.1；数据用途分别见 1.3.1（报告直接使用考试系统正式发布总分）、1.4.1（掌握度与高光&错题依赖题目「知识点」字段）、1.5.1（展示学生作答） |
| 共用触发点 | 可行。证书与报告均以「成绩发布」为前置条件，建议共用同一触发点 | 业务需求梳理.md 2.1 |

**差异说明**：报告生成不依赖电子签章环节，报告生成完成后即可查看；电子证书需完成签发（生成 PDF → 第三方签章 → 已签发）后才可查看/下载（逻辑校验：证书 PRD 3.9.2「已签发」才可点击查看）。因此两者共用触发点、各自独立异步流水线。

### S3.1.3 覆盖范围

| 维度 | 个人报告 | 电子证书 | 出处 |
|---|---|---|---|
| 覆盖对象 | **所有**已批改且有正式总分的考生 | 仅成绩达标（通过）考生 | 业务需求梳理.md 2.1 |
| 未通过考生 | 生成报告，等级呈现「待提升」 | 不生成证书，查询端显示「未获得证书」 | 业务需求梳理.md 2.1、1.3.1；逻辑校验：证书 PRD 3.9.2 |
| 结论 | **同一时机触发、覆盖范围不同** | | 业务需求梳理.md 2.1 |

**待确认项（20260806 第 1 轮 Reviewer 反馈）**：证书「成绩达标」判定与报告「通过（score ≥ 60，S1 1.2 / 1.3.1）」**并非同一规则**——证书达标判定走证书 PRD 3.3.2「证书分数线规则」，达标线**可配置、未必等于 60 分**（逻辑校验）；故存在「score ≥ 60 但证书未达标」「score < 60 但证书达标」的边界。S3.2.4 按钮并存矩阵结论均**暂按「证书达标线 = 60 分」假设**表述，最终以证书分数线规则配置为准，**需另行确认**。

### S3.1.4 异步生成机制

| 项 | 内容 | 出处 |
|---|---|---|
| 生成方式 | 异步任务生成，参考证书签发的消息队列机制 | 业务需求梳理.md 2.1 |
| 证书侧参照 | 每个用户证书的签发为一条异步任务，通过消息队列消费，签发中心提供全局启停开关 | **逻辑校验**：证书 PRD 2.3 |
| 报告侧建议 | 复用同类机制：成绩发布事件 → 按考生批量入队 → 消费者拉取生成 → 回写报告状态；失败重试与导出文件管理建议复用 admin 端消息中心（异步任务/导出文件管理能力） | 索引文档 admin 端「系统支撑：消息中心」 |
| 入口展示约束 | 生成完成后，考试卡片才展示「查看报告」入口 | 业务需求梳理.md 2.1 |

### S3.1.5 报告状态机

| 状态 | 触发条件 | 用户端表现 | 对应证书状态（逻辑校验） |
|---|---|---|---|
| 未生成 | 成绩未发布 | 不展示「查看报告」按钮 | 等待成绩 |
| 生成中 | 成绩已发布、报告异步任务生成中 | 不展示「查看报告」按钮 | 生成中 |
| 已生成 | 报告异步生成完成 | 展示「查看报告」按钮，可进入详情页 | 待签发 / 已签发（报告不依赖签发环节） |
| 生成失败（**服务端任务态，不新增用户端状态**） | 生成任务重试耗尽 / 超时置失败（建议：指数退避 + 重试上限 3 次 + 单任务超时 30 分钟） | 等同「未生成」：不展示「查看报告」按钮；失败原因与手动重试仅 admin 端可见 | —（证书侧失败走证书自身重试链路，证书 PRD 2.3 逻辑校验） |

> 出处：三态定义依据业务需求梳理.md 2.1（「生成完成后考试卡片才展示查看报告入口」）与 2.2.1（「成绩未发布或报告生成中的卡片不展示该按钮」）；与证书状态对应关系为**逻辑校验**，引用证书 PRD 3.9.2。
> **失败态说明（20260806 第 1 轮 Reviewer 反馈增补）**：新增「生成失败」服务端任务态，与 S3.1.4「失败重试建议复用 admin 消息中心」对齐；失败/重试机制与参数见 **S4-2-1**（交叉引用，重试上限/超时为**建议值，待技术评审**）；「失败态不新增用户端可见状态」约束见 **S4.0.2**（用户端可见状态仍为三态，与 S4 口径一致）。

**待确认项（S3 全局，20260806 第 1 轮 Reviewer 反馈）**：
- 成绩复核改分 / 成绩重新发布后，已生成报告是否重新生成：原文未定义。建议口径见 **S4-3-5**（参考证书重签机制提供「重新生成」能力、快照一致性，**需另行确认**）。
- 补考 / 重考对报告的影响：补考/重考成绩是否覆盖原报告、历史报告保留策略，原文未定义，**需另行确认**（建议沿用 S4-3-5 快照口径：新成绩触发重新生成；历史报告保留策略见 S4-4-3）。

## S3.4 PDF 下载实现方案对比（待技术评审）

> 背景：业务需求梳理.md 仅要求「支持下载为 PDF」，未定实现方式。以下为可选方案对比，**选型待技术评审确认**，本 PRD 不拍板。

| 方案 | 实现方式 | 优点 | 缺点 / 风险 | 建议适用 |
|---|---|---|---|---|
| 方案 A：前端打印 / 截图 | 页面 CSS `@media print` 分页样式 + 浏览器「打印→另存为 PDF」；或前端合成（html2canvas + jsPDF） | 实现成本低；与页面样式天然一致；无需后端资源 | 分页控制弱，长报告易截断；依赖浏览器打印行为，跨浏览器/移动端差异大；移动端体验差 | Web 端快速上线场景 |
| 方案 B：后端生成 PDF | 服务端渲染报告 HTML → Headless 浏览器（Chromium / Puppeteer 等）或 PDF 引擎生成文件，用户端直接下载 | 输出稳定一致、分页可控；Web 与移动端均可直接下载；可与证书 PDF 生成链路复用技术栈（证书 PRD 已具备 PDF 生成能力） | 开发成本较高；需维护报告模板；中文字体嵌入需处理 | 推荐候选（与证书链路一致性更好），仍需技术评审定夺 |

> 结论：两方案均可行，权衡点为开发成本、输出一致性、移动端体验、与证书 PDF 链路的技术栈复用，最终选型**待技术评审确认**。
