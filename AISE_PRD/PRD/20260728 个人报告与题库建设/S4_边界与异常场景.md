# S4 边界与异常场景

> 本章定义 AISE「个人报告」的**边界与异常场景**及处理策略，覆盖数据异常、生成链路、用户端体验、并发容量四类。
> 依赖基线：内容规则见 S1（1.1～1.7）；样式与验收标准见 S2（含 Q1～Q14 待确认清单）；生成时机、状态机、用户端入口见 S3（S3.1～S3.5）。
> 标注约定：凡源文档（业务需求梳理.md / S1 / S3 / 证书签发 PRD / 导出证书包 PRD）已定义的处理规则，标注出处；凡源文档未定义、本章给出的默认取值或降级形态，一律显式标注「**建议**」或「**需另行确认**」，不编造为既定规则。与 S1 中已标注的「需另行确认」边界编号一一对应引用（如「S1 1.3.1 已标注」），不重复造规则。

## S4.0 总则

### 4.0.1 处理策略四类定义

| 策略 | 定义 | 适用原则 |
|------|------|---------|
| 拦截 | 在数据校验层/触发层阻止异常数据进入生成或展示链路，不产出错误内容 | 能拦截则拦截，优先于一切降级 |
| 降级 | 异常数据无法拦截时，以占位/局部隐藏/通用文案保证报告可读、可渲染，不破坏五模块骨架（S1 1.1 模块顺序固定、不允许省略） | 拦截失败后的第二优先级 |
| 重试 | 生成链路/下载等可恢复性失败，按重试机制自动或人工重新执行 | 仅限可恢复失败，需有次数/超时上限 |
| 提示 | 用户端/管理端的异常提示文案与呈现形态 | 所有异常最终必须有可理解的呈现 |

优先级：**拦截 > 降级 > 重试 > 提示**；同一场景可组合使用（如「拦截 + 提示」「降级 + 提示」）。

### 4.0.2 用户端呈现总约束

- 报告**用户端可见**状态仅三态：未生成 / 生成中 / 已生成（S3.1.5 状态机；20260806 修订后另含服务端「生成失败」任务态，见 S4-2-1）。**生成链路失败、重试中等服务端任务状态不新增用户端可见状态**：失败考生用户端表现等同「未生成/生成中」——不展示「查看报告」入口（S3.2.2「成绩未发布或报告生成中的卡片不展示该按钮」）；失败原因与重试操作仅 admin 端可见（建议，见 S4-2-1）。
- 所有「已生成」报告的内容必须来自通过校验的数据；校验不通过即不置「已生成」。
- 异常提示文案统一登记于本章各表「处理策略」列；涉及警示色的样式遵循 S2 配色板（如 C7 高亮粉红系），具体样式归属 S2 实现，本章不重复定义。
- 本章所有「建议」值（重试次数、超时时长、保留期、文案）均为默认建议，最终以需求确认/技术评审结论为准。

## S4.1 数据异常类

> 数据异常发生在报告生成链路的**数据读取与计算阶段**（S3.1.2 三类依赖数据：正式总分、题目知识点字段、学生作答）。本章只定义报告侧（下游）的防御与降级；题目录入侧的字段必填校验由独立题库 PRD 覆盖（S1 1.4.1「题目录入侧的后台实现由独立的题目录入 PRD 覆盖」），本 PRD 不展开。

| 编号 | 异常场景 | 触发条件 | 影响 | 处理策略（拦截/降级/重试/提示） | 依据 / 标注 |
|------|---------|---------|------|-------------------------------|------------|
| S4-1-1 | 正式总分 score 超出 [0,100] | score < 0 或 score > 100；或 score 非数值（null / NaN / Infinity / 非数字字符串） | score 同时驱动 S1 1.2 通过状态、1.3.1 等级映射、1.5.1 满分/非满分画像分支；越界值会落入错误区间（如 101 分被误判为满分画像）或导致比较异常 | **拦截**：报告生成任务入口做数据校验，score 越界/非数值 → 该考生报告任务置失败，不生成内容；**提示**：admin 消息中心失败记录标注「正式总分越界（score=…）」，数据修复后由 admin 重试（链路同 S4-2-1）；**不采用钳制修正**（将 score 钳到 [0,100] 与 S1 1.3.1「不取整、不四舍五入、不重新汇总」口径冲突，且掩盖数据问题）；**用户端**：不展示「查看报告」入口（等同未生成，S3.1.5） | **S1 1.3.1 已标注**：「score 超出 [0,100] 视为异常数据，走数据校验（原文未定义处理流程，需另行确认）」；非数值校验与「拦截而非钳制」为**建议** |
| S4-1-2 | 题目缺少「知识点」字段（部分题目 / 全部题目缺失） | 题目「知识点」字段为空（题目录入侧未配置；知识树人工补充待确认，S1 1.4.1 待确认事项 #2） | M3 掌握度（S1 1.4.2 按二级知识点聚合）与 M4 非满分点评【】知识点占位（S1 1.5.1）依赖该字段；缺失将导致聚合错漏、点评占位为空 | **降级（部分缺失）**：缺失「知识点」字段的题目**不参与任何知识点聚合**（不入掌握率分子/分母），掌握度按剩余带知识点题目计算；M4 取题不依赖知识点，不受影响；**降级（全部缺失）**：M3 模块保留骨架（S1 1.1 不允许省略模块），内容区展示占位文案「知识点数据暂缺」（**建议**文案），不展示掌握状态；**提示**：admin 端按考试维度标记「知识点字段缺失」告警，推动题库侧补录；**红线**：任何情况下**不得回退使用「题目标签」**兜底（S1 1.4.1 补充说明 #1）；非满分点评占位为空时的降级文案（**建议**：「建议重点提升本题对应知识点。」）**需另行确认** | S1 1.4.1 补充说明 #1（报告依赖「知识点」字段、不得回退题目标签）；降级文案与告警为**建议/需另行确认** |
| S4-1-3 | 某二级知识点下无关联题目（掌握率除零） | 该级别知识树中某二级知识点无任何关联题目，或关联题目均缺「知识点」字段（叠加 S4-1-2）；掌握率 = sum(得分)/sum(满分值)，除数为 0，未定义 | 该知识点掌握状态无法判定；S1 1.4.3 排序规则（重点提升 < 稳定掌握）中该知识点位置不确定 | **降级（建议默认）**：该二级知识点行**仍按知识树顺序展示**（不破坏知识树结构），掌握状态展示为「暂无数据」灰态（样式取 S2 C8 次要文字色系），**不进入**「重点提升/稳定掌握」的排序竞争；**替代形态**：整行隐藏（**需另行确认**二选一，建议采用展示「暂无数据」以暴露数据缺口）；**提示**：admin 端统计「无题目关联的二级知识点」清单，推动题库补题 | **S1 1.4.2 已标注**：「若某二级知识点下无关联题目…掌握率未定义；原文未定义该边界，需另行确认」；「暂无数据」展示形态为**建议** |
| S4-1-4 | 学生作答数据缺失（编程题无作答 / 客观题未答） | 考生某题未作答：客观题未选、编程题未提交代码或提交空代码 | S1 1.5.1 取题逻辑（首道满分编程题 / 首道错误客观题 / 首道扣分编程题）与 1.5.2 截断规则（对空代码无意义）受影响 | **降级**：未作答客观题 → 得分 0 分，按「错误的客观题」（S1 名词定义：得分未达满分，含 0 分）正常参与取题；未作答编程题 → 得分 0 分，按「扣分的编程题」候选参与取题，代码块区域展示「未作答」（**建议**占位文案，样式沿用 S2 C10 代码块深色主题）；**拦截（组合兜底）**：满分画像（score=100）下不可能存在 0 分作答题目（否则总分 < 100），若出现该组合则属于 score 数据异常，走 S4-1-1 拦截；全部编程题未作答且非满分画像时，叠加 S4-1-5 的取题落空降级 | S1 1.5.1 名词定义（推导）、1.5.2；「未作答」占位形态**需另行确认**（建议如上） |
| S4-1-5 | 满分画像无「满分的编程题」；非满分画像无「扣分的编程题」 | 满分画像（score=100）但卷面无编程题或编程题均非满分（如纯客观题卷面，或题目类型/得分数据异常）；非满分画像（score<100）但编程题全部满分（扣分全在客观题） | S1 1.5.1 两套展示逻辑的取题结果为空 → M4 模块展示内容未定义 | **降级（非满分画像）**：无「扣分的编程题」时仅展示「首道错误的客观题」（1 道）——推导自 S1 1.5.1 反向逻辑「如客观题全对，则仅展示编程题」，正向（仅剩客观题）原文未定义，**建议**按对称规则处理；若客观题也全对则与 score<100 矛盾（总分应为 100），属数据异常走 S4-1-1；「无错误的客观题」（客观题全对）S1 原文已定义：仅展示编程题，非异常；**降级（满分画像）**：无「满分的编程题」时 M4 保留模块骨架（S1 1.1），内容区展示占位文案「暂无满分编程题记录」（**建议**文案），等级/概览等其余模块不受影响；**提示**：admin 端标记「取题落空」报告以便核查卷面配置 | **S1 1.5.1 已标注**：「① 非满分画像中若不存在『首道扣分的编程题』…② 满分画像中若不存在『满分的编程题』…需另行确认，本章不编造规则。实现时以上述原文规则为准，并预留降级策略的确认点」；本条降级形态为**建议**，文案与是否整模块隐藏**需另行确认** |
| S4-1-6 | 题目满分值为 0 / 缺失（补充推导场景） | 题目满分值字段未配置或为 0 | 掌握率分母异常（叠加 S4-1-3 除零）；「满分的编程题/扣分的编程题」判定（S1 1.5.1 名词定义依赖满分值）失准 | **降级（建议）**：满分值缺失/为 0 的题目视同无有效数据，**不参与**掌握率聚合与 M4 满分/扣分判定（与 S4-1-2 缺失处理口径一致）；该题不作为「满分的编程题」候选，避免 0 分题被误判为满分题；**提示**：admin 端标记题目数据异常 | 推导自 S1 1.5.1 名词定义；处理口径为**建议，需另行确认** |

## S4.2 生成链路类

> 生成链路以 S3.1 为基线：成绩发布 → 与证书共用触发点 → 按考生批量异步任务入队（消息队列）→ 消费者生成 → 状态置「已生成」→ 展示入口。失败重试与导出文件管理复用 admin 端消息中心（S3.1.4）；重试机制参考证书签发 PRD 2.3「失败重试机制（指数退避 + 次数上限）」（逻辑校验）。

| 编号 | 异常场景 | 触发条件 | 影响 | 处理策略（拦截/降级/重试/提示） | 依据 / 标注 |
|------|---------|---------|------|-------------------------------|------------|
| S4-2-1 | 报告生成任务失败 / 超时 | 消费者生成异常（依赖数据读取失败、渲染异常、服务异常）；任务超时未完成 | 报告状态无法置「已生成」；用户端入口不出现（S3.1.5） | **重试**：失败重试机制，指数退避 + 次数上限（参考证书签发 PRD 2.3，逻辑校验）；**建议**重试上限 3 次（参考导出证书包 PRD「attempt_count < 3」口径，建议值）、单任务超时 30 分钟置失败（参考导出证书包 PRD 超时口径，建议值），避免「生成中」长期悬挂；**记录**：失败记录（含失败原因）回写 admin 消息中心（异步任务/导出文件管理能力，S3.1.4），admin 可查看并手动重试（**建议**）；**用户端**：保持不展示「查看报告」按钮（等同未生成，S3.1.5），**不新增用户端失败态**（S4.0.2）；连续重试失败由 admin 人工介入；**提示**：admin 消息中心展示失败状态与原因 | S3.1.4、S3.1.5；证书 PRD 2.3（逻辑校验）；重试次数/超时值为**建议**（参考导出证书包 PRD 口径） |
| S4-2-2 | 成绩发布与报告生成不同步（批量队列积压） | 大批量考生成绩集中发布 → 队列积压，报告生成滞后于成绩发布 | 成绩已可查但「查看报告」入口迟迟不出现；user/20 出现「有成绩、无报告」中间态 | **拦截（入口约束）**：严格按 S3.1.5 状态机——报告未「已生成」前一律不展示「查看报告」按钮（S3.2.2），不因成绩已发布而提前放行；user/20 按 S3.2.4 按钮并存矩阵执行（报告生成中 → 不展示「查看报告」，证书按钮状态独立）；**提示（建议，需另行确认）**：原文仅规定「不展示按钮」；是否在卡片上增加「报告生成中」灰态占位文案为**建议**增强项，确认前不实现；**容量兜底**：队列限流/削峰见 S4-4-1 | S3.1.5、S3.2.2、S3.2.4；「生成中」占位提示为**建议/需另行确认** |
| S4-2-3 | 报告部分生成（同场考试某考生成功、某考生失败） | 批量任务中个别考生生成失败/超时，其余成功 | 同一场考试部分考生有入口、部分没有 | **隔离**：按考生逐条独立任务（S3.1.4），个别失败不影响其他考生；**不回滚**：不因部分失败回滚已成功报告，已生成报告保持有效；**重试**：失败考生走 S4-2-1 重试/失败记录链路，重试成功后入口自动出现（用户无需操作）；**提示（建议）**：admin 消息中心支持按考试筛选「生成失败」考生并批量重试（复用消息中心能力） | S3.1.3（覆盖所有已批改且有正式总分的考生）、S3.1.4；admin 批量重试为**建议** |
| S4-2-4 | 数据源缺失：未批改完成就触发（触发条件防御） | 成绩发布事件提前/重复到达，批改未完成或正式总分未发布时消费者开始执行 | 报告依赖三类数据（正式总分、题目知识点字段、学生作答，S3.1.2）未齐备 → 产出空/错报告 | **拦截（触发条件）**：触发条件固定为「考试批改完成且正式总分已发布」（S3.1.1），与证书共用触发点（S3.1.2）；**防御实现（建议）**：消费者执行前做数据齐备性校验（正式总分存在、批改状态 = 已完成），不齐备 → 任务不执行、按指数退避延迟重试，**不产出残缺报告、不置失败**（等待数据就绪而非放弃）；**用户端**：未发布/未生成不展示入口（S3.1.5「未生成」态） | S3.1.1、S3.1.2（逻辑校验：三类数据在批改完成、成绩发布后齐备）、S3.1.5；消费者侧防御校验为**建议** |

## S4.3 用户端/体验类

> 用户端基线：入口为 user/15 我的活动、user/20 成绩与证书_独立页（S3.2）；详情页新增，支持 Web/移动端响应式查看与 PDF 下载（S3.3）；渲染验收标准见 S1 1.7 与 S2.5（390×844、正文 ≥15px、辅助标签 ≥12px、核心标题 20–24px）。

| 编号 | 异常场景 | 触发条件 | 影响 | 处理策略（拦截/降级/重试/提示） | 依据 / 标注 |
