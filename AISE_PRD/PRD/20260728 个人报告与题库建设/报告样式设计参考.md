## 三、PDF 文字层信息（需求说明部分，非报告 UI 字体）

- 正文：11pt，HelveticaNeue / ArialMT / Unnamed-T3（由 HeadlessChrome 打印），文字色 #25272a / #000000
- 标题：SegoeUI-Bold 27pt（封面）、Arial-BoldMT 14pt（章节）
- 代码/变量：Consolas 10pt，#202124
- 强调红字：ArialMT 11pt #e03e3e（如「不取整、不四舍五入」类警示）
- 注意：PDF 文字层是需求说明排版，报告 UI 的真实样式以嵌入图（第一节）为准

## 四、报告页面结构（复刻骨架，与《业务需求梳理.md》一致）

五模块自上而下：
1. 标题栏：级别、学生姓名、考试年月、通过/未通过状态
2. 考级结果概览：报告等级 + 成长区间 + 一句话总结 + 小提琴图
3. 知识点掌握情况：一级知识模块 → 二级知识点，状态「重点提升/稳定掌握」
4. 考级具体表现：满分高光（1 道首道满分编程题）/ 非满分错题（首错客观题 + 首扣分编程题），代码截断前 5 行
5. 下一阶段建议：考级衔接 + 课程学习建议

验收标准：移动端基准视口 390×844；正文/题目 ≥15px；辅助标签 ≥12px；核心标题 20-24px

## 五、UI 视觉核验（vision_analyze，20260805）

> page2_render.png 为「报告 UI + PRD 文档」左右对照图；左侧报告 UI（移动端竖版）结构如下，组件描述来自视觉模型：

### 5.1 页面结构（从上到下）

1. **头部信息区**：副标题 + 紫色大标题 + 学生卡（左：卡通吉祥物头像；右：姓名 / 奖牌 / 年龄 / 学校）
2. **评定结果区**：两行胶囊标签（本次等级「良好」绿高亮、同级参照「熟练掌握」橙高亮）+ 灰色总结条
3. **同级参照分布**：小提琴图（紫→青渐变填充，紫色圆点标记当前位置）
4. **知识点掌握情况**：树状列表（一级模块→二级知识点）+ 右侧状态标签（「稳定」绿 /「重点提升」橙）
5. **本次评定表现**：深色代码块 + 选项按钮矩阵（你的作答 / 参考答案标注）
6. 下一阶段建议（模块 6 位于长截图后半段，待 page2_img1/2 分析补充确认）

### 5.3 组件样式要点

- 学生卡：左头像 + 右信息（姓名/奖牌/年龄/学校），圆角卡片
- 等级标签：胶囊形（pill），绿色高亮「良好」、橙色高亮「熟练掌握」
- 小提琴图：渐变填充（紫→青），标记点为紫色圆点，固定在阶段中心
- 知识点列表：树状 + 右侧状态标签（绿「稳定」/ 橙「重点提升」）
- 代码块：深藏青底，深色主题

## 六、复刻建议

1. HTML 报告以 page2_img1.jpeg / page2_img2.jpeg 两张长截图为主要视觉基准（结构、卡片、标签、间距）。
2. 主色建议：深藏青 #0f1835 做标题文字，品牌紫 #8777d3 系做强调，粉红 #f0646b 系做错题/重点提升状态，亮蓝 #2555e7 系做按钮/链接。
3. 代码块用深色主题（#1d1d1e 底 + #e9e9e9 文字 + #1d90fa 高亮）。
4. 由于无视觉模型，语义级细节（圆角、阴影、图标形态）需对照原图人工核验；数据级细节（色值、尺寸、结构）以上述为准。
