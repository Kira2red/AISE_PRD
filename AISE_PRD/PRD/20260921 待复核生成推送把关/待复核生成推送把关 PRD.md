# 待复核环节生成与推送把关 PRD

> 需求编号：20260921 待复核生成推送把关 ｜ 版本：V1.0 ｜ 状态：评审中
> 需求提出：张二红（2026-09-21）
> 方案依据：[方案V1.md](方案V1.md)（Q1-Q5 已拍板，见拍板记录）

## 1. 背景与收益

**需求简介**：在「测评证书管理」的待复核环节，把证书/报告生成从系统自动触发改为运营点击按钮显式触发，生成成功后由运营手动点击推送；证书与报告全部生成且推送完成后才能流转成绩公示，各环节进度可查。

**现状依据**：
- 现行证书生成：学生申请触发，仅覆盖成绩达标考生（20260512 证书签发流程 PRD）
- 现行报告生成：批改完成自动触发（20260728 报告 PRD，2026-09-10 改向）
- 现状痛点：生成是自动的，运营在成绩公示前没有统一的「生成结果确认」动作，出错时无法在公示前拦截

**收益**：
- 运营在公示前拥有完整的校验与放行控制，证书/报告内容错误可在公示前发现并修正
- 生成与推送全程进度可见，失败可定位到具体学生并单个重试
- 公示门禁保证学员看到成绩时证书报告已全部就绪，减少「有成绩无证书」类客诉

## 2. 业务流程

待复核环节动作链：

```
批改中 → 待复核：
  ① 运营在测评详情页点「生成证书」「生成报告」→ 显示生成进度
  ② 生成完成后运营手动点「推送证书」「推送报告」→ 显示推送进度（列表页可查两项进度）
  ③ 证书 + 报告全部生成且推送完成 → 流转入口解锁 → 成绩公示
```

配套规则：
- 生成失败可单个重试或批量重试；生成成功后发现配置错误可整场重新生成（覆盖+二次确认）
- 未流转公示前，整场重新生成会使已推送学员回退为待推送
- 已流转成绩公示后，生成/重新生成入口隐藏，走既有证书修改流程

## 5. 详细功能说明

### 5.1 详情页生成操作区（admin/15 测评证书管理详情）

HTML Demo：15_测评证书管理_详情.html（见下方文件，直接点击浏览）

| 项 | 说明 |
|---|---|
| 位置 | admin/15 测评证书管理详情页，测评处于「待复核」环节时显示 |
| 布局 | 「证书与报告生成」操作区：证书、报告两张并排卡片，每张含「生成」与「推送」两个动作 |
| 初始态 | 状态徽章「未生成」，按钮「生成证书」「生成报告」可点击 |
| 点击生成 | 按钮变为「生成中…」禁用态，显示进度条（成功/失败/总数），进度实时刷新 |
| 失败处理 | 生成中出现失败时，进度条下方出现「查看失败明细并重试」链接；全部跑完后状态徽章变「部分失败」，按钮变「重试失败项」 |
| 生成完成 | 状态徽章变「待推送」，生成按钮变「生成完成」并置灰；出现「推送」按钮等待运营手动点击 |
| 手动推送 | 生成完成后状态徽章变「待推送」，出现「推送证书」「推送报告」按钮；点击后徽章变「推送中」，推送完成变「已推送」；未推送不影响重新生成以外的操作，但阻塞公示门禁 |
| 整场重新生成 | 任一模块推送完成后，操作区右上角出现「整场重新生成」；点击二次确认：「将覆盖已生成的全部证书与报告，已推送的学员将回退为待推送。确认继续？」 |
| 覆盖范围 | 证书进度总数 = 成绩达标学员数；报告进度总数 = 全部参测学员数（沿用 20260728 口径） |
| 并发约束 | 同一测评同一时刻仅允许一个生成任务运行，重复点击提示进行中 |

### 5.2 列表页进度展示（admin/14 测评证书管理）

HTML Demo：14_测评证书管理.html（见下方文件，直接点击浏览）

| 项 | 说明 |
|---|---|
| 位置 | admin/14 测评证书管理列表，新增「生成进度」「推送进度」两列（批改情况之后） |
| 只读原则 | 列表页仅展示进度，不提供任何生成/推送操作（Q1 拍板：按钮只放详情页） |
| 进行中展示 | 进度条 + 「成功数/总数」+ 状态标签（生成中/推送中，蓝色呼吸动效） |
| 完成展示 | 绿色「完成」标签 + 「总数/总数」 |
| 未开始展示 | 推送进度条置灰，提示「推送进度：生成完成后可推送」 |
| 进度明细弹窗 | 点击进度打开弹窗：顶部成功/失败/剩余三项统计 + 「重新生成失败项」批量按钮；列表逐条显示失败学生（姓名、编号、失败原因）+ 单个「重新生成」按钮 |
| 环节外展示 | 已流转公示中/已寄送的测评，两列固定显示「完成」 |

### 5.3 成绩公示流转门禁（admin/15 状态流转控制）

| 项 | 说明 |
|---|---|
| 位置 | admin/15 页「状态流转控制」卡片（既有入口，Q4 拍板沿用） |
| 门禁规则 | 「立即流转至下一步」「设定定时流转」执行时校验：证书 100% 生成且推送完成，且报告 100% 生成且推送完成 |
| 未满足 | 流转被拦截，弹窗提示「须全部生成且推送完成后才能流转成绩公示」；卡片内门禁提示条显示具体缺失项（如「不可流转：报告生成中 902/1,240」「证书已生成待推送」） |
| 已满足 | 门禁提示条变绿「证书与报告已全部生成并推送完成，可流转至成绩公示」，流转正常执行 |
| 撤销回退 | 流转后如撤销回待复核，门禁重新生效（生成/推送状态保留，无需重新生成） |
| 公示后锁定 | 流转至公示中后，生成操作区与重新生成入口隐藏；后续修正走既有证书修改/重新生成流程 |

### 5.4 重新生成规则

| 场景 | 规则 |
|---|---|
| 单个失败重试 | 明细弹窗内单个学生「重新生成」；成功后计入进度 |
| 批量失败重试 | 弹窗顶部「重新生成失败项」，一次重跑全部失败项 |
| 整场重新生成 | 详情页操作区入口，二次确认后覆盖整场；已推送学员回退待推送并重新推送 |
| 推送失败 | 本期从简：推送进度中标记失败，可重推（Q3 拍板：不处理服务号未绑定等细分原因） |
| 推送时机 | 生成与推送为两个独立手动动作：生成完成不自动推送，必须点击「推送」按钮（2026-09-21 二次确认修订） |

## 6. 验收标准

| # | 场景 | 前置条件 | 操作 | 期望结果 | 判定 |
|---|---|---|---|---|---|
| 1 | 初始态 | 测评批改完成进入待复核 | 打开详情页 | 显示生成操作区，两模块均「未生成」 | 布局与文案正确 |
| 2 | 生成证书 | 待复核，未生成 | 点「生成证书」 | 进度条实时刷新，完成后停在「待推送」，出现推送按钮 | 进度与状态流转正确 |
| 3 | 生成报告 | 待复核 | 点「生成报告」 | 同上，证书与报告进度互不影响 | 两模块独立 |
| 4 | 部分失败 | 生成中若干失败 | 查看失败明细 | 弹窗列出失败学生与原因 | 明细准确 |
| 5 | 失败重试 | 存在失败项 | 单个/批量重新生成 | 失败项补齐后状态变「待推送」，等待手动推送 | 补齐后状态正确 |
| 6 | 手动推送 | 生成 100% 成功（待推送） | 点「推送证书/推送报告」 | 推送进度条独立计数，完成后徽章变「已推送」 | 推送进度正确 |
| 7 | 门禁拦截 | 任一模块未完成 | 点立即流转/设定定时流转 | 拦截并提示具体缺失项 | 提示与实际一致 |
| 8 | 门禁放行 | 双模块已推送 | 点立即流转 | 成功流转至公示中 | 门禁提示翻绿 |
| 9 | 列表进度 | 任一环节 | 查看列表两列 | 进行中/完成状态与详情页一致 | 数据一致 |
| 10 | 整场重新生成 | 已推送后 | 点整场重新生成并确认 | 覆盖重生成，已推送回退待推送 | 二次确认与回退正确 |
| 11 | 公示后锁定 | 已流转公示中 | 查看详情页 | 生成入口隐藏 | 无生成入口 |
| 12 | 回归：报告覆盖 | 双模块生成完成 | 核对报告人数 | 报告=全部参测（含未达标），证书=达标 | 覆盖口径正确 |
| 13 | 回归：流转撤销 | 流转后撤销 | 回到待复核 | 生成/推送状态保留，门禁重新生效 | 状态不丢失 |
| 14 | 回归：既有证书流程 | 公示后学生申请补证 | 走既有流程 | 不受本需求影响 | 流程正常 |
