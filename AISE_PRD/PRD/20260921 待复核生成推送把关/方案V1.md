# 待复核环节证书报告生成与推送 方案V1

> 需求日期：2026-09-21 ｜ 状态：待拍板
> 需求原文：在「测评证书管理」页面，待复核环节增加「生成证书」「生成报告」按钮，点击后才开始生成；全部生成成功后可用「推送证书」「推送报告」；推送后可单独查看证书/报告推送进度；支持重新生成；所有证书和报告都推送成功才能流转到成绩公示；待复核环节可查看生成进度。

## 1. 背景与目标

**一句话**：把待复核环节的证书/报告生成从「系统自动触发」改为「运营点击按钮显式触发」，并增加「全部生成成功→推送→全部推送成功→才能公示」的把关链路，让运营在成绩公示前拥有完整的校验与放行控制。

**现状依据**：
- 流转链路：批改中 → 待复核 → 公示中（demo 15 页步骤条；20260512 PRD 流程线）
- 现行证书生成：学生申请触发，仅覆盖成绩达标考生（20260512 证书签发流程 PRD）
- 现行报告生成：批改完成自动触发，覆盖全部考生（20260728 报告 PRD，2026-09-10 改向）
- 现状痛点：生成是自动的，运营在公示前没有统一的「生成结果确认」动作；推送（服务号通知）挂在签发事件上自动发出，出问题无法拦截

**变化点**：生成与推送均改为手动触发 + 前置校验（全成功才可下一步）。这改变了 20260728 报告「批改完成自动生成」的口径和 20260816 服务号「签发完成自动通知」的口径，需要明确改造范围。

## 2. 核心流程（待复核环节新增动作链）

```
批改中 → 待复核
           ├─ ① 生成证书（按钮）→ 进度：成功 N / 失败 M / 总 T
           ├─ ② 生成报告（按钮）→ 进度：成功 N / 失败 M / 总 T
           ├─ ③ 推送证书（按钮，①全部成功才可点）→ 推送进度：成功 N / 失败 M
           ├─ ④ 推送报告（按钮，②全部成功才可点）→ 推送进度：成功 N / 失败 M
           └─ ⑤ 流转成绩公示（①②③④全部完成才可操作）
```

## 3. 功能清单

| # | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 待复核环节操作区 | P0 | 测评处于「待复核」时，14 页列表行内/详情页显示「生成证书」「生成报告」按钮；其他环节不显示 |
| F2 | 生成进度展示 | P0 | 点击生成后行内显示进度条：成功/失败/总数；可点开看失败明细（学生+失败原因） |
| F3 | 重新生成 | P0 | 生成失败的可单个「重新生成」；也支持「重新生成全部失败」；成功的不重复生成。生成成功后发现内容有误的场景（如模板配错），支持整场重新生成，需二次确认并覆盖旧证书 |
| F4 | 推送门禁 | P0 | 「推送证书」仅当该测评证书 100% 生成成功才可点；「推送报告」同理；未满足时按钮置灰并提示缺多少 |
| F5 | 推送进度展示 | P0 | 推送后显示推送进度：成功/失败/总数；证书推送与报告推送进度分开查看 |
| F6 | 推送失败处理 | P1 | 推送失败的（如学生未绑定服务号）单个「重推」；未绑定的列提示原因，不计入失败重试 |
| F7 | 公示门禁 | P0 | 「流转成绩公示」仅当证书+报告都 100% 推送成功才可操作；否则置灰并提示 |
| F8 | 重新生成对推送的影响 | P1 | 已推送后重新生成证书/报告的，该学生推送状态回退为「待推送」，需重新推送；已流转公示后不允许重新生成（走既有证书修改/重新生成流程） |

## 4. 边界与异常场景

| # | 场景 | 处理 |
|---|---|---|
| B1 | 生成中关页面/断网 | 生成任务后台继续，重进页面进度仍在 |
| B2 | 生成失败率过高 | 不特殊拦截，逐个看失败原因重试；全部失败时提示联系技术支持 |
| B3 | 生成后发现配错（模板/字段映射错） | 整场重新生成：二次确认「将覆盖已生成的 N 份证书，且已推送的 M 份需重新推送」 |
| B4 | 学生未关注/未绑定服务号 | 推送标记「不可推送」，单独归类展示（不算失败，不阻塞公示门禁——见 Q3） |
| B5 | 推送后、公示前发现证书内容错误 | 先整场重新生成（B3 流程），受影响学生重推，再流转公示 |
| B6 | 已流转成绩公示 | 生成/推送按钮全部隐藏；重新生成走既有流程 |
| B7 | 并发生成 | 同一测评同一时刻只允许一个生成任务运行中，重复点击提示进行中 |
| B8 | 证书通过线配置 | 未达通过线的学生无证书可生成——证书进度总数按「达标人数」计，报告按「全部参测」计（沿用 20260728 覆盖范围口径） |
