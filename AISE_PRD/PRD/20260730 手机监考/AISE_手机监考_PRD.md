# AISE 手机监考 PRD

## 1. 项目背景

### 1.1 需求简介

为 AISE 考试系统增加手机监考能力——考生在电脑端设备调试页扫码后，用手机替代电脑摄像头完成视频监考推流。

### 1.2 业务诉求

现有视频监考依赖电脑自带摄像头。部分考生电脑无摄像头（如台式机未配外接摄像头），导致设备调试无法通过、无法进入考试。手机监考作为备选方案，覆盖无摄像头考生场景，降低考试准入门槛。

---

## 2. 业务流程简述

```
考生进入设备调试页
  ├── 电脑摄像头检测（原有流程，不变）
  └── 手机监考入口（新增，始终展示）
        └── 扫码 → 手机打开引导页 → 查看摆放指引 → 点击「开始监考」→ 进入直播页
              └── 摄像头推流 → 电脑端感知连接 → 设备调试页摄像头项标记通过 → 可进入考试
```

手机监考与电脑摄像头**平级**——电脑摄像头通过或手机连接成功，均视为「摄像头检测通过」。两者都可通过时以电脑摄像头为准。

---

## 3. 详细功能说明

### 3.1 设备调试页改造

- **位置**：考试入口 → 设备调试页（现有页面 `21_测评_设备调试`）
- **目标**：在现有摄像头/录屏调试模块右侧新增「手机监考」模块，作为备选入口

#### 3.1.1 页面布局

设备调试页为居中白色卡片式布局，三列等宽：

| 列 | 内容 |
|----|------|
| 左 | 摄像头调试 |
| 中 | 录屏调试 |
| 右 | 手机监考（新增） |

每列结构一致：顶部状态圆点 + 标签名称 → 灰色圆角卡片（图标 + 操作区）→ 操作区下方说明文字。

#### 3.1.2 手机监考模块

**卡片内部元素（自上而下）：**

- 手机图标（灰色，与另两列图标同尺寸）
- 二维码（白色底色、黑色模块、三个定位角完整，约 88×88px）
- 引导文案：「电脑没有摄像头？手机扫码开启视频监考」

**二维码生成规则：**
- 二维码内容为 URL：`{AISE域名}/proctor/mobile?token={唯一token}`
- token 由服务端在考生进入设备调试页时生成，关联当前考生 ID + 考试场次
- 同一考生同一考试场次多次进入设备调试页时，复用同一 token（不重新生成）
- token 有效期与考试时间窗口一致，考试结束后失效

**二维码刷新规则：**
- 每 60 秒自动刷新，直接替换不做过渡动效
- 手动刷新入口：二维码右下角小字「刷新」，点击后立即重新生成 token 并更新二维码

**二维码状态（仅展示层，不做复杂状态机）：**

| 状态 | 视觉表现 |
|------|---------|
| 默认 | 正常展示二维码 + 引导文案 |
| 手机已连接 | 二维码替换为绿色对勾图标 + 「手机已连接」文字 |

卡片上方状态圆点同步变化：灰→绿（手机已连接时）。

#### 3.1.3 与摄像头检测的关系

- 手机监考作为独立模块，不与电脑摄像头检测互斥
- 「进入测评」按钮的激活条件：**摄像头检测通过（电脑或手机任一）且录屏检测通过**
- 电脑摄像头通过时，手机监考模块仍展示但不影响流程
- 手机先连接成功 → 摄像头检测项标记为「✓ 手机已连接」（绿色），等同于摄像头通过
- 之后电脑摄像头再检测通过 → 以电脑摄像头为准，手机保持备用

#### 3.1.4 交互细节

- 二维码区域可点击：点击后模拟扫码连接态切换，方便 Demo 演示。正式环境此交互由服务端 WebSocket 推送状态。
- 状态标签文案随状态动态变化：
  - 未检测：灰点「摄像头调试」
  - 电脑摄像头通过：绿点「摄像头调试」
  - 手机连接成功：绿点「摄像头调试」，卡片内按钮变为「✓ 手机已连接」

### 3.2 手机监考引导页

- **位置**：扫描二维码后，在手机浏览器中打开
- **URL**：`{AISE域名}/proctor/mobile/guide?token={token}`
- **目标**：告知考生手机摆放位置，确认后进入直播

#### 3.2.1 页面结构（手机竖屏，自上而下）

1. **标题**：「AISE手机端监考」
2. **副标题**：「请按下方示意摆放手机，确保监考画面完整」
3. **示意图一**：俯视视角摆放示意图（图片待替换）
   - 说明文字：「将手机立在考生座位左前方或右前方约 45° 位置，确保摄像头能同时拍到考生上半身和电脑屏幕」
4. **示意图二**：实景摆放效果参考（图片待替换）
   - 说明文字：「调整手机角度，让取景画面中桌面、双手、屏幕均在可视范围内，避免遮挡摄像头」
5. **注意事项卡片**：
   - 手机需保持屏幕常亮，关闭自动锁屏
   - 建议连接 WiFi，避免消耗手机流量
   - 请勿在考试期间切换应用或锁屏
6. **确认按钮**：「已按要求摆放，开始监考」
   - 按钮固定吸底，白色背景 + 顶部分割线
   - 点击后跳转至直播页

#### 3.2.2 交互细节

- 页面无返回按钮，扫码即进入，不需要返回上一级
- 点击确认按钮 → 跳转直播页，URL 携带同一 token
- 引导图未提供前，使用虚线占位框 + 图片图标示意

### 3.3 手机监考直播页

- **位置**：引导页点击「开始监考」后进入
- **URL**：`{AISE域名}/proctor/mobile/live?token={token}`
- **目标**：采集手机摄像头画面并推流至监考端

#### 3.3.1 页面结构

**视频预览区：**
- 全屏铺满，`object-fit: cover`，无视口黑边
- 深色背景（`#000`），视频未加载时深灰底色
- 使用浏览器 `getUserMedia` API 获取摄像头流，默认后置摄像头（`facingMode: 'environment'`）

**悬浮控件（四角，半透明毛玻璃）：**

| 位置 | 控件 | 内容 |
|------|------|------|
| 左上 | 监考状态 | 红色脉冲圆点 + 「监考中」+ 计时器（`MM:SS`） |
| 右上 | 网络状态 | 绿色/黄色/红色圆点 + 「正常」「波动」「断开」 |
| 左下 | 停止按钮 | 半透明胶囊按钮「停止」，点击停止推流 |
| 右下 | 翻转按钮 | 圆形图标按钮，切换前置/后置摄像头 |

#### 3.3.2 摄像头逻辑

- 页面加载时自动请求摄像头权限
- 默认启动后置摄像头
- 点击翻转按钮 → 切换前置/后置 → 重新获取流
- 摄像头权限被拒绝或不可用时：
  - 视频区显示摄像头禁用图标
  - 提示文字：「无法访问摄像头」
  - 副提示：「请检查权限设置后重试」
  - 「重试」按钮，点击重新请求权限

#### 3.3.3 计时器

- 摄像头成功开启时启动，格式 `MM:SS`
- 页面切后台（`visibilitychange`）时暂停计时，切回前台后恢复
- 停止推流时归零

#### 3.3.4 网络状态检测

- 每 8 秒检测一次
- 检测方式：加载极小图片（1×1 data URI），根据加载耗时判断
  - 延迟 < 600ms → 绿色「正常」
  - 延迟 ≥ 600ms → 黄色「波动」
  - 加载失败或 `navigator.onLine === false` → 红色「断开」

#### 3.3.5 停止监考

- 点击「停止」→ 停止摄像头流 → 计时清零 → 显示摄像头不可用状态
- 停止后不自动关闭页面，不跳转

#### 3.3.6 推流说明（产品层面）

- 手机端视频推流使用 WebRTC 或 H5 直播协议，具体方案由研发确定
- 推流目标：监考端已有的「查看摄像头」功能，手机推流与电脑推流对监考官透明
- 锁屏或切换应用可能导致推流中断，页面恢复前台后自动重连

---

### 3.4 二维码与考生绑定

- 考生进入设备调试页 → 服务端生成唯一 token
- token 编码进二维码 URL：`{域名}/proctor/mobile?token={token}`
- 手机扫码 → 服务端根据 token 识别考生身份 + 考试场次 → 绑定手机端推流会话
- 同一考生同一考试场次只能有一个手机推流连接，新连接踢旧
- token 有效期：考试时间窗口 + 30 分钟缓冲，超期失效
- 电脑端通过 WebSocket 或轮询感知手机连接状态

## 4. 流程与状态图表

### 4.1 页面流转

```
设备调试页（PC）                    手机端
     │                                │
     ├─ 展示二维码 ──────────────────→ 扫码
     │                                │
     │                             引导页
     │                                │
     │                             点击「开始监考」
     │                                │
     │                             直播页（推流中）
     │                                │
     ├← 感知手机连接 ←─────────────── 推流连接建立
     │                                │
     ├─ 摄像头项标记通过              │
     │                                │
     ├─ 进入考试                      │
     │                                ├─ 持续推流
     │                                │
     ├─ 考试结束 ──────────────────→ 停止推流
```

### 4.2 设备调试页 — 摄像头检测状态机

```
        ┌──────────┐
        │  未检测   │ ← 初始状态，灰点
        └────┬─────┘
             │
    ┌────────┼────────┐
    ▼        ▼        ▼
┌───────┐ ┌──────┐ ┌──────────┐
│电脑检测│ │手机扫码│ │电脑+手机 │
│ 通过  │ │ 连接  │ │  均通过   │
└───┬───┘ └──┬───┘ └────┬─────┘
    │        │          │
    └────────┼──────────┘
             ▼
      ┌──────────┐
      │ 摄像头通过 │ ← 绿点，可进入考试
      └──────────┘
```

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 二维码刷新间隔 | 60 秒 |
| 网络检测间隔 | 8 秒 |
| 网络正常阈值 | < 600ms |
| token 有效期 | 考试时间窗口 + 30 分钟 |
| 手机推流分辨率 | 720p（1280×720） |
| 浏览器兼容 | iOS Safari 14+ / Android Chrome 90+ |
| 同时推流数 | 同一考生仅 1 路手机流 |
