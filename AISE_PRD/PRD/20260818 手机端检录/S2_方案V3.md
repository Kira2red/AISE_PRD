### 2. 方案正文

#### 2.1 背景与目标

**目标产品/平台**：AISE 手机监考通道的「手机检录页」`/proctor/mobile/checkin`（新增页面，S1 F2）。本子任务 S2 只负责该页的 UI、交互、上传存储与异常埋点，不涉触发分流（S1 F1）、三态分支语义（S1 F3）、去向（S1 F4）、token（S1 F5）、来源通道（S1 F8）。

**核心用户画像**：无电脑摄像头的考生（D 级，手机监考 PRD §1.2），在手机监考通道内用自备手机完成检录（前置自拍正面照 + 检录视频）。

**现状与问题**：
- 线上电脑端检录页（`10_检录.html`）为桌面横屏布局（左实时画面 + 右「检录要求/示意图/拍照」信息区），其核心交互为「拍照 → 重新拍照 / 开始答题」。手机检录页需在**竖屏单列**布局下还原这一交互语义。
- 手机监考通道现有页面均为移动端竖屏（`30_手机监考_引导页.html` 用 `max-w-md mx-auto` 单列 + sticky 底部按钮；`31_手机监考_直播页.html` 用 `getUserMedia` + 权限拒绝 fallback「重试」+ 翻转按钮 + 网络检测）。
- 手机检录页需在竖屏约束下把「实时取景 + 拍照 + 检录视频 + 上传」整合为一个可完成、可重试、可续接的闭环，并补齐 S1 仅点名的「拍照即上传 / 录制完成即上传 / 半完成态续接」三处页级落点。

**目标**：给出手机检录页的竖屏 UI 结构、按钮状态机（拍照→重新拍照/开始监考）、前置摄像头调用与权限拒绝重试、照片/视频上传与失败重试（含卡死兜底）、半完成态续接，及覆盖全链路的埋点清单。上传与续接遵循锁定决策 7（拍照即上传）、8（检录页强制前置 `facingMode:'user'`）、10（仅实时拍摄、禁用相册/滤镜）。

#### 2.2 用户故事与用户旅程

| 用户故事 | 用户价值依据等级 | 来源 |
|---------|----------------|------|
| US1 作为考生，我能在手机检录页看到**前置取景实时画面**，确认自己入镜后再拍照 | D 级（既有机制延伸，自研 demo） | 检录 demo `10_检录.html`（左实时画面 +「请端正面对摄像头」提示） |
| US2 作为考生，我拍得不满意可以**重新拍照**，不必被迫使用不满意的照片 | D 级（既有机制延伸，自研 demo） | 检录 demo `10_检录.html`（拍照后按钮变「重新拍照」） |
| US3 作为非强制档考生，我可以**跳过检录**直接进入引导页，不阻塞入场 | E 级（经验判断，锁定决策 3 的直接后果，仅辅助） | 锁定决策 3（非强制有「跳过」） |
| US4 作为考生，我**拍照/录制完成即上传**，中途退出不会丢检录成果 | D 级（运营/既有机制延伸） | 锁定决策 7（拍照即上传） |

| US6 作为考生，摄像头权限被拒时我能看到明确提示并**重试** | D 级（既有机制延伸，自研 demo） | 直播页 demo `31_手机监考_直播页.html`（fallback「无法访问摄像头…重试」） |

**核心用户旅程（无摄像头考生，检录=强制档）**：

```
扫码落地分流 → 手机检录页（强制前置取景框 + 拍照示意）
  → 拍照（前置自拍正面照）→ 照片即时上传
  → 录制检录视频 → 视频即时上传
  → 「开始监考」→ 引导页 → 直播页（切后置推流）
```

**关键旅程差异**：与电脑端检录 demo 的「拍照 → 重新拍照 / 开始答题」对应，手机端为「拍照 → 重新拍照 / 开始监考」（「开始监考」即去向引导页的 CTA）。与电脑端横屏双栏不同，手机端为竖屏单列：**上方前置取景框 + 下方照片示意/拍照按钮组**。检录阶段摄像头始终前置（`facingMode:'user'`，锁定决策 8），**无翻转按钮**（翻转属直播页交互，`31_手机监考_直播页.html` 保留）。

|------|--------|-----------|---------|------|
| S0 初始 | 前置实时画面 | 检录示意图 | 「拍照」（primary） | 进入即申请前置摄像头；非强制档另有「跳过」 |
| S1 已拍照 | 前置实时画面 | 实际照片 | 「重新拍照」（ghost）+「开始录制检录视频」（primary） | 拍照即上传；上传中主按钮禁用显「上传中…」；上传失败显「重试上传」 |
| S2 录制中 | 前置画面 + 录制红点/计时 pill | 实际照片 | 「完成录制」（primary） | 时长/自动停止规则见待确认 #1 |
| S3 已录制 | 前置画面 | 实际照片 | 「重新拍照」（ghost）+「开始监考」（primary） | 视频录制完成即上传；上传失败显「重试上传」；**「开始监考」= 去向引导页**；**「重新拍照」→ 丢弃已录视频（不上传）→ 回 S1 重拍 + 重录**（照片/视频同轮一致） |
| S4 半完成态续接 | 前置实时画面 | 已传照片（回显，取最后一次） | 「重新拍照」（ghost）+「继续录制检录视频」（primary） | 重进检录页查到「仅照片」记录时进入（F9） |

> 与线上检录 demo 映射：「拍照」→「重新拍照 / 开始答题」在手机端映射为「拍照」→（录制视频）→「重新拍照 / 开始监考」。检录视频作为「照片→开始监考」之间的必经步骤（S1：检录=照片+视频），故状态机在 S1→S3 间插入录制步骤；最终完成态与任务要求一致为「重新拍照 / 开始监考」。

**（3）前置摄像头逻辑（含权限拒绝重试）**

```
进入检录页 → getUserMedia({ video:{ facingMode:'user', width:{ideal:1280}, height:{ideal:960} }, audio:false })  // 4:3 约束，与取景框一致；audio:false 为默认静音，是否含音频待与线上检录规格对齐（待确认 #1）
  ├─ 成功 → 渲染取景框，进入 S0
  └─ 失败（NotAllowedError 权限拒绝 / NotFoundError 无摄像头）
       → fallback 态：「无法访问摄像头，请检查权限设置后重试」+「重试」按钮
       → 点击重试 → 再次 getUserMedia（权限被永久拒绝时引导至系统设置，见 §2.5）
```

- 检录页**强制前置**，不提供翻转按钮（锁定决策 8），与直播页（`facingMode:'environment'` + 翻转按钮）明确区分。
- 权限拒绝 fallback 文案与交互对齐直播页 demo `31_手机监考_直播页.html`（「无法访问摄像头 / 请检查权限设置后重试 / 重试」），保证手机监考通道内错误态体验一致。
- 前置取景约束采用 **4:3 约束**（`width:1280 × height:960` ideal，与取景框 `aspect-ratio 4:3` 一致）；若设备不支持 4:3 输出，取景框以 `object-fit: cover` 居中裁剪为 4:3，保证所见即所得（裁剪策略见待确认 #4）。实际分辨率以线上检录规格为准（待确认 #1）。
- **audio 口径（回应 #5）**：检录视频默认 `audio:false`（静音），是否含音频待确认 #1 与线上检录规格对齐；若线上检录视频含音频则改 `audio:true` 并同步录制音频轨。

**（4）照片/视频上传（失败重试 + 幂等）**

| 对象 | 产生时点 | 上传时点 | 落库反查 | 失败处理 |
|------|---------|---------|---------|---------|
| 照片 | 「拍照」点击，canvas 截帧 → `toDataURL('image/jpeg', 0.9)` → Blob | 即拍即传（锁定决策 7） | token 反查「考生 + 场次 + 来源通道=手机」（S1 F5/F8） | 按钮显「重试上传」；连续失败（≥3 次或 10s 超时）→「检查网络」引导 +「退出检录」（兜底，逃生通道非跳过）；非强制档可跳过 |
| 检录视频 | 「完成录制」点击，`MediaRecorder` stop → Blob | 录制完成即传（锁定决策 7） | 同上 | 同上（超时阈值 60s） |

- 照片与视频**各自独立上传、可分别成功/失败**（S1 F6）；上传状态在按钮组就地反馈（禁用 +「上传中…」/「重试上传」），不弹窗打断。
- **卡死判定（回应 #3）**：超时阈值分设——照片 10s、视频 60s（视频体积大，弱网合法上传时长更长；可按文件大小动态调整）；**有上传进度（分片/进度回调）则重置计时、不判定卡死**，仅在无任何进度回传的静默期内计时，避免误杀弱网长传。
- 上传均为**仅实时拍摄产物**，禁用相册选图与美颜/滤镜（锁定决策 10），保证监考端核验真实性（S1 §2.4(3) 缓解）。
- **上传接口幂等（回应 #6）**：以「业务 ID（考生 + 场次 + 来源通道 + 对象类型）+ 内容哈希」为幂等键，重试命中同一键**不重复落库**。区分两类：①考生**主动**多次拍照 → 不同内容哈希 → 追加多份记录（S1 F8「追加保留」，生效取最后一次）；②同一次上传的**重试**（网络抖动 / 服务端已成功但响应丢失）→ 同内容哈希 → 幂等去重，不产生重复记录。二者不冲突。
- 具体上传接口、存储桶、鉴权方式沿用手监考/线上检录既有实现，本方案不新设计，见待确认 #1。

**（5）去向衔接**

- 「开始监考」（S3）→ `/proctor/mobile/guide?token={token}`（token 沿 URL query 透传，S1 F5）。
- 「跳过」（非强制档，任意状态可点）→ 同样去向引导页；**录制中（S2）点击「跳过」时，MediaRecorder 立即 stop 并丢弃（不上传），回初始态后进引导页**（见 §2.5 B）。
- 「退出检录」（上传卡死兜底，任意状态可点）→ 引导回设备调试页重新扫码（token 复用，S1 F5），重进后触发半完成态续接（F9）。
- 检录页**不经过候考**（S1 F4/锁定决策 6），不出现倒计时/等候元素。

#### 2.5 边界与异常场景（穷举）

**A. 摄像头权限与调用**

| 场景 | 行为 |
|------|------|
| 首次进入弹权限，用户点「允许」 | 进入 S0 正常取景 |
| 用户点「拒绝」 | fallback 态：提示 + 重试；强制档被卡在检录页（S1 R3 已定性） |
| 用户浏览器/系统级「永久拒绝」（iOS 无再次弹窗，需去系统设置） | fallback 文案升级为「请在系统设置中开启摄像头权限后返回」+ 提供引导；是否内置「去设置」跳转见待确认 #5 |
| 无摄像头设备（`NotFoundError`） | fallback 态，文案「未检测到摄像头」，无法检录 |
| 检录页调用前置失败但设备有后置 | 不自动降级后置（锁定决策 8 强制前置，检录不拍环境），提示用户检查前置摄像头 |

**B. 拍照/视频交互**

| 场景 | 行为 |
|------|------|
| 拍照时取景画面卡顿/黑屏 | 「拍照」输出空帧时提示「拍摄失败，请重试」，不生成照片、不触发上传 |
| 录制中切后台/锁屏/来电 | `visibilitychange` 触发停止录制，录制**中断**（视频不完整），提示重新录制（对齐 S1 §2.5 E「视频录制中断需重新录制」） |
| 录制中摄像头流意外停止（track ended） | 提示「录制中断，请重试」，回退 S1 状态 |
| 用户反复拍照多次 | 每次拍照均即传并**追加**记录，生效/通过判定取最后一次（S1 F8） |
| 录制中（S2）点击「跳过」（非强制档） | `MediaRecorder` **立即 stop 并丢弃（不上传）**，回初始态后进引导页（回应 #4） |
| 已录制（S3）点击「重新拍照」 | **丢弃已录视频（不上传）→ 回 S1** 重新拍照 + 重新录制，照片/视频同轮一致（回应 #1） |

**C. 上传与网络**

| 场景 | 行为 |
|------|------|
| 照片上传弱网失败 | 按钮显「重试上传」，可重试；连续失败（≥3 次或 10s 超时）触发兜底「检查网络」引导 +「退出检录」；强制档未成功不可进引导页（**兜底 ≠ 跳过**）；非强制档可「跳过」 |
| 视频上传弱网失败 | 同上（超时阈值 60s）；已传照片记录保留，重进可续接 |
| 服务端已成功但响应丢失（网络中断致客户端未收到成功） | 重试上传命中幂等键（业务 ID + 内容哈希），**不重复落库**（回应 #6） |
| 连续失败触发「退出检录」 | 回到设备调试页重新扫码（token 复用，S1 F5），重进检录页触发半完成态续接（F9），已传照片不丢 |
| 上传中切后台/锁屏 | 上传中断，回到按钮「重试上传」；照片已截取但未上传成功 → 无落库，重进需重拍（「产生即上传」下无「已拍未传」悬置态，S1 §2.5 E） |
| 上传接口返回 token 无效 | 阻断并引导回扫码（对齐 S1 §2.5 B「token 失效」） |

> 兜底 = 逃生通道非跳过（回应 #3）：连续失败提供「检查网络」引导 +「退出检录」按钮，让考生退出卡死的上传态、回到设备调试页重新扫码（token 复用），重进后触发半完成态续接（F9），**已上传成果不丢**；但强制档仍**不允许跳过检录**（「不豁免、不兜底」的强制档语义不变，S1 §2.5 C）。**超时分设阈值：照片 10s / 视频 60s（可按文件大小调整），有上传进度则重置计时、不判定卡死（回应 #3）**。此兜底与 S1 R3「摄像头卡死」同源，属 S2 页级逃生通道的补齐（S1 R3 的页级落点）。

**D. 半完成态续接（异常态）**

| 场景 | 行为 |
|------|------|
| 照片已传、视频未录，退出重进 | 查「来源通道=手机」自身「仅照片」记录 → 进入 S4，回显**最后一次**照片 + 「继续录制检录视频」；也可「重新拍照」（追加新记录） |
| 照片已传、视频已传（完整态）重进 | 按「不去重」允许重新检录**追加**，不拦截（S1 §2.5 E） |
| 「仅照片」记录查询失败（服务端未支持） | 降级为 S0 初始态（需重拍），并在页面隐藏续接入口；此降级路径见待确认 #2 |

> 回显口径（回应 #4）：S4 回显「已拍照片」取**最后一次**（按上传时间倒序取最新一条），对齐 S1 F8「生效/通过判定取最后一次」；同一考生「仅照片」多条记录时，续接展示的是最新一次，避免回显旧照片误导考生。

**E. 三态与去向**

| 场景 | 行为 |
|------|------|
| 强制档未完成（照片或视频任一未成功上传） | 「开始监考」不可用/不可进入引导页 |
| 非强制档任意状态点「跳过」 | 直接去向引导页，跳过检录（录制中则先立即 stop 丢弃，见 §2.5 B） |
| 检录=不开启 | 不出现本页（S1 F1 分流直接到引导页），S2 无逻辑 |

#### 2.6 成功度量与指标

| 指标 | 定义 | 数据来源 / 估算依据 |
|------|------|-------------------|
| 手机检录完成率（强制档） | 完成检录（完整态）的扫码会话占比 | 待验证（埋点，token 关联，沿用 S1 §2.6） |
| 拍照成功率 | 拍照上传成功次数 /（拍照 + 重新拍照）总点击次数（`手机检录_拍照` + `手机检录_重新拍照` 埋点合并计数） | 待验证（埋点 F11） |
| 视频上传成功率 | 视频上传成功次数 / 完成录制次数（完成录制 = `手机检录_完成录制` 事件次数） | 待验证（埋点 F11） |
| 摄像头权限拒绝率 | 权限拒绝进入 fallback 的次数 / 进入检录页次数 | 待验证（埋点 F11） |
| 上传失败重试率 | 触发「重试上传」的上传次数 / 总上传次数 | 待验证（埋点 F11） |
| 上传卡死兜底率 | 触发「退出检录」的会话数 / 总上传会话数 | 待验证（埋点 F11，`手机检录_退出检录` 事件） |
| 半完成态续接率 | 进入 S4 续接的会话数 / 「仅照片」重进会话数 | 待验证（埋点 F11，依赖服务端「仅照片」查询） |
| 手机检录耗时 | 进入检录页 → 检录完成（或跳过）中位时长 | 待验证（埋点 F11，沿用 S1 §2.6） |

> 所有指标均为「待验证」，首轮不预置假设数值（避免凭空编造），上线以埋点回填基准。

**硬件依赖风险（单独列出）**：手机检录页新增依赖「`MediaRecorder` 视频录制」与「前置摄像头分辨率能否满足检录照片规格」。前置摄像头为既有依赖（无新增硬件）；`MediaRecorder` 为**新增软件能力依赖**，iOS Safari 兼容面（<14.5 默认不支持，14.0–14.4 仅实验特性）需在开发前确认，见 R3/待确认 #3。
