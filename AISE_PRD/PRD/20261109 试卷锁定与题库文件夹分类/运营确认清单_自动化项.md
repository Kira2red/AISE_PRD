# 运营确认清单：可自动化设计项（2026-11-09）

> 用途：与运营逐条确认「手动操作改为自动化流程」的口径，确认后统一修订 PRD 与 demo。
> 每条含：原始需求表述 / 当前设计 / 手动操作的后果 / 自动化后的体验。

## 1. 锁定动作：手动锁 → 开考自动快照（最重要）

- 原始需求表述：正式开考前，管理员对考场执行锁定；锁定生效时冻结试卷引用的题目版本。每场考试都要管理员手动点一次锁定。
- 当前设计：锁定=冻结追溯基线+拦截改题，两者绑在同一个手动动作上。
- 手动操作的后果：考场数量持续增长（当前 572 场），每场考试前都要有人记得点锁定；忘锁一场，该场题目快照缺失，考后改题直接穿透到成绩追溯，回到需求要解决的原始问题。人工动作的可靠性撑不起证书公信力目标。
- 自动化后的体验：考试开始时间到达时，系统自动保存当时引用的题目版本快照（与是否手动锁定无关）。追溯基线自动建立、永不遗漏。锁定入口保留，降级为「提前锁定」的可选操作，用途仅剩：考卷定稿后、开考前防止误改题目。忘锁不再有后果。
- 连带变化：追溯快照（自动）与锁定（手动可选）分离；共卷同锁弹窗只在提前手动锁时出现，可简化。
- 待运营确认：是否接受「自动快照 + 锁定可选」；提前锁定要不要保留。

## 2. 解锁动作：手动解锁 → 考试结束自动解除

- 原始需求表述：考试结束、证书公示后管理员解除锁定。
- 当前设计：管理员随时手动解锁，解锁后试卷恢复可编辑。
- 手动操作的后果：每场考完都要记得解锁；忘了解锁，锁定卷引用的题目一直只读，运营改不了题也不知道原因。管理成本随考场数线性增长。
- 自动化后的体验：考试结束时间到达后自动解除锁定。安全兜底不依赖解锁时机：追溯靠自动快照（第 1 条），出分后改题走二次确认+留痕。即使自动解锁，也不存在「考完的卷被悄悄改掉」的风险。
- 连带变化：解锁确认弹窗与「仍被引用保持只读」规则大幅简化；操作日志仍记录，操作人记「系统」。
- 待运营确认：自动解锁的时点（考试结束时间到达 / 成绩与报告生成完成后）。

## 3. 存量题目迁移：手工分批归类 → 上线自动初始化

- 原始需求表述：功能上线后由管理员执行存量题目归类，可按考期分批推进（存量 939 题）。
- 当前设计：默认题库/我的题库两值自动转文件夹，其余细分归类靠管理员手工。
- 手动操作的后果：939 题手工归类工作量大、完成度无约束；「旧题找不到」的痛点解决进度完全依赖运营执行力，容易烂尾。
- 自动化后的体验：上线时按规则一次性自动初始化，如按题目创建时间自动建「2026年10月」类月份文件夹并归入（或按已有标签映射），运营只做微调。
- 待运营确认：自动初始化规则用哪条（创建月份 / 标签映射 / 原所属题库）。

## 4. 录题归属：管理员事后归类 → 录题时直接选归属

- 原始需求表述：管理员选中题目归入文件夹（归类为管理员专属动作）。
- 当前设计：普通账号无文件夹概念，题目默认未归类，全靠管理员事后归。
- 手动操作的后果：新录题目持续堆积在未归类，管理员归类速度追不上录入速度，目录秩序靠一个人维持。
- 自动化后的体验：录题表单增加「归属文件夹」可选字段（树形选择，默认未归类），录题时顺手归位。属权限口径调整：录题老师可否选归属需运营拍板（建议：可选用，仅允许选已有文件夹、不能建新夹）。
- 待运营确认：录题老师能否选择归属文件夹。

## 5. 下期组卷找旧卷：试卷列表翻找 → 考场一键复制

- 原始需求表述：老师复制旧卷生成独立副本，修改副本作为下期新卷（入口在试卷管理，需先找到上一期的卷）。
- 当前设计：试卷管理列表提供复制按钮（原始需求形态）。
- 手动操作的后果：要先弄清上期用的是哪份卷（试卷 195 份且大量「-副本」），找错卷、复制到旧版本的风险靠人眼把关。
- 自动化后的体验：考场列表行内增加「复制试卷为新卷」入口，从上一期考场直接复制其绑定的卷，来源天然正确。
- 待运营确认：是否需要该入口（交互优化，改动小）。

## 建议优先级

- 1、2 必做：决定整套机制是否依赖人工可靠性
- 3 强烈建议：不做则存量迁移大概率烂尾
- 4、5 跟随运营意见

## 确认结果（2026-11-09 运营确认）

- 第 1 条：确认。开考时自动保存题目快照，后续考试数据都跟快照有关，原始题目怎么修改都不影响。
- 考中/考后修改：存在但极少。新增兜底入口——不在题目列表，在考试（考场详情）里，只改这个考试的某个题目（运营确认 OK）。
- 第 2 条：未单独拍板；手动锁定/解锁已随第 1 条口径整体取消（修订记录 V1.1 留痕）。若后续需要「提前锁定」类流程控制再单独立项。
- 第 3、4、5 条：待运营确认（本次未涉及）。
- 附加口径：爱测评不区分练习和考试，都认为是考试；练习是 AISE 的业务逻辑，不会同步给爱测评。
- 落地：PRD 升 V1.1（需求一重构为「考试题目快照 + 复制试卷」），demo 30 重写并更名 30_考场管理_题目快照.html，飞书文档原位修订。
