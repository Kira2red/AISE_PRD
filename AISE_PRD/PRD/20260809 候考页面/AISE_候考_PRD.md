## 1. 项目背景

### 1.1 需求简介

让考生在正式测评开始前，先完成环境检测（摄像头/麦克风/录屏/手机监考）和检录，然后在等候页等待开考，开考后一键进入考试，不占用正式测评时间。模拟测同样提供检测检录环节，完成后直接进入模拟测。考试后台可配置候考时长（候考窗口 = 开考前 N 分钟 ~ 开考时间），未配置时系统行为与现在完全一致。

### 1.2 业务诉求

运营反馈：正式测评开始时，部分考生因环境检测、设备调试占用开考后的时间，导致迟到进场、延迟开考；同时考生普遍不知道可以提前准备环境。模拟测时间一般提前于正式测，考场直接开放，也需要同样的检测检录环节，且完成后直接进入模拟测（不需要返回个人中心再点一次）。

**核心收益**：减少正式测评开始时段因设备问题（摄像头/录屏未开、权限未授权）占用考试时间，降低开考瞬间入场阻塞。
**度量方式**：候考上线的场次中「开考后 5 分钟内完成入场」的考生比例，与未上线候考的场次对比；对比优先同一考试（同系列）上线前后，或同期配置了/未配置候考的相似考试（避免不同考试人群混杂）。

### 1.3 范围界定

- **做**：考试入口三态（未开始/准备考试/开始考试）、候考流程编排（检测→检录→等候→开始考试）、等候页、考试管理「候考时长」配置
- **不做**：检测/检录的交互与校验逻辑修改（沿用现有实现，结果以爱测评后台为准）、消息通知、监考端入场统计（记后续迭代）

## 2. 业务流程简述

### 2.1 正式测评（配置了候考时长 N 分钟）

```
考试入口（三态）
  ├── 开考前 N 分钟之前：入口「考试未开始」（点击提示开始时间与最早可候考时间）
  └── 开考前 N 分钟 ~ 开考时间：入口「准备考试」
        └── 设备检测（现有逻辑）→ 检录（现有逻辑）→ 等候页（倒计时等待）
              └── 开考后出现「开始考试」→ 点击直接进入考试（不重复检测检录）
  └── 开考后：入口「开始考试」→ 设备检测 → 检录 → 直接进入考试（原流程，不走等候页）
```

### 2.2 模拟测评

```
入口「模拟测评」（随时可进，不受候考窗口限制）
  └── 设备检测（现有逻辑）→ 检录（现有逻辑）→ 直接进入模拟测（无等候页、无倒计时）
```

### 2.3 未配置候考时长

入口与流程与现在完全一致（「进入测评」→ 检测 → 检录 → 进入考试）。

### 2.4 涉及页面清单

| 页面 | 类型 | 说明 |
|------|------|------|
| 爱测评考试管理（监考信息区） | 修改 | 新增「候考时长」配置项 |
| 设备检测（弹窗） | 修改 | 流程编排：检测完成后按时序规则进入等候页或直接进考试 |
| 检录（页面） | 修改 | 检录完成后按时序规则进入等候页或直接进考试；跳过按钮文案「准备开始考试」 |
| 等候页 | 新增 | 考试名称 + 开始时间 + 倒计时 + 状态标识 + 开考后「开始考试」按钮 |
| 考试入口（AISE 我的活动/我的考试、iceping 端） | 修改 | 入口三态：未开始 / 准备考试 / 开考后原文案 |

## 3. 详细功能说明

### 3.1 考试入口（AISE 用户端 + iceping 端统一改造）

所有考试入口页面统一生效：AISE 我的活动、我的考试等页面，以及 iceping 端答题入口上的正式测评入口按钮。

入口按钮文案与行为按时序分三态（时间以服务端为准）：

| 状态 | 入口按钮 | 点击行为 |
|------|----------|----------|
| 开考前 N 分钟之前 | 「考试未开始」（灰色禁用样式，可点击） | 提示：考试尚未开始，显示考试开始时间 + 最早可进入考场（候考）时间 |
| 开考前 N 分钟 ~ 开考时间 | 「准备考试」 | 进入候考流程（检测 → 检录 → 等候页） |
| 开考后 | 原文案（「进入测评」/「开始考试」） | 走原流程（检测 → 检录 → 直接进考试） |

说明：开考后入口保留各端原文案。同一列表页可能出现「配置了候考的考试显示『开始考试』、未配置的显示『进入测评』」并存，属预期表现，不强制统一。

模拟测评入口不受时序限制，始终可用，文案保持「模拟测评」。

### 3.2 设备检测（沿用现有，不修改）

进入候考流程后第一步仍是现有设备检测弹窗：摄像头+麦克风一起检测、录屏单独检测、手机监考备选（扫码用手机推流），各项按考试配置强制/非强制/不开启，全部通过后进入下一步。检测结果与现有行为一致，存储于爱测评后台，本需求不定义不修改。

### 3.3 检录（沿用现有，出口变化）

检测通过后进入现有检录页（拍照 + 检录视频），按考试配置三档（强制/非强制/不开启）。与现有流程的唯一差异在检录完成/跳过后的出口：

- **候考窗口内**：检录完成或跳过 → 按 §4 时序判定进入等候页或直接进考试；检录可跳过时，跳过按钮文案用「准备开始考试」
- **开考后**：与原流程一致，直接进入考试
- **模拟测**：检录完成或跳过 → 直接进入模拟测

### 3.4 等候页（新增）

考生完成检测检录、且当前时间未到开考时间时进入。页面内容自上而下：

1. **考试信息**：考试名称、场次信息
2. **状态标识**：设备检测已通过、检录已完成（绿色状态徽章，动态展示，未完成项不显示）
3. **倒计时**：距离开考剩余时间（分:秒），下方显示考试开始时间
4. **考试信息明细**：「考试时长（取考试配置，示例 60 分钟）」「交卷限制（取考试配置，示例 开考 15 分钟后可交卷）」，标签与值紧凑相邻（组内距离小于组间距离）
5. **考生须知**：保持摄像头和录屏开启、开考后点击「开始考试」直接进入无需重复检测、设备异常联系客服
6. **离开提示**：「请勿关闭或刷新本页面，离开后需重新进入候考流程」
7. **等待提示**：「等待开考，请勿离开」（倒计时进行中显示）；倒计时归零后该提示消失，出现「开始考试」主按钮

**倒计时规则**：
- 倒计时归零时若考生停留在等候页，直接展示「开始考试」按钮，考生手动点击进入（不自动跳转，避免打断考生准备）
- 点击「开始考试」时服务端二次校验当前时间 ≥ 开考时间，校验通过才放行；未到开考时间则停留在等候页并刷新倒计时

**异常处理**：
- 考生离开等候页（关闭/刷新/退出）：再次进入考试入口时，按 §4 时序判定；候考进度以爱测评后台记录为准（见 §4 状态机与 §6 技术前置确认）
- 换设备：检测结果与设备/浏览器会话相关，重进若检测到设备变更需重做设备检测；检录结果与账号绑定，已完成检录不重复
- 开考时间被修改：等候页轮询考试状态，倒计时同步更新并提示
- 考试被取消：等候页显示终止提示（考试已取消），不出现开始考试按钮
- 断网：倒计时暂停并显示异常提示，网络恢复后以服务端时间校准

### 3.5 考试管理配置（爱测评）

考试管理「监考信息」区新增字段：

| 字段 | 控件 | 规则 |
|------|------|------|
| 候考时长 | 数字输入框 + 「分钟」后缀（与考试时长同款样式） | 留空或 0 = 不开启候考；上限 120 分钟（超限提示并钳制）；考试已开考后修改不生效；候考时长显著大于「配置时距开考时间」时给出确认提示，防止误配 |

配置说明文案：「开启后：开考前 {N} 分钟入口显示『准备考试』，考生可提前完成设备检测和检录并等待开考（上限 120 分钟；考试已开考后修改不生效）」

## 4. 时序判定规则（核心）

所有时间判定以服务端时间为准，边界区间左闭右开。

**候考进度状态机**：未开始 → 检测通过 → 检录完成（或被跳过）→ 已入等候 → 已进考试。

**「完成时刻」定义**：设备检测与检录全部完成（或检录被跳过）的时刻，即状态机进入「已入等候」前的最后一步完成时刻。检录配置为「不开启」的考试，完成时刻 = 检测完成时刻；检录「非强制」且考生选择跳过，完成时刻 = 跳过操作时刻。

**中间态续接**：检测完成但检录未完成时退出重进，从检录步骤继续（不重做检测）。状态持久化复用爱测评现有检测/检录结果存储，重进时按「账号 + 考试场次」查询进度。

| 场景 | 判定 | 行为 |
|------|------|------|
| 当前时间 < 开考前 N 分钟 | 入口态 | 「考试未开始」+ 点击提示 |
| 开考前 N 分钟 ≤ 当前时间 < 开考时间 | 入口态 | 「准备考试」 |
| 当前时间 ≥ 开考时间 | 入口态 | 原文案（进入测评/开始考试） |
| 候考流程中，完成时刻 < 开考时间 | 流程去向 | 进等候页 |
| 候考流程中，完成时刻 ≥ 开考时间 | 流程去向 | 直接进考试（不进等候页） |
| 开考后新进入 | 流程去向 | 原流程（检测 → 检录 → 直接进考试），不走候考 |

## 6. 技术前置确认（与爱测评技术侧对齐）

1. **检测通过状态的服务端记录**：设备检测通过结果是否已按「账号+考试场次」持久化，支撑「重进不重复检测」；若未持久化，降级方案为重进需重新检测、不重复检录
2. **检测结果与设备/浏览器会话的绑定能力**：支撑换设备重测判定（§3.4 异常处理）
3. **时钟源**：入口三态与倒计时判定统一以服务端时间为准（前端服务端下发剩余秒数 + 本地走秒 + 定期校准；点击「开始考试」服务端二次校验）
4. **等候页轮询**：开考时间变更/考试取消的感知方式（轮询间隔与接口）
5. **开考并发**：候考把考生聚集到开考瞬间集中点击「开始考试」，瞬时入场峰值可能高于现状，需做并发预估/压测，并确认进考试接口限流策略

---

## 7. 不做项

- 不改设备检测、检录页面的样式与交互逻辑（线上样式即基准）
- 不做短信/推送提醒（考生是否候考由运营引导）
- 不做监考端「已候考/已检录/已入场」统计（数据已具备，后续迭代）
- 不做候考时长按考场覆盖配置（统一按考试配置）
- 不新增检测/检录结果定义（以爱测评后台为准）

## 8. 验收要点

**主流程**：
- 配置候考时长 30 分钟后：开考前 30 分钟~开考时间，各入口显示「准备考试」；30 分钟前显示「考试未开始」+ 提示最早可候考时间；开考后显示原文案
- 候考流程：准备考试 → 检测 → 检录 → 等候页倒计时 → 开考后「开始考试」直接进考试，不重复检测检录
- 完成时刻已过开考时间 → 直接进考试，不进等候页
- 模拟测：随时可进，检测检录后直接进，无等候页
- 未配置候考时长 → 所有入口与流程与现状一致
- 检录不开启的考试 → 候考流程跳过检录步骤；非强制 → 可跳过（按钮「准备开始考试」）
- 候考时长上限 120、已开考后修改不生效
- 等候页倒计时归零出现「开始考试」，点击后服务端校验通过才进入

**异常路径**：
- 离开等候页后重进：不重复检测检录、从断点继续（中间态落点正确）
- 换设备重进：检测到设备变更需重做设备检测，检录不重复
- 开考时间修改：等候页倒计时同步更新并提示
- 考试取消：等候页显示终止提示，不出现开始考试按钮
- 断网：倒计时暂停并显示异常提示，恢复后校准
