## 一、需求背景与收益

运营诉求：让用户在正式测评开始前完成环境检测和检录，不占用正式测评时间；模拟测同样提供候考环节，检测检录完成后直接进入模拟测。

**收益**：减少正式测评开始时段因设备问题（摄像头/录屏未开、权限未授权）占用考试时间，降低开考瞬间入场阻塞和客诉。

**度量方式**（评审补充口径）：
- 核心指标：候考上线的场次中，「开考后 5 分钟内完成入场」的考生比例，与未上线候考的场次对比
- 对比方式：优先同一考试（同系列）上线前后对比，或同期配置了/未配置候考的相似考试对比（避免不同考试人群混杂）
- 需补埋点：候考进入、检测完成、检录完成、等候页停留时长、开考后实际入场时间

## 二、方案总览

爱测评考试后台新增「候考时长（分钟）」配置项。配置后，考试开始前 N 分钟开放候考窗口：用户从入口进入后依次完成设备检测、检录，然后停留在等候页等待开考；开考时间到，等候页出现「开始考试」按钮，点击直接进入考试，不重复检测检录。

未配置候考时长（留空或 0）的考试，全部走现有流程，行为不变。

**时钟源原则**（评审发现 🔴2 修正）：所有时序判定（候考窗口、完成时刻 vs 开考时间、倒计时归零）以服务端时间为准。前端倒计时由服务端下发剩余秒数 + 本地走秒、定期校准实现；点击「开始考试」时服务端二次校验当前时刻 ≥ 开考时间，未到则停留在等候页并刷新倒计时。

## 三、详细设计

### 3.1 配置：候考时长

- 位置：爱测评考试管理 → 监考信息区（摄像头监考/录屏监考/检录照片等配置之后）。
- 控件：数字输入框 + 后缀「分钟」，样式与「考试时长」一致。
- 取值：正整数，上限 120（覆盖大型考试提前组织入场的最长时长）。留空或 0 = 不开启候考。
- 配置提示（评审 💡14 修正）：考试已开考后再修改候考时长不生效；候考时长显著大于「配置时距开考时间」时给出确认提示，防止误配。

### 3.2 时序规则（判定表，评审 🔴1/🟡5/🟡6 修正）

| 用户进入时刻 | 流程 |
|---|---|
| 开考前 N 分钟之前 | 提示未到候考时间（显示考试开始时间与可候考时间），不进入考试流程 |
| 开考前 N 分钟 ~ 开考时间（左闭右开：恰好开考前 N 分钟视为窗口内；恰好开考时间视为已开考） | 设备检测 → 检录 → 等候页 → 开考后点「开始考试」进考试 |
| 开考时间之后 | 设备检测 → 检录 → 直接进入考试（现有流程，不经等候页） |

**检测检录完成时刻的判定**：
- 完成时刻 < 开考时间 → 进入等候页（显示考试名称、开始时间、倒计时）
- 完成时刻 >= 开考时间 → 直接进入考试，不进等候页

**候考进度状态机**（评审 🟡5 补充）：
- 未开始 → 检测通过 → 检录完成（或被跳过）→ 已入等候 → 已进考试
- 「完成时刻」= 检录完成或被跳过的时刻
- 状态持久化：复用爱测评现有检测/检录结果存储（用户确认：检测和检录的结果已在爱测评后台，本需求不定义不修改其存储）；重进时按「账号 + 考试场次」查询进度，从断点继续
- 换设备场景（评审 🟡8 补充）：检测结果与设备/浏览器会话相关，重进若检测到设备变更需重做设备检测；检录结果与账号绑定，已完成检录不重复
- 中间态：检测完成但检录未完成时退出重进 → 从检录步骤继续（不重做检测）

**等候页内行为**：
- 等待中：倒计时显示剩余时间
- 倒计时归零：出现「开始考试」按钮，点击直接进考试；点击瞬间服务端校验（时钟源原则）
- 断网（评审 🟡6 补充）：倒计时暂停显示异常提示，网络恢复后以服务端时间校准
- 考试状态变更（评审 🟡9 补充）：等候页轻量轮询考试状态，开考时间被修改则更新倒计时并提示；考试被取消则显示终止提示

**并发**（评审 🟡7 补充）：开考瞬间入场请求可能出现集中峰值，列为技术评估项（压测 + 可选缓解：倒计时归零后按钮可用 + 3~5 秒缓冲，缓解方案由技术评审决策）。

### 3.3 入口与文案（评审 💡11 修正）

入口按钮三态：
| 时刻 | 按钮文案 | 行为 |
|---|---|---|
| 开考前 N 分钟之前 | 「考试未开始」 | 入口显示未开始状态；点击提示未到候考时间，展示考试开始时间和最早可进入考场（候考）的时间 |
| 候考窗口内 | 「准备考试」 | 进入候考流程 |
| 开考后 | 原文案（开始考试/进入测评） | 现有流程 |

### 3.4 模拟测规则（评审 🟡3 修正）

模拟测不受候考窗口和开考时间限制（考场直接开放，随时可进入）。配置了候考时长的考试，模拟测入口同样先执行设备检测 → 检录，完成后直接进入模拟测（无等候页、无倒计时、无「开始考试」按钮）。与正式测的差异仅在「无等待环节」。

### 3.5 与检测/检录配置联动（评审 🟡4 修正）

| 考试配置 | 候考流程表现 |
|---|---|
| 检录照片 = 强制开启 | 必须完成检录拍照才能继续 |
| 检录照片 = 非强制开启 | 检录可跳过；跳过后的出口与完成检录一致，按时序规则判定（进等候页或直接进考试）；候考窗口内跳过按钮文案为「准备开始考试」 |
| 检录照片 = 不开启 | 候考流程跳过检录步骤，检测完成后按时序规则进入等候页或直接进考试 |
| 摄像头/录屏 = 非强制/不开启 | 沿用现有检测逻辑，相应检测项可跳过 |

检测/检录的页面交互、校验逻辑、结果存储均沿用现有实现，本需求只调整流程编排和新增等候页。

### 3.6 等候页（评审 💡12 补充）

新页面。内容：考试名称、开始时间、剩余时间倒计时；倒计时归零后显示「开始考试」按钮。补充信息：考试时长、「设备检测已通过 / 检录已完成」状态标识、简版考生须知、「请勿关闭页面，离开需重新进入」提示。视觉风格与现有检录页一致（浅色背景 + 点阵纹理 + 白色卡片）。

## 五、不做范围

- 不改设备检测/检录页面的交互和视觉（线上样式已定型）。
- 不改检测/录屏/检录的强制程度配置逻辑。
- 不做站内消息通知（用户端无此能力）。
- 不做候考期间的监考行为（候考期间不录像，开考后检测/录屏按现有逻辑启动）。
- 监考端入场进度统计（已候考/已检录/已入场人数）——评审 💡15，记后续迭代，本期不做。

## 六、技术前置确认（评审 🔴1 修正）

- 确认爱测评是否已有「设备检测通过」的服务端记录（账号 + 场次维度），支撑「重进不重复检测」。已有则复用；没有则需新增记录（本需求范围内）；无法新增则降级为「重进需重新检测、不重复检录」，相应修订 §3.2。
- 确认检测结果与设备/浏览器会话的绑定能力（支撑换设备重测判定）。
