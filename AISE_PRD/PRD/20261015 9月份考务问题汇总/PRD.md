## 需求一：报名管理功能升级

### 1. 背景与收益

需求简介：报名管理列表页补充考务核验所需的核心信息列，搜索栏支持考务常用维度的精确与模糊查询。

业务诉求：考务人员在报名列表页核验学生照片、准考证、联系方式、考试时间等信息时，需要跳转多个页面逐个查看，核验效率低；现有搜索仅支持订单号/姓名/手机号，缺少准考证号、用户ID 等考务常用查询维度，订单号查询存在失效问题（考务反馈原表 #10）。本需求将核验动作收口到列表页一屏内完成，并提供多维度查询能力。

### 2. 业务流程

考务人员进入「报名管理」列表页：

1. 浏览列表，直接读取每条报名记录的照片状态、准考证、登录手机号、联系电话、所属分组、考试时间
2. 需要定位特定记录时，在搜索栏选择查询类型（准考证号/身份证号/订单号/用户ID/手机号），输入内容查询
3. 不确定完整编号时，使用综合模式模糊搜索姓名、手机号等字段
4. 点击「详情」查看完整报名信息并执行后续操作

### 3. 详细功能说明

#### 3.1 列表新增展示列

在现有列结构基础上新增/调整以下列（列顺序从左到右）：

| 列 | 位置 | 展示内容 |
|---|---|---|
| 照片状态 | 学员信息之后 | 四种状态徽标：合格（绿）/ 待审核（黄）/ 不合格（红）/ 未提交（灰） |
| 准考证 | 照片状态之后 | 准考证号；生成失败或未生成的显示「未生成」灰字 |
| 登录手机号 | 准考证之后 | 学生账号的登录手机号，等宽字体展示 |
| 联系电话 | 登录手机号之后 | 报名时填写的联系电话；与登录手机号可能不同，分列展示 |
| 所属分组 | 联系电话之后 | 学生在该活动-分组体系下所属的分组（如「上午场 A组」） |
| 用户ID | 学员信息单元格内 | 报名学生账号的用户ID，展示在姓名下方 |
| 考试时间 | 状态之后、报名时间之前 | 学生所在考场（测评×渠道）的配置时间，具体年月日与区间（如「2026-07-15 09:00–11:00」）；未关联考场时显示「—」 |

明细见下：

- 照片状态四种状态互相独立判定：未提交照片的学生显示「未提交」，已提交但未审核的显示「待审核」，审核结论为通过/不通过的分别显示「合格/不合格」
- 所属分组取新的活动-分组体系；原渠道管理体系后续整体切换，本需求不做渠道分组展示
- 考试时间数据来源：学生所在考场（测评×渠道）的配置时间，与详情页考场时间同源；客服调整考场后列表时间同步更新（见需求三联动）
- 两列手机号均可导出、均可搜索（见 3.2），列宽固定，长号码不折行

#### 3.2 搜索栏多维度查询

搜索栏改为「查询类型下拉 + 输入框」组合，支持以下类型：

| 查询类型 | 匹配方式 | 说明 |
|---|---|---|
| 综合（默认） | 模糊 | 对姓名、订单号、准考证号、身份证号、用户ID、两列手机号全字段模糊匹配 |
| 准考证号 | 精确 | 完整准考证号匹配 |
| 身份证号 | 精确 | 完整身份证号匹配 |
| 订单号 | 精确 | 修复现有订单号查询失效问题，新旧订单号格式均兼容 |
| 用户ID | 精确 | 数字ID匹配 |
| 手机号 | 模糊 | 登录手机号与联系电话均参与匹配，支持任意连续片段（如后4位） |

明细见下：

- 切换查询类型时，输入框提示文案跟随变化（如选择准考证号后提示「输入准考证号精确查询...」）
- 全字段均支持模糊搜索：综合模式与手机号类型按包含匹配，其余类型按完整值匹配
- 查询无结果时，列表区显示「未找到匹配的报名记录，请调整搜索条件后重试」
- 导出功能跟随当前筛选结果：新增列（照片状态、准考证、登录手机号、联系电话、所属分组、用户ID、考试时间）全部纳入导出文件

#### 3.3 页面参考

原型见下方嵌入文件（基于现有报名管理页面改造，原有详情、退款、代报名功能不受影响）。

### 4. 验收标准

| 验收项 | 期望结果 |
|---|---|
| 新增列展示 | 列表页一屏可见照片状态/准考证/两列手机号/所属分组/用户ID/考试时间，无需进入详情 |
| 照片状态判定 | 四种状态按提交与审核情况正确显示，颜色区分明显 |
| 准考证未生成 | 显示「未生成」，不显示空值或报错 |
| 精确查询 | 准考证号/身份证号/订单号/用户ID 输入完整值后命中唯一记录 |
| 订单号修复 | 现网订单号查询失效问题不再复现 |
| 模糊搜索 | 姓名片段、手机号后4位均可命中；两列手机号都参与匹配 |
| 无结果提示 | 查询无命中时出现空状态提示文案 |
| 导出 | 导出文件包含全部新增列数据 |
| 功能回归 | 详情抽屉、退款流程、后台代报名、AISE编号复制等原有功能行为不变 |

## 需求二：批量导入校验重构

### 1. 背景与收益

需求简介：批量导入取消前置测评选择，报名归属信息（测评ID、渠道ID、支付状态等）放入表格列，导入时逐行与系统数据自动匹配校验，任一行失败整表拦截，并输出带行号的失败明细。

业务诉求：现网批量导入每文件只能导入一个测评，运营要按测评把名单拆成多个文件逐个导入；表格只填基础信息，支付状态靠导入后手动补；校验只查格式不查内容，ID填错也照常导入，导完数据挂错渠道难排查；失败只有条数没有行号，运营定位错误靠肉眼逐行找。本需求支持一个文件多活动、多测评、多渠道混合导入，错误在导入前拦截并精确到行号和字段。

### 2. 业务流程

运营进入「报名管理」列表页，点击「批量导入」：

1. 第一步「上传文件」：下载标准模板，按模板填写名单（一个文件可混合多个活动/测评/渠道），上传 .xlsx 文件
2. 系统解析并逐行校验，自动进入第二步「预览校验」
3. 第二步查看校验结果：
   - 无任何失败 → 点击「确认导入」
   - 存在失败 → 整表拦截，修正 Excel 后重新上传
4. 第三步「导入结果」：逐行展示新建/更新结果，可下载结果明细

### 3. 详细功能说明

#### 3.1 取消前置测评选择

弹窗第一步不再要求选择测评项目，直接进入文件上传。

明细见下：

- 报名归属（测评、渠道）由表格列的ID决定，同一文件可混合多个活动、多个测评、多个渠道的报名数据
- 原第一步提示「批量导入的学生将直接生成订单且状态默认为已支付」随本需求取消，支付状态以表格列为准
- 上传步保留「下载标准Excel模板」入口，并新增模板填写规则说明（可折叠面板）

#### 3.2 表格列与字段校验规则

标准模板 7 列，逐列校验规则如下（列标题带「必填」标注，与下载的模板文件一致）：

| 列名 | 校验规则 |
|---|---|
| 姓名（必填） | 更新已有报名时可空=沿用系统档案；填了则以表格为准覆盖 |
| 证件类型（必填） | 取线上支持的全部证件类型（居民身份证、港澳通行证、台湾通行证、护照等），以模板下拉选项为准 |
| 证件号（必填） | 定位学生的唯一依据；证件类型+证件号联合唯一 |
| 联系电话 | 可空=不修改原值；登录手机号任何情况不被导入修改 |
| 测评ID（必填） | 填测评唯一ID，系统自动关联所属活动与测评 |
| 渠道ID（必填） | 填渠道唯一ID，系统自动确定报名渠道与分组归属 |
| 支付状态（必填） | 取值：已支付/未支付 |

明细见下：

- 归属信息由ID推导：测评ID 唯一确定活动与测评，渠道ID 唯一确定报名渠道；活动名/测评名/渠道名/分组均无需填写，降低填写出错面
- 渠道ID 只决定报名渠道；学员资料中的「所属渠道」是独立字段，导入不修改
- 订单属性：导入生成的订单，来源标记为「批量导入」，支付金额按测评配置的报名费记录，支付状态以表格为准；订单标注后台导入来源供对账筛选，交易流水与导入数据的差异以报名来源筛选核对

#### 3.3 校验拦截与失败明细

任一行校验失败，本次导入整表拦截，全部数据不写入系统。

明细见下：

- 预览步顶部显示四张统计卡：校验通过条数、校验失败条数、更新已有报名条数、新建报名条数
- 存在失败时显示红色拦截横幅：说明失败条数、本次导入已被拦截、需修正后重新上传
- 预览表格按「全部 / 错误 / 更新预告」三个页签过滤，错误行显示行号、失败字段与失败原因（如「渠道ID『XW999』在系统中不存在」「证件类型『台胞证』不在系统支持的证件类型范围内」）
- 提供「下载失败明细」：.xlsx 文件含行号、失败字段、失败原因、系统正确值参考
- 原「自动忽略异常数据并提交」勾选框取消，拦截期间确认导入按钮禁用

#### 3.4 空值不改与更新预告

预览步对每行标注处理方式与字段变更预告。

明细见下：

- 姓名带「新建/更新」角标：系统无此证件类型+证件号组合=新建；已有=更新
- 更新行的变更字段用「原值 → 新值」展示（蓝色为新值）；留空字段标注「未填写（保持原值）」；无变更行标注「无字段变更」
- 校验结果列汇总该行将更新的字段数
- 边界说明：空单元格表示「不修改」，导入不支持通过留空来清空字段；需清空时在系统内单独操作

#### 3.5 导入结果明细

导入完成后第三步逐行展示结果并可下载明细。

明细见下：

- 结果逐行标注「新建成功/更新成功」，说明列写明：新建行显示生成的订单号与支付状态，更新行列出实际变更的字段
- 提供「下载导入结果明细」（.xlsx），供运营留存核对
- 重复报名保护沿用现网规则：已支付仅更新用户信息；未支付则更新信息并将报名状态置为后台支付

#### 3.6 页面参考

原型见下方嵌入文件（三步弹窗：上传文件 → 预览校验 → 导入结果）。

### 4. 验收标准

| 验收项 | 期望结果 |
|---|---|
| 取消前置选择 | 弹窗第一步直接上传文件，无测评下拉框 |
| 多活动混合导入 | 同一文件含多个测评/渠道时，逐行按ID归档正确 |
| ID推导归属 | 测评ID 正确关联活动与测评；渠道ID 正确确定报名渠道；无需填写活动/测评/渠道/分组名称 |
| 内容级校验 | 证件类型/证件号/测评ID/渠道ID 与系统数据逐行比对，格式正确但内容不匹配的行报失败 |
| 证件类型 | 支持线上全部证件类型；不在支持范围内的类型报失败 |
| 必填标注 | 模板列标题带「必填」标注，页面上传步的规则说明同步标注 |
| 整表拦截 | 任一行失败时确认导入按钮禁用，全部数据不写入 |
| 失败明细 | 行号、失败字段、失败原因逐行可查，可下载 .xlsx 明细 |
| 空值不改 | 更新行留空字段保持原值，不覆盖、不报错 |
| 登录手机号保护 | 任何导入数据不修改登录手机号 |
| 所属渠道隔离 | 导入只修改报名渠道，不改动学员的所属渠道 |
| 更新预告 | 预览步逐行展示将变更的字段与改前改后值 |
| 结果明细 | 导入完成逐行展示新建/更新结果并可下载明细 |
| 功能回归 | 批量导入入口位置、弹窗框架、导入后列表刷新（NEW 标记）行为不变 |

## 需求三：报名详情页可编辑（调整考场与时间）

### 1. 背景与收益

需求简介：报名管理「详情」页改为可编辑模式，客服可调整学生所在考场与考试时间，保存后系统自动同步更新准考证号、列表展示信息及已签发证书。

业务诉求：学生因时间冲突、转场等原因需要换考场或换场次时，客服目前没有操作入口，只能走退款重报或线下登记人工改库，流程重且容易漏同步准考证。本需求将调整动作收口到详情页一键完成，联动信息由系统自动同步，避免人工遗漏。

### 2. 业务流程

客服在「报名管理」列表点击「详情」打开抽屉：

1. 在「报考信息」区查看当前考场（渠道→活动→分组→测评路径）与考场时间、准考证号
2. 点击「调整考场/时间」进入编辑态，通过渠道→活动→分组→测评四级下拉定位目标考场
3. 确认保存后系统自动执行同步（准考证重排、列表更新、证书同步），操作记录写入操作日志

### 3. 详细功能说明

#### 3.1 考场模型与编辑入口

明细见下：

- 考场=「测评×渠道」：活动渠道关联矩阵（活动›分组›测评三级 × 渠道）中的每个关联格即为一个考场，考场时间取该格的配置（20260912 活动渠道关联矩阵体系；多考场独立方案已弃用）
- 「报考信息」区标题行右侧提供「调整考场/时间」入口
- 仅「已支付」「待支付」状态的报名可编辑；已退款、测评已开始的报名入口置灰并提示「已退款或测评开始，不可调整」
- 详情页考场行展示完整路径「活动 › 分组 › 测评 › 渠道」及考场时间

#### 3.2 编辑表单（四级级联定位考场）

| 表单项 | 形式 | 说明 |
|---|---|---|
| 渠道 | 下拉单选 | 全量已关联渠道，默认学员当前报名渠道 |
| 活动 | 下拉单选 | 仅列该渠道已关联的活动，默认当前活动 |
| 分组 | 下拉单选 | 仅列该渠道在该活动下已关联的分组 |
| 测评 | 下拉单选 | 仅列该渠道在该分组下已关联的测评 |
| 新考场时间 | 只读展示 | 取所选「测评×渠道」格的矩阵配置时间，不可修改 |

明细见下：

- 四级全部可选手动选择；级联过滤，上游选定后下游只出现有真实关联的选项
- 选中组合未在矩阵中关联时提示「该『测评×渠道』组合未在矩阵中关联，无法调整」，保存不执行
- 考场与时间均未变化时保存不执行，提示先选择不同的考场
- 已签发证书的学员，编辑区额外提示「证书上的考场与时间将同步更新」
- 时间如需调整，在活动管理的矩阵格配置处修改，报名详情页不做时间编辑，避免两处数据打架

#### 3.3 保存后自动同步

明细见下：

- 报名记录的渠道、分组归属更新为新格；准考证号按新考场日期重新生成，原号作废；未生成过准考证的报名在保存后生成新号
- 列表页对应行的准考证、所属分组、渠道来源、考试时间即时刷新
- 操作日志新增一条「调整考场」记录，含变更前后完整路径与时间、操作人、操作时间
- 已签发证书同步更新考场与考试时间信息

### 4. 验收标准

| 验收项 | 期望结果 |
|---|---|
| 考场模型 | 考场=测评×渠道矩阵格；详情展示「活动›分组›测评›渠道」路径与格配置时间 |
| 编辑入口 | 详情页报考信息区提供「调整考场/时间」入口 |
| 状态限制 | 仅已支付/待支付可编辑；已退款与已开始的报名不可编辑并有提示 |
| 四级级联 | 渠道→活动→分组→测评四级均可选，下游选项按上游已关联关系过滤 |
| 未关联拦截 | 组合未在矩阵关联时保存不执行并提示 |
| 时间锁定 | 考试时间只读展示矩阵格配置，编辑表单不可修改时间 |
| 联动准考证 | 保存后准考证按新考场日期重新生成，详情与列表同步显示新号 |
| 联动列表 | 列表对应行的准考证、所属分组、渠道来源、考试时间即时更新 |
| 联动证书 | 已签发证书的报名保存前展示同步提示，证书信息随保存更新 |
| 操作日志 | 每次调整记录变更前后路径与时间、操作人与时间 |
| 无变化拦截 | 考场未变化时保存不执行并提示 |

## 需求四：审核拆分与查询扩展

### 1. 背景与收益

需求简介：报名管理搜索新增活动筛选（活动→测评联动）；照片审核收口到报名管理页支持批量审核并默认继承历史结果；信息审核页只处理学生在个人中心主动提交的资料变更申请（独立记录+前后对比）；修复学生未修改信息二次报名仍进入待审核的 Bug。

业务诉求：运营找不到按活动筛选报名的入口，只能靠测评名逐个辨认；照片审核与个人信息变更审核混在同一个页面，两类审核的处理人和处理节奏不同，互相干扰；学生没有修改任何信息、二次报名时照片还要重新审一遍，审核量虚高。本需求把两类审核拆到各自归属的页面，审核动作只发生在真正需要审核的数据上。

### 2. 业务流程

运营在「报名管理」列表页：

1. 筛选区先选活动，测评项目下拉联动只显示该活动下的测评
2. 对照片状态为「待审核」的报名，列表勾选后批量通过/不通过
3. 学生二次报名且无任何信息修改时，照片直接继承历史审核结果，不产生新的待审核

学生变更资料的审核走「信息审核」页：学生每次在个人中心提交资料变更生成一条独立申请记录，运营逐条审核，查看修改前后对比。

### 3. 详细功能说明

#### 3.1 搜索筛选扩展

| 变更项 | 说明 |
|---|---|
| 新增「活动」筛选 | 下拉单选，选项为全部活动 |
| 活动→测评联动 | 选中活动后，「测评项目」下拉只显示该活动下的测评；未选活动时显示全部测评 |
| 订单号搜索修复 | 修复按订单号搜索无结果的问题（原表 #10），改为订单号全值精确匹配 |

明细见下：

- 身份证号、学生ID（用户ID）查询条件需求一已覆盖，本需求不重复建设
- 活动筛选与测评筛选可叠加，与支付状态、渠道来源等筛选并行生效

#### 3.2 照片审核收口报名管理页

明细见下：

- 照片状态列前置缩略图，点击缩略图或放大图标打开照片预览弹窗（大图+当前状态）；待审核的照片可在弹窗内直接「通过/不通过」，已审核与未提交的仅查看
- 列表新增勾选列，表头支持全选；勾选后页面底部浮出批量操作条，显示已选条数与其中待审核照片条数
- 批量操作条提供「照片批量通过」「批量不通过」；仅照片状态为「待审核」的行执行变更，其余行跳过并在结果提示中说明
- 单条审核在详情抽屉内操作，批量与单条结果一致
- 继承规则：同一证件号的学生已存在照片审核结论（合格/不合格）时，再次报名任何测评默认沿用该结论，照片状态直接落为已审核，不进入待审核队列；仅学生更换照片或无任何历史结论时才产生新的待审核
- 本需求为 V1.6 中「照片审核本期不做」的正式立项，替代该暂缓说明

#### 3.3 信息审核页只处理主动变更申请

明细见下：

- 信息审核页（原用户信息审核）移除照片审核类记录，仅处理学生在个人中心主动提交的资料变更申请；页面顶部明示分工说明
- 学生每次提交变更生成一条独立申请记录，含申请编号、学员、变更字段、提交时间、申请来源（个人中心）；同一学生多次提交即多条记录，逐条独立审核、互不影响
- 列表「修改前 → 修改后」列直接展示变更摘要；详情页展示变更内容对比表（字段/修改前/修改后）与该学生的历史申请次数
- 审核通过后变更同步至学员档案与报名信息；驳回时学生端展示驳回原因，可修改后重新提交（重新提交生成新的申请记录）
- 支持批量通过/驳回（沿用页面既有批量能力）

#### 3.4 未修改信息二次报名 Bug 修复

明细见下：

- 现网问题：学生未修改任何信息、二次报名时报名记录仍进入照片待审核状态
- 修复口径：报名提交时系统比对本次提交与档案现存信息，无差异且存在有效历史照片审核结论的，直接继承结论，不产生待审核记录；有差异或无历史结论的按正常流程进入待审核

### 4. 验收标准

| 验收项 | 期望结果 |
|---|---|
| 活动筛选 | 筛选区可单独按活动筛选；选中活动后测评下拉只显示该活动下的测评 |
| 订单号修复 | 按列表中的订单号搜索能命中对应记录 |
| 批量审核 | 勾选多行浮出批量操作条，批量通过/不通过仅作用于待审核行，其余行跳过并提示 |
| 继承历史 | 有照片审核结论的学生再次报名，照片直接落为历史结论，不进待审核 |
| 换照片重审 | 学生更换照片后新的照片进入待审核 |
| 审核拆分 | 信息审核页不再出现照片审核记录，仅展示个人中心主动提交的变更申请 |
| 独立申请 | 每次变更提交生成独立记录，含申请编号与前后对比，逐条独立审核 |
| 通过同步 | 变更审核通过后学员档案与报名信息同步更新 |
| 驳回重提 | 驳回后学生端可见原因，可重新提交并生成新申请 |
| 二次报名修复 | 未修改信息的二次报名不进入待审核 |
