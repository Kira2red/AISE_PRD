# 20260110 批量导入

## 项目背景

当前的“后台代报名”功能仅支持单人录入，无法满足B端的批量报名需求。

## 业务流程

流程简述：列表页入口 -> 1.选择测评项目 -> 2.上传Excel文件 -> 3.预览与校验 -> 4.写入数据库并反馈。

## 详细功能需求说明

### 3.1 功能入口

🖼️[图片]

- 位置：报名记录管理 列表页面顶部，搜索栏上方，[后台代报名] 按钮左侧。

- 交互：点击 [批量导入] 按钮，在当前页面弹出模态窗口。背景需添加遮罩层，禁止操作底层页面。

### 3.2 批量导入弹窗 - 第一步：选择测评

🖼️[图片]

目标：明确这批学生要报名哪个具体的考试项目。

- 界面元素：

- 测评下拉选择框：

- 数据来源：仅加载状态≠【已结束】的测评项目。已结束的测评不予显示。

- 默认状态：显示“-- 请选择 --”。

- 提示文案：需醒目提示“批量导入的学生将直接生成订单，且状态默认为 [已支付]”。

- 交互逻辑：

- 下一步按钮状态：

- 当下拉框未选择有效值时，[下一步] 按钮为禁用状态（灰色，不可点击）。

- 选中任意有效测评后，[下一步] 按钮激活（亮蓝色，可点击）。

### 3.3 批量导入弹窗 - 第二步：上传文件

🖼️[图片]

目标：获取用户整理好的学生名单。

- 界面元素：

- 下载模板入口：提供“下载标准Excel模板”的文字链接或按钮。

- 上传区域：

- 支持点击上传和拖拽上传。

- 格式限制：文案明确标注“仅支持 .xlsx 格式”。

- 视觉反馈：鼠标悬停时，上传区域边框高亮颜色变化。

- 交互逻辑：

- 文件校验：

- 若用户上传非 .xlsx 文件（如 .csv, .doc），前端直接拦截并提示“格式不支持”。

- 若文件体积超过限制（如 10MB，研发定一下值），提示“文件过大”。

- 上传过程：文件选中后，显示“正在解析数据...”的加载动画，解析完成后自动跳转至第三步。

- 模板表格表头（必填）：

- 姓名

- 性别

- 身份证号

- 联系电话

- 监护人姓名

- 监护人电话

- 详细寄送地址

- 渠道识别码

### 3.4 批量导入弹窗 - 第三步：数据预览与校验

🖼️[图片]

目标：让管理员在提交前确认识别结果，并处理异常数据。

- 界面元素：

- 统计卡片：

- 绿色卡片：显示“识别成功”的条数。

- 红色卡片：显示“格式错误”的条数（如无错误则显示 0）。

- 预览表格：

- 展示字段：姓名、手机号、渠道码、校验结果。

- 异常行样式：背景色淡红，校验结果列显示红色文字及错误原因（【列名】无效，如“手机号无效”、“身份证无效”）。

- 正常行样式：校验结果列显示绿色对勾图标。

- “自动忽略”勾选框：

- 文案：自动忽略异常数据并提交。

- 默认状态：默认勾选。

- 错误警告提示条：位于勾选框下方，红色背景框，默认隐藏。

- 操作按钮：[取消]、[确认导入]。

- 交互逻辑：

- 场景 A：数据全部正确

- “自动忽略”勾选框可以隐藏或置灰。

- [确认导入] 按钮：高亮可用。

- 场景 B：存在异常数据

- 情况 1（默认）：勾选了“自动忽略”

- [确认导入] 按钮：高亮可用。

- 点击后果：系统仅导入“识别成功”的数据，自动丢弃“格式错误”的数据。

- 情况 2：用户取消勾选“自动忽略”

- [确认导入] 按钮：立即变更为禁用状态（置灰，不可点击）。

- 警告提示：同时在底部显示红色提示文案：“当前存在异常数据。若不勾选‘忽略’，则无法提交...”。

- 设计意图：强制用户做出决策——要么接受丢失部分数据（勾选忽略），要么回去修改文件（取消并重新上传）。

### 3.5 批量导入弹窗 - 第四步：完成反馈

目标：告知用户处理结果，并引导后续操作。

- 界面展示：

- 显示绿色成功图标。

- 文案提示：“成功创建 XX 条报名记录，状态已置为‘已支付’。”

- 后续动作：

- 点击 [完成] 按钮，关闭弹窗。

- 列表刷新：底层列表页需自动刷新，按时间倒序排列，刚刚导入的数据应带有 NEW 标记显示在列表最上方。

## 核心数据策略 

### 4.1 自动判重与更新策略

系统依据 身份证号 进行匹配：

1. 新用户：

- 系统中无此身份证号 -> 创建新账号 -> 创建该测评的订单。

1. 老用户：

- 系统中已有此身份证号 -> 更新该用户的基本信息（以本次Excel为准，覆盖旧的姓名/手机号等） -> 创建该测评的订单。

1. 重复报名保护：

- 若该身份证号下的用户，已经报名了当前选择的测评

- 如果已支付 ->  仅更新用户信息

- 如果未支付 ->  更新用户信息、修改报名状态为【后台支付】

### 4.3 订单属性

- 支付状态：默认置为 【后台支付】

- 订单来源：标记为 【批量导入】，以便在列表中通过筛选器快速筛选。

- 支付金额：默认为0元。

## 异常情况处理

1. Excel 模板错误：若用户上传了表头不匹配的文件，第二步解析时提示“表头格式不正确，请下载最新模板”。

1. 网络中断：上传过程中网络断开，显示“上传失败，请重试”。

1. 数据量过大：建议单次导入限制在 5000 条（研发定一个值）以内。超过限制提示“单次导入数量过多，请分批上传”。
