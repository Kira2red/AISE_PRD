# 人才库智能体（AI人才大脑1.0）业务需求梳理

> 版本 V1.0 ｜ 日期 2026-08-22 ｜ 状态：初稿（基于 07-10 会议纪要 + 用户 08-22 口头决策）

## 需求总览

| 编号 | 模块 | 需求概述 | 优先级 |
|------|------|---------|--------|
| M1 | 作品上传与智能体预审 | 用户上传作品（代码/图片/PDF），智能体阅读分析，判断单作品质量能否入库，并输出标签与评价 | 高 |
| M2 | 人工终审与作品归档 | 后台审核工作台展示 AI 预审结论，人工确认/修改/驳回；通过后作品归档入库，标签写入人才画像 | 高 |
| M3 | 简历材料智能体审核 | 人才卡三个上传模块（社会实践与人才培养记录/专利和软著/其他荣誉记录）提交时触发智能体预审 | 高 |
| M4 | 数据分析 | 基于简历、作品、成绩、题目作答情况分析学生数据，输出个体水平评估、成长建议与分析报告 | 高 |
| M5 | 本地可运行 Demo | 全链路本地跑通：上传→自动审核归档→人工检查确认修改→前台看评价；大模型用本机 DeepSeek V4 Flash；共享包不含 token | 高 |

## 已确认决策（2026-08-22 用户拍板，本文档以此为准）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 审核模式 | **智能体预审给结论 + 人工终审**，AI 不放行，人工最终拍板 |
| 2 | 作品类型 | **代码、图片、PDF**（不含视频），智能体需具备三类阅读能力 |
| 3 | 准入逻辑 | 两级：**①单作品质量判断（能否入库）→ ②入库后深度理解单个作品** |
| 4 | 标签 | 由智能体**根据作品内容动态生成**，非预设固定列表 |
| 5 | 简历审核对象 | 人才卡上用户上传的三个材料模块（含其现有字段），简历修改同样走智能体审核 |
| 6 | 数量线与质量线 | **C 方案**：智能体只对单作品质量给结论，数量门槛（如 20 个作品可入库）留在人工/业务侧把守 |

## 1. 项目背景与收益预估

### 1.1 需求简介

人才库 1.0 基础功能（人才入库、信息审核、查询）之上，新增 AI 人才大脑 1.0 智能体能力：用大模型对用户上传的作品做预审与理解，对人才数据做分析评估，先解决"从无到有"问题，上线后持续迭代（出处：同文件夹《纪要_07-10 AI人才大脑1.0建设.md》）。

### 1.2 业务诉求

- **审核成本高**：现行人才库所有材料由管理员逐条人工审核（出处：[AISE人才库_PRD §5.6 后台用户管理](<../20260615 人才库/AISE人才库_PRD.md>)），作品类材料没有智能手段辅助，量大后审核是瓶颈。
- **产品缺 AI 属性**：人才卡「特长领域」「综合分析」均为静态模板（出处：20260615 会议纪要"初期将采用固定模板展示，后续可结合 AI 模型实现动态化"），平台缺少智能体元素，创新感知不足。
- **数据价值未释放**：AISE 已沉淀逐题答题记录、测评成绩等数据（出处：AISE人才库_PRD §4 系统关联与依赖），缺少深度挖掘与主动化服务能力。

### 1.3 收益预估（待验证的假设）

> ⚠️ 以下收益为定性判断、待上线后验证的假设（依据等级 E，经验判断），不构成收益承诺。

- **用户收益**：作品审核获得 AI 预审 + 人工终审的双重保障，更快得到反馈；获得作品标签与评价，能力可视化；获得个性化水平评估与成长建议，从"只有分数"升级为"知道差在哪、下一步学什么"。
- **业务收益**：审核效率提升（AI 预审替代人工初审）；人才卡「特长领域」由静态模板变为动态生成，产品 AI 属性可感知；测评服务由"给出分数"升级为"给出诊断与建议"，形成差异化竞争力。
- **不做风险**：审核完全依赖人工，作品量大后积压；人才卡长期静态展示，产品缺少创新感知；AISE 沉淀的逐题数据持续闲置，无法对外产生价值。

## 2. 业务流程简述

### 2.1 作品审核链路（用户端）

1. 用户登录人才库，进入「作品上传」页，选择作品类型（代码/图片/PDF），填写作品名称，上传文件，提交审核。
2. 系统接收作品后，智能体异步预审：阅读、分析、理解作品内容。
3. 预审完成后，用户可在「我的作品」查看预审状态（预审中 → 预审完成），预审结论仅供后台人工参考，前端不直接展示 AI 结论。
4. 后台人工终审（见 2.2）通过后，作品归档入库；用户的人才卡「特长领域」展示动态标签、作品区展示评价结果。
5. 若被驳回，用户查看驳回原因，可修改后重新提交。

### 2.2 审核链路（后台）

1. 管理员登录后台审核工作台，查看待审核队列（含 AI 预审结论摘要）。
2. 打开作品详情：预览原文件，查看 AI 预审结论（准入结论/理由/标签/评价）与作品理解结果。
3. 人工裁决：确认通过 / 驳回 / 修改（编辑标签、评价或理由后通过）；人工可推翻 AI 结论，裁决结果留痕。
4. 通过的作品归档入库，标签进入人才画像；驳回的作品通知用户并释放提交额度。

### 2.3 简历材料审核链路

用户提交人才卡三模块材料（社会实践与人才培养记录/专利和软著/其他荣誉记录）→ 智能体自动预审（规范性/一致性/敏感信息）→ 管理员终审（沿用现有逐条审核流程，AI 意见作为参考）→ 通过后录入人才卡对应模块。

### 2.4 数据分析链路

已关联 AISE 的用户，其简历、作品（含 AI 理解结果）、成绩、题目作答记录进入人才档案 → 智能体生成个体水平评估（知识点掌握度、错误归因、能力追踪）与成长建议 → 汇入人才卡「综合分析」及分析报告（支持导出），报告经质量审核后对外提供。

## 4. 系统关联与依赖

- **AISE 测评系统**：数据分析模块依赖 AISE 测评记录与逐题答题记录，经「证件类型+证件号」桥接读取（出处：[20260818 人才库账号打通业务需求梳理](<../20260818 人才库账号打通/业务需求梳理.md>)）。只有「已关联 AISE」的用户才有可分析的测评数据。
- **大模型服务**：智能体预审与数据分析的生成能力依赖已接入的大模型通用能力（07-10 纪要）。Demo 环境使用 DeepSeek V4 Flash（见 §6），生产环境大模型由研发确定，业务侧不写死。
- **文件存储**：作品文件（代码/图片/PDF）与现有证明材料一致，存储在服务端，支持后台预览（沿用 [AISE人才库_PRD §4](<../20260615 人才库/AISE人才库_PRD.md>) 口径）。
- **个人报告能力复用**：知识点掌握度分析口径（得分和÷满分和、<60% 重点提升等）直接复用 [20260728 个人报告 PRD](<../20260728 个人报告与题库建设/PRD.md>)，本文档不重新定义（逻辑校验：两处数据基础同为逐题答题记录）。

## 5. 详细功能说明

### 5.1 模块一：审核准入

#### 5.1.1 作品上传

**位置**：人才库登录后新增「作品上传」入口（现有人才卡底部材料上传区旁）。

**表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 作品名称 | 是 | 文本输入，用于列表与人才卡展示 |
| 作品类型 | 是 | 下拉选择：代码 / 图片 / PDF（不含视频，决策 #2） |
| 作品文件 | 是 | 按类型限制格式；图片限 PNG/JPG/JPEG/WEBP，代码限文本类源文件，PDF 限 .pdf |
| 作品描述 | 否 | 选填文本，辅助智能体理解作品背景（待确认 Q3） |

**上传限制**：单个文件大小上限 10MB（沿用材料上传口径，出处：AISE人才库_PRD §5.5.4）；每个类型最多 3 条待审核（沿用材料上传锁定逻辑，出处：§5.5.3），驳回后释放额度。

**异常处理**：格式不支持时提示"以下文件格式不支持：xxx"；上传失败单条可重试，不影响其他条目。

#### 5.1.2 智能体预审

**目标**：对单作品质量给出准入结论，并深度理解作品内容（决策 #3 两级逻辑）。

**预审内容**（按作品类型差异化阅读）：

| 作品类型 | 智能体阅读能力 | 预审关注点 |
|---------|---------------|-----------|
| 代码 | 静态阅读源代码（结构、逻辑、注释） | 完整性（能否运行/是否残缺）、原创性迹象、功能实现程度 |
| 图片 | 视觉理解（内容识别、画面分析） | 内容质量、与描述的一致性、是否有明显不当内容 |
| PDF | 文本与版面解析 | 内容完整性、结构质量、是否有明显不当内容 |

**预审输出**（智能体给结论，不放行，决策 #1）：

- **准入结论**：建议通过 / 建议驳回
- **结论理由**：驳回时必须给出理由，人工终审据此判断
- **作品标签**：根据作品内容动态生成（决策 #4），进入人才画像、展示于人才卡「特长领域」
- **作品评价**：一段评价评语（文本），审核通过后展示于人才卡作品区（评价形式细化见 Q6）
- **作品理解结果**：入库后的深度理解内容（内容摘要/结构解析等），作为人才档案与分析的数据输入（决策 #3 ②级）

**质量线与数量线**：智能体只判断单作品质量；"以作品数量为依据（如 20 个可入库）"的数量门槛由人工终审/业务侧把守，智能体不输出数量判定（决策 #6）。

**处理方式**：大模型分析耗时，提交后**异步预审**，不阻塞用户；「我的作品」中展示状态（待预审 → 预审中 → 预审完成）。

**降级处理**：大模型调用失败时，条目状态置为「预审失败」，人工可直接终审（退化为纯人工审核），并提供重试入口。预审结论不对前端用户展示，仅供后台人工参考。

#### 5.1.3 人工终审与作品归档

**位置**：后台新增「审核工作台」。

**待审队列**：

| 列表字段 | 说明 |
|---------|------|
| 作品名称、提交人、类型、提交时间 | 基础信息 |
| 预审状态 | 预审中 / 预审完成 / 预审失败 |
| AI 结论摘要 | 建议通过 / 建议驳回（驳回附理由摘要） |

**作品详情页**：

- 原文件预览：代码语法高亮 / 图片预览 / PDF 在线预览
- AI 预审结论完整展示：准入结论、理由、标签、评价、理解结果
- 人工操作：
  - **确认通过**：采纳 AI 结论（或推翻 AI 的"建议驳回"），作品归档入库
  - **驳回**：填写驳回原因，通知用户，释放该类型提交额度
  - **修改后通过**：人工编辑标签/评价/理由后通过（AI 结论可被人工修正）
- 所有操作留痕：AI 结论、人工裁决、修改前后内容、审核人、时间，支持审计溯源

**归档结果**：通过的作品进入人才档案/作品集；标签写入人才卡「特长领域」（动态展示）；评价与理解结果写入作品记录。

#### 5.1.4 简历材料智能体审核

**范围**：人才卡用户上传的三个材料模块（决策 #5）：

| 模块 | 字段 | 智能体审核维度 |
|------|------|---------------|
| 社会实践与人才培养记录 | 活动名称（必填）、时间（必填）、获得荣誉（必填） | 规范性、一致性、敏感信息 |
| 专利和软著 | 专利/软著名称（必填） | 规范性、一致性、敏感信息 |
| 其他荣誉记录 | 获得荣誉（必填）、时间（必填） | 规范性、一致性、敏感信息 |

**审核维度定义**：

- **规范性**：必填项完整、时间格式符合规范（如"2025年8月"）
- **一致性**：与档案已有数据矛盾检查（如时间晚于当前、荣誉与已知记录明显冲突）
- **敏感信息**：材料内容中出现证件号、手机号等敏感个人信息时提示

**能力边界**（必须明确）：智能体**无法验证材料真实性**（不依赖外部数据源、查不了外部数据库），真实性由人工终审兜底。AI 预审意见插入现有审核流程：用户提交 → 智能体预审 → 管理员终审（查看 AI 意见后逐条通过/驳回，沿用 AISE人才库_PRD §5.6 流程）。

#### 5.1.5 标签与评价生成

- 标签由智能体根据作品内容**动态生成**（决策 #4），数量与内容不预设
- 标签用途：人才卡「特长领域」由静态模板（现写死"程序设计""生成式人工智能"）改为**动态展示**
- 归一化问题：动态自由标签可能导致展示混乱，是否归一化到考核模块/知识点体系标签池，挂待确认 Q1（一期按动态生成执行）

### 5.2 模块二：数据分析

#### 5.2.1 数据来源

| 数据 | 来源 | 说明 |
|------|------|------|
| 简历 | 人才库用户自填材料（三模块）＋ 基本信息 | 审核通过后的内容 |
| 作品 | 审核通过的作品 + AI 理解结果 | 模块一产出 |
| 成绩 | AISE 测评记录（模块/等级/日期） | 已关联 AISE 的用户 |
| 题目作答 | AISE 逐题答题记录 | 已关联 AISE 的用户 |

**空态**：未关联 AISE 的用户，分析区展示"暂未关联 AISE 测评数据，如已参加 AISE 考试请联系管理员"（沿用人才卡现有空态文案，出处：AISE人才库_PRD §5.4.4）。

#### 5.2.2 个体人才水平评估

- 基于逐题答题记录，分析知识点掌握程度
- 错误类型归因：**未掌握 / 粗心 / 概念混淆** 三类（07-10 纪要）
- 跨考试追踪能力变化，量化能力水平，精准定位能力短板
- 知识点掌握度口径复用 [20260728 个人报告 PRD](<../20260728 个人报告与题库建设/PRD.md>)（得分和÷满分和，<60% 重点提升、≥60% 稳定掌握），不另定义

#### 5.2.3 成长建议自动生成

- 依据教育与学习规律生成个性化建议：**优先补齐关键短板 → 难度递进 → 定期巩固**（07-10 纪要）
- 配套练习方向建议，明确下一步学习重点
- 建议内容不含培训课程，只给方向与练习材料定位

#### 5.2.4 分析报告生成与输出

- 利用大模型通用能力自动生成**标准化人才分析报告**（含成长档案 + 评价报告）
- 报告**支持导出**
- 生成内容经**质量审核后**对外提供，守住内容准确性与合规底线（07-10 纪要）
- 落点：人才卡「综合分析」模块由静态四维雷达图（认知层/应用层/创新层/责任层）改为**动态生成**；报告入口与独立页面形态挂待确认 Q2

## 6. Demo 方案（本地完整跑通）

### 6.1 目标与范围

做一个**本地能完整跑起来**的 demo，把全链路串起来：

> 用户上传作品 → 后台自动审核归档（智能体预审）→ 后台人工检查确认修改 → 前台看到评价结果

范围覆盖 M1~M4 全部环节，并包含简历材料审核链路。发给别人也能跑（见 6.3 token 安全设计）。

### 6.2 技术形态

| 组成 | 方案 | 说明 |
|------|------|------|
| 前端 | 静态 HTML 页面（用户端 + 后台） | 与现有 `html/talent_pool/` demo 风格一致，响应式 |
| 本地服务端 | Python3 轻量后端（**仅标准库，零依赖**） | 职责：文件接收与存储、审核状态管理、调用大模型、无 key 时返回模拟结果 |
| 大模型 | DeepSeek V4 Flash（本机） | OpenAI 兼容接口；key 从本地 `.env` 读取 `DEEPSEEK_API_KEY`，不进代码 |

**为什么必须有本地服务端**：大模型调用必须携带 API key，key 放在前端（纯 HTML）等于直接暴露给任何打开页面的人。因此调用统一由本地服务端代理，前端只与服务端交互。收件人电脑上有 Python3 即可运行，无需安装任何包。

### 6.3 Token 安全设计（硬约束）

**要求：把 demo 发给别人，不能使用我的 token。**

| 模式 | 条件 | 行为 |
|------|------|------|
| 真实模式 | 本地 `.env` 配了 `DEEPSEEK_API_KEY` | 智能体预审真实调用 DeepSeek V4 Flash |
| Mock 模式 | 未配置 key | 服务端返回**显式标注「模拟结果」**的预设样例结论（按作品类型给出），全链路照常演示，不真实调用大模型 |
| 自备 key | 收件人填入自己的 key | 与真实模式一致 |

落实规则：

- 共享包（发给他人的压缩包/文件夹）**不含任何 key**：`.env` 不进共享包、加入 `.gitignore`
- 服务端启动时检测 key 存在性，并在日志与页面明确提示当前运行模式（真实 / 模拟）
- Mock 输出的审核结论一律带「模拟结果」标识，避免与真实 AI 结论混淆
