> 版本 V1.2 ｜ 日期 2026-08-22 ｜ 状态：V1.2（回应三轮 3 条决策，附录 A 待确认全部闭环）

## 需求总览

| 编号 | 模块 | 需求概述 | 优先级 |
|------|------|---------|--------|
| M1 | 作品上传与智能体预审 | 用户上传作品（代码/图片/PDF），智能体阅读分析，判断单作品质量能否入库，并输出标签与评价（仅入库，前台不展示） | 高 |
| M2 | 人工终审与作品归档 | 后台审核工作台展示 AI 预审结论，人工确认/修改/驳回；通过后作品归档入库，标签写入人才画像 | 高 |
| M3 | 简历材料智能体审核 | 人才卡三个上传模块（社会实践与人才培养记录/专利和软著/其他荣誉记录）按条目触发智能体预审（上传或修改哪条审哪条） | 高 |
| M4 | 数据分析 | 基于简历、作品评价、成绩、题目作答情况分析学生数据，输出个人画像分析报告（标题栏独立 tab 入口），更新人才卡能力雷达与特长领域 | 高 |
| M5 | 本地可运行 Demo | 全链路本地跑通：上传→自动审核归档→人工检查确认修改→前台看结果；大模型用本机 DeepSeek V4 Flash；共享包不含 token | 高 |

### 一轮决策（2026-08-22 用户拍板）

| 1 | 审核模式 | **智能体预审给结论 + 人工终审**，AI 不放行，人工最终拍板 |
| 2 | 作品类型 | **代码、图片、PDF**（不含视频），智能体需具备三类阅读能力 |

## 1. 项目背景与收益预估

### 1.1 需求简介

人才库 1.0 基础功能（人才入库、信息审核、查询）之上，新增 AI 人才大脑 1.0 智能体能力：用大模型对用户上传的作品做预审与理解，对人才数据做分析评估，先解决"从无到有"问题，上线后持续迭代（出处：同文件夹《纪要_07-10 AI人才大脑1.0建设.md》）。

### 1.2 业务诉求

- **审核成本高**：现行人才库所有材料由管理员逐条人工审核（出处：[AISE人才库_PRD §5.6 后台用户管理](<../20260615 人才库/AISE人才库_PRD.md>)），作品类材料没有智能手段辅助，量大后审核是瓶颈。
- **产品缺 AI 属性**：人才卡「特长领域」「综合分析」均为静态模板（出处：20260615 会议纪要"初期将采用固定模板展示，后续可结合 AI 模型实现动态化"），平台缺少智能体元素，创新感知不足。
- **数据价值未释放**：AISE 已沉淀逐题答题记录、测评成绩等数据（出处：AISE人才库_PRD §4 系统关联与依赖），缺少深度挖掘与主动化服务能力。

### 1.3 收益预估（待验证的假设）

> ⚠️ 以下收益为定性判断、待上线后验证的假设（依据等级 E，经验判断），不构成收益承诺。

- **用户收益**：作品审核获得 AI 预审 + 人工终审的双重保障，更快得到审核结果；人才卡特长领域标签与能力雷达动态化，能力可视化增强；获得个性化画像分析与成长建议，从"只有分数"升级为"知道差在哪、下一步学什么"。
- **业务收益**：审核效率提升（AI 预审替代人工初审）；作品评价沉淀入库，后续画像分析直接复用、无需重复分析作品，分析成本随规模递减；测评服务由"给出分数"升级为"给出诊断与建议"，形成差异化竞争力。
- **不做风险**：审核完全依赖人工，作品量大后积压；人才卡长期静态展示，产品缺少创新感知；AISE 沉淀的逐题数据持续闲置，无法对外产生价值。

## 2. 业务流程简述

### 2.1 作品审核链路（用户端）

1. 用户登录人才库，进入「作品上传」页，选择作品类型（代码/图片/PDF），填写作品名称与描述（选填），上传文件，提交审核。
2. 提交后，条目状态显示「审核中」（含预审失败等所有中间态，对用户不可见细节，决策 #9）。**连续上传不受条数限制**（决策 #18）。
3. 后台人工终审（见 2.2）通过后，状态变为「审核完成」，作品归档入库；人才卡「特长领域」更新动态标签、「综合分析」能力雷达更新（结构不变，决策 #15）。
4. 若被驳回，状态显示「未通过」+ 驳回原因，用户可修改后重新提交，**不限次数**（决策 #11）。
5. 作品评价（标签/得分/评语）只入库供画像分析使用，**不在前台展示**（决策 #12）。

### 2.2 审核链路（后台）

1. 管理员登录后台审核工作台，查看待审核队列（含预审状态与 AI 预审结论摘要，中间态仅在后台可见）。
2. 打开作品详情：预览原文件，查看 AI 预审结论（准入结论/理由/标签/得分/评语）与作品理解结果。
3. 人工裁决：确认通过 / 驳回 / 修改（编辑标签、得分、评语或理由后通过）；人工可推翻 AI 结论，裁决结果留痕。
4. 通过的作品归档入库，评价与理解结果写入作品记录；驳回的作品通知用户。

### 2.3 简历材料审核链路

用户上传或修改人才卡三模块材料（社会实践与人才培养记录/专利和软著/其他荣誉记录）的某一条 → 该条目触发智能体预审（审上传或修改的那一条，决策 #14）→ 管理员终审（沿用现有逐条审核流程，AI 意见作为参考）→ 通过后录入人才卡对应模块。

### 2.4 数据分析链路

已关联 AISE 的用户，其简历、作品评价与理解结果、成绩、题目作答记录进入人才档案 → 智能体生成个体水平评估（知识点掌握度、错误归因、能力追踪）与成长建议 → 更新人才卡「特长领域」标签与「综合分析」能力雷达 → 生成个人画像分析报告（样式沿用个人报告、内容为画像分析，决策 #8），支持导出，经质量审核后对外提供。**报告为独立页面，入口是人才库标题栏新增的「画像分析」tab**（决策 #16）。

## 4. 系统关联与依赖

- **AISE 测评系统**：数据分析模块依赖 AISE 测评记录与逐题答题记录，经「证件类型+证件号」桥接读取（出处：[20260818 人才库账号打通业务需求梳理](<../20260818 人才库账号打通/业务需求梳理.md>)）。只有「已关联 AISE」的用户才有可分析的测评数据。
- **大模型服务**：智能体预审与数据分析的生成能力依赖已接入的大模型通用能力（07-10 纪要）。Demo 环境使用 DeepSeek V4 Flash（见 §6），生产环境大模型由研发确定，业务侧不写死。
- **文件存储**：作品文件（代码/图片/PDF）与现有证明材料一致，存储在服务端，支持后台预览（沿用 [AISE人才库_PRD §4](<../20260615 人才库/AISE人才库_PRD.md>) 口径）。
- **个人报告能力复用**：知识点掌握度口径（得分和÷满分和、<60% 重点提升等）复用 [20260728 个人报告 PRD](<../20260728 个人报告与题库建设/PRD.md>)；画像分析报告的**样式体系沿用个人报告**（决策 #8），本文档不重新定义（逻辑校验：两处数据基础同为逐题答题记录）。

## 5. 详细功能说明

### 5.1 模块一：审核准入

#### 5.1.1 作品上传

**位置**：人才库登录后新增「作品上传」入口（现有人才卡底部材料上传区旁）。

**表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 作品名称 | 是 | 文本输入，用于列表与后台展示 |
| 作品类型 | 是 | 下拉选择：代码 / 图片 / PDF（不含视频，决策 #2） |
| 作品文件 | 是 | 按类型限制格式；图片限 PNG/JPG/JPEG/WEBP，代码限文本类源文件，PDF 限 .pdf |
| 作品描述 | 否 | 选填文本，辅助智能体理解作品背景（决策 #17） |

**上传限制**：单个文件大小上限 10MB（沿用材料上传口径，出处：AISE人才库_PRD §5.5.4）。**不设用户可见的并发条数限制**：用户可连续上传多条作品，每条提交后即显示「审核中」；后台并发处理量由研发按实现灵活调整（决策 #18）。

**异常处理**：格式不支持时提示"以下文件格式不支持：xxx"；上传失败单条可重试，不影响其他条目。

#### 5.1.2 智能体预审

**目标**：对单作品质量给出准入结论，并深度理解作品内容（决策 #3 两级逻辑）。

**预审内容**（按作品类型差异化阅读）：

| 作品类型 | 智能体阅读能力 | 预审关注点 |
|---------|---------------|-----------|
| 代码 | 静态阅读源代码（结构、逻辑、注释） | 完整性（能否运行/是否残缺）、原创性迹象、功能实现程度 |
| 图片 | 视觉理解（内容识别、画面分析） | 内容质量、与描述的一致性、是否有明显不当内容 |
| PDF | 文本与版面解析 | 内容完整性、结构质量、是否有明显不当内容 |

**预审输出**（智能体给结论，不放行，决策 #1）：

- **准入结论**：建议通过 / 建议驳回
- **结论理由**：驳回时必须给出理由，人工终审据此判断
- **作品评价**：**标签 + 得分（100 分制）+ 评语**（决策 #12）。评价仅入库、后台可见，**前台不展示**；用途是后期画像分析直接取用，无需重复分析作品
- **作品理解结果**：入库后的深度理解内容（内容摘要/结构解析等），作为人才档案与分析的数据输入（决策 #3 ②级）

**质量线与数量线**：智能体只判断单作品质量；"以作品数量为依据（如 20 个可入库）"的数量门槛由人工终审/业务侧把守，智能体不输出数量判定（决策 #6）。

**处理方式**：大模型分析耗时，提交后**异步预审**，不阻塞用户。**前台状态极简化**：用户端只显示「审核中」→「审核完成」（未通过时显示「未通过」+原因）；待预审/预审中/预审完成等中间态**仅在后台可见**（决策 #9）。预审时效由研发确定（决策 #10）。

**降级处理**：大模型调用失败时，条目后台状态置为「预审失败」，**前台仍显示「审核中」**（决策 #9）；人工可直接终审（退化为纯人工审核），并提供重试入口。预审结论不对前端用户展示，仅供后台人工参考。

#### 5.1.3 人工终审与作品归档

**位置**：后台新增「审核工作台」。

**待审队列**：

| 列表字段 | 说明 |
|---------|------|
| 作品名称、提交人、类型、提交时间 | 基础信息 |
| 预审状态 | 预审中 / 预审完成 / 预审失败（仅后台可见） |
| AI 结论摘要 | 建议通过 / 建议驳回（驳回附理由摘要） |

**作品详情页**：

- 原文件预览：代码语法高亮 / 图片预览 / PDF 在线预览
- AI 预审结论完整展示：准入结论、理由、标签、得分、评语、理解结果
- 人工操作：
  - **确认通过**：采纳 AI 结论（或推翻 AI 的"建议驳回"），作品归档入库
  - **驳回**：填写驳回原因，通知用户；用户可重新提交，**不限次数**（决策 #11）
  - **修改后通过**：人工编辑标签/得分/评语或理由后通过（AI 结论可被人工修正）
- 所有操作留痕：AI 结论、人工裁决、修改前后内容、审核人、时间，支持审计溯源

**归档结果**：通过的作品进入人才档案/作品集；标签写入人才卡「特长领域」（动态展示）；评价（标签/得分/评语）与理解结果写入作品记录，**仅入库供画像分析复用，前台不展示**（决策 #12）。

#### 5.1.4 简历材料智能体审核

**范围**：人才卡用户上传的三个材料模块（决策 #5），**按条目触发**——上传或修改哪一条，就审哪一条（决策 #14）：

| 模块 | 字段 | 智能体审核维度 |
|------|------|---------------|
| 社会实践与人才培养记录 | 活动名称（必填）、时间（必填）、获得荣誉（必填） | 规范性、一致性、敏感信息 |
| 专利和软著 | 专利/软著名称（必填） | 规范性、一致性、敏感信息 |
| 其他荣誉记录 | 获得荣誉（必填）、时间（必填） | 规范性、一致性、敏感信息 |

**审核维度定义**：

- **规范性**：必填项完整、时间格式符合规范（如"2025年8月"）
- **一致性**：与档案已有数据矛盾检查（如时间晚于当前、荣誉与已知记录明显冲突）
- **敏感信息**：材料内容中出现证件号、手机号等敏感个人信息时提示

**能力边界**（必须明确）：智能体**无法验证材料真实性**（不依赖外部数据源、查不了外部数据库），真实性由人工终审兜底。AI 预审意见插入现有审核流程：用户提交条目 → 该条目触发智能体预审 → 管理员终审（查看 AI 意见后逐条通过/驳回，沿用 AISE人才库_PRD §5.6 流程）。

#### 5.1.5 标签与评价生成

- 标签由智能体根据作品内容**动态生成**（决策 #4），数量与内容不预设
- **不归一化**：一期标签独立生成，不映射到任何预设标签池；待人才库标签体系成熟后，由**智能体做匹配替换**（决策 #7，列入后续范围）
- 标签用途：人才卡「特长领域」由静态模板（现写死"程序设计""生成式人工智能"）改为**动态展示**（人才卡结构不变，仅更新该模块内容，决策 #15）
- 评价形态：标签 + 得分（100 分制）+ 评语，仅入库、后台可见（决策 #12）

### 5.2 模块二：数据分析

#### 5.2.1 数据来源

| 数据 | 来源 | 说明 |
|------|------|------|
| 简历 | 人才库用户自填材料（三模块）＋ 基本信息 | 审核通过后的内容 |
| 作品 | 审核通过的作品**评价（标签/得分/评语）**与 AI 理解结果 | 模块一产出；画像分析直接取用评价，**无需重复分析作品**（决策 #12） |
| 成绩 | AISE 测评记录（模块/等级/日期） | 已关联 AISE 的用户 |
| 题目作答 | AISE 逐题答题记录 | 已关联 AISE 的用户 |

**空态**：未关联 AISE 的用户，分析区展示"暂未关联 AISE 测评数据，如已参加 AISE 考试请联系管理员"（沿用人才卡现有空态文案，出处：AISE人才库_PRD §5.4.4）。

#### 5.2.2 个体人才水平评估

- 基于逐题答题记录，分析知识点掌握程度
- 错误类型归因：**未掌握 / 粗心 / 概念混淆** 三类（07-10 纪要）
- 跨考试追踪能力变化，量化能力水平，精准定位能力短板
- 知识点掌握度口径复用 [20260728 个人报告 PRD](<../20260728 个人报告与题库建设/PRD.md>)（得分和÷满分和，<60% 重点提升、≥60% 稳定掌握），不另定义

#### 5.2.3 成长建议自动生成

- 依据教育与学习规律生成个性化建议：**优先补齐关键短板 → 难度递进 → 定期巩固**（07-10 纪要）
- 配套练习方向建议，明确下一步学习重点
- 建议内容不含培训课程，只给方向与练习材料定位

#### 5.2.4 个人画像分析报告与人才卡更新

- **画像分析报告**：利用大模型能力自动生成个人画像分析报告，**样式沿用个人报告**（20260728 PRD 样式体系），**内容为对该人的画像分析**（决策 #8）；支持导出；生成内容经质量审核后对外提供（07-10 纪要）
- **报告入口**：**独立页面**，人才库标题栏新增「画像分析」独立 tab 进入（决策 #16）
- **人才卡更新范围**：人才卡**结构不变**，数据分析只更新两块内容（决策 #15）：
  - 「特长领域」：更新为动态标签
  - 「综合分析」：能力雷达（认知层/应用层/创新层/责任层）更新为动态分析结果
- **作品分析不入前台**：作品评价与理解结果只在后台可见（决策 #12）

## 6. Demo 方案（本地完整跑通）

### 6.1 目标与范围

做一个**本地能完整跑起来**的 demo，把全链路串起来：

> 用户上传作品 → 后台自动审核归档（智能体预审）→ 后台人工检查确认修改 → 前台看到结果（人才卡标签与能力雷达更新、画像分析报告）

范围覆盖 M1~M4 全部环节，并包含简历材料审核链路。发给别人也能跑（见 6.3 token 安全设计）。

### 6.2 技术形态

| 组成 | 方案 | 说明 |
|------|------|------|
| 前端 | 静态 HTML 页面（用户端 + 后台） | 与现有 `html/talent_pool/` demo 风格一致，响应式 |
| 本地服务端 | Python3 轻量后端（**仅标准库，零依赖**，决策 #13） | 职责：文件接收与存储、审核状态管理、调用大模型、无 key 时返回模拟结果 |
| 大模型 | DeepSeek V4 Flash（本机） | OpenAI 兼容接口；key 从本地 `.env` 读取 `DEEPSEEK_API_KEY`，不进代码 |

**为什么必须有本地服务端**：大模型调用必须携带 API key，key 放在前端（纯 HTML）等于直接暴露给任何打开页面的人。因此调用统一由本地服务端代理，前端只与服务端交互。收件人电脑上有 Python3 即可运行，无需安装任何包。

### 6.3 Token 安全设计（硬约束）

**要求：把 demo 发给别人，不能使用我的 token。**

| 模式 | 条件 | 行为 |
|------|------|------|
| 真实模式 | 本地 `.env` 配了 `DEEPSEEK_API_KEY` | 智能体预审真实调用 DeepSeek V4 Flash |
| Mock 模式 | 未配置 key | 服务端返回**显式标注「模拟结果」**的预设样例结论（按作品类型给出），全链路照常演示，不真实调用大模型 |
| 自备 key | 收件人填入自己的 key | 与真实模式一致 |

落实规则：

- 共享包（发给他人的压缩包/文件夹）**不含任何 key**：`.env` 不进共享包、加入 `.gitignore`
- 服务端启动时检测 key 存在性，并在日志与页面明确提示当前运行模式（真实 / 模拟）
- Mock 输出的审核结论一律带「模拟结果」标识，避免与真实 AI 结论混淆

### 6.4 页面清单

| 页面 | 端 | 类型 | 说明 |
|------|-----|------|------|
| 标题栏（新增 tab） | 用户端 | 改造 | 人才库标题栏新增「画像分析」独立 tab（决策 #16） |
| 作品上传页 | 用户端 | 新增 | 类型选择、名称/描述、文件上传；提交后显示「审核中」，连续上传不受限 |
| 我的作品 | 用户端 | 新增 | 记录列表，状态极简：审核中 / 审核完成 / 未通过（+驳回原因+重新提交，不限次数）；中间态不展示 |
| 人才卡（标签与雷达更新） | 用户端 | 改造 | **结构不变**：仅「特长领域」更新动态标签、「综合分析」能力雷达更新；不展示作品评价 |
| 画像分析报告页 | 用户端 | 新增 | 独立页，标题栏「画像分析」tab 进入；样式沿用个人报告，内容为个人画像分析；未关联 AISE 用户显示空态 |

| 作品详情审核页 | 后台 | 新增 | 原文件预览（代码高亮/图片/PDF）、AI 预审结论（含标签/得分/评语）与理解结果、人工裁决留痕 |
| 用户详情（材料审核） | 后台 | 改造 | 三模块材料逐条审核，按条目展示 AI 预审意见（规范性/一致性/敏感信息），沿用现有通过/驳回交互 |
