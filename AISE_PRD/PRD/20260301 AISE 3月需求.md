## 功能一：题目管理页面改版

### 1. 项目背景
- **需求简介**：对爱测评后台"题目管理"页面进行全面改版，将原有卡片式/大行高的题目列表替换为高密度紧凑型列表视图，同时引入多试题篮机制，提升教师选题组卷的操作效率。
- **业务诉求**：原列表每道题占用空间过大，在小屏笔记本上一屏仅能展示 3-4 道题，严重影响浏览效率；同时试题篮功能较为基础，不支持多篮管理和全量预览，无法满足教师同时为多套试卷选题的场景。

### 2. 业务流程简述
教师进入题目管理页面 -> 通过筛选器组合检索目标题目 -> 在紧凑型列表中快速浏览题目（支持题干预览） -> 点击"选题"将题目加入当前试题篮 -> 打开试题篮弹窗查看已选题目 -> 在多个试题篮之间切换管理 -> 生成试卷。

### 3. 详细功能需求说明

---

### 3.1 全局布局结构
- **位置**：爱测评后台顶部导航 -> [测评管理] -> 左侧边栏 -> [题目管理]。
- **目标**：提供清晰的三层导航架构（顶部全局导航 + 侧边栏模块导航 + 内容区），使教师可以快速定位至题目管理功能。

#### 3.1.1 界面元素与展示规则
1. **顶部导航栏**：
   - 静态文案：左侧展示网站名称"爱测评"及品牌标识。
   - 导航项包含：首页、测评管理、测评报告。当前激活项高亮显示。
   - 右侧展示"个人信息"入口（头像）。
2. **侧边栏**：
   - 位于内容区左侧，宽度 220px。
   - 导航项包含：题目管理、试卷库、考试任务。当前页高亮"题目管理"。
3. **内容区**：
   - 顶部为筛选器区域，下方为题目列表区域。
   - "新增试题"按钮置于列表工具栏右侧（非顶部导航栏内）。

---

### 3.2 筛选查询区
- **位置**：内容区顶部，独立卡片容器。
- **目标**：提供多维度组合检索能力，帮助教师快速定位目标题目。

#### 3.2.1 界面元素与数据校验约束
1. **题干关键词（文本输入框）**：
   - 静态文案：占位符显示"请输入..."。
   - 交互规则：支持模糊搜索，点击"查询"按钮或按回车键触发检索。
   - 边界校验：限制最多输入 100 个字符。
2. **所属题库（下拉选择框）**：
   - 默认选中"全部"。下拉选项动态加载用户有权查看的题库列表。
3. **题型（下拉选择框）**：
   - 默认选中"全部"。固定选项包括：单选题、多选题、判断题、编程题、简答题。
4. **标签（文本输入框）**：
   - 静态文案：占位符显示"如：高频、必考"。
   - 交互规则：支持模糊匹配标签名称。
5. **难度（下拉选择框）**：
   - 默认选中"全部"。固定选项包括：简单、中等、困难。
6. **功能按钮**：
   - "查询"按钮：主按钮样式，触发筛选查询并刷新列表。
   - "重置"按钮：次级按钮样式，清空所有筛选条件恢复默认值并重新加载列表。

### 3.3 题目列表区（紧凑型列表）
- **位置**：筛选区下方，独立卡片容器。
- **目标**：以高密度列表形式展示题目数据，单屏可展示 10-30 道题，大幅提升浏览效率。

#### 3.3.1 界面元素与展示规则
1. **列表工具栏**：
   - 左侧动态文案：`"共找到 {N} 道试题"`，N 为当前筛选条件下的总数（动态，来源于接口返回的分页总数）。
   - 右侧：放置"+ 新增试题"按钮。
2. **表头字段与列定义**：
   - 题目 ID：展示题目唯一编号，固定宽度 70px。
   - 题型：展示题型文本，固定宽度 70px。
   - 题干：展示题干纯文本摘要，弹性宽度占据剩余空间。**溢出处理**：单行截断，尾部展示"..."。
   - 知识点：展示关联知识点标签（胶囊样式），固定宽度 130px。
   - 标签：展示题目标签（胶囊样式），固定宽度 120px。
   - 可见范围：展示"公开""团队内""私有"等范围标签，固定宽度 80px。
   - 出题人：展示出题人姓名，固定宽度 80px。
   - 操作：展示行内操作链接，固定宽度 180px。
3. **数据为空（空态）**：列表区域展示空状态插画，底部文案提示"暂无符合条件的题目"。
4. **横向溢出处理**：当浏览器窗口宽度不足以完整展示所有列时，列表区域出现水平滚动条（列表设置最小宽度 1060px）。
5. **分页**：底部右侧展示分页控件，包含当前页码范围、总条数和翻页按钮。

#### 3.3.2 题干预览交互（点击展开富文本气泡）
- **交互触发方式**：
  - 用户**点击**题干文字或行尾的眼睛图标，弹出固定的富文本预览气泡。
  - 眼睛图标在行悬停时才显示（默认隐藏），被激活后高亮为主题色。
- **气泡内容**：渲染题干的完整富文本内容（支持图片、代码块、列表等 HTML 元素）。
- **气泡定位**：默认在题干下方展示，若下方空间不足则翻转到上方。气泡最大宽度 450px，最大高度 350px，超出部分内部可滚动。
- **关闭逻辑**：
  - 点击同一行的眼睛图标可切换关闭。
  - 点击气泡外任意区域关闭。
  - 内容区滚动时自动关闭。

#### 3.3.3 行内操作（动态按钮逻辑）
操作列根据当前登录用户与出题人的关系，动态展示不同的操作按钮：

| 条件 | 展示的操作按钮 |
| :--- | :--- |
| 题目尚未加入当前试题篮 | "选题"（蓝色链接） + 后续按钮 |
| 题目已在当前试题篮中 | "移出"（红色链接） + 后续按钮 |
| 出题人是当前用户 | "编辑" + "详情" |
| 出题人非当前用户 | "复制且编辑" + "详情" |

- **选题按钮**：点击后将该题目加入当前激活的试题篮，按钮立即变为红色"移出"。
- **移出按钮**：点击后将该题目从当前试题篮中移除，按钮恢复为蓝色"选题"。
- **编辑按钮**：仅当出题人为当前登录用户时展示，点击进入题目编辑页。
- **复制且编辑按钮**：当出题人非当前用户时展示，点击后系统复制一道新题（归属当前用户），原题不变，自动跳转至新题的编辑详情页。
- **详情按钮**：始终展示，点击进入题目只读详情页。

### 3.4 试题篮（悬浮面板）
- **位置**：页面右下角固定悬浮。
- **目标**：提供轻量化的试题篮快捷入口，方便教师随时查看已选题目概况并快速操作。

#### 3.4.1 界面元素与展示规则
1. **悬浮按钮**：
   - 圆形主色按钮，固定在右下角。
   - 右上角展示红色角标，动态显示当前试题篮中的题目数量。
2. **展开面板**（点击悬浮按钮切换展开/收起）：
   - **头部**：标题"试题篮"，右侧"清空"操作链接。
   - **汇总区**：
     - 动态文案：`"已选 {N} 道题目"`。
     - 题型统计标签：以胶囊标签展示各题型的已选数量（如"单选题 2""编程题 1"）。
   - **题目列表**：展示已选题目的缩略列表，每项含题型标注、单行截断的题干文本、删除按钮。列表最大高度 240px，超出部分内部滚动。
   - **底部操作**：
     - "查看已选题目"按钮（次级按钮）：点击打开试题篮详情弹窗。
     - "生成试卷"按钮（主按钮）：触发组卷流程。
3. **空态**：汇总区显示"已选 0 道题目"，题目列表区显示居中文案"试题篮为空，请从列表中选题"。
4. **点击面板外区域**：自动收起面板。
5. **防遮挡设计**：内容区底部预留 120px 的内边距（`padding-bottom`），确保最底部的题目列表行不会被悬浮按钮永久遮挡。

### 3.5 试题篮详情弹窗（多试题篮管理）
- **位置**：点击试题篮悬浮面板中的"查看已选题目"按钮触发。
- **目标**：提供完整的试题篮查看与管理界面，支持多个试题篮的切换、新增和题目管理。

#### 3.5.1 界面元素与展示规则
1. **弹窗容器**：
   - 模态框覆盖层（半透明遮罩），点击遮罩层可关闭弹窗。
   - 弹窗宽度 720px，最大高度 80vh，内容超出垂直滚动。
   - 右上角展示关闭按钮"X"。
2. **试题篮标签页（多篮切换）**：
   - 弹窗标题下方展示 Tab 标签页，每个 Tab 对应一个试题篮，文案格式为 `"{篮名}（{已选数量}）"`。
   - 当前激活的试题篮 Tab 高亮显示（底部边框主题色）。
   - Tab 行末尾展示"+ 新增试题篮"按钮（虚线边框样式），点击后弹出系统的输入框提示用户输入篮名，确认后创建新篮并自动切换到该篮。
3. **题目列表表格**：
   - 表头字段：序号（居中，自增编号）、题干（弹性宽度，单行截断）、题型（固定宽度 80px）、操作（固定宽度 60px）。

4. **底部栏**：
   - 左侧动态文案：`"已选 {N} 道题目"`。
   - 右侧："生成试卷"主按钮。

#### 3.5.2 多试题篮业务逻辑
- 系统支持同时存在多个试题篮，用户在题目列表中点击"选题"时，题目加入**当前激活的试题篮**。
- 切换 Tab 后，主列表中的"选题/移出"状态随之联动刷新（仅与当前激活试题篮的内容对比）。
- 每个试题篮的数据独立管理，互不影响。

## 功能二：试卷编辑页题目详情增强

### 1. 项目背景
- **需求简介**：在"试卷编辑"页面的题目详情弹窗内，新增一套基于出题人权限的动态操作流程：支持当前用户修改自己的题目，或在遇到他人题目时进行"复制且修改"的无缝替换操作。
- **业务诉求**：教师在组卷时经常需要基于已有题目微调（如改数据、改选项）。如果原题是他人创建的，直接修改会影响其他试卷；如果要求教师手动去题库复制再回来替换，操作路径过于繁琐。本次优化旨在提供"所见即所需"的快捷改题体验。

### 2. 业务流程简述
教师在试卷编辑页点击某题的"题目详情" -> 系统展示题目完整信息及底部操作按钮 -> 
- 若出题人是自己：点击"修改题目" -> 在新页面进行编辑 -> 提交后试卷内题目同步更新。
- 若出题人非自己：点击"复制且修改" -> 系统自动生成一道归属自己的新题 -> 试卷中的原题被系统静默替换为新题 -> 跳转至新题的编辑页 -> 提交修改后试卷同步更新。

### 3. 详细功能需求说明

#### 3.1 试卷题目列表区（入口展示规则）
- **位置**：试卷编辑页面 -> 各大题模块下的题目列表。
- **目标**：提供进入题目详情的快捷操作入口。
1. **界面元素**：
   - 每道题的行末固定展示右侧对齐的操作链接："题目详情"与"移除"。
2. **交互规则**：
   - 用户点击"题目详情"，唤起本功能核心的【题目详情弹窗】。

#### 3.2 题目详情弹窗
- **位置**：全屏覆盖的局部模态框（居中显示，包含遮罩层）。
- **目标**：展示详情并提供上下文化的编辑/复制入口。

##### 3.2.1 界面元素与展示规则
1. **内容展示区**（只读态）：
   - 包含题干完整富文本、选项（正确项高亮标注）、题型/难度/分值/知识点等元数据，以及解析。
2. **底部操作栏**（动态判定逻辑）：
   - 底部固定展示"关闭"按钮。
   - **动态按钮判定机制**：
     - 当后台数据表明 `当前题目.author == 当前登录用户` 时，左侧展示蓝色主按钮 **"修改题目"**。
     - 当后台数据表明 `当前题目.author != 当前登录用户` 时，左侧展示橙色/警告色主按钮 **"复制且修改"**。

##### 3.2.2 交互逻辑与状态流转
**A. "修改题目"操作生命周期**：
1. **触发指令**：用户点击蓝色"修改题目"按钮。
2. **执行中过程态**：当前题目详情弹窗关闭。并在当前视图弹出轻提示：`"正在打开题目的编辑页面..."`。
3. **执行成功（跳转与状态挂起）**：
   - 系统新开浏览器页签（或无缝页面跳转）进入该题目的标准编辑页。
   - 保留原试卷编辑页的状态。当用户在编辑页完成修改并保存后，原试卷视图应通过接口刷新或前端状态机同步展示最新的题目内容。

**B. "复制且修改"操作生命周期（核心复杂交互）**：
1. **触发指令**：用户点击橙色"复制且修改"按钮。
2. **执行中过程态（防抖与阻断）**：
   - 按钮显示加载圈动画，防止重复连击。
   - 系统后台执行原子操作：① 完全深拷贝当前题目数据；② 将新题的 `author` 属性强行变更为当前系统登录用户，并生成新 `ID`。
3. **执行成功（视图替换与跳转）**：
   - 关闭当前题目详情弹窗。
   - 原试卷列表中，被点击的这道题目的渲染数据被**静默替换**为刚才生成的新题（列表上体现为 ID、出题人变更为当前用户的新题目）。
   - 在当前视图弹出轻提示：`"已复制该题并一键替换试卷内容，正在打开编辑页面..."`。
   - 系统新开浏览器页签（或无缝页面跳转）进入**新题**的标准编辑页。

##### 3.2.3 异常与系统边界
- **并发冲突拦截**：如果试卷本身处于已被他人锁定编辑的状态，点击这两个按钮时，应该前置阻断并弹窗提示："当前试卷正由其他教师编辑，无法执行题目替换或修改操作"。
- **网络降级**：在"复制且修改"的克隆阶段若遭遇断网，须立即停止转圈，停留在当前弹窗并弹窗警告："复制题目失败，请检查网络"。此时绝不执行后续的试卷替换与页面跳转。

## 功能三：试卷编辑页实践题赋分增强

### 1. 项目背景
- **需求简介**：在试卷编辑页面针对每一道题目的"赋分"弹窗中，扩展现有的单维度总分配置。当遇到"实践题"时，允许教师配置由 $N$ 个具体"打分维度"组成的评分明细，且保证各维度分值之和严谨匹配设定的该题总分。
- **业务诉求**：实践题（如项目代码实操、设计稿输出）的给分标准往往不仅是一个总分，而是由多个具体评价维度（如"可用性"、"业务逻辑"、"边界处理"）构成。通过本功能，试卷在配置阶段即可固化实践题的评分量表（Rubric），不仅明确了考生的具体得分项，也为后续的阅卷统分提供了结构化依据。

### 2. 业务流程简述
教师在试卷编辑页点击某道题的"赋分" -> 系统弹出赋分弹窗并展示当前各项试卷总分统计 -> 教师修改本题总分 -> （若为实践题）教师点击"添加维度"配置多个评分项 -> 系统实时校验各维度分值加和是否等于本题总分 -> 校验通过后保存 -> 试卷及各种总计维度分数同步更新。

### 3. 详细功能需求说明

#### 3.1 赋分弹窗全局数据展示（只读统计区）
- **位置**：赋分弹窗的上半部分（灰色承载卡片内）。
- **目标**：为教师赋分提供实时的参考依据与影响范围预览。
- **界面元素与展示逻辑**：
  采用 $2 \times 3$ 的网格布局，分别静态/动态展示以下高亮数据：
  1. **建议分值**：取自题库中该题目原本自带的默认分值。
  2. **当前分值**：该题在当前试卷中当前被赋予的分值。
  3. **当前本题型总分**：当前大题范围内的题目总分加和。
  4. **修改后本题型总分**：`动态计算 = 当前本题型总分 + (设定的新分值 - 当前分值)`。文本需使用主题色高亮。
  5. **当前试卷总分**：整张试卷的当前满分。
  6. **修改后试卷总分**：`动态计算 = 当前试卷总分 + (设定的新分值 - 当前分值)`。文本需使用主题色高亮。

#### 3.2 基础分值设定（输入区）
- **界面元素**：
  - 标签文案："设定分值"。
  - 输入框：数字类型（Number），失去焦点及键入时立即触发上述动态总分的重算。
- **数据约束**：
  - 必须为 $> 0$ 的数字。若输入 $0$、负数或清空，输入框标红，并置灰底部的"确定"按钮。

#### 3.3 实践题打分维度配置（动态输入区）
- **前置条件**：仅当当前操作的题目类型为**"实践题"**时，此区域才可见。其他题型隐去此区域。
- **位置**：基础分值设定下方。
- **目标**：提供灵活的评分量表配置能力，并施加严格的总分一致性校验。

##### 3.3.1 界面元素与交互规则
1. **标题与引导**：
   - 静态标签文案："打分维度配置"。
   - 静态帮扶提示："针对本道实践题，您可以拆解多个打分维度，各维度分值之和必须等于设定的本题分值。"。
2. **维度列表与新增**：
   - 列表头部右侧提供 **"+ 添加维度"** 按钮（次级按钮样式）。点击后在列表尾部追加一行空白维度输入项。
   - 每一行维度包含三个元素：
     - ① **维度名称输入框**：占位提示"维度名称"，必填文本。
     - ② **分值输入框**：数字类型，必填，必须 $\ge 0$。
     - ③ **删除操作**：行尾红色的 "X" 测试图标。当列表只剩最后 $1$ 行时，此按钮置灰禁用，保证至少存在一个维度。
3. **底部计算汇总条**：
   - 左侧动态文案：`"当前各维度总和：{Sum} 分"`。此数值随着列表中任意分值的更改而实时重算。
   - 右侧动态文案：`"目标：{Target} 分"`。Target 为上方设定的本题总分值。
   - **状态判定逻辑**：
     - 若 `Sum == Target`：左侧文本显示常规黑色。
     - 若 `Sum != Target`：左侧文本变为红色危险色。

##### 3.3.2 强校验与阻断流转
在用户点击底部主按钮"确定"时，必须依次执行以下严密逻辑检验：
1. 本题的设定总分必须合法（$> 0$）。
2. 若为实践题，逐行检查所有"维度名称"是否填写完整，若存在空值，在底部显示红色警戒提示：`"⚠️ 提示：请填写完整所有维度的名称。"`。
3. 若为实践题，校验各维度加和：`Sum == Target`。若不等于，在底部显示红色警戒提示：`"⚠️ 提示：各维度分值加和不等于设定的总分值。"`。
4. 任何一项校验失败，"确定"按钮始终处于禁用（Disabled）状态，无法被点击。
5. 只有当各项均符合规则要求，点击"确定"后方可关闭弹窗，执行本地题目的分值覆盖（若是实践题亦同步覆盖其内部的维度 JSON 结构），并局部刷新外层试卷列表与总分统计。

## 功能四：测评活动交卷时间限制配置

### 1. 项目背景
- **需求简介**：在后台"测评活动管理 - 新建/编辑测评活动"的表单中，于现存的"测评时长"字段旁，新增【交卷时间限制（分钟）】配置项。
- **业务诉求**：为了统筹考场纪律，防止考生利用极短时间提交试卷后泄露考题，或规范考试流程，主办方往往要求在开考后的特定时间段内（如开考前 15 分钟）禁止提前交卷。

### 2. 界面元素说明
- **位置**：测评活动信息配置区域（紧邻"测评时长"）。
- **字段名称**：`<span class="text-red-500">*</span> 交卷时间限制（分钟）`
- **组件类型**：数字输入框（Number Input）。
- **默认值**：建议默认为 `15`（分钟）或 `0`（不限制）。
- **占位符/提示文本**：输入限制交卷的分钟数。

### 3. 表单校验与业务规则

#### 3.1 基础格式校验
- 必须输入**正整数或 0**。（若用户输入小数、负数，前端可向下取整或强制重置为 0，防止非法提交）。
- 表示"开考后的前 $N$ 分钟内不允许考生点击交卷按钮"。
- 若输入 $0$，则表示完全不限制，考生随时可以交卷。

#### 3.2 逻辑关联网校验（核心约束）
- 此字段与**"测评时长（分钟）"**强相关。
- **约束条件**：`交卷时间限制 <= 测评总时长`。
  - *举例*：如果一场考试总时长只有 60 分钟，交卷时间限制最多只能设置为 60 分钟（即全程不准提前交卷，只能等时间到系统自动收卷）。如果输入了 90，这在业务逻辑上是自相矛盾的。
- **前端实时反馈机制**：
  - 当用户输入数值后，前端在失焦（`onblur`）或输入时（`oninput`）实时比对两个字段的值。
  - 若打破约束（即 `交卷时间限制 > 测评总时长`）：
    1. 输入框边框变为红色警戒态。
    2. 输入框底部立即显示红色提示语：`"不能超过测评总时长"`。
    3. 此时表单底部的"保存" 或 "保存并同步" 主体按钮必须处于禁用（Disabled）状态，阻断非法数据的产生。
  - 若符合约束，清除红色警报状态，恢复按钮交互。

- **弹窗形态**：居中模态框，包含半透明黑色遮罩，点击遮罩外围或右上角 `x` 可关闭。

## 功能六：学生端答题页 - AIGC 剩余次数提示与控制

### 1. 项目背景
- **需求简介**：在学生端答题页面（针对 AIGC 题型，如文生文、文生图等），当组卷教师为该题配置了"答题生成次数限制"时，答题页需要明确向学生展示剩余的可用次数，并在次数耗尽后禁止其继续生成新的内容。
- **业务诉求**：承接【功能五】，在作答端闭环次数限制逻辑。给予学生明确的预期管理，避免盲目试错浪费算力，同时也保障了考试的公平性与纪律性。

### 2. 界面元素说明与交互设计

#### 2.1 剩余次数提示徽标（Badge）
- **位置**：位于 AIGC 题型专属的【让 AI 开始写作 (Generate)】主操作按钮的右侧（或紧邻的视觉关联区域）。
- **视觉样式**：
  - 采用醒目的警告色调（如橙/黄色系，例如背景 `#fff3e0`，边框 `#ffcc80`，文字 `#e65100`），以引起考生的充分注意。
  - 需要保持一定的内边距与圆角，使其呈现一个清晰的徽标（Badge）或胶囊状。
- **文案结构**：`剩余次数: {Remaining}/{Max} `（如：`剩余次数: 3/3`）。

#### 2.2 核心业务与状态流转逻辑

**A. 初始化态**
- 页面加载时，系统拉取该题的 `attemptsLimit`，如果无限制则隐藏徽标，如果有且为 $Max$ 次，则显示 `剩余次数: {Max}/{Max}`。按钮正常可用。

**B. 消耗态（点击生成）**
- 每次学生合法点击【生成】按钮并成功发起请求后，剩余次数立即 `-1`（即 `Remaining = Remaining - 1`）。
- 徽标文字实时更新（如变为 `2/3`）。

**C. 耗尽阻断态（极值保护）**
- 当 `Remaining == 0` 时：
  - **按钮禁用**：【生成】按钮立刻进入 Disabled（不可交互）状态，背景灰置，去除所有悬停和点击动效。
  - **文案变更**：【生成】按钮内部文案从 `"🖊️ 让 AI 开始写作"` 变更为警戒提示 `"🛑 次数已用尽"`。
  - **输入框锁定**（可选辅助）：锁定 Prompt 的 `textarea` 输入框为 Disabled 状态（因为也无法再生成了），防止无效输入。
  - **弹窗阻断**：若系统因异常发生超限点击请求，需在前端直接 alert 前置拦截（`"生成次数已用尽！"`），绝对禁止额外发包。

## 功能七：题目管理详情页 - 读题文本 (TTS) 配置

### 1. 项目背景
- **需求简介**：在"爱测评 - 题目库/题目管理"的题目详情编辑页面中，针对单题级别新增一个【读题文本配置 (TTS)】的多行文本输入框。
- **业务诉求**：很多低龄学生或特殊考生在阅读结构复杂的题干时存在困难。允许命题教师额外配置一段"口语化、利于听觉理解"的转述文本。在实际考场的答题页面中，学生可以点击"播放读题"按钮，由系统前端调用语音合成（TTS）引擎直接朗读这段自定义文案。

### 2. 界面元素说明与交互设计

#### 2.1 读题文本输入区域
- **所处位置**：题目编辑表单内，放置于【解析说明】的下方，作为常规的表单项存在，不作过度夸张的视觉强调，保持页面统一的清爽白底与标准边距。
- **组件结构**：
  - **字段标签**：标准的表单 Label `读题文本配置 (TTS)`。右侧对齐放置“试听发音”按钮。
  - **文本框**：一个支持多行的标准 `<textarea>`，取消了富文本功能（因为语音合成引擎通常只接受纯文本或带特定 SSML 标记的文本，不支持 HTML 标签图文混合）。
  - **提示占位符（Placeholder）**："请在此输入系统朗读的文案，如果不填则默认直接朗读原题干纯文本。如果题干中有图片或代码，建议填写针对听觉优化的转述文案。"
  - **辅助说明（Helper Text）**："学生在考试端点击“播放读题”时，系统将通过语音合成引擎朗读上方配置的纯文本内容。"

#### 2.2 试听发音功能（Audition）
- **功能按钮**：在文本框右下方提供一个 **[🎧 试听发音]** 的快捷交互按钮。
- **交互逻辑**：
  - 命题人编辑完文本后，点击该按钮，前端立即拦截并剥离文本框内的特殊无声字符。
  - 调用底层的 TTS API（或浏览器原生的 `SpeechSynthesis` 接口），模拟考场环境朗读该段文本。
  - 若文本框为空，则系统读取原【题干内容】剥离 HTML 标签后的纯文本进行试听。
  - 试听过程中，按钮可转变为"⏹ 停止试听"状态。

### 3. 数据层与业务流转说明

1. **题目结构扩展**：在后端的核心题目表结构中，针对 Question 实体新增 `tts_text` (String/Text) 字段。
2. **入库覆盖逻辑**：
   - 教师填写了该字段，则将其随题目常规属性一并保存入库。
   - 教师若留空，则在业务侧无需存入冗余数据（保存为 NULL 或空字符串）。
3. **分发到考场端（渲染逻辑）**：
   - 考场端渲染题目时，判定该题的 JSON 数据体中是否包含有效的 `tts_text`：
     - **存在**：绑定的播报动作参数取这串经过教师口语化优化的专属文本。
     - **不存在/为空**：前端自动执行 Plan B —— 使用正则过滤掉 HTML `<p>、<img>、<style>` 等不可读标签，提取纯净题干文本（Raw Text）作为朗读入参。
4. **适配场景拓展**：由于题干中经常包含不可直接播报的公式（MathML/LaTeX）或示意图片，该字段极大丰富了爱测评试卷的“无障碍读题体验”，为将来的语音题、听力题打下数据结构基础。

## 功能八：学生端答题页 - 读题文本 (TTS) 音频播放

### 1. 项目背景
- **需求简介**：在所有存在题目内容展示的学生端答题页面（无论单选、多选、编程题还是实践题等全题型），于题目题头统一增加一个【播放读题】的交互按钮。

### 2. 界面元素说明与设计规范

#### 2.1 按钮位置与外观
- **注入位置**：紧跟在各答题页的题型与分值徽标（例如 `<span class="q-badge">单选题 · 5分</span>`）之后，与分值/进度标识保持在同一行（`flex` 或 `inline-block` 布局）。
- **组件结构**：
  - **核心部件**：一个附带声音播放 Icon 的 `播放读题` 小巧按钮。
  - **视觉设计**：采用与整体系统相协调的青蓝色微渐变与圆角边框（`background: #e1f5fe; border: 1px solid #81d4fa;`），文本色彩对应主题色（`color: var(--primary-dark);`）。

#### 2.2 核心业务与状态流转逻辑
- **发音内容匹配**：当学生点击按钮时，前端 JavaScript 按如下优先级调用系统 `SpeechSynthesis`（或服务端云 TTS 接口）：

- **播控防并发拦截**：当正在播放某题的声音时：
  1. 按钮状态可变为 `⏸ 停止读题` 或增加播放中的动效。
  2. 如果学生点击了另外一题的播放按钮，必须先打断静音（`cancel()`）上一个语音任务，再开始下一个，绝对禁止多音轨同时发声造成的听觉污染。

## 功能九：学生端答题页 - 实践题上传附件大小限制 (150MB)

### 1. 项目背景
- **需求简介**：在学生端答题页面中，针对“实践题”题型，学生提交作品附件时，系统需严格限制单个文件的最大体积，上限配置为 **150MB**。

### 2. 界面设计与交互拦截
- **文案提示修改**：在“实践题”右半部分的作答/上传引导区域内：
  - 【格式要求】卡片底部的文字统一更新为：“请将所有内容整合为一个文档（Word、PDF 或 PPT），**文件大小不超过 150MB**。”
  - 上传拖拽区域下方的小字线索更新为：“支持格式：.docx, .pdf, .pptx, .zip **(Max 150MB)**”
- **前端动作拦截**：
  - 当学生通过点击弹出资源管理器或拖拽选取了源文件（File 对象）后，前端在发起正式的 AJAX/OSS 直传请求前，必须第一时间通过 `file.size` 对文件体积进行合法性校验验算。
  - **超限阻断**：若文件大小超过 `150 * 1024 * 1024` Bytes，则直接弹窗警告学生：“**上传失败：文件大小不能超过 150MB！**”，同时重置（清空）本次该标签的选取状态，拦截业务请求，且**不允许强行交卷包含超大附件的脏数据**。
  - **体验防跌落**：一旦文件大小通过前置校验，即可正常走进度条动画并进入 `upload-done` 卡片展示态，方可进行最终交卷操作。
