# 考后批量生成证书报告 PRD

> 版本：V1.0 ｜ 状态：评审中
> 需求提出：张二红（2026-10-26）
> 原始需求：《9月12日测评后考务需求整理》1012 会议条目：「考后这些考场的证书和报告批量生成、推送」

## 1. 背景与收益

**需求简介**：在活动详情页提供批量生成入口，一次圈选活动下多场测评，批量生成证书与报告，统一查看进度并批量推送。

**业务诉求与收益**：活动详情支持批量创建多场同构测评，一个活动下常有十几场考场。现行证书/报告生成与推送在单场维度操作（测评证书管理的详情页逐场触发），场次多时运营要逐场进入、逐场等待、逐场推送，考后收尾耗时长。批量生成把多场操作收敛为一次圈选，生成与推送进度集中展示，失败学员统一重试，缩短考后收尾周期。

## 2. 业务流程

```
活动详情 →「生成证书 / 报告」→ 圈选场次（逐场资格校验）
  → 确认 → 批量生成（进度可见、失败可单个或批量重试）
  → 生成完成 → 批量推送证书 / 批量推送报告（手动触发，各自独立进度）
  → 各场次按既有单场门禁流转成绩公示
```

配套口径：
- 批量入口管多场，14 / 15 页的既有单场生成与推送入口保留，负责零星补漏
- 各场次的成绩公示流转维持单场门禁，批量视图提供「已满足公示条件的场次数」汇总
- 报告覆盖全部参测学员（含未通过），证书仅覆盖达到分数线学员，沿用 20260728 个人报告 PRD 口径

## 3. 详细功能说明

### 3.1 入口

HTML Demo：33_活动详情.html（见下方文件，直接点击浏览）

| 项 | 说明 |
|---|---|
| 位置 | 活动详情页工具栏，新增「生成证书 / 报告」按钮，与「批量修改」「渠道关联」并列 |
| 点击后 | 打开「批量生成证书 / 报告」弹窗，覆盖该活动下全部分组的全部测评 |
| 前置 | 活动下无测评时按钮点击提示「该活动暂无测评」 |
| 任务互斥 | 同一活动同一时刻仅允许一个批量任务：任务进行中再次点击按钮，弹窗直接回到进度视图；任务结束前不能发起新的批量 |

### 3.2 圈选：逐场资格检查

| 项 | 说明 |
|---|---|
| 列表结构 | 按分组呈现该活动全部测评，每行展示：生成对象勾选（证书、报告两个独立勾选框）、测评名称、测评时间、参测人数 / 达标人数、资格状态 |
| 报告资格 | 批改完成即可勾选；批改中的场次锁定并标注「批改中，暂不可生成」 |
| 证书资格 | 批改完成、证书实例已配置、分数线已设置，三项齐备才可勾选；缺项时锁定并在资格列标注具体原因（「证书实例未配置」「分数线未设置」） |
| 快捷操作 | 「全选可生成」一键勾选全部可生成对象；「清空」清空全部勾选 |
| 已生成跳过 | 已经批量生成过的场次，名称下方显示「已生成过，跳过」，再次执行时自动排除，防止覆盖 |
| 实时汇总 | 底部汇总条随勾选实时刷新：证书 N 场 · X 人；报告 N 场 · Y 人 |
| 开始按钮 | 无任何勾选时置灰；有勾选时按钮文案带汇总（如「开始生成（证书 2 场 · 1630 人；报告 3 场 · 2883 人）」） |
| 确认 | 点击开始弹出系统确认框：「将为 N 场测评生成证书 X 份、报告 Y 份；已生成过的场次自动跳过。确认开始？」 |

### 3.3 生成进度

| 项 | 说明 |
|---|---|
| 总进度 | 顶部总进度条 + 百分比，附「证书 N/总数 · 报告 N/总数」双计数 |
| 场次明细 | 逐场展示证书、报告各自的「成功 · 失败 / 总数」与进度条；有失败的场次进度条转红 |
| 异步执行 | 生成在后台执行：关闭弹窗任务继续，重新打开弹窗回到进度视图；关闭进行中的任务时弹确认「关闭后任务继续执行」 |
| 失败处理 | 失败明细区逐条列出：学员姓名、所属测评、生成对象、失败原因；每条带「重新生成」按钮，顶部带「重试全部失败项」按钮 |
| 重新生成规则 | 成功的不重复生成；重试成功后计入成功数，失败明细相应移除 |
| 生成完成 | 总进度标签变「生成完成」；本场次批量生成的场次标记为已生成 |

### 3.4 批量推送

| 项 | 说明 |
|---|---|
| 推送时机 | 手动触发：证书、报告各自「批量推送」按钮，在生成完成后出现 |
| 推送门禁 | 该对象全部生成成功才可点；存在生成失败项时按钮置灰，提示先重试 |
| 推送进度 | 证书推送与报告推送各自独立进度行：进度条 + 成功/失败计数 |
| 推送失败 | 失败的标记并显示「重推失败项」按钮，重推成功后计数归位 |
| 弹窗样式 | 弹窗以系统原生样式为准，层级最高；demo 里的弹窗样式仅作交互参考，研发以 alert 文案为准实现 |

### 3.5 公示条件汇总

| 项 | 说明 |
|---|---|
| 汇总行 | 进度视图底部固定展示：本次批量涉及的场次中，已满足公示条件的场次数（如「3 / 3 场已满足」或「2 / 3 场已满足」） |
| 判定口径 | 该场次勾选的生成对象全部生成成功且推送完成即为满足 |
| 与单场门禁关系 | 各场次仍按既有单场门禁独立流转（14 / 15 页），本汇总只做活动级进度提示，改变不了单场流转规则 |

## 4. 验收标准

| # | 场景 | 前置条件 | 操作 | 期望结果 | 判定 |
|---|------|---------|------|---------|------|
| 1 | 打开批量入口 | 活动下已有测评 | 点击「生成证书 / 报告」 | 弹窗打开，按分组列出全部测评与资格状态 | 布局与文案正确 |
| 2 | 资格锁 | 某场批改中 / 证书实例未配置 / 分数线未设置 | 查看该场勾选框 | 对应勾选框锁定，资格列标注具体原因 | 锁定与原因一致 |
| 3 | 全选可生成 | 存在多种资格状态的场次 | 点「全选可生成」 | 仅可生成对象被勾选，汇总条与开始按钮同步刷新 | 勾选与汇总一致 |
| 4 | 开始确认 | 已勾选 | 点「开始生成」并确认 | 弹出确认框，份数与勾选一致；确认后切到进度视图 | 确认信息准确 |
| 5 | 生成进度 | 任务执行中 | 查看总进度与场次明细 | 总进度条推进，逐场证书/报告独立计数 | 进度数据正确 |
| 6 | 异步恢复 | 生成进行中 | 关闭弹窗后重新点入口 | 提示任务继续；重开弹窗直接回到进度视图 | 进度不丢失 |
| 7 | 生成失败 | 任务完成且有失败项 | 查看失败明细 | 学员级明细含原因，可单个重新生成 | 明细准确 |
| 8 | 批量重试 | 存在多条失败 | 点「重试全部失败项」 | 全部失败项重跑成功，失败区收起 | 计数归位 |
| 9 | 推送门禁 | 某对象存在生成失败 | 查看该对象推送按钮 | 按钮置灰，提示先重试；重试成功后可点 | 门禁判定正确 |
| 10 | 手动推送 | 证书、报告均已生成成功 | 分别点两个推送按钮 | 各自独立进度行，完成后计数为全部推送 | 推送进度正确 |
| 11 | 重推失败项 | 推送出现失败 | 点「重推失败项」 | 失败项补齐，计数显示已全部推送 | 重推有效 |
| 12 | 已生成跳过 | 上次批量已覆盖部分场次 | 再次进入圈选并执行 | 已生成场次标注跳过，确认框份数不含它们 | 防覆盖正确 |
| 13 | 公示汇总 | 批量完成后 | 查看底部汇总行 | 满足条件的场次数与实际生成推送状态一致 | 汇总准确 |
| 14 | 任务互斥 | 批量任务进行中 | 再次点入口 | 回到进度视图，不能发起新批量 | 互斥有效 |
| 15 | 回归：单场流程 | 任意测评 | 走 14 / 15 页既有单场生成、推送、流转 | 流程与改造前一致，不受批量影响 | 单场功能正常 |
| 16 | 回归：活动详情既有功能 | 活动详情页 | 创建测评 / 批量修改 / 渠道关联 / 分组管理 | 全部正常可用 | 既有功能无回归 |
