# 需求一：证书导出印刷交付

## 1. 背景与收益

需求简介：「学生证书管理」导出升级为印刷交付模式——单「导出数据」按钮带出导出任务设置弹窗，运营在弹窗内确认筛选条件、勾选导出内容（Excel 明细表 / 学生照片压缩包）与考场拆分方式（合并 / 按考场分开），两者均走异步任务，任务完成后在导出任务抽屉按文件下载。

业务诉求与收益：证书公示后进入印刷环节，导出物从内部核对扩展为印厂交付包。原「导出数据」单按钮无法区分表格与照片、无法按考场拆分交付。升级后运营一次操作即可产出印厂所需的全套文件；Excel sheet2 记录导出条件、照片按「证书编号+学生姓名」命名，交付与复核在系统内闭环。

## 2. 业务流程

运营在「学生证书管理」页筛选目标学员后：

1. 点击「导出数据」→ 弹出导出任务设置弹窗，自动带出当前筛选条件（只读确认，需调整回筛选区修改后重新导出）
2. 在弹窗内勾选导出内容：Excel 明细表 / 学生照片压缩包（均为异步任务），可两者都选
3. 勾选考场拆分方式：合并导出（一张总表 / 一个总压缩包）或按考场分开导出（每个考场各一份）
4. 点击「开始导出」→ Excel 即刻下载到本地；照片压缩包在后台异步生成，右上角「导出任务」入口可看进度
5. 任务完成后在导出任务抽屉按文件下载；Excel sheet2 记录本次导出条件，供交付复核

## 3. 详细功能说明

### 3.1 导出设置弹窗（筛选条件只读 + 内容与拆分勾选）

| 变更项 | 说明 |
|---|---|
| 导出条件（只读） | 弹窗自动带出当前页面筛选条件，只读确认不可修改；需调整时回筛选区修改后重新点击导出 |
| 导出内容 | 勾选 Excel 明细表 / 学生照片压缩包（均为异步任务），可任意组合；全不勾时「开始导出」置灰 |
| 考场拆分方式 | 合并导出（一张总表 / 一个总压缩包）或按考场分开导出（每个考场各一份） |
| 汇总预览 | 底部实时展示「本次将产生：Excel×N、照片压缩包×N」，分开导出时按考场数计 N |
| 命中学员与提醒 | 展示当前筛选命中学员数；包含无证书学生时展示黄色提醒（向印厂交付请确认范围），不拦截操作 |
| 确认导出 | 点击「开始导出」执行；Excel 即刻下载，照片包创建异步任务 |

### 3.2 Excel 导出（异步任务）

| 变更项 | 说明 |
|---|---|
| 任务形态 | Excel 与照片压缩包一致，走异步任务；任务完成后在「导出任务」抽屉按文件下载，不存在同步下载 |
| 按筛选导出 | 按当前筛选结果导出，筛多少人导出多少人 |
| 字段清单 | 考场名称、准考证号码、手机号（学生账号）、姓名、证件号码、参测模块、评估结果、证书编号、订单编号、发证日期（待考务老师终版确认） |
| 字段来源口径 | 订单编号＝报名支付订单号；发证日期＝电子证书签发完成日期；考场名称＝活动渠道关联矩阵「测评×渠道」格 |
| sheet2 留痕 | Excel 第二个 sheet 记录本次导出条件、导出时间、导出行数与导出范围（合并 / 本文件所属考场） |
| 按考场拆分 | 勾选分开导出时每个考场各一份 Excel，文件名含考场名称 |
| 合并导出 | 一张总表覆盖全部筛选命中学员 |

### 3.3 学生照片压缩包（异步任务）

| 变更项 | 说明 |
|---|---|
| 任务形态 | 照片压缩包走异步任务：点击「开始导出」即创建任务，生成过程不阻塞页面 |
| 任务入口与进度 | 页面右上角「导出任务」入口（带进行中角标）→ 任务抽屉展示任务号、发起时间、导出条件快照、状态 |
| 文件分行 | 分开导出时一个任务挂 N 个考场文件，抽屉内按文件分行展示；每个文件生成成功后可单独下载 |
| 照片命名 | 每张照片命名＝证书编号＋学生姓名；zip 格式（与此前程宇提供的照片包一致） |
| 照片范围 | 仅含照片合格且有证书的学生；按考场分开时，无有证书学生的考场不产出该考场照片包 |
| 消息中心 | 消息中心仅留任务消息，下载统一走导出任务抽屉，避免消息中心过乱 |
| 失败与重试 | 任务失败时抽屉内展示失败原因并提供重试 |

补充说明：

- 导出设置弹窗内的筛选条件只读；分开导出按「筛选命中的考场」拆分，勾选多个考场即可一次产出多份
- Excel 与照片压缩包**全部走异步任务**，不存在同步下载；任务完成后文件按考场**分行展示**，每个文件导出成功后可**单独下载**
- 导出条件快照随任务留痕，任务抽屉与 Excel sheet2 均可回查本次导出条件
- 缺证书学生不计入「导出次数」（导出次数追踪沿用原需求口径，见附录备份）
- 字段清单与计数口径如与考务老师终版确认结果有差异，以终版为准更新本需求

### 3.4 口径说明

1. 特殊修改：身份证改名等特殊证书修改不提供后台入口，由技术团队直接修改数据库（线下流程）；常规信息修改走列表既有「修改信息」入口
2. 证书生成时机（源表 #32）：正式环境证书在证书流转第二环节「待复核」生成；成绩公示与推送把关由「20260921 待复核生成推送把关」承接
3. 导出白屏修复（源表 #28）：导出证书包点击下载白屏的存量 bug 随本需求一并修复

# 需求二：测评考场排序优化

### 1. 背景与收益

需求简介：测评管理、报名管理、渠道关联测评、关联新测评下拉四个展示面统一改为按创建时间倒序排列，最新创建在最上，修改配置不再引起顺序变动。

业务诉求与收益：各列表当前按修改时间排序，运营修改测评名称、考试时间、报名费等配置后顺序跳动，核对名单、复制链接、配置费用时找不到刚看过的那一行。排序稳定后，运营按固定顺序核对数据，跨日操作位置记忆一致，减少漏看错配。

### 2. 业务流程

1. 运营打开任一列表 → 按创建时间倒序展示（最新创建在最上）
2. 修改测评或关联的任意配置 → 顺序保持不变
3. 新建测评或新建渠道关联 → 插入列表最上

### 3. 详细功能说明

#### 3.1 涉及页面与排序对象

| # | 页面 | 排序对象 |
|---|---|---|
| 1 | 测评管理列表 | 测评行 |
| 2 | 报名管理（报名记录管理） | 报名记录行 |
| 3 | 渠道管理-关联测评管理（当前渠道视图） | 树内测评行（活动›分组›测评） |
| 4 | 关联新测评弹窗（选择测评下拉） | 下拉选项 |

#### 3.2 排序规则

| 规则项 | 内容 |
|---|---|
| 排序字段 | 创建时间（渠道关联场景=关联创建时间；测评/报名列表=各自创建时间） |
| 方向 | 倒序，最新创建在最上 |
| 修改不动序 | 修改名称、时间、费用、展示开关等配置均不触发重排；只有新建才入列（插最上） |
| 层级结构 | 组内测评行按创建时间倒序；活动行、分组行按其下最新测评的创建时间倒序 |
| 新建入列 | 新建关联写入当前时间，插入列表最上 |
| 展示 | 不新增「创建时间」列，仅调整顺序 |

#### 3.3 页面参考

HTML demo：03_测评列表.html、11_报名管理.html、02_渠道管理.html（文件块见下，点击可查看；03 与 11 为整列表倒序效果，02 打开渠道的「关联测评管理」看树形排序、打开「关联新测评」看下拉倒序）

# 需求三：复制测评 / 复制活动

## 1. 背景与收益

需求简介：管理后台补齐「复制测评」完整能力并新增「复制活动」，复制生成的对象完整保留试卷、监考设置与时间配置，运营搭新一期考试从逐项重配变为一键复制后微调。

业务诉求与收益：每期考试的试卷结构、监考设置、时间安排高度相似，运营新建测评要逐项重配一遍，活动下挂多个测评时工作量翻倍。复制能力把重复配置收敛为一次点击；预期单场新测评配置时间从逐项手工录入降为复核式微调，降低漏配错配。

## 2. 业务流程

1. 运营在 33 活动详情的测评行「…」菜单点「复制测评」→ 确认框提示「时间保持不变，渠道关联需重新配置」→ 确认后生成副本测评
2. 副本测评：名称为原名 +「-副本」，试卷（正式卷 + 模拟卷）、监考 8 项、更多设置、考试时间全部保留原值，插入原测评行之后
3. 运营在 32 活动管理的活动行点「复制」→ 生成副本活动：活动名与组内全部测评名加「-副本」，活动基本信息、分组结构、组内测评整棵保留，起止日期不变
4. 运营对新测评 / 新活动重新配置渠道关联（费用、人数由运营重新填写）

## 3. 详细功能说明

### 3.1 复制测评

| 变更项 | 说明 |
|---|---|
| 入口 | 33 活动详情测评行「…」菜单「复制测评」（强化既有演示项为完整功能） |
| 名称 | 原名称 +「-副本」 |
| 试卷 | 正式卷 + 模拟卷的试卷内容与设置完整复用 |
| 监考与设置 | 监考 8 项、更多设置原样保留 |
| 时间 | 考试时间保持原值不变，由运营复制后手动调整 |
| 插入位置 | 原测评行之后 |
| 确认框 | 点击后提示「时间不变、渠道关联需重新配置」，确认后执行 |
| 渠道关联 | 不随复制，新测评的渠道关联（费用/人数）由运营重新配置 |

### 3.2 复制活动

| 变更项 | 说明 |
|---|---|
| 入口 | 32 活动管理活动行「复制」按钮 |
| 名称 | 活动名 +「-副本」，组内全部测评名 +「-副本」 |
| 结构 | 活动基本信息、分组结构、组内测评整棵复制（每条测评按复制测评逻辑处理） |
| 起止日期 | 保持原起止日期不变 |
| 渠道关联 | 不随复制，links 清零，由运营重新配置 |

# 需求四：学员答卷数据导出

## 1. 背景与收益

需求简介：36 数据分析新增「学员明细 · 答卷数据」区块，逐学员一行展示环境检测、试卷状态、开考交卷时间与逐小题得分，支持按正式卷 / 模拟卷分别导出 xlsx。

业务诉求与收益：运营核对考试数据时需要逐学员的环境检测情况与得分明细，现有页面只有分阶段汇总统计，逐学员数据无处可看、无表可导。明细区块与导出能力把「汇总看趋势、明细查个人」补齐，家长或考点核对成绩时运营直接出表。

## 2. 业务流程

1. 运营进入 36 数据分析，选择场次的测评卡片 → 考中阶段起显示「学员明细 · 答卷数据」区块
2. 区块内「正式卷 / 模拟卷」两个 Tab 切换，各自独立数据与列结构
3. 表内逐学员一行：环境检测五类分列展示状态，试卷状态、开考时间、交卷时间、逐小题得分、总分依列排布
4. 点击「导出明细」→ 提示已创建异步导出任务，文件名带卷别，走消息中心下载

## 3. 详细功能说明

### 3.1 学员明细区块

| 变更项 | 说明 |
|---|---|
| 入口与可见时机 | 36 数据分析测评卡片内「学员明细 · 答卷数据」区块，考中阶段起显示，随阶段累积渲染 |
| Tab 结构 | 正式卷 / 模拟卷两个 Tab，各自独立数据与列结构 |

# 需求五：报名页修改信息触发审核

## 1. 背景与收益

需求简介：报名填写信息页新增审核触发规则：首次注册加首次报名提交即生效不审核；再次报名且修改了个人信息时，信息修改进入审核流，审核期间考试正常参加。

业务诉求与收益：报名环节的个人信息修改此前无审核拦截，关键信息（如姓名、证件）被随意改动后与证书、检录数据冲突。规则上线后信息变更受控，真实误填可经审核纠正，恶意或误操作改动不再直接生效。

## 2. 业务流程

1. 用户在小鹿 APP 注册并首次报名，填写信息提交 → 报名直接生效，不产生审核记录
2. 用户再次报名（任一测评），报名页修改个人信息 → 与学生档案现有值逐字段比对，有差异即触发审核
3. 提交后提示「报名已提交，信息修改进入审核」→ 审核记录进入用户信息审核页按既有形态流转（前后对比、独立生效）
4. 审核期间该次报名状态正常，用户按准考证参加考试
5. 再次报名未修改信息 → 沿用既有继承规则，直接继承历史审核结果，不进审核

## 3. 详细功能说明

### 3.1 审核触发规则

| 规则项 | 内容 |
|---|---|
| 首次注册 + 首次报名 | 提交即过，信息无需审核，报名直接生效 |
| 再次报名 + 未修改信息 | 无差异，沿用继承规则，不进审核 |
| 再次报名 + 修改信息 | 与学生档案现有值逐字段比对，有差异 = 修改，产生待审核记录，走信息审核流 |
| 审核范围 | 仅审信息修改，不拦考试 |
| 与审核页衔接 | 报名触发的审核记录在用户信息审核页按既有形态展示（前后对比、独立生效） |

HTML demo：09_测评报名_填写信息.html（表单顶部「首次注册+报名 / 再次报名·已修改信息」场景切换，两种提交结果弹窗；文件块见下，点击可查看）

# 附录：原需求一备份（证书与学生报告管理）

> 2026-11-03 起需求一升级为「证书导出印刷交付」，原证书查询与导出追踪需求内容备份于此，已交付能力维持现状继续生效。

## 1. 背景与收益

需求简介：管理后台「学生证书管理」补齐证书编号精确查询与导出追踪能力，运营据此核对纸质证书发放批次，并确认证书生成时机口径。

业务诉求与收益：纸质证书分批印制寄出后，运营无法回答「这份证书是否已导出制作过、何时导出、第几批寄出」，核对靠翻聊天记录；证书编号作为唯一凭证没有后台查询入口，家长报编号后运营只能按姓名手机号间接找。本需求把导出动作沉淀为可查记录，纸质发放核对在系统内闭环；预期消除导出台账手工维护，证书查询从「间接猜」变为「编号直达」。

## 2. 业务流程

运营在「学生证书管理」页：

1. 家长或合作方提供证书编号 → 筛选区输入编号精确查询 → 列表直接定位该学员
2. 导出证书包（既有能力，走消息中心下载）
3. 导出完成后，系统自动累计包内每个学员的导出次数，并写入导出记录
4. 印制寄出后，运营点开该学员的「导出记录与备注」弹窗，在备注里登记批次和时间（如「第2批 10-09 寄出」）
5. 下次核对时，列表直接看导出次数与备注摘要，点开弹窗看每次导出明细

## 3. 详细功能说明

### 3.1 证书编号精确搜索

| 变更项 | 说明 |
|---|---|
| 新增「证书编号」筛选 | 筛选区身份证号后新增输入框，占位文案「证书编号（精确搜索）」 |

### 3.4 口径说明（本需求不含开发）

1. 特殊修改：身份证改名等特殊证书修改不提供后台入口，由技术团队直接修改数据库（线下流程）；常规信息修改走列表既有「修改信息」；改库后的证书重生成按「20260816 重新生成证书」流程执行
2. 证书生成时机（源表 #32）：正式环境证书在证书流转第二环节「待复核」生成，生成后考务老师即可在后台复核证书信息；成绩公示与推送把关由「20260921 待复核生成推送把关」承接
3. 导出白屏修复（源表 #28）：学生证书管理导出白屏按缺陷直接修复，修复后导出能力（含证书编号、照片、身份证号、级别）即达成，不占本需求范围
