# 需求一：证书与学生报告管理

## 1. 背景与收益

需求简介：管理后台「学生证书管理」补齐证书编号精确查询与导出追踪能力，运营据此核对纸质证书发放批次，并确认证书生成时机口径。

业务诉求与收益：纸质证书分批印制寄出后，运营无法回答「这份证书是否已导出制作过、何时导出、第几批寄出」，核对靠翻聊天记录；证书编号作为唯一凭证没有后台查询入口，家长报编号后运营只能按姓名手机号间接找。本需求把导出动作沉淀为可查记录，纸质发放核对在系统内闭环；预期消除导出台账手工维护，证书查询从「间接猜」变为「编号直达」。

## 2. 业务流程

运营在「学生证书管理」页：

1. 家长或合作方提供证书编号 → 筛选区输入编号精确查询 → 列表直接定位该学员
2. 导出证书包（既有能力，走消息中心下载）
3. 导出完成后，系统自动累计包内每个学员的导出次数，并写入导出记录
4. 印制寄出后，运营点开该学员的「导出记录与备注」弹窗，在备注里登记批次和时间（如「第2批 10-09 寄出」）
5. 下次核对时，列表直接看导出次数与备注摘要，点开弹窗看每次导出明细

## 3. 详细功能说明

### 3.1 证书编号精确搜索

| 变更项 | 说明 |
|---|---|
| 新增「证书编号」筛选 | 筛选区身份证号后新增输入框，占位文案「证书编号（精确搜索）」 |
| 匹配方式 | 精确匹配（全值比对，编号唯一） |
| 触发方式 | 点击「查询数据」或在输入框内按回车 |
| 命中 | 列表只显示证书编号等于输入值的学员 |
| 无命中 | 列表清空，表格上方显示提示条「未找到证书编号为「XX」的记录（精确匹配）」 |
| 清除条件 | 清空输入后再次查询、或点击「重置」，恢复显示全部并清除提示条 |

明细见下：

- 证书编号为空的学员不参与编号匹配（输入任意编号均不命中）
- 编号查询与筛选区既有条件叠加生效

### 3.2 导出追踪（导出次数与备注）

| 变更项 | 说明 |
|---|---|
| 新增「导出次数」列 | 位置在「照片」列后；显示该学员证书被包含在导出包中的累计次数；点击打开导出记录弹窗 |
| 新增「备注」列 | 同排；显示备注摘要，超长截断显示省略号（悬停看全文）；点击打开导出记录弹窗；无备注显示「—」 |
| 导出次数计数口径 | 每次导出证书包，包内包含该学员即计 1 次；导出任务失败不计入 |
| 计数时机 | 导出任务生成成功（消息中心可下载）后自动累加，运营无需手工记录 |
| 备注用途 | 追踪纸质证书发放批次和时间；运营手工填写 |
| 备注编辑位置 | 详情弹窗内编辑，列表不提供内联编辑 |
| 导出表格同步 | 导出证书包内的名单表格新增「导出次数」「备注」两列，纸质发放核对在表内闭环 |

明细见下：

- 列表仅展示已获得证书的学员（源表 #31 口径维持现状）
- 备注属于证书记录维度，跟着学员证书记录走

### 3.3 导出记录与备注弹窗

| 项 | 说明 |
|---|---|
| 入口 | 点击列表「导出次数」数字或「备注」内容 |
| 头部信息 | 学员姓名 + 身份证号、证书编号、照片状态 |
| 导出记录表 | 列：导出任务号、导出时间、包内总行数、操作人；按导出时间倒序 |
| 空态 | 该学员从未被包含在导出包中时，记录表显示「暂无导出记录」 |
| 备注编辑 | 多行文本框，placeholder 示例「记录纸质证书发放批次和时间，如：第2批 10-09 寄出」 |
| 保存 | 点击「保存备注」后保存、关闭弹窗、列表备注列即时刷新、轻提示「备注已保存」 |
| 取消 | 点击「取消」、右上角关闭或遮罩层，关闭弹窗不保存 |

### 3.4 口径说明（本需求不含开发）

1. 特殊修改：身份证改名等特殊证书修改不提供后台入口，由技术团队直接修改数据库（线下流程）；常规信息修改走列表既有「修改信息」；改库后的证书重生成按「20260816 重新生成证书」流程执行
2. 证书生成时机（源表 #32）：正式环境证书在证书流转第二环节「待复核」生成，生成后考务老师即可在后台复核证书信息；成绩公示与推送把关由「20260921 待复核生成推送把关」承接
3. 导出白屏修复（源表 #28）：学生证书管理导出白屏按缺陷直接修复，修复后导出能力（含证书编号、照片、身份证号、级别）即达成，不占本需求范围

# 需求二：测评考场排序优化

### 1. 背景与收益

需求简介：测评管理、报名管理、渠道关联测评、关联新测评下拉四个展示面统一改为按创建时间倒序排列，最新创建在最上，修改配置不再引起顺序变动。

业务诉求与收益：各列表当前按修改时间排序，运营修改测评名称、考试时间、报名费等配置后顺序跳动，核对名单、复制链接、配置费用时找不到刚看过的那一行。排序稳定后，运营按固定顺序核对数据，跨日操作位置记忆一致，减少漏看错配。

### 2. 业务流程

1. 运营打开任一列表 → 按创建时间倒序展示（最新创建在最上）
2. 修改测评或关联的任意配置 → 顺序保持不变
3. 新建测评或新建渠道关联 → 插入列表最上

### 3. 详细功能说明

#### 3.1 涉及页面与排序对象

| # | 页面 | 排序对象 |
|---|---|---|
| 1 | 测评管理列表 | 测评行 |
| 2 | 报名管理（报名记录管理） | 报名记录行 |
| 3 | 渠道管理-关联测评管理（当前渠道视图） | 树内测评行（活动›分组›测评） |
| 4 | 关联新测评弹窗（选择测评下拉） | 下拉选项 |

#### 3.2 排序规则

| 规则项 | 内容 |
|---|---|
| 排序字段 | 创建时间（渠道关联场景=关联创建时间；测评/报名列表=各自创建时间） |
| 方向 | 倒序，最新创建在最上 |
| 修改不动序 | 修改名称、时间、费用、展示开关等配置均不触发重排；只有新建才入列（插最上） |
| 层级结构 | 组内测评行按创建时间倒序；活动行、分组行按其下最新测评的创建时间倒序 |
| 新建入列 | 新建关联写入当前时间，插入列表最上 |
| 展示 | 不新增「创建时间」列，仅调整顺序 |

#### 3.3 页面参考

HTML demo：03_测评列表.html、11_报名管理.html、02_渠道管理.html（文件块见下，点击可查看；03 与 11 为整列表倒序效果，02 打开渠道的「关联测评管理」看树形排序、打开「关联新测评」看下拉倒序）

# 需求三：复制测评 / 复制活动

## 1. 背景与收益

需求简介：管理后台补齐「复制测评」完整能力并新增「复制活动」，复制生成的对象完整保留试卷、监考设置与时间配置，运营搭新一期考试从逐项重配变为一键复制后微调。

业务诉求与收益：每期考试的试卷结构、监考设置、时间安排高度相似，运营新建测评要逐项重配一遍，活动下挂多个测评时工作量翻倍。复制能力把重复配置收敛为一次点击；预期单场新测评配置时间从逐项手工录入降为复核式微调，降低漏配错配。

## 2. 业务流程

1. 运营在 33 活动详情的测评行「…」菜单点「复制测评」→ 确认框提示「时间保持不变，渠道关联需重新配置」→ 确认后生成副本测评
2. 副本测评：名称为原名 +「-副本」，试卷（正式卷 + 模拟卷）、监考 8 项、更多设置、考试时间全部保留原值，插入原测评行之后
3. 运营在 32 活动管理的活动行点「复制」→ 生成副本活动：活动名与组内全部测评名加「-副本」，活动基本信息、分组结构、组内测评整棵保留，起止日期不变
4. 运营对新测评 / 新活动重新配置渠道关联（费用、人数由运营重新填写）

## 3. 详细功能说明

# 需求五：报名页修改信息触发审核

## 1. 背景与收益

需求简介：报名填写信息页新增审核触发规则：首次注册加首次报名提交即生效不审核；再次报名且修改了个人信息时，信息修改进入审核流，审核期间考试正常参加。

业务诉求与收益：报名环节的个人信息修改此前无审核拦截，关键信息（如姓名、证件）被随意改动后与证书、检录数据冲突。规则上线后信息变更受控，真实误填可经审核纠正，恶意或误操作改动不再直接生效。

## 2. 业务流程

1. 用户在小鹿 APP 注册并首次报名，填写信息提交 → 报名直接生效，不产生审核记录
2. 用户再次报名（任一测评），报名页修改个人信息 → 与学生档案现有值逐字段比对，有差异即触发审核
3. 提交后提示「报名已提交，信息修改进入审核」→ 审核记录进入用户信息审核页按既有形态流转（前后对比、独立生效）
4. 审核期间该次报名状态正常，用户按准考证参加考试
5. 再次报名未修改信息 → 沿用既有继承规则，直接继承历史审核结果，不进审核

## 3. 详细功能说明

### 3.1 审核触发规则

| 规则项 | 内容 |
|---|---|
| 首次注册 + 首次报名 | 提交即过，信息无需审核，报名直接生效 |
| 再次报名 + 未修改信息 | 无差异，沿用继承规则，不进审核 |
| 再次报名 + 修改信息 | 与学生档案现有值逐字段比对，有差异 = 修改，产生待审核记录，走信息审核流 |
| 审核范围 | 仅审信息修改，不拦考试 |
| 与审核页衔接 | 报名触发的审核记录在用户信息审核页按既有形态展示（前后对比、独立生效） |

### 3.2 页面参考

HTML demo：09_测评报名_填写信息.html（表单顶部「首次注册+报名 / 再次报名·已修改信息」场景切换，两种提交结果弹窗；文件块见下，点击可查看）

# 需求六：人才信息卡测评记录点击展示证书

## 1. 背景与收益

需求简介：人才信息卡「人工智能应用创新能力」模块的测评记录行改为可点击，点击直接弹出对应电子证书预览弹窗（证书图样 + 编号 / 等级 / 日期 / 状态）。

业务诉求与收益：人才卡上的考试测评记录此前是纯文字，用人方或运营想核对证书要跳转证书模块另查。点击即看证书后，人才能力的展示与凭证核验在一张卡上闭环。

## 2. 业务流程

1. 打开人才信息卡 →「人工智能应用创新能力」模块的测评记录行带可点击态（虚线下划线 + 箭头 + 悬停主色）
2. 点击测评记录行 → 弹出「电子证书预览」弹窗：证书图样（品牌 / 标题 / 等级徽章）+ 证书编号、发证日期、测评项目、证书状态
3. 关闭弹窗回到人才卡
4. 无对应证书的记录行（如第二组评定记录）保持普通文字态，不响应点击

## 3. 详细功能说明

# 需求七：考中状态查询

## 1. 背景与收益

需求简介：37 学员明细页新增姓名/手机号/准考证号统一搜索与所在考场列，学员行可直接跳转爱测评核实考场内实时状态；爱测评测评详情页筛选区新增手机号筛选，数据来自 AISE 同步。

业务诉求与收益：考中阶段接到用户反馈时，凭单一姓名、手机号或准考证号查用户答题状态的链路过长——先在学员信息/报名管理找到所在考场，再去爱测评搜考场、进考场搜用户，才能看到答题状态。搜索与考场列把「输入一个号 → 定位到人和考场」收敛为一步，行内跳转把「核实爱测评考场状态」收敛为一键，考务反馈处理从多页跨查变为单页直达。

## 2. 业务流程

1. 考中阶段接到用户反馈，运营进入 36 数据分析 → 37 学员明细（或从指标卡片带筛选进入）
2. 在搜索框输入姓名 / 手机号 / 准考证号任一字段，列表即时过滤定位到学员
3. 从「所在考场」列读取该学员的考场（测评 × 渠道格）与考试时间
4. 点击行内「查看爱测评状态」→ 携带登录态跳转爱测评对应测评详情页，自动按该学员筛选定位，确认考场内实时答题状态

## 3. 详细功能说明

### 3.1 学员明细搜索与列表增强

| 变更项 | 说明 |
|---|---|
| 搜索框 | 37 学员明细筛选区首位新增搜索框，占位文案「姓名 / 手机号 / 准考证号」；单框对三个字段做模糊匹配（准考证号支持精确），输入即时过滤，无需点击查询按钮 |
| 手机号列 | 列表新增「手机号」列，取学员登录手机号（与报名管理「登录手机号」同源） |
| 准考证号列 | 列表新增「准考证号」列，展示格式与报名管理准考证弹窗一致；该列同时是跳爱测评核实的入口链接 |
| 所在考场列 | 列表新增「所在考场」列，考场=测评×渠道关联格（与需求三/调整考场同口径），两行展示：第一行「渠道 · 测评」，第二行格配置的考试时间 |
| 列宽约束 | 新增后共 12 列，全部列设固定宽度，单元格单行不换行，容器内横向滚动，不允许列挤压错位 |
| 统计条 | 搜索命中时统计条展示命中关键词，命中人数与状态分布随搜索结果联动 |

### 3.2 跳转爱测评核实

| 变更项 | 说明 |
|---|---|
| 入口 | 每行操作列「查看爱测评状态」按钮，不依赖先搜索，任意行可用 |
| 跳转链路 | 携带登录态免登跳转爱测评 → 该学员所在测评的测评详情页，自动按该学员姓名/手机号填入筛选并定位到对应学员行（免登票据单次有效、短时效） |
| 定位参数 | 携带测评、渠道（考场格）、学员手机号三项；准考证号不传爱测评（爱测评侧无准考证数据） |
| 异常处理 | 学员未进入过爱测评考场时，爱测评测评详情无该学员记录，页面展示空结果即可，不做额外提示；跳转失败时轻提示「跳转失败，请重试」 |

### 3.3 爱测评测评详情手机号筛选

| 变更项 | 说明 |
|---|---|
| 筛选字段 | 爱测评管理端测评详情页筛选区，在「学生姓名」后新增「手机号」输入框，与摄像头状态、录屏监控状态筛选并列，「查询」按钮统一触发 |
| 数据来源 | 手机号为 AISE 学员登录手机号，随 AISE 组织用户数据同步到爱测评；同步时机与链路由研发评估，业务只约定「手机号筛选可用，数据与 AISE 一致」 |
| 匹配规则 | 手机号精确匹配；与姓名筛选可组合（同时填写时取交集） |
| 批改数据页 | 批改数据页保持按批改任务进入，不加学员筛选；学员定位统一由测评详情页承担 |
