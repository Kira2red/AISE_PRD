## 1. 背景与目标

**一句话**：AISE 已登录用户，通过官网 banner 的人才库链接一键授权登录人才库；人才库按证件号自动「有则登录、无则建档」，免除重复注册与重复填表。

**现状依据**（出处：[AISE人才库_PRD.md](<../20260615 人才库/AISE人才库_PRD.md>)）：

- 人才库与 AISE 是**两套独立用户体系**，仅在注册时以用户填写的证件号做一次性匹配（§4）。
- 人才库独立注册（§5.2）需填姓名/证件类型/证件号/手机号/验证码/密码；独立登录（§5.3）为「证件号 + 密码（默认证件号后 6 位）+ 图形验证码」。
- AISE 侧登录为「手机号 + 验证码」（出处：[AISE&爱测评平台能力梳理.md](<../../Functional_Specs/AISE&爱测评平台能力梳理.md>) 01_登录注册）；证件号是挂在「考生身份」下的字段，一个账号可关联多个考生（10_选择考生身份：本人 / 代报名）。

**结论**：本需求是把人才库从「独立账号 + 注册后证件号匹配」改为「AISE 授权登录 + 首次自动建档」，属账号体系的方向性变更，而非增量功能。

---

## 2. 用户故事与旅程

**用户故事**（价值依据：D 级，用户需求原话）：

> 作为已在 AISE 报名考试的考生，我登录 AISE 后点一下官网的人才库链接，就能直接进入人才库、看到我的人才卡，而不是再注册一遍、再填一遍姓名/证件号/手机号。

**旅程**：

1. 用户在 AISE 官网（已登录）点击 banner 人才库链接；或直接在人才库登录页点「AISE 登录」按钮。
2. 系统判断用户是否已在 AISE 登录：未登录 → 引导先登录 AISE，登录后回跳继续。
3. 弹授权窗，列明将提供哪些个人信息，用户单独同意。
4. 人才库按证件号查询：有账号 → 直接登录；无账号 → 用授权字段自动建档。
5. 进入人才卡页。

## 4. 核心流程

```
AISE 已登录（或先登录）
  → 进入人才库入口（banner / 登录页「AISE 登录」按钮）
  → 授权弹窗（列明 6 字段 + 用途，单独同意）
  → 人才库按证件号查询
      ├─ 命中 → 直接登录
      └─ 未命中 → 自动建档（默认密码 = 证件号后 6 位）→ 登录
  → 进入人才卡页
```

**用户已拍板的关键决策（本次直接采纳，不再征询）**：

- 授权字段：姓名、证件号、证件类型、手机号、邮箱、性别（6 个）。
- 默认密码：证件号后 6 位。
- 保留独立登录入口，新增「AISE 登录」。
- 人才库链接 = banner 位配置的固定链接，本质是「带登录态访问人才库」。
- AISE 与人才库为不同域名。
- 跨域登录的技术实现（OAuth 等）由研发自评，业务侧不写死。
- 账号合并：本期不做，延后。

## 5. 边界与异常场景（穷举）

| # | 场景 | 处理方向 |
|---|------|---------|
| 1 | AISE 未登录点 banner | 引导先登录 AISE，回跳继续 |
| 2 | AISE 登录态过期 | 按未登录处理，重新登录 |
| 3 | 一个 AISE 账号下多个考生身份 | 见待确认 Q1（授权粒度） |
| 4 | 证件号在人才库已有账号（老用户手动注册） | 见待确认 Q3（撞号处理） |
| 5 | 授权字段缺失（如邮箱选填为空） | 见待确认 Q5 |
| 6 | 证件号为空 / 格式异常 | 阻断，提示重新授权或走独立注册 |
| 7 | 用户点「拒绝」授权 | 不取任何字段、不登录，返回原页 |
| 8 | 授权后再次进入人才库 | 见待确认 Q2（是否记住授权） |
| 9 | 用户撤回授权 | 见待确认 Q6 |
| 10 | banner 未配置 / 已下线 | 不影响独立登录/注册，仅失去一键入口 |

## 7. 风险与依赖

- **前置依赖**：AISE 侧需提供授权能力（登录态识别 + 授权字段出参），跨域实现由研发自评；AISE 侧是否已有 OAuth 能力，PRD 层面查无痕迹，以研发确认为准。
- **账号数据质量**：AISE 账号下证件号的完整性/唯一性待研发确认。
- **合规风险**：证件号为敏感个人信息，授权必须单独同意、明示用途。
- **老用户衔接**：存量人才库账号与授权账号的关系，本期仅「有则登录」，不合并（已拍板）。

## 待确认清单（逐项等你拍板）

> 以下点上一版 Agent 曾自行设定默认口径，本次**全部重新交回给你**，我不替你决定。每项附我的倾向性建议（供参考，非结论）。

**Q1 授权粒度：账号级 or 考生级？**（最关键，决定流程结构）
AISE 账号 = 手机号，证件号挂在「考生身份」下，一个账号可能关联多个考生（含代报名）。授权时用谁的证件号？
- 建议 A：**考生级**——授权前先让用户选「用哪个考生身份」，每个考生分别授权、分别对应人才库档案（贴合"用这个账号的证件号登录"的语义，也符合代报名场景）。
- 建议 B：账号级——整个账号授一次权，默认取主考生，忽略多考生场景（实现最简单，但代报名用户会错乱）。

**Q2 授权后再次进入，是否「记住授权」静默登录？**
- 建议：首次授权时提供「记住授权」勾选，勾选后下次点 banner 静默登录；不勾则每次弹窗。这才能兑现你说的「AISE 已登录时自动登录」体验（否则每次都要点一次同意）。

**Q3 证件号在人才库已有账号（老用户手动注册过），怎么处理？**
- 建议：**有则直接登录、不合并、不迁移**（符合"账号合并以后再说"）；若该已有账号 AISE 关联状态是「未关联」，授权后是否翻转为「已关联 AISE」——这点你定。

**Q4 桥接键口径：证件号单键，还是「证件类型 + 证件号」组合键？**
- 现状：人才库注册表单有「证件类型」字段（§5.2.1），但现行 PRD 以「证件号」作唯一标识。
- 建议：组合键更严谨（不同证件类型号码理论可能重复），但会改动现行「以证件号为唯一标识」的口径。你倾向哪个？

**Q5 授权字段缺失兜底**（如 AISE 侧无邮箱/某字段为空）：
- 建议：以已有字段建档，缺失字段留空，不阻断登录。

**Q6 撤回授权入口放哪？**
- 建议：人才库个人设置 / AISE 个人中心 / 两者都放——你定；撤回后仅停用一键登录，账号与档案保留（撤回 ≠ 注销）。

**Q7 收益口径确认**：
- 本需求收益目前无数据支撑，我按「待埋点验证的假设」处理、不做量化承诺，上线后以埋点数据为准。是否接受？
