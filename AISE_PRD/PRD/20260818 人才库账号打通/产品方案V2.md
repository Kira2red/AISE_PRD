## 1. 背景与目标

AISE 已登录用户，通过官网 banner 人才库链接（或人才库登录页「AISE 登录」按钮）一键授权登录人才库；人才库按「证件类型+证件号」查询，无账号则自动建档，免除重复注册与重复填表。已有账号的老用户仍走独立登录，授权不覆盖、不合并。

现状依据：[AISE人才库_PRD.md](<../20260615 人才库/AISE人才库_PRD.md>)（两套独立用户体系 §4、独立注册 §5.2、独立登录 §5.3）、[AISE&爱测评平台能力梳理.md](<../../Functional_Specs/AISE&爱测评平台能力梳理.md>)（AISE 手机号+验证码登录、多考生选身份、Banner 链接配置）。

## 2. 用户故事与旅程

**用户故事**（价值依据 D 级，用户需求原话）：已在 AISE 报名的考生，登录 AISE 后点一下人才库链接即可进入人才库看到人才卡，免重复注册、重复填表。

**旅程**：

1. AISE 已登录用户点 banner 人才库链接（未登录先引导登录 AISE 回跳）；或人才库登录页点「AISE 登录」。
2. 若该 AISE 账号下有多个考生身份 → 先选身份（考生级授权）。
3. 该考生首次授权 → 弹授权窗列明 6 字段+用途，单独同意；已授权过 → 静默登录。
4. 人才库按「证件类型+证件号」查询：无 → 自动建档并登录；有 → 授权失败，提示用人才库账号登录。
5. 进入人才卡页。

## 4. 核心流程

```
AISE 已登录（未登录→先登录回跳）
  → 进入入口（banner / 登录页「AISE 登录」）
  → 多考生？→ 选考生身份
  → 该考生已授权过？→ 静默登录（跳过弹窗）
  → 否则：授权弹窗（6 字段 + 单独同意）→ 同意
  → 人才库按「证件类型+证件号」查询
      ├─ 无账号 → 自动建档（默认密码=证件号后6位）→ 登录 → 人才卡
      └─ 有账号 → 授权失败，提示「用人才库账号直接登录」
```

## 5. 边界与异常场景

| # | 场景 | 处理 |
|---|------|------|
| 1 | AISE 未登录点 banner | 引导先登录 AISE，回跳继续 |
| 2 | AISE 登录态过期 | 按未登录处理 |
| 3 | 一个 AISE 账号多个考生 | 先选考生身份（D1） |
| 4 | 证件号在人才库已有账号 | 授权失败，提示用人才库账号登录（D3） |
| 5 | 授权字段缺失 | 不传，留空（D5） |
| 6 | 证件号为空/格式异常 | 阻断，提示重新授权或走独立注册 |
| 7 | 用户点「拒绝」 | 不取字段、不登录，返回原页 |
| 8 | 已授权考生再次进入 | 静默登录（D2） |
| 9 | banner 未配置/下线 | 不影响独立登录，仅失去一键入口 |

（撤回授权、账号合并、收益指标均不在本期范围，见 D6/D7 + 账号合并延后。）

---

## 6. 风险与依赖

- 前置依赖：AISE 侧授权能力（登录态识别 + 授权字段出参），跨域实现研发自评。
- 账号数据质量：AISE 账号下证件号完整性/唯一性待研发确认。
- 合规：证件号为敏感个人信息，授权单独同意、明示用途。
- 老用户衔接：存量账号与授权账号仅「撞号即失败」分流，不合并。
