# 渠道分组与报名活动卡片 — 方案概要（V1）

> 日期：2026-08-26 | 作者：产品大师（阶段一：产品方案，待确认后进入 demo）

## 1. 背景与目标

多考场需求（20260708）试图在一个测评活动内嵌套多个考场（时间段、容量、标签独立配置），对测评活动模型、爱测评考试创建链路改动过大，被判定为不可行。

本需求改为在渠道维度做轻量分组：运营在渠道管理里给活动分组，用户报名时按「渠道 → 分组 → 活动卡片」选择活动。用「一个渠道下的多个活动 + 分组」替代「一个活动 + 多个考场」，实现同样的「多时间段报名」业务效果，但不改动测评活动模型，复用现有渠道管理和报名页联动逻辑。

一句话：渠道内加分组、活动挂分组；报名时活动从下拉框改为卡片展示选择。

## 2. 用户故事与旅程

### 2.1 运营侧

- 作为运营，我希望在渠道管理里把已关联的活动分到不同分组（如按考期分组），让用户端报名页结构清晰。（价值依据 D：用户反馈——多考场方案被否，本方案为其替代）
- 作为运营，我希望新建活动、调整活动分组、调整分组排序都在关联活动管理弹窗内完成，不新增独立页面。（依据 D）

### 2.2 用户侧

- 作为考生，我选择渠道后先看到分组（如「3月批」「6月批」），选完分组后看到该分组下的活动卡片（名称、起止时间等重要信息），而不是一长串下拉选项。（依据 D + C：多考场考场卡片样式）
- 作为考生，我希望不可报名的活动（未开始报名、已结束）在卡片上明确置灰，不会点错。（依据 C）

| # | 功能 | 优先级 | 端 | 价值依据 |

## 4. 核心流程

### 4.1 运营配置流程

渠道管理 → 某渠道「关联活动管理」弹窗 → 分组管理（新建分组、调整顺序）→ 关联新测评时指定所属分组（或对已关联活动改分组）→ 保存生效。

### 4.2 用户报名流程

进入报名 → 选机构（渠道）→ 该渠道设置了分组则出现「分组」下拉 → 选分组 → 该分组下活动以卡片列表展示 → 点选活动卡片 → 确认信息 → 支付。

无分组渠道：选机构后直接展示该渠道全部可报名活动卡片，不出现分组下拉。

## 5. 界面设计要点

### 5.1 渠道管理 — 关联活动管理弹窗（改造 admin/02）

- 弹窗内新增分组维度：顶部「分组管理」入口（新建/重命名/删除/排序）＋ 分组筛选；
- 活动表格新增「分组」列；
- 「关联新测评」弹窗新增「所属分组」下拉（渠道已有分组时可选，未建分组时可留空/当场新建，见待确认 2）。

### 5.2 报名页（改造 user/08，仅常规报名流程，不涉及定制报名）

- 步骤 2 中，原「测评项目」下拉框移除，替换为：
  - 渠道有分组：渠道下拉 → 分组下拉 → 活动卡片区；
  - 渠道无分组：渠道下拉 → 活动卡片区（直接平铺）。
- 活动卡片样式参考多考场 PRD 的考场选择卡片：圆角卡片（rounded-xl、border-2）、hover 蓝框阴影、选中态蓝框浅蓝底、右上角状态标签（可选/已选/未开始/已结束）。
- 卡片字段：活动名称（加粗）、考试起止时间、报名费（该渠道配置价）、报名状态标签。
- 选中活动后底部显示「已选择：{活动名称}（{考试日期}）」，下一步激活，进入确认信息步骤；确认页展示所选活动（沿用现有 view-project 字段）。
- 渠道识别码（扫码/链接锁定渠道）逻辑保持不变：锁定渠道后照常联动分组下拉。

## 6. 边界与异常场景

| 场景 | 处理 |
|------|------|
| 渠道未设置任何分组 | 不显示分组下拉，直接展示该渠道全部可展示活动卡片 |
| 渠道有分组，但存在未分组的活动 | 待确认 3：隐藏 或 归入「其他」分组展示 |
| 分组下无活动 | 卡片区显示空状态「该分组暂无可报名活动」 |
| 活动未到/已过「前端展示时间」 | 不展示（沿用关联活动弹窗展示时间逻辑） |
| 活动考试已结束 | 卡片置灰显示「已结束」，不可点 |
| 切换分组 | 卡片列表刷新，已选活动清空，下一步按钮禁用 |
| 重新选择渠道 | 分组下拉、卡片列表、已选活动全部重置 |
| 活动被移入/移出分组 | 用户端下次进入报名页生效 |
| 删除分组 | 分组内有活动时禁止删除，需先移出活动（见待确认 2） |
| 无活动可选（该渠道下无任何可展示活动） | 空状态提示，下一步禁用 |

## 7. 成功度量

- 不做量化业务指标（报名转化等受活动本身影响，无依据不设指标）。
- 交互验收标准：报名流程步骤数不增加；活动信息（名称/时间/费用/状态）在报名页可视；运营配置分组全程不离开渠道管理页面。
- 待验证（假设值）：一个含 10+ 活动的渠道，运营完成分组配置耗时 ≤ 5 分钟。

## 8. 风险与依赖

- 依赖渠道管理已有「关联活动管理」能力（已存在，无需新建）。
- 依赖报名页渠道→活动联动逻辑（已存在）。
- **多考场去留**：本需求替代多考场方案，demo 中已实现的多考场「选择考场」步骤与测评活动详情的多考场模式是否回退，待确认 4。
- 活动卡片所需数据（考试时间、渠道报名费、展示开关）在现有数据模型中均已存在，无新数据依赖。

## 9. 待确认清单

1. **活动与分组关系**：一个活动只能属于一个分组？（建议：一对一，最简单，可满足多时间段场景）
2. **分组管理 UI 形态**：全部在「关联活动管理」弹窗内完成（建议）？分组删除的规则：有活动禁止删除？
3. **未分组活动的处理**：渠道有分组时，未分配分组的活动隐藏？还是归入「其他」分组展示？
4. **多考场去留**：本需求上线后，demo 已实现的多考场报名步骤（user/08 选择考场、测评活动详情多考场模式）是否回退删除？（建议：回退，本需求为替代方案）
5. **卡片字段**：活动名称 + 考试起止时间 + 报名费 + 报名状态，是否足够？是否需要展示剩余名额（活动目前无容量概念，建议不展示）？
6. **卡片排序**：分组内活动按考试开始时间排序？（建议：按考试开始时间升序）
7. **分组下拉顺序**：按后台配置顺序（运营可调排序）？（建议：后台配置顺序）
8. **报名状态判定口径**：卡片「未开始/报名中/已结束」按活动考试时间判断，还是按关联活动弹窗的「前端展示时间」判断？（建议：展示时间控制是否出现，考试时间控制是否可报名）
