## 3. 新增功能设计要点

### 3.1 筛选扩展（16 号页筛选区）

| 筛选项 | 形态 | 说明 |
|---|---|---|
| 活动 | 下拉单选 | 选中后分组联动过滤 |
| 分组 | 下拉单选 | 选项取活动-分组体系，随活动联动 |
| 照片状态 | 下拉 | 合格、不合格、待审核、未提交；数据=该学生报名照片的当前审核状态（只读引用报名数据） |
| 证书编号 | 输入框 | 精确匹配（拍板点 2） |

- 与现有条件（姓名、手机、身份证、渠道、实体证书状态、电子证书状态、结果、分数范围、模块、级别）并行生效
- 「结果」条件语义确认为测评结果（合格、不合格），页面文案同步改

### 3.2 导出追踪字段（16 号页列表）

| 项 | 设计 |
|---|---|
| 导出次数 | 系统自动累计；口径=每次导出证书包，包内含该学员即计 1 次（拍板点 3 确认） |
| 备注标记 | 文本字段，运营手填；用途=纸质证书发放批次和时间；编辑入口在详情弹窗内（拍板点 4） |
| 列表展示 | 新增「导出次数」（只读列）、「备注」（列内展示+编辑入口）两列 |
| 导出联动 | 导出表格新增「导出次数」「备注」两列，纸质发放核对在表内闭环查看 |

### 3.3 口径说明（不开发）

1. 特殊修改：身份证改名等特殊证书修改不提供后台入口，由技术团队直接修改数据库（线下流程）；常规修改走既有「修改信息」；改库后的证书重生成走 20260816 证书重新生成链路
2. 待复核生成：源表 #32 的诉求（后台生成与学生端查询时间区分开、考务老师先复核）由 20260921 待复核生成推送把关承接，本需求不含开发；正式环境证书生成时间点=证书流转第二环节「待复核」，考务老师此时即可在后台复核证书信息
3. 导出白屏（源表 #28 标 bug）：直接修复不走立项，测试环境先复现；修复后导出能力即源表 #28 全量达成
