AISE 考试平台会开放三种考试能力：
1.在 AISE 平台的网页端直接测评
2.AISE 开放 api，由合作方在自己的平台嵌入考试能力，对应的管理功能在 AISE-组织后台模块。
3.合作方自己组织内部测评（现在叫预备测），不用 AISE 的测评能力，但是可以把部分测评结果返回给AISE

另外还有个爱测评平台，是个基于学校部署的考试平台，其中考试相关的能力被我摘出来复用到 AISE 了，AISE 是 C 端和 B 端用户自主报名、接入的平台，考试、试卷管理等功能都是复用爱测评的，对于爱测评来说，AISE平台就是一个特殊的学校组织。

现在要做一件事，要做个证书生成的功能，然后单独做一个签发平台，签发平台是我们实现，给软协用。

一些讨论内容：
用户端：
- 正式测：AISE 测评 / API 测评
- 预备测：合作方测评返回数据


管理平台：
- 【新增】证书模板：配置一份证书样式
- 【新增】证书实例：根据证书样式，生成一份证书，并跟具体的测评关联
- 【新增】用户证书查看：查看已经生成的证书、签发过程等等

签发中心【新增】
- 【新增】签发证书：所有已生成的证书+签发状态，管理所有测评的签发状态启动/停止
比如同时几场测评都在出证书，签发中心那儿就是一个大的 list，所有的证书混在一起，如果停就全停了。

1. 开发者调用证书申请 API

2. 开放平台创建申请记录
   状态：pending_issue / 待签发

3. 开放平台生成证书 PDF

   - 姓名
   - 测评名称
   - 成绩
   - 等级
   - 证书编号
   - 签发日期

4. 开放平台调用第三方电子签章 API
   提交：
   - PDF 文件
   - 电子章 ID
   - 签章位置

6. 成功：
   开放平台状态改为 issued
   保存证书编号、PDF 地址、验签地址

7. 失败：
   开放平台状态改为 issue_failed
   保存失败原因

8. 开放平台把结果返回开发者

## 阶段性讨论结论（2026-05-12）

### 一、产品架构（修正）

#### 核心模型关系

```
证书模板 ──1:N──> 证书实例 ──1:N──> 用户证书
(样式)          (测评配置)        (个人证书)
```

| 对象 | 职责 | 关联 |
|---|---|---|
| 证书模板 | 纯样式层：背景、布局、字体、字段占位符、电子章位置 | 无业务关联 |
| 证书实例 | 一次测评的证书配置：绑定某场测评 + 选用哪个模板 + 定义数据字段从哪取 | 关联一场测评（1:1） |
| 用户证书 | 某用户在某证书实例下生成的具体证书，含个人信息、PDF 地址、签发状态 | 关联用户 + 证书实例 |

**签发对象是用户证书**，不是证书实例。

#### 三种测评类型的数据来源差异

| 测评类型 | 考试数据位置 | 数据获取方式 |
|---|---|---|
| AISE 网页测评 | AISE 平台内 | 直接查 AISE 考试记录 |
| API 嵌入测评 | AISE 平台内（合作方调 API，数据落 AISE） | 直接查 AISE 考试记录 |
| 预备测（外部测评） | 合作方自己系统，仅结果 JSON 回传 AISE | 解析 JSON 结构取字段 |

网页测评和 API 测评的数据来源是同一套（都在 AISE 的考试库里），统一处理。预备测是独立的，走 JSON 解析路径。

#### 签发中心定位

面向所有**用户证书**，不区分测评类型和来源：
- 查看全部用户证书的签发状态
- 控制签发流程的启停（全局 / 按考试维度）
- 不关心数据从哪来，只看签发流水线

### 二、字段映射规则

#### 三层数据流

```
预备测 JSON → 解析引擎（内置映射表）→ 证书字段
                              ↘ 未识别字段列表 → 人工补配
```

#### 证书模板声明所需字段

| 模板字段标识 | 字段含义 | 来源 |
|---|---|---|
| `name` | 姓名 | 数据源映射 |
| `exam_title` | 测评名称 | 数据源映射 |
| `total_score` | 总成绩 | 数据源映射 |
| `grade` | 等级 | 数据源映射 |
| `cert_no` | 证书编号 | 系统自动生成 |
| `issue_date` | 签发日期 | 系统自动生成 |

#### 内置映射表（系统维护）

系统预置 JSON 路径 → 模板字段的映射规则：

```json
{
  "userName": "name",
  "examName": "exam_title",
  "totalScore": "total_score",
  "gradeLevel": "grade"
}
```

解析时按映射表自动匹配。

#### 未识别字段处理

JSON 解析后分离已识别和未识别字段：

- **已识别**：自动映射成功，直接使用
- **未识别**：JSON 中存在但映射表不认识的字段，暴露出来供用户手动操作：
  - 手动关联到模板的某个字段
  - 标记为"忽略，不用于证书"

#### 复合字段处理（如 userSkills）

数组/对象类型字段提供两种解析模式，在证书实例配置中选择：

- **平铺模式**：按 key 拆成独立字段，如 `能力-认知层: 9.75`
- **计算模式**：聚合计算，如取平均分 / 最高分 / 加权总分

#### 映射持久化

用户手动关联的映射关系保存到**证书实例**级别，同场测评重新解析时直接用已保存的映射，无需重复配置。

### 三、证书模板可视化编辑器

#### 交互布局

```
┌──────────────────────────────────────────────────────┐
│  编辑区                                │  属性面板    │
│  ┌──────────────────────────────┐     │             │
│  │                              │     │ 元素类型    │
│  │       (底图背景)              │     │ 绑定字段    │
│  │                              │     │ 字体/字号   │
│  │    ┌──────────┐              │     │ 颜色/对齐   │
│  │    │  张三     │ ← 拖拽文本   │     │ X/Y坐标    │
│  │    └──────────┘              │     │ 宽/高       │
│  │       ┌───┐                  │     │             │
│  │       │章 │  ← 电子章占位    │     │             │
│  │       └───┘                  │     │             │
│  └──────────────────────────────┘     │             │
│  可用字段列表：[姓名][成绩][等级]...   │             │
└──────────────────────────────────────────────────────┘
```

操作流：上传底图 → 从字段列表拖入文案到画布 → 调整位置/样式 → 预览 → 保存模板。

#### 模板存储结构

```json
{
  "background": "图片URL",
  "canvasSize": { "width": 297, "height": 210, "unit": "mm" },
  "elements": [
    {
      "type": "text",
      "fieldKey": "name",
      "position": { "x": 50, "y": 100 },
      "style": {
        "fontFamily": "SimSun",
        "fontSize": 14,
        "color": "#000000",
        "bold": false,
        "italic": false,
        "align": "center",
        "maxWidth": 120,
        "lineHeight": 1.5
      }
    },
    {
      "type": "seal",
      "position": { "x": 200, "y": 180 },
      "size": { "width": 80, "height": 80 }
    }
  ]
}
```

#### 关键设计点

1. **拖入行为**：从字段列表拖入字段时自动创建文本元素，默认显示 `{{姓名}}` 占位文案。未放置完所有字段时工具栏提示"还有 X 个字段未放置"。

2. **预览模式**：支持填入示例数据，所有占位符替换为真实值，直观查看最终效果，验证长文本折行/截断。

3. **物理尺寸坐标**：画布坐标使用物理尺寸（毫米），不能是屏幕像素。编辑器内置 A4 / 横版 / 竖版等常见画布规格，底图等比缩放铺满。

4. **辅助对齐**：参考线 + 吸附对齐（中心线自动吸附、元素间对齐）。

5. **电子章**：固定尺寸占位区域，签发时第三方签章 API 按此位置盖章。占位元素可锁定不可拖动。

### 四、其他设计决策

#### 签发中心启停粒度

- 保留全局开关（紧急熔断）
- 暂时不支持按考试维度的签发暂停

#### 模板渲染方案

采用 HTML 模板 + Puppeteer/无头浏览器方案，灵活性高，运营可自行配置样式。

#### 异步签发流程

- 消息队列消费（每张用户证书一条任务）
- 失败重试机制（指数退避 + 次数上限）
- 签发状态回调/Webhook 通知开发者

#### 预备测数据存储

- 公共字段（姓名、成绩、等级、证书编号）走结构化列
- 扩展数据走 JSONB 列（evaluation_data）
- 接口预留 evaluation_data 扩展节点
