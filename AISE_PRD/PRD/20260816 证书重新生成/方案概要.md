# 方案概要 — 证书重新生成

## 一、需求概述

运营调整证书模板后，能在后台自助把历史证书按新模板重新生成，不再找技术手动处理。入口放证书实例管理页，按测评粒度批量重出已签发和失败的证书。

## 二、改动点

### 改动 1：28_证书实例管理 — 新增「重新生成」操作

**按钮显示条件**：实例已绑定模板，且已签发数 > 0 或存在失败记录。未绑定模板的实例不显示（重生成必然失败）。已禁用实例仍可重生成（禁用语义是"不再生成新证书"，不影响已有证书）。

**确认弹窗内容**：
- 本次将重新生成的数量：已签发 N 张 + 失败 M 张，合计共 N+M 张
- 明确告知：证书编号不变、签发日期保留原日期、原 PDF 将被覆盖
- 绑定模板为禁用态时，追加警告「绑定模板已禁用，仍将按该模板重新生成」
- 当前签发中心全局开关为关闭时，明示「当前签发已暂停，任务提交后将排队，恢复签发后自动执行」
- 确认按钮为警示色

**重新生成规则**：
- 重跑范围 = 提交时点状态为「已签发」或「签发失败」的证书。排除「待签发」（本来就会用当前模板）和「签发中」（避免与原有任务并发双签章）
- 任务提交时对模板做快照，整批证书用同一快照版本渲染，避免任务执行期间模板又被改导致同批两种样式
- 按快照模板重新渲染 PDF + 重新签章，成功后覆盖原 PDF
- 证书编号不变；签发日期字段保留原日期；签章平台记录的签章时间为重新生成时间，两者不对齐（对外口径：证书上日期为准）
- 验签地址更新指向新 PDF

**状态呈现（关键设计）**：
- 重新生成期间，对外可见状态保持「已签发」不变（旧 PDF 继续可访问），16_学生证书管理、user 端 19/20 页不出现「签发中」回退——避免用户误以为证书失效
- 「更新中」仅作为内部任务状态在 admin 端可见：28 页该实例行内显示更新中标记
- 新 PDF 替换成功后才更新状态；失败则旧 PDF 保留

**结果反馈与防重**：
- 确认后按钮立即置灰（防连点），有进行中任务时不可再次提交
- 任务完成后，实例行内显示上次结果：成功 N / 失败 M，失败可查看原因
- 二次重跑会对全部已签发证书重新签章，弹窗中说明此影响；「仅重跑上次失败」本期不做，保持范围克制

### 改动 2：26_证书模板管理 — 新增使用情况提示

- 模板卡片信息区新增提示行：显示该模板被多少个实例使用（口径 = 所有绑定该模板的实例，含已禁用）
- 已被实例使用的模板，卡片上增加引导文案「调整模板不影响已签发证书，需重新生成请前往证书实例管理」

### 不改动的地方

- 签发中心仪表盘：重新生成的证书走现有签发管道，仪表盘自然可见「签发中→已签发/失败」。单条重签、批量重签失败能力保留
- 19_消息中心：本期不接入，重新生成结果仅在 28 页查看
- 16_学生证书管理、user 端 19/20 页：不改动，状态自动保持「已签发」直到替换成功

## 三、与现有系统的边界

- 同一证书同时只允许一个重签任务（与签发中心的重签互斥校验），避免双签章
- 设计原则更新说明：admin 端现在可发起批量重跑并感知「更新中」状态；签发中心仍是签发的详细状态管理中心，单条重签/批量重签失败职责不变

## 四、已定案决策

**全局签发开关关闭时（用户已拍板，方案 b）**：按钮可点，任务可提交，提交后排队，恢复签发后自动执行。确认弹窗中明示当前暂停状态。

## 五、涉及页面清单

| 页面 | 类型 | 改动内容 |
|---|---|---|
| 28_证书实例管理 | 修改 | 操作列加「重新生成」按钮 + 确认弹窗 + 行内结果提示 |
| 26_证书模板管理 | 修改 | 卡片加使用实例数提示 + 引导文案 |

## 六、验收标准草案

1. 已签发证书重新生成后，样式更新为新模板，编号、签发日期不变，验签地址指向新 PDF
2. 失败证书重新生成后进入签发管道，成功转已签发
3. 重新生成期间对外状态保持「已签发」，旧 PDF 可访问；替换成功后更新；失败则旧 PDF 保留
4. 重跑范围只含提交时点的「已签发」「签发失败」，排除待签发与签发中
5. 未绑定模板的实例不显示按钮；绑定模板禁用时弹窗有警告
6. 确认后按钮立即置灰，进行中不可重复提交；完成后行内显示成功/失败数量
7. 同批证书用同一模板快照渲染
8. 26 页正确显示使用实例数（含禁用实例）和引导文案
9. 全局开关关闭时任务照常提交并排队，恢复签发后自动执行，弹窗中明示暂停状态
