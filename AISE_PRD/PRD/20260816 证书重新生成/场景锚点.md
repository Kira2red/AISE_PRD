# 场景锚点 — 证书重新生成

## 产品定位

AISE 电子证书链路的运营自助能力补充。目标：证书模板调整后，运营可在后台自助对历史证书按新模板重新生成，不再依赖技术手动处理。

## 现状（调研结论）

三层模型：证书模板（样式）→ 证书实例（一场测评绑定模板+字段映射）→ 用户证书（个人 PDF + 签发状态）。

关键事实：

1. 模板编辑只影响之后新生成的证书。已签发证书保留旧样式（20260512 PRD §3.1.3 设计原则，当时有意为之）。
2. "重签"能力只存在于签发中心（软协独立平台）：单条重签（已签发/失败）+ 批量重签失败（仅失败记录）。没有"因模板调整批量重出已签发证书"的入口。
3. AISE admin 端三个页面（26 模板管理 / 28 实例管理 / 16 学生证书管理）均无重新生成操作。模板调整后只能找技术手动处理。

## 需求

在 admin 端给运营一个"重新生成"入口：按证书实例（一场测评）粒度，对已签发 + 失败的证书批量重新渲染 + 重新签章。

## 已拍板的决策点

| 决策点 | 结论 |
|---|---|
| 入口位置 | 28_证书实例管理（不是 26 模板管理） |
| 签发日期 | 保留原日期 |
| 旧 PDF | 覆盖式更新，不留档 |
| 范围 | 已签发 + 失败一起重跑 |
| 模板管理提示 | 26 页面加提示 |

## 补充决策点（方案概要中给建议，待用户确认）

1. 重新生成期间证书对用户端的可见性（建议：旧 PDF 仍可访问，生成成功后替换）
2. 防重复触发（建议：有进行中任务时按钮置灰）
3. 与签发中心全局启停开关的关系（建议：走现有签发管道，受开关控制）
4. 证书编号不变（业务标识，与模板无关）
