# AISE 登录手机号与联系电话分离 PRD

## 1. 背景与收益

**需求简介**：将现「联系电话」字段拆分为「登录手机号」与「联系电话」两个独立字段，登录手机号为账号唯一凭证不允许用户自行修改，联系电话作为普通联系信息可自由填写。

**业务诉求**：当前个人中心的联系电话是无校验文本框，学员或家长修改后账号登录手机号随之被改掉，导致用户无法用原手机号登录。拆分后登录凭证与联系信息解耦，杜绝误改登录号引发的登录故障与客诉。

## 2. 业务流程

注册流程不变：用户以手机号 + 短信验证码注册，该号码即**登录手机号**。登录手机号全系统唯一，仅能由客服在管理后台修改；用户侧（学生端、管理后台之外）只读。

联系电话为账号级的联系信息（主账号维度），类似电商收货地址中的手机号：可自由修改；未填写时系统自动使用登录手机号。存量用户联系电话统一初始化为其登录手机号。

## 3. 详细功能说明

### 3.1 字段定义

| 字段 | 定义 | 归属层级 | 修改权限 | 校验规则 |
|------|------|----------|----------|----------|
| 登录手机号 | 注册时通过短信校验的号码，账号唯一登录凭证，用于登录与接收验证码 | 主账号 | 用户不可修改；客服通过管理后台修改 | 全系统唯一；11 位手机号格式 |
| 联系电话 | 与学员/家长取得联系的电话，用于通知触达等场景 | 主账号 | 用户与后台均可自由修改 | 仅允许数字，长度 5~20 位；可为空 |

规则：

1. 联系电话为空时，系统一切展示与触达场景自动使用登录手机号。
2. 联系电话的修改即时生效，无需审核。
3. 修改登录手机号由客服在管理后台直接执行（管理后台登录手机号字段可编辑），修改时需人工核实用户身份；修改后用户以新手机号登录。
4. 注册环节不采集联系电话，注册完成后联系电话默认取登录手机号。

### 3.2 学生端 · 个人中心（单学生视图 13_个人中心）

「联系方式」区块字段调整为：

| 字段 | 控件 | 说明 |
|------|------|------|
| 登录手机号 | 只读展示（灰底） | 完整显示；下方小字提示「登录手机号用于登录和接收验证码，如需修改请联系客服」，无在线修改入口 |
| 电子邮箱 | 文本输入 | 维持现状 |
| 联系电话 | 文本输入 | 空值占位提示「不填写时默认使用登录手机号」；失焦校验：仅数字、5~20 位，不合规则红字提示「请输入 5~20 位数字的联系电话」，阻断保存 |
| 监护人姓名 / 监护人电话 | 文本输入 | 维持现状，属考生档案字段，与登录手机号无关 |

### 3.3 学生端 · 个人中心（多学生视图 14_个人中心_多学生）

字段同 3.2，其中登录手机号与联系电话为**主账号级**字段（家长维度，所有考生共用），监护人姓名/电话为考生档案级字段。

### 3.4 管理后台 · 学员管理（12_学员管理）

**列表**：原「联系方式」列拆分为「联系电话」「登录手机号」两列，各自独立展示一列数据。

**详情表单**：原「手机号码」字段拆分为：

| 字段 | 控件 | 说明 |
|------|------|------|
| 登录手机号 | 可编辑输入框 | 客服/管理员核实身份后可直接修改；用户端不可修改 |
| 联系电话 | 文本输入框 | 同用户端校验规则，可直接修改 |

搜索框支持按联系电话检索（placeholder：「输入姓名 / 手机号 / 联系电话 / 身份证号...」）。

[12_学员管理.html](<../../html/admin/12_学员管理.html>)

### 3.5 存量数据迁移

上线时执行一次性迁移：全部存量账号的联系电话初始化为其登录手机号。迁移后用户修改或清空联系电话均不影响登录手机号。

### 3.6 关联口径修订

《20260216 多学生账号与个人中心优化》中「监护人电话（自动回填当前登录账号手机号，支持修改）」的表述维持不变，但需知悉：监护人电话与本次拆分的联系电话为两个独立字段——监护人电话属考生档案，联系电话属主账号。
