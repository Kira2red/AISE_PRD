# AISE 数据分析（测评全流程数据统计）

> 页面原型：管理后台 36_数据分析 页与 32_活动管理 页（行内入口）。
> 撰写日期：2026-09-14　|　状态：待评审

## 1. 背景与收益

AISE 平台的测评数据目前分散在报名管理、学员监控、证书与报告等各业务页面，运营与渠道客户无法在一个入口看全一场活动的运行全貌。本期在管理后台新增「数据分析」页：从活动管理进入，按报名、模拟考、候考、考中、考后五个阶段组织页面，展示报名至考中的全部关键数据（考后为完结节点，本期不承载数据区块），运营掌握进展、渠道客户核对己方数据，减少跨页面拼数据与开发临时取数。

## 2. 业务流程

### 2.1 入口与页面结构

- 入口：管理后台「活动管理」列表，每行操作区「数据分析」按钮，打开该活动的数据分析页（地址携带活动编号）。
- 页面从上到下：顶栏（返回活动管理、活动基本信息、导出按钮）→ 阶段进度条（页面最顶部，紧贴顶栏下方）→ 筛选区（渠道、分组、测评三个下拉 + 筛选数据按钮）→ 当前筛选测评清单 → 按阶段分区的数据内容。
- 阶段进度条：横向五个节点——报名、模拟考、候考、考中、考后；当前节点高亮，已完成节点打勾，未到节点置灰。
- 每个节点下方展示该阶段的起止时间；当前节点额外展示结束提醒（如「距结束还有 3 天」「距结束还有 5 小时」）。
- 阶段起止时间取自活动配置与各测评的实际开始/结束时间：多场测评时取该阶段最早开始与最晚结束。
- 当前筛选测评清单：筛选区下方横排展示当前筛选命中的测评标签（至少一个）；点击标签跳转爱测评对应测评的详情页。
- 跳转免登：AISE 携带当前登录态跳转爱测评，用户无需重新登录（双方统一的免登票据，单次有效、短时效）。
- 单活动视角：页面只呈现所选活动的数据，不提供跨活动对比。

### 2.2 统计范围与筛选

- 几乎全部数据项都通过筛选确定统计范围，层级为：活动（最大颗粒度）→ 分组 → 测评；渠道为横切维度，任意层级均可按渠道拆分查看。
- 三个筛选均为下拉多选：下拉面板内支持输入关键词模糊检索选项，勾选后需点击「筛选数据」按钮才应用到页面全部数据；勾选未应用时页面提示「有未应用的筛选」；「重置」一键回到全量。
- 筛选联动规则：筛选了某维度，对应分布图只显示已选项；该维度自身占比不再参与数值折算，其余维度照常折算。

### 2.3 阶段与数据可见规则

- 数据按五阶段组织：报名、模拟考、候考（均属考前）、考中、考后。
- 考后为进度条上的完结节点（展示起止时间），本期不承载数据区块。
- 页面只展示当前进展阶段及之前的数据；未到的阶段不展示。顶栏显示当前阶段标签。
- 数据更新总体规则：报名阶段为事件驱动（业务动作落库即更新）；考中实时类每分钟更新，计算量大时可放宽至最长五分钟；测评进行中每分钟采样留存一帧（每位学员的测评状态、监考状态、答题明细），供趋势图与事后分析；测评结束时学员统计类数据冻结为最终值、监考接入类实时数据展示「—」，测评开始前考中类实时指标全部展示「—」；数据展示截止到考中阶段结束。
- 各数据项的可见起点、更新周期、停止时点以第 3 章各阶段「指标口径总表」为准。

### 2.4 数据权限

- 管理员与渠道客户使用同一套指标口径；客户侧数据自动限定本渠道（组织后台入口与页面本期暂缓，后续需求承接，结构与本页一致）。
- 各数据模块对每个渠道客户可按组织维度配置开放或隐藏；金额等敏感模块默认关闭，按商务需要逐组织放开。

## 3. 详细功能说明

### 3.1 报名阶段

- 3.1.1 指标卡：报名总人数（一人一单，人数即单量）、有效报名（已支付或免支付的单，待支付不计）、待支付单量、已退款单量。
- 3.1.2 每日新增报名趋势：折线图，按自然日展示新增人数，支持整体与逐日两种统计口径。
- 3.1.3 审核数据：堆叠柱状图（每日通过、不通过、待审核）与整体指标（累计通过、累计不通过、当前待审核）；审核来源为首次报名信息审核、照片审核（随报名信息审核闭环需求落地）与定制报名既有审核。
- 3.1.4 支付方式统计：各支付方式人数与单量（现阶段微信支付，新增支付方式自动纳入维度），支持整体与每日。
- 3.1.5 支付状态统计：已支付、待支付、已退款的环形分布，支持整体与每日。
- 3.1.6 分布三图：分组分布、测评分布、渠道分布的报名量柱状图；渠道分布支持按报名可见性（正常、隐藏报名）筛选。
- 3.1.7 报名量矩阵表：行为分组（一级，加粗带小计）与测评（二级，缩进），列为渠道，单元格为对应报名量；底部为各渠道合计与总计；随筛选联动裁剪行列，筛选后无数据时显示「当前筛选下没有测评」。
- 3.1.8 费用概览：报名费收款与退款金额概览卡（明细分析由交易数据统计页承载，本页不重复）；对渠道客户默认关闭，按组织数据权限放开。

### 3.2 模拟考阶段（属考前）

- 3.2.1 参与漏斗：应参人数、参考人数（进入过即算，含未完成）、完成人数（完成交卷），漏斗条同时展示各级占比。
- 3.2.2 监考开启率四组（成对显示实际人数、应开启人数与比率）：摄像头监考、录屏监考、手机监考、检录照片上传；分母为实际参考学员中该监考项配置为强制或非强制的人数，「不开启」配置排除并显示「未启用」；模拟考监考按其生效配置计算（可跟随正式测评或自定义）。

### 3.3 候考阶段（属考前）

- 3.3.1 指标卡四张：应参人数（有效报名）、候考人数（进入过候考页即算）、候考率（候考人数÷应参人数）、平均候考时长（进入候考页至测评开始）；测评未配置候考时相关项显示「未启用」。
- 3.3.2 监考开启四组（成对显示与开启率、上传率）：摄像头监考、录屏监考、手机监考、检录照片；摄像头与录屏的「实际开启」口径为设备检测对应项通过的学员数（同一数据源不重复统计）；检录视频随照片环节一并提交，不单独统计；分母排除「不开启」配置；测评开始时本组数据冻结，考中的在线监考情况由考中阶段另行统计。

### 3.5 导出

- 页面「导出」按钮导出当前筛选范围的数据，走消息中心异步导出链路（与既有导出一致）。

### 3.6 边界与状态

- 未配置环节（如该测评未开模拟考、未配置候考、某监考项为「不开启」）：对应模块整体或单项显示「未启用」，不参与分母计算。
- 阶段未开始：该阶段及之后的数据区块不展示，页面只保留已发生阶段的内容。
- 测评已结束：学员统计类数据冻结为最终值；监考接入类实时数据全部展示「—」。
- 筛选后无匹配数据：矩阵表显示空态文案，图表显示空态。


## 4. 组织后台（租户侧）

### 4.1 活动管理页

- 入口：组织后台侧边栏「活动中心」分区新增「活动管理」菜单；活动数据分析为活动管理的子页面，侧边栏不设独立入口。
- 活动列表：卡片式列出本渠道可参与的活动；每张卡片展示活动名称、阶段标签（报名中/考中/已完结/未开始）、起止时间、分组数与测评场数、活动编号；当前阶段的活动附结束提醒标签。
- 每张卡片右侧提供「数据分析」按钮，点击进入本渠道的活动数据分析页。

### 4.2 活动数据分析页（租户视角）

- 布局与管理后台数据分析页一致：顶栏（返回活动管理、活动基本信息、阶段进度条、导出）→ 筛选区 → 按阶段分区的数据内容。
- 阶段进度条与管理后台一致：五节点、起止时间、当前阶段结束倒计时提醒。
- 数据范围固定为本渠道（租户）：筛选区仅保留分组、测评两个维度，无渠道筛选；所有指标口径与管理后台一致，数据自动限定本渠道。
- 分布类图表与管理后台一致地保留分组分布、测评分布；报名量矩阵为分组/测评 × 本渠道报名量视角。
- 无「当前筛选测评清单」：不展示测评标签，也不提供跳转爱测评测评详情页的入口（租户无该跳转权限）。
- 页面配色沿用组织后台视觉（青色主色调），页面结构、指标口径、交互规则与管理后台完全一致。
