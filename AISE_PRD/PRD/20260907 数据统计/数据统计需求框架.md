# AISE 数据统计需求框架

> 文档性质：需求框架稿，用于对齐统计范围、阶段划分与指标口径；确认后可细化为正式 PRD 与页面 demo。
> 目标用户：AISE 管理员（运营后台）、AISE toB 客户（组织后台）
> 创建日期：2026-09-07

## 一、背景与收益

AISE 平台目前的数据分散在各个业务页面：报名数据在报名管理、考试过程数据在考生监控、成绩与证书数据在证书与报告相关页面，缺少一个按考试全流程聚合的统计视图。管理员与 toB 客户都需要在统一入口查看各阶段的关键数据与进度，快速掌握测评活动的整体运行情况。

本需求提供覆盖「考前—开考后—考中—考后」全流程的数据统计能力，管理员与客户使用同一套指标口径，客户仅限定为本组织的数据范围。

## 二、用户与数据范围

### 2.1 两类用户

| 用户 | 使用端 | 数据范围 | 说明 |
|------|--------|----------|------|
| AISE 管理员 | admin 运营后台 | 全平台数据 | 平台运营视角，可跨渠道/组织汇总与对比 |
| toB 客户（合作组织管理员） | org_admin 组织后台 | 仅本组织数据 | 沿用组织后台现有账号与数据隔离体系（学生列表、报名列表、项目管理均已按组织隔离） |

### 2.2 数据范围总原则

1. **指标全集一致**：管理员与客户看到的统计指标种类、口径、页面结构完全一致，客户的数据权限等同于管理员的指标全集。
2. **差异只在数据范围**：管理员看全平台并可按渠道/组织拆分；客户仅看本组织名下的报名、考生、考试过程与成果数据。
3. 数据隔离沿用组织后台既有设计：客户登录组织后台后，所有统计自动限定在该组织范围内，无需额外配置。

## 三、统计框架总览

统计按考试生命周期分四个阶段，每个阶段回答一类问题：

| 阶段 | 时间窗口 | 核心问题 |
|------|----------|----------|
| 考前 | 报名开启 → 开考 | 报了多少人、审核与缴费进展如何 |
| 开考后（考前环节） | 模拟考开启 / 正式考开考前 | 模拟考参与情况、身份校验、录屏、到场情况 |
| 考中 | 正式考试进行中 | 作答进度、交卷进度、异常情况 |
| 考后 | 考试结束 → 成果交付完成 | 批改、成绩、报告、证书各环节进度与结果 |

统计对象层级：平台（仅管理员）→ 渠道/组织 → 测评活动 → 场次；部分指标支持下钻到考生名单。

## 四、分阶段指标明细

> 加粗指标为本次讨论明确提出的，其余为框架补全建议项，待逐项确认。正式 PRD 阶段再细化每项的展示形态与筛选条件。

### 4.1 考前：报名统计

| 分组 | 指标 | 口径说明 |
|------|------|----------|
| 报名规模 | **报名人数 / 报名单量**、每日新增趋势 | 按活动、场次、日趋势展示 |
| 报名状态分布 | 各状态报名量与占比 | 待支付/已支付/审核中/已通过/已驳回/已退款，状态口径对齐报名管理 |
| 审核进展 | 待审核量、已审核量、平均审核时长 | 用户信息审核与证件照审核合并统计，支持按审核类型拆分 |
| 渠道分布 | 各渠道/组织报名量 | 管理员视角指标；客户视角自动限定为本组织 |
| 场次饱和 | 各场次报名人数与饱和度 | 对照场次容量展示 |
| 费用概览 | 报名费收/退金额概览 | 口径待确认：金额明细报表已由交易数据统计（admin 30）承载，客户侧是否开放金额见 Q1 |

### 4.2 开考后：模拟考与考前环节统计

模拟考：

| 指标 | 口径说明 |
|------|----------|
| **模拟考参与率** | 参加过模拟考的考生 ÷ 已报名考生（分母口径见 Q4） |
| 模拟考完成情况 | 参与人数、完成人次、人均次数 |

正式考·考前环节（按考试监考配置区分统计口径，配置为「不开启」的环节计入「未启用」，排除在分母外）：

| 指标 | 口径说明 |
|------|----------|
| **到场数据** | 应考人数、实际到场人数、到场率、未到场人数 |
| **身份校验情况** | 校验通过 / 校验未通过 / 未校验 |
| **录屏开启情况** | 已开启 / 未开启 / 开启异常 |
| 设备检测完成情况 | 摄像头、麦克风等设备检测完成率 |
| 检录提交情况 | 检录照片/视频已提交量（检录按考试配置为强制/非强制/不开启三态） |

### 4.3 考中：作答与交卷统计

| 指标 | 口径说明 |
|------|----------|
| **作答进度** | 已开始作答 / 未开始人数；整体平均作答进度（已作答题目占比） |
| **交卷进度** | 已交卷 / 未交卷人数；交卷时间分布 |
| 考中异常 | 切屏人数与次数、摄像头异常人数（数据来源为考生监控已有记录） |
| 刷新要求 | 考中数据准实时刷新，频率见 Q3 |

### 4.4 考后：批改、成绩、报告与证书统计

| 分组 | 指标 | 口径说明 |
|------|------|----------|
| 批改进度 | **待批改 / 批改中 / 已完成（量与占比）** | 主观题（编程、实践等）批改进度，含平均批改时长 |
| 成绩统计 | **平均分、最高/最低分、分数段分布、达标率、等级分布** | 按活动/场次维度；等级对齐成绩等级映射 |
| 报告进度 | **报告生成进度** | 已生成 / 生成中 / 未开始 / 失败；生成时机为成绩发布后自动触发 |
| 证书进度 | **证书生成进度（电子）** | 等待成绩 / 生成中 / 待签发 / 已签发 / 失败，对齐电子证书签发状态链路 |
| | 证书制作进度（实体） | 待复核 / 公示 / 制作中 / 已寄送各环节量，对齐实体证书生命周期 |

## 五、统一功能规则

| 规则项 | 内容 |
|--------|------|
| 页面载体 | admin 端与 org_admin 端各新增「数据统计」一级菜单；admin 页面编号自 31 起顺延、org_admin 自 09 起顺延 |
| 展示形态 | 指标卡片 + 图表（趋势/分布）+ 明细列表，支持下钻到考生名单 |
| 筛选维度 | 时间范围、测评活动、场次、渠道（仅管理员）、报名/考试状态 |
| 数据导出 | 统计结果与明细支持导出，沿用消息中心异步导出链路 |
| 权限 | 管理员沿用 admin 账号体系；客户沿用组织后台账号体系，数据自动限定本组织 |

## 六、与既有模块的边界

| 既有模块 | 边界说明 |
|----------|----------|
| admin 30_交易数据统计 | 收入对账报表由其承载；本需求在报名概览中只引用金额结论，明细与多维分析跳转该页面（见 Q1） |
| iceping 测评详情（考生成绩/监控） | 单场考试的过程明细由其承载；本需求做跨活动聚合与组织视角汇总 |
| issuance 签发中心 | 证书签发的管控操作（启停/重签）由其承载；本需求只读展示签发进度 |
| admin 14_活动证书管理 | 单活动的证书生命周期管理由其承载；本需求统计各环节数量与进度 |

## 七、待确认事项

| 编号 | 事项 | 建议 |
|------|------|------|
| Q1 | 金额类指标（收款/退款）是否对组织客户开放 | 涉及商务口径，建议首期对客户隐藏金额、仅管理员可见，后续按商务需要放开 |
| Q2 | 渠道对比视图（各渠道并排对比）是否需要 | 建议管理员端提供，客户端无需 |
| Q3 | 考中数据刷新频率 | 建议考中准实时（30 秒~1 分钟级），考后进度类 5 分钟级 |
| Q4 | 模拟考参与率分母 | 建议为全部已报名考生（模拟考默认对报名考生开放） |
| Q5 | 是否支持历史活动回溯 | 建议支持按时间范围回看往期活动统计 |
| Q6 | 成绩统计是否下探知识点维度 | 个人报告侧已有知识点掌握数据，建议作为二期扩展 |
