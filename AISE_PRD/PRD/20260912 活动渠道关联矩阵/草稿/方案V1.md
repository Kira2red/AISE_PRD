# 活动渠道关联矩阵 改版方案 V1

> 需求文件夹：20260912 活动渠道关联矩阵 ｜ 上游需求：[20260908 考试管理看板](<../20260908 考试管理看板/活动管理与考试批量配置 PRD.md>) ｜ 评审背景：2026-09-12 考务系统需求评审（结论：现方案太乱看不明白，需重新设计）
> 状态：**方案讨论稿，未拍板不开工**

## 一、评审反馈与改版核心

2026-09-12 评审意见：现有「考试 × 渠道矩阵」（一行 = 渠道 × 考试 × 分组）信息密度过高、行内字段太多（14 列），评审人看不明白。

**改版核心思路：转置 + 分层。**

| | 现方案（20260908） | 新方案 |
|---|---|---|
| 矩阵横轴（列） | 全部字段平铺 14 列 | **渠道**（一个渠道一列） |
| 矩阵纵轴（行） | 渠道 × 考试 × 分组平铺 | **活动下分组 × 考试**（一行 = 分组下的一场考试） |
| 单元格 | 无（每行只有一个渠道） | 该考试在该渠道的**关联状态**（含报名费） |
| 一眼看出 | 某渠道某考试的配置明细 | **一个活动下，各分组各考试有哪些渠道参加** |

新矩阵回答的问题从「某行配置是什么」变成「某考试在哪些渠道有/没有」——覆盖与缺失一目了然。

## 二、页面结构（活动详情页重构）

1. **头部**：返回、活动名称/ID、时间段与状态、导出（保留）
2. **统计卡**：考试场次、参与渠道、总报名量、异常数（创建失败/未关联）——精简为 4 张
3. **筛选**：分组、考试状态、爱测评创建状态（渠道维度由矩阵天然呈现，不再做渠道下拉）
4. **渠道关联矩阵**（主体，见第三节）
5. **行操作**：详情抽屉（全部配置字段收进抽屉，不再平铺列）

## 三、渠道关联矩阵

**行 = 分组 × 考试**：按分组分区展示（分组名做分组表头行），组内一行一场考试。行头列：勾选框、考试名称 + ID、标签、考试时间、报名量、爱测评状态。

**列 = 渠道**：活动有关联的渠道全部列出（渠道名 + 渠道号表头），可横向滚动；尾部一列「+ 添加渠道」。

**单元格 = 关联状态**（点击打开单元格编辑）：

| 状态 | 展示 |
|---|---|
| 已关联 | ✓ + 报名费（如「¥300」）；隐藏报名另加小标「隐」 |
| 未关联 | 浅灰空格子 + 悬浮「点击关联」 |
| 创建失败 | 红 ! + 原因悬浮；未关联同 |

单元格点击 = 关联/编辑弹窗（报名费、分组归属、报名可见性、展示配置——详情字段收进这里，不再占矩阵列）。

## 四、批量操作（增删改查的核心交互）

### 4.1 批量添加渠道

- 勾选方式：**勾选多个考试行 / 勾选整个分组（勾分组头 = 全选该组）/ 全选**
- 点「+ 添加渠道」→ 弹窗：选渠道（多选）→ 每渠道填统一报名费 → 提交
- 效果：所选渠道一次性关联到**所有勾选行**（每行每渠道生成一条关联，单元格从空变 ✓）
- 已存在的关联**跳过不覆盖**（保留原报名费），结果提示「新增 N 条，跳过 M 条（已存在）」

### 4.2 批量删除（渠道解除关联）

- 同样的勾选方式（多行/整组/全选）→ 点「删除渠道关联」→ 弹窗**选要删除的渠道**（多选）
- 效果：勾选行中**带所选渠道**的关联全部删除
- **拦截规则**：该渠道下已有报名的关联行默认跳过并提示「N 条因已有报名未删除」（防止误删真实报名数据）；确要强删需二次确认
- 二次确认弹窗列出将删除的关联数量

### 4.3 批量修改（保留现能力，入口收进单元格）

- 勾选行 →「批量修改」：只保留渠道关联类高频字段（报名费、报名可见性、展示开关/时间）；考试要素批量修改收进行内「…」菜单（评委反馈矩阵太乱的根因之一就是批量修改字段太多）
- 单元格点击 = 单条关联编辑（等价现「编辑考试配置」弹窗的渠道关联部分）

### 4.4 查

- 单元格 ✓ 点击 → 详情抽屉（该考试该渠道的完整配置 + 考试要素只读查看）
- 行尾「详情」→ 该考试跨渠道全配置（抽屉内按渠道分区）

## 五、边界与口径（沿袭 + 新定）

1. **分组仍挂渠道下**（20260826 渠道分组 PRD 口径不变）；矩阵行按「行头考试 + 单元格渠道」呈现，分组分区表头只做视觉聚合
2. **隐藏报名**：单元格「隐」标 + 单元格编辑弹窗内设置；定向链接迁移约定不变（迁移不重新生成链接）
3. **锁定规则**：已有报名的关联行，删除该渠道关联需走 4.2 拦截；考试要素锁定规则不变
4. **行级复制考试**：保留，但入口收进行尾「…」菜单（减少矩阵列拥挤）
5. **旧矩阵数据兼容**：现「一行 = 渠道×考试×分组」数据模型不变，只是呈现层转置；同一考试在同渠道多分组时，单元格内显示分组标签（如「3月批 · 6月批」）
6. 标签字段下拉选项（会议另一决议）不在本页面改动范围，归批量创建表单改版
