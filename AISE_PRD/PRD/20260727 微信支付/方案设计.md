# AISE 微信支付集成方案

## 一、背景

软协授权支付通道走不通（要求全流程审计 + 额外抽成 15%），支付宝通道不可用。改用 AISE 自有微信服务号「AISE青少年AI人才培养工程」（主体：爱测评科技，已认证）承接支付，一并解决用户触达和账号绑定问题。

---

## 二、用户流程

### 2.1 PC端报名 → 微信支付（标准流程）

```
用户在 PC 打开报名页（08_考试报名_主页）
  → Step1 报名须知 → Step2 填写信息 → Step3 确认信息
  → Step4 支付费用
      │
      ├─ 页面只展示微信支付（移除支付宝选项）
      ├─ 展示动态二维码（含临时 session token）
      ├─ 提示文案："请使用微信扫码支付"
      │
用户打开微信扫一扫 → 扫码
      │
      ├─ 微信内打开 H5 支付页
      │   ├─ 展示订单摘要（测评名称、金额）
      │   ├─ 调起微信 JSAPI 支付（需要微信服务号 appId + 商户号）
      │   └─ 支付结果：成功 → 展示成功页 / 失败 → 展示失败原因
      │
支付成功后：
      ├─ 🔴 强引导关注公众号
      │   ├─ 支付成功页显著位置展示公众号二维码 + 引导文案
      │   ├─ 文案："关注公众号，实时获取报名结果、测评安排、成绩通知"
      │   └─ 未关注用户必须看到此引导，不能一闪而过
      ├─ 推送模板消息：「报名成功通知」（测评名称、金额、时间）
      └─ PC 端页面轮询支付状态 → 自动跳转至「报名成功」页
          └─ 报名成功页同样展示公众号关注引导（与微信端一致）
```

### 2.2 全流程微信端（未来方向，对话中提及）

对话中张老师提到「如果在微信公众号端完成报名、上传照片、缴费」的完整闭环，本期不做完整迁移，但架构预留：

- 微信内 H5 报名表单（复用现有报名字段）
- 照片上传（微信 JS-SDK 调用相册/拍照）
- 支付闭环在微信内完成
- 模板消息覆盖全流程节点：报名提交 → 审核通过/驳回 → 考试提醒 → 成绩发布

本期先做**支付+通知+绑定**最小闭环。

## 三、技术方案

### 3.1 整体架构

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  AISE web端  │────▶│  AISE 后端   │────▶│ 微信服务号   │
│  (PC报名页)  │     │  (订单/用户) │     │ (支付/消息)  │
└──────┬───────┘     └──────┬───────┘     └──────┬───────┘
       │                    │                     │
       │ ①生成动态二维码     │                     │
       │◀───────────────────│                     │
       │                    │                     │
       │ ②用户扫码           │                     │
       │───────────────────▶│                     │
       │                    │ ③重定向至微信H5     │
       │                    │◀────────────────────│
       │                    │                     │
       │                    │ ④微信JSAPI支付       │
       │                    │────────────────────▶│
       │                    │    ⑤支付回调         │
       │                    │◀────────────────────│
       │                    │                     │
       │ ⑥轮询支付结果       │                     │
       │◀───────────────────│                     │
       │                    │                     │
       │                    │ ⑦推送模板消息         │
       │                    │────────────────────▶│
```

### 3.2 核心模块

#### A. 动态二维码

- 用户进入支付步骤时，后端生成临时 `pay_session_token`（有效期 15 分钟，与订单绑定）
- 二维码内容 = `https://aise.cn/wxpay/{pay_session_token}`
- 二维码每 30 秒自动刷新（防止过期）
- PC 端同时启动轮询：`GET /api/pay/status?token={pay_session_token}`，每 2 秒一次

#### B. 微信H5支付页

- 用户扫码进入 `/wxpay/{token}` → 后端校验 token 有效性 → 返回订单摘要页面
- 页面加载后调起 `wx.chooseWXPay()`（微信 JSAPI）
- 需要的前置条件：
  - 微信服务号 appId（已认证）
  - 微信支付商户号（mchId）
  - JSAPI 支付目录配置（`aise.cn/wxpay/`）
  - 服务端预下单接口（统一下单 → 返回 prepay_id → 前端签名 → 调起支付）

#### C. 支付回调

- 微信支付成功后异步通知 AISE 后端（`/api/pay/notify`）
- 后端收到回调后：更新订单状态为「已支付」→ 将 `pay_session_token` 标记为已完成 → 触发后续流程
- PC 端轮询检测到支付完成 → 自动跳转「报名成功」页

#### D. 模板消息通知

- 支付成功后 → 后端通过微信模板消息接口推送
- 第一期推送节点：
  1. 支付成功通知：「您的报名已提交，报名费 ¥XX.00 已支付」
  2. 审核结果通知（后续需求，预留接口）
- 前提：用户已关注服务号（支付成功后强引导关注，见下方 §3.6）

#### E. 公众号关注引导（🔴 关键体验点）

支付完成不是终点，关注公众号才是。用户关注后才能收到后续所有通知，否则模板消息无法触达。

**引导时机**：
- 时机 1：微信支付成功页 — 支付成功后立即展示公众号二维码 + 引导文案，占据页面核心区域，不可关闭或跳过
- 时机 2：PC 端报名成功页 — 支付轮询完成后跳转的页面，同样展示公众号二维码

**引导文案**：
> 关注「AISE青少年AI人才培养工程」公众号
> 及时获取报名审核结果、测评安排、成绩发布通知

**交互要求**：
- 公众号二维码清晰可扫（同时展示在微信 H5 和 PC 页面）
- 微信端可长按识别二维码直接关注
- PC 端展示二维码 + 提示「请使用微信扫码关注」
- 用户已关注时不展示引导（通过 openid 查 subscribe 状态判断）

#### F. 账号绑定（openid ↔ AISE 用户）

- 扫码进入微信 H5 时，通过微信 OAuth 静默授权获取 openid
- 后端记录 `openid → pay_session_token → order_id → user_id` 的映射链
- 支付成功后完成绑定：`user_id ↔ openid` 持久化
- 后续模板消息通过 openid 推送，无需用户再次扫码

### 3.3 数据模型（新增）

```
微信绑定表 (user_wechat_bind)
├── user_id        FK → AISE用户
├── openid         微信openid
├── unionid        微信unionid（如有）
├── subscribe      是否关注服务号
├── bound_at       绑定时间

支付会话表 (pay_session)
├── token          临时会话token
├── order_id       FK → 订单
├── user_id        FK → 用户
├── amount         金额
├── status         待支付/已支付/已过期
├── openid         扫码后回填
├── created_at
├── expires_at
```

### 3.4 现有系统改动

| 模块 | 改动 |
|------|------|
| 报名支付页（Step4） | 移除支付宝选项，二维码改为动态生成 + 轮询状态 |
| 报名成功页 | 新增：支付成功后自动跳转，展示「请关注公众号接收通知」引导 |
| admin 交易流水 (29) | 支付方式筛选项新增「微信JSAPI」，数据列填 openid 为空时标注 |
| admin 交易统计 (30) | 无需改，微信支付数据进入统计口径 |

### 3.5 不做/后续

- **不在本期做全流程微信端报名**（报名表单仍在PC端）
- **模板消息「审核结果通知」本期不做**（依赖审核流程打通，后续单独需求）
- **用户端站内消息通知不依赖本次需求**（用户端仍然没有站内通知能力，模板消息只是微信侧推送，AISE站内没有对应展示）
- **不改造已有支付方式的数据结构**（支付宝历史订单保留不动，新增微信 JSAPI 订单用新标识）
