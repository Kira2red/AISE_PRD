# AISE 微信支付集成 — 方案概要

## 一、背景与问题

AISE 考试报名支付环节当前存在四个问题，本次需求一并解决：

1. **支付无闭环**：用户扫码后手动点「我已完成支付」，系统无法验证支付状态
2. **支付宝通道不可用**：软协授权被拒，只剩微信支付
3. **用户无触达**：用户端没有站内通知，报名进度、审核结果无法推送
4. **账号未绑定**：web端用户与微信 openid 无关联，无法精准触达

## 二、业务范围

| 维度 | 本期范围 |
|------|---------|
| 支付方式 | 仅微信 JSAPI 支付（移除支付宝） |
| 报名入口 | PC端不变，不迁移到微信端 |
| 通知渠道 | 微信模板消息（支付成功通知） |
| 账号绑定 | openid ↔ AISE用户 静默绑定 |
| 管理端 | 交易流水新增「微信JSAPI」支付方式筛选项 |
| 适配 | PC + 手机端自适应（报名页可能从手机浏览器打开） |

**本期不做**：全流程微信端报名、审核结果模板消息通知、站内消息通知、支付宝历史数据迁移。

## 三、用户流程

### 3.1 PC 端报名 → 微信支付（主流程）

```
Step1 报名须知 → Step2 填写信息 → Step3 确认信息 → Step4 支付费用
                                                          │
                                        ┌─────────────────┘
                                        ▼
                                  页面只展示微信支付
                                  动态二维码（30秒刷新）
                                  文案：「请使用微信扫码支付」
                                        │
                                  用户打开微信扫一扫
                                        │
                                        ▼
                                  微信内 H5 支付页
                                  ├─ 订单摘要（测评名称、金额）
                                  ├─ 调起微信 JSAPI 支付
                                  └─ 支付结果展示
                                        │
                          ┌─────────────┴─────────────┐
                          ▼                           ▼
                     支付成功                      支付失败
                     ├─ 展示成功页               ├─ 展示失败原因
                     ├─ 强引导关注公众号          └─ 可重新支付
                     │  文案：「关注后及时获取
                     │  报名审核结果、测评安排、
                     │  成绩发布通知」
                     └─ 模板消息推送
                          │
                          ▼
                    PC 端轮询检测到支付成功
                    自动跳转「报名成功」页
                    页面同样展示公众号关注引导
```

### 3.2 未关注用户 vs 已关注用户

| 场景 | 行为 |
|------|------|
| 未关注 | 支付成功后展示公众号二维码 + 引导文案，占据页面核心区域 |
| 已关注 | 不展示引导，直接展示支付成功（通过 openid subscribe 状态判断） |

## 五、技术要点

### 5.1 动态二维码机制

- 用户进入 Step4 时，后端生成 `pay_session_token`（15分钟有效）
- 二维码内容 = `https://{域名}/wxpay/{token}`
- 每 30 秒自动刷新（前端定时重新请求 token）
- PC 端同步启动轮询：`GET /api/pay/status?token={token}`，间隔 2 秒
- 轮询到「已支付」状态 → 自动跳转报名成功页
- 轮询到「token 过期」→ 展示过期提示，用户可刷新重新生成

### 5.2 微信 JSAPI 支付

- 扫码进入 H5 页 → 后端校验 token → 展示订单摘要
- 微信 OAuth 静默授权获取 openid（snsapi_base）
- 后端调用统一下单接口 → 返回 prepay_id + 签名参数
- 前端调起 `wx.chooseWXPay()`（传入 prepay_id、paySign、nonceStr 等签名参数，由后端生成）
- 支付结果 → 展示对应页面

### 5.3 支付回调

- 微信异步通知 → 后端更新订单状态 → 标记 token 已完成
- PC 端轮询到已支付后自动跳转

### 5.4 账号绑定

- 扫码进入 H5 时获取 openid
- 关联链：openid → pay_session_token → order_id → user_id
- 支付成功后持久化绑定 user_id ↔ openid

### 5.5 模板消息

- 支付成功后，后端查询用户是否关注服务号
- 已关注 → 推送「报名成功通知」模板消息
- 未关注 → 引导关注后再推送（或跳过，关注后补推）
