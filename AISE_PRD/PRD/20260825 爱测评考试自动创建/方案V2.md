## 1. 背景与目标

**现状**：AISE admin 端新建测评活动时，「关联爱测评源数据」关联的是**爱测评的考试**——运营需先去爱测评手动新建考试，再回 AISE 关联。考试创建是纯手动环节，运营在两个平台来回操作。

**目标**：运营只在爱测评新建/维护**试卷**（组卷）。在 AISE 新建考试时关联爱测评**试卷**，系统按 AISE 填写的考试起止时间等要素，**在 AISE 创建考试的同时自动在爱测评对应组织生成考场（考试）**。

**写作口径**（用户明确）：研发团队为同一团队，**本文档只讲业务逻辑，不涉及 API 实现细节**。爱测评侧创建考试等能力需要开发，由研发自行排期实现。

## 2. 核心规则（用户拍板结论）

| # | 规则 |
|---|------|
| R1 | AISE 创建考试（测评活动）→ 系统**同时**自动在爱测评生成对应考场（考试）。爱测评考场一律程序创建，人工只做「爱测评组卷 + AISE 关联试卷」 |
| R2 | 概念映射：单考场考试 = 1 个爱测评考试；多考场考试 = 每个 AISE 考场映射 1 个爱测评考试，**不同考场可关联不同试卷** |
| R3 | 模拟考：AISE 开启模拟考 → 系统自动在爱测评创建对应模拟考试（关联模拟卷）。落地方式由研发定 |
| R4 | 强一致：爱测评考场未自动创建成功 → AISE 考试创建也不成功。报错 + 可重试；或允许先保存为「未关联爱测评」状态，补关联试卷时自动触发创建 |
| R5 | 时间重叠：允许同组织多场考试时间重叠（与多考场 PRD 一致） |
| R6 | 试卷删除保护：一份试卷已被考场使用后，该试卷不允许删除 |
| R7 | 要素下发：**容量限制删除**；其他限制（时长、交卷限制等）爱测评侧有对应能力则下发爱测评执行，没有则由 AISE 执行业务逻辑 |
| R8 | 「未关联」状态不取消：AISE 可先建考试不关联试卷（未关联状态）；之后编辑补关联爱测评试卷时，自动创建爱测评考试 |
| R9 | 存量活动（已同步/未同步/未关联）：处理方式由研发评估，业务上不强制迁移 |
| R10 | 试卷查询、预览等能力：提需求即可，实现由研发定 |

## 5. 核心流程

### 5.1 目标态流程

1. 运营在爱测评：新建试卷（组卷）——**唯一人工环节**
2. 运营在 AISE：新建测评活动
   - 选考试形态：单考场 / 多考场 /（开启模拟考）
   - 关联爱测评试卷（可暂不关联）
   - 填要素：名称、起止时间、时长、交卷限制、标签、模拟考配置（开启时）
3. 保存：
   - **已关联试卷** → 系统自动在爱测评生成考场（单考场 1 个 / 多考场每考场 1 个 / 模拟考 1 个）
     - 全部成功 → AISE 考试创建成功，活动可用
     - 任一失败 → AISE 考试创建不成功（强一致），报错；运营可重试，或先保存为「未关联」状态
   - **未关联试卷** → 保存为「未关联」状态
4. 未关联活动后续编辑补关联试卷 → 保存 → 自动创建爱测评考试
5. 考生在 AISE 报名、在爱测评考试引擎作答（下游链路不变）

### 5.2 状态流转

```
新建考试(未关联试卷) ──保存──▶ 未关联
新建考试(已关联试卷) ──保存──▶ 创建中 ──成功──▶ 已创建(可用)
                                 └─失败──▶ 创建失败 ──重试──▶ 创建中
未关联 ──编辑补关联试卷+保存──▶ 创建中 ──▶ 已创建
创建失败 ──重试──▶ 创建中；创建失败 ──保存为未关联──▶ 未关联
```

## 6. 边界与异常场景

- 关联试卷必填性：非必填（未关联状态合法，R8）；补关联即触发自动创建。
- 试卷删除保护：已被考场使用的试卷不允许删除（R6）。
- 自动创建失败：报错 + 可重试 + 可保存为未关联（R4、Q11 结论）。
- 多考场批量创建：强一致——任一考场创建失败则整体失败，重试/报错（Q7 结论）。
- 时间重叠：允许（R5）。
- 容量限制删除：考场不再有容量上限；联动影响——admin 统计卡片移除总容量/剩余容量，考场列表移除容量列，user 端报名选考场移除「满员不可选」逻辑（原多考场 PRD 相关规则随之移除）。
- 时间边界校验：AISE 侧先行校验（起止时间合法、时长≥交卷限制、考场时间在测评边界内），再下发。
- 编辑已报名考场的时间被禁止（多考场 PRD 已有规则）→ 编辑联动不触发。
- 编辑联动：修改考试/考场要素（时间、时长、交卷限制、试卷）后同步更新爱测评侧考试；实现方式研发定（研发判断）。
- 存量活动：由研发评估处理方式，不强制迁移（R9）。
- 模拟考落地：研发定（R3）；业务上模拟考要素（模拟卷、起止时间、次数限制）随考试自动创建下发。

## 8. 风险与依赖

- 爱测评侧需开发「以 AISE 组织身份程序创建考试」「试卷列表/详情」「试卷删除保护」等能力（研发同一团队，本文档只定业务规则，实现与排期研发定）。
- 下游依赖：证书签发、个人报告等依赖考试数据；程序创建的爱测评考试需正确回写 AISE，保证下游链路不中断（实现层面，研发负责）。
- 容量限制删除对多考场 PRD 既有功能（统计卡片、满员逻辑）的联动移除，需在多考场 PRD 中同步更新。
