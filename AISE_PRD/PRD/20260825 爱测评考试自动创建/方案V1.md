# 方案V1：AISE 新建考试关联爱测评试卷，自动创建爱测评考试

> 版本：V1 | 日期：2026-08-25 | 阶段：产品方案（产品大师·阶段一）
> 所属仓库：AISE_PRD | 相关已有需求：[测评多考场_PRD](<../20260708 多考场/测评多考场_PRD.md>)

---

## 1. 背景与目标

**现状**（依据：[AISE&爱测评平台能力梳理.md](../../Functional_Specs/AISE&爱测评平台能力梳理.md)、admin/05_新建测评活动.html、admin/04_测评活动详情.html）：

- AISE admin 端新建测评活动时，「关联爱测评源数据」下拉关联的是**爱测评的考试**（demo 选项如「0206验收测试04【刘玮】(未同步)」），同步状态分已同步/未同步/未关联。
- 即：运营需要**先去爱测评手动新建考试**，再回到 AISE 新建测评活动并关联该考试——考试创建是纯手动环节，运营要在两个平台来回操作。
- 多考场 PRD（20260708）已在考场层级定义「关联爱测评试卷」字段（demo 已实现选择器），但爱测评侧考试仍需人工创建，该字段仅是 AISE 侧记录。

**目标**：运营只在爱测评新建/维护**试卷**（组卷）。在 AISE 新建考试时直接关联爱测评**试卷**，系统按 AISE 填写的考试起止时间等要素，**自动在爱测评对应组织程序化创建考试**（索引文档已明确「对于爱测评来说，AISE 平台就是一个特殊的学校组织」）。

**期望效果**：

- 爱测评侧考试一律由程序创建，人工环节只剩「在爱测评组卷 + 在 AISE 关联试卷」。
- 考试要素（起止时间、时长、交卷限制、容量、试卷）以 AISE 为单一数据源，消除双平台人工不一致。
- 运营在 AISE 一个平台内完成考试创建全流程。

## 2. 用户故事与旅程

用户：AISE 运营（admin 端）。

| U2 | 我新建单考场考试，只填 AISE 侧要素（名称/起止时间/时长/交卷限制/标签/试卷），系统自动在爱测评创建 1 个对应考试 | D |
| U3 | 我新建多考场考试，每个考场自动对应爱测评一个考试，考场要素（时间/时长/交卷限制/容量/试卷）自动下发爱测评 | D + 多考场 PRD 已有考场要素定义 |
| U4 | 我开启模拟考，系统自动在爱测评创建模拟考试并关联模拟卷，模拟考要素（起止时间/次数限制）自动下发 | C（AISE demo 已有模拟考配置 UI，爱测评侧能力待确认） |

## 4. 核心流程

**目标态流程**：

1. 运营在爱测评：新建试卷（组卷）——**唯一人工环节**
2. 运营在 AISE：新建测评活动
   - 选考试形态：单考场 / 多考场 /（开启模拟考）
   - 关联爱测评试卷（必填）
   - 填要素：名称、起止时间、时长、交卷限制、标签、容量（多考场下每考场）、模拟考配置（开启时）
3. 保存 → AISE 调用爱测评 API 程序创建：
   - 单考场：创建 1 个考试，要素写入
   - 多考场：为每个考场创建 1 个考试
   - 模拟考：创建模拟考试（关联模拟卷）
4. 爱测评返回创建结果 → AISE 展示；成功则活动可用，失败则展示原因 + 可重试
5. 考生在 AISE 报名、在爱测评考试引擎作答（下游链路不变）

**现状流程对比**：爱测评手动新建考试 → AISE 新建活动关联该考试（同步）。

## 5. 边界与异常场景

- 关联试卷必填校验：未选试卷不允许保存。
- 关联时试卷已被删除/下架：选择器不再展示；已关联试卷后续被删除的影响待确认（Q6）。
- 爱测评 API 创建失败（超时/配额/参数校验失败/网络异常）：活动标记「创建失败」，可重试，不影响再次保存修正。
- 多考场批量创建部分成功：事务策略待确认（全部回滚 / 保留成功的 / 逐个重试）（Q7）。
- 时间要素边界：AISE 侧先行校验（起止时间合法、时长>交卷限制、考场时间在测评边界内——多考场 PRD 已有规则），减少爱测评侧校验失败。
- 爱测评侧同组织多场考试时间重叠：AISE 多考场 PRD 允许考场时间重叠；爱测评侧是否允许待确认（Q8）。
- 模拟考要素爱测评不支持：降级提示或仅 AISE 侧生效（随 Q2 结论）。
- 编辑已报名考场的时间被禁止（多考场 PRD 已有规则）→ 编辑联动不触发。
- 存量活动不受影响：存量「已同步」活动仍关联爱测评考试（随 Q4 结论）。

## 6. 成功度量

| 指标 | 目标 | 数据来源/口径 |
|------|------|--------------|
| 爱测评侧人工建考试次数 | 0（新链路 100% 程序创建） | 待验证：以爱测评侧操作日志统计，口径待双方确认 |
| 自动创建成功率 | ≥ 99%（假设值） | 上线后监控：创建失败数/创建总数 |
| 单场考试创建耗时 | 保存至爱测评考试就绪 ≤ 1 分钟（假设值） | 上线后埋点（待验证） |
| 运营操作平台数 | 2 → 1（新建考试环节） | D 依据：现状需双平台操作 |

## 7. 风险与依赖

- **核心依赖（最高风险）**：爱测评开放 API——以 AISE 组织身份程序化创建考试、查询试卷列表。若 API 不存在或未开放，需爱测评侧排期开发，本需求上线时间受制。**Q1 必须先行确认。**
- **概念映射**：爱测评「考试」与 AISE「考试/考场」的对应关系需双方明确（Q9）。
- **模拟考概念对齐**：爱测评侧是否有模拟考试概念（Q2）。
- **与多考场 PRD 的关系**：本需求改造其「关联爱测评试卷」字段所在链路的自动化，考场管理规则（克隆/停用/删除/时间校验）保持不变。
- **下游依赖**：证书签发、个人报告等下游依赖考试数据；程序创建的爱测评考试 ID 必须正确回写 AISE，保证下游链路不中断。
