## 1. 背景与目标

admin 端「16_学生证书管理」页面的「导出数据」按钮当前为纯前端 mock：按钮 loading → Toast → 2 秒后恢复，不产生任何真实文件（出处：`html/admin/16_学生证书管理.html` L376-409 `exportData()`）。服务端导出任务能力已在 S1 V4 定型（创建导出任务接口 + 异步执行 + 消息中心消费），本方案负责前端侧的最小改造：把 `exportData()` 从 mock 改为调用创建接口，**保持按钮名「导出数据」与 Toast 文案不变**（用户锁定决策 3）。

**用户锁定决策（本方案必须遵守）**
1. 导出范围：按当前筛选条件全量导出（跨页）——服务端逻辑，前端只需把完整 filter 提交
2. PDF 只打包已签发、Excel 保留全量行、zip 附缺证书说明.txt——服务端逻辑，前端无需感知细节
3. 按钮保持「导出数据」原名、不改文案；仍走异步导出链路（按钮 loading → Toast「正在导出，请稍后在「消息中心」查看下载」→ 恢复）
4. 无硬件依赖、无外部系统集成

**本方案范围**：仅 `16_学生证书管理.html` 的导出链路改造（控件补 id、`collectFilter()`、`exportData()` 改造）。不涉及消息中心（S3）、不涉及服务端（S1）。

以下均为实际读取 `html/admin/16_学生证书管理.html` 的核验结果：

| 项 | 现状 | 出处（行号） |
|---|---|---|

| Toast 容器/文案 | `<div id="toast">`，文案「正在导出，请稍后在「消息中心」查看下载」 | L42-45（文案在 L44，已核验原文为「消息中心」弯引号） |
| 筛选区控件 | 姓名/手机/身份证/渠道/证书状态(实体)/电子证书/测评结果/分数范围/模块/级别，**均无 id 属性** | L84-148（详见 3.1） |
| 查询数据按钮 | **无 id、无 onclick、无查询逻辑**（纯静态占位按钮） | L156-158 |
| 重置按钮 | 无 id、无 onclick（静态占位） | L152 |

**关键核验结论（须如实说明的两点）**：

1. **筛选控件与查询按钮均无 id**：改造前需先为 11 个筛选控件补 id（最小 DOM 改动，见 3.1）。取值方式若不用 id，只能依赖 placeholder 属性选择器（脆弱、易错），不推荐。
2. **「导出 filter 应与列表查询同源」在现状 demo 中无对应实现**：查询按钮为静态占位（L156-158），页面不存在任何列表查询 JS。因此本方案将 `collectFilter()` 定义为筛选条件的**唯一取值来源**，导出直接使用；落地阶段若查询逻辑接入同一函数，即天然满足「同源」，避免语义分叉（与 S1 V4 2.4.1「filter 对象与列表查询接口完全同源」的约定对齐）。

## 3. 改造点清单

### 3.1 前置小改动：筛选控件补 id（仅加属性，不动结构与样式）

为 L84-148 的 11 个控件补 id，取值逻辑与空值处理如下：

| 控件 | 现状位置 | 补 id | 类型 | 取值逻辑 | 空值处理 |
|---|---|---|---|---|---|
| 学生姓名 | L87 | `filter-name` | input text | `value.trim()` | 空 → 不传 |
| 手机号 | L91 | `filter-phone` | input text | `value.trim()` | 空 → 不传 |
| 身份证号 | L95 | `filter-idcard` | input text | `value.trim()` | 空 → 不传 |
| 渠道 | L98-103 | `filter-channel` | select（**现状单选**，文案写「可多选」） | `value` 有值 → `channelIds:[value]` | 空 → 不传（等价全部，S1 V4 L94） |
| 证书状态（实体） | L107-114 | `filter-cert-status` | select | `value`（processing/completed/publicity/making/sent） | 空 → 不传 |
| 电子证书 | L116-122 | `filter-elec-cert` | select | `value`（issued/pending/failed/unconfigured） | 空 → 不传 |
| 测评结果 | L124-130 | `filter-result` | select | `value`（优秀/良好/合格） | 空 → 不传 |
| 分数下限 | L132 | `filter-score-min` | input number | `Number(value)`（**保留小数**，与列表查询口径一致），value 非空且非 NaN 才传 | 空/非数字 → 不传 |
| 分数上限 | L134 | `filter-score-max` | input number | 同上（`Number(value)`） | 空/非数字 → 不传 |
| 模块 | L138-142 | `filter-module` | select（现状单选，文案写「可多选」） | 有值 → `moduleIds:[value]` | 空 → 不传（等价全部） |
| 级别 | L144-148 | `filter-level` | select（现状单选） | 有值 → `levelIds:[value]` | 空 → 不传（等价全部） |

> 说明：渠道/模块/级别文案标注「可多选」，但现状 DOM 是单选 select。**多选交互改造不在本任务范围**（本任务只改导出链路），取值按单选处理（有值传单元素数组、空不传=等价全部）；服务端契约字段本就是数组，形态兼容。空值表述统一为「空→不传（等价全部）」，与 `collectFilter()` 代码一致（🟢#4）。

### 3.2 新增 `collectFilter()`：筛选条件唯一取值来源

- 读取 3.1 全部控件，按「空=不传（等价全部）」规则组装 filter 对象（字段名与 S1 V4 附录 A 契约一致：`name/phone/idCard/channelIds/certStatus/elecCertStatus/result/scoreMin/scoreMax/moduleIds/levelIds`）。
- 空筛选时返回 `{}` 或仅含非空字段的对象，属合法请求体，前端不做拦截（服务端按全量处理，见第 6 节）。
- 落地阶段查询按钮接入同一函数即与导出同源。

### 3.3 `exportData()` 改造（最小改动）

| 环节 | 做法 |
|---|---|
| 收集 filter | 调用 `collectFilter()`，组装请求体 `{ type:"student_cert_package", filter, desensitize:true }`（契约：S1 V4 附录 A L355） |
| 调用方式 | `fetch` + `AbortController` 30 秒超时（**假设值，联调验证**；创建接口为同步轻量预估，正常应秒级返回；超时按网络异常处理） |
| 认证 | **同源 cookie 会话**：`credentials:'same-origin'`，与 admin 端其他真实接口保持一致（**标注「与后端确认」**——若接口不依赖 cookie 会话，则改用 `Authorization` 请求头携带登录态令牌，来源与登录态一致）；联调前与后端对齐 |
| 按钮 loading | 复用现状逻辑（L383-385）：`btn.disabled = true` + spinner + 样式类 |
| 成功（code=0） | Toast 保持原文案（L44「正在导出，请稍后在「消息中心」查看下载」）→ 按钮恢复；若 `data.warning` 存在，追加信息性提示（不弹确认、不阻塞、带任务守卫，见 3.4） |
| QUOTA_EXCEEDED | Toast「存储配额不足，请联系管理员」，按钮恢复。业务错误以响应体 `code` 为准（S1 创建接口 code!=0 载体）；catch 中 **HTTP 507/429 兜底映射**为同一文案（置于 5xx 分支之前，🟡#2） |
| 其他业务 code | Toast「导出失败（{code}），请稍后重试」，按钮恢复 |
| 网络错误 / 5xx（非 507/429）/ 超时 | Toast「网络异常，请稍后重试」，按钮恢复；其余 4xx 按「导出失败（{status}），请稍后重试」处理 |
| 重复点击防护 | 请求发出即 `disabled`（现状已有，L385）；函数开头加 `if (btn.disabled) return;` 兜底 |

### 3.4 warning 信息性提示（不阻塞）

- 契约：warning = `{ estimatedSize, estimatedTime, message }`，触发于预估 zip ≥2GB 或已签发数 >10000；任务照常创建执行，**信息性提示、不弹阻塞确认、不提供取消**（S1 V4 2.4.7 L242、2.5-7 L259）。
- 前端做法：原文案 Toast 展示约 3 秒后，追加第二条 Toast 展示 warning。文案优先取服务端 `message` 原文；无 `message` 时兜底拼接：
  - 「本次导出预计约 {estimatedSize}、耗时约 {estimatedTime}，请稍后在「消息中心」查看下载」
- **任务守卫（🟡#3）**：第二条 Toast 由 3500ms 延迟定时器触发，展示前校验导出序号 `exportSeq` 仍为当前值（期间用户再次导出成功则序号已自增，旧 warning 直接丢弃，避免覆盖新任务 Toast）。
- 整个流程用户可继续操作页面（Toast 不阻塞交互）。

### 3.5 错误提示文案汇总

| 场景 | 提示文案 | 按钮状态 |
|---|---|---|
| 创建成功（无 warning） | 正在导出，请稍后在「消息中心」查看下载（原文案，L44） | 恢复 |
| 创建成功（有 warning） | 原文案 + 追加 warning 信息性提示 | 恢复 |
| QUOTA_EXCEEDED（业务 code；HTTP 507/429 兜底映射） | 存储配额不足，请联系管理员 | 恢复 |
| 其他业务 code | 导出失败（{code}），请稍后重试 | 恢复 |
| 网络错误 / 5xx / 超时 | 网络异常，请稍后重试 | 恢复 |
| 其他异常 | 导出失败，请稍后重试 | 恢复 |

## 4. 关键代码示意（改造后的 exportData，可直接用于 demo）

```html
<script>
    // ========== 通用 Toast（抽取自现状 exportData 内联逻辑，L387-391/L401-407） ==========
    function showToast(text, duration = 3000) {
        const toast = document.getElementById('toast');
        toast.querySelector('span').textContent = text;
        toast.classList.remove('hidden');
        void toast.offsetWidth; // Force reflow（现状 L389）
        toast.classList.add('animation-fade-in-down', 'opacity-100', 'translate-y-0');
        toast.classList.remove('opacity-0', '-translate-y-5');
        if (toast._hideTimer) clearTimeout(toast._hideTimer);
        toast._hideTimer = setTimeout(() => {
            toast.classList.remove('opacity-100', 'translate-y-0');
            toast.classList.add('opacity-0', '-translate-y-5');
            setTimeout(() => toast.classList.add('hidden'), 300);
        }, duration);
    }

    // ========== 筛选条件收集（唯一取值来源；落地阶段查询按钮复用 = 与列表查询同源） ==========
    function collectFilter() {
        const v = (id) => { const el = document.getElementById(id); return el ? el.value.trim() : ''; };
        const filter = {};

        // 文本：空值不传
        const name = v('filter-name');    if (name)    filter.name = name;
        const phone = v('filter-phone');  if (phone)   filter.phone = phone;
        const idCard = v('filter-idcard');if (idCard)  filter.idCard = idCard;

        // 单选下拉：空=全部，不传
        const certStatus = v('filter-cert-status');   if (certStatus)   filter.certStatus = certStatus;
        const elecCertStatus = v('filter-elec-cert'); if (elecCertStatus) filter.elecCertStatus = elecCertStatus;
        const result = v('filter-result');            if (result)       filter.result = result;

        // 数组字段（现状为单选 select）：空=[]，有值=[value]
        const channelId = v('filter-channel'); if (channelId) filter.channelIds = [channelId];
        const moduleId  = v('filter-module');  if (moduleId)  filter.moduleIds = [moduleId];
        const levelId   = v('filter-level');   if (levelId)   filter.levelIds = [levelId];

        // 分数范围：Number() 保留小数（与列表查询口径一致，98.5 不截断，🟢#5）；
        // 仅传有效数字；空串/非数字不传；单端填写只传一端（闭区间语义由服务端处理）
        const scoreMinRaw = v('filter-score-min');
        const scoreMaxRaw = v('filter-score-max');
        if (scoreMinRaw !== '' && !Number.isNaN(Number(scoreMinRaw))) filter.scoreMin = Number(scoreMinRaw);
        if (scoreMaxRaw !== '' && !Number.isNaN(Number(scoreMaxRaw))) filter.scoreMax = Number(scoreMaxRaw);

        return filter;
    }

    // ========== 导出序号：warning 延迟 Toast 的任务守卫（🟡#3） ==========
    let exportSeq = 0;

    // ========== 导出（改造：纯前端 mock → 调用创建导出任务接口） ==========
    function exportData() {
        const btn = document.getElementById('btn-export');
        const originalContent = '<i class="fa-solid fa-file-excel"></i> <span>导出数据</span>';
        const loadingContent = '<i class="fa-solid fa-spinner fa-spin"></i> <span>正在导出...</span>';
        if (btn.disabled) return; // 重复点击兜底（disabled 按钮本不触发 onclick，双保险）
        const seq = ++exportSeq; // 本次导出序号（新导出会使旧 warning 定时器失效）

        // 1. 按钮 loading + 禁用（复用现状逻辑 L383-385）
        btn.innerHTML = loadingContent;
        btn.classList.add('opacity-75', 'cursor-not-allowed');
        btn.disabled = true;

        // 2. 组装请求体（契约：S1 V4 附录 A L355；desensitize 恒 true）
        const payload = {
            type: 'student_cert_package',
            filter: collectFilter(),   // 点击时刻快照，后续控件变化不影响本次任务
            desensitize: true
        };

        // 3. 调用创建接口（30s 超时为假设值，联调验证，🟢#7）
        const controller = new AbortController();
        const timer = setTimeout(() => controller.abort(), 30000);

        fetch('/api/admin/export/tasks', {
            method: 'POST',
            // 认证：同源 cookie 会话（与 admin 端其他真实接口保持一致；与后端确认，
            // 若接口不依赖 cookie 则改用 Authorization 请求头携带登录态令牌，来源与登录态一致，🟡#1）
            credentials: 'same-origin',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(payload),
            signal: controller.signal
        })
            .then((res) => {
                if (!res.ok) throw new Error('HTTP_' + res.status);
                return res.json();
            })
            .then((body) => {
                if (body.code !== 0) {
                    throw Object.assign(new Error('BIZ_' + body.code), { code: body.code });
                }
                // 4. 成功：Toast 保持原文案（L44）
                showToast('正在导出，请稍后在「消息中心」查看下载', 3000);
                // 5. warning：信息性追加提示，不阻塞、不弹确认（S1 V4 2.4.7）
                const warning = body.data && body.data.warning;
                if (warning) {
                    setTimeout(() => {
                        if (seq !== exportSeq) return; // 期间已发起新导出，丢弃旧 warning（🟡#3）
                        showToast(
                            warning.message ||
                            `本次导出预计约 ${warning.estimatedSize}、耗时约 ${warning.estimatedTime}，请稍后在「消息中心」查看下载`,
                            6000
                        );
                    }, 3500);
                }
            })
            .catch((err) => {
                const msg = String(err.message || '');
                // 业务错误以响应体 code 为准（S1 创建接口 code!=0 载体）；
                // HTTP 507/429 兜底映射为配额不足（须置于 5xx 分支之前，🟡#2）
                if (err.code === 'QUOTA_EXCEEDED' || msg === 'HTTP_507' || msg === 'HTTP_429') {
                    showToast('存储配额不足，请联系管理员', 4000);
                } else if (err.name === 'AbortError' || msg.startsWith('HTTP_5')) {
                    showToast('网络异常，请稍后重试', 4000);
                } else if (msg.startsWith('HTTP_')) {
                    showToast('导出失败（' + err.message.slice(5) + '），请稍后重试', 4000);
                } else if (msg.startsWith('BIZ_')) {
                    showToast('导出失败（' + err.code + '），请稍后重试', 4000);
                } else {
                    showToast('导出失败，请稍后重试', 4000);
                }
            })
            .finally(() => {
                clearTimeout(timer);
                // 6. 按钮恢复（复用现状 L396-398），无论成功失败
                btn.innerHTML = originalContent;
                btn.classList.remove('opacity-75', 'cursor-not-allowed');
                btn.disabled = false;
            });
    }
</script>
```

> 落地说明：若 demo 联调阶段后端接口未就绪，可在 `fetch` 分支保留原 mock 逻辑作为演示分支（注释标注「演示用，联调后移除」），生产形态以上述 fetch 为准。此为可选，不影响契约。

## 6. 边界处理

1. **筛选条件为空时点击导出**：`collectFilter()` 返回空/仅含非空字段的 filter，请求体合法；服务端按「空=全部」全量处理（S1 V4 L94、2.5-1：空结果/全量场景任务照常创建并成功）。**前端无需特殊判断、不拦截**；全量导出数据量大时服务端会按需返回 warning，前端照常信息性展示。
2. **导出进行中再次点击**：现状 loading 已设 `btn.disabled = true`（L385），disabled 按钮不触发 onclick，**现状 loading 逻辑已足够**；本次仅在函数开头加 `if (btn.disabled) return;` 双保险。结论：无需新增防抖/锁变量。
3. **分数只填一端**：只传有值端（如仅 `scoreMin`），闭区间另一端由服务端按缺省处理；前端不做猜测填充。分数用 `Number()` 取值、支持小数（98.5 正常传入，与列表查询口径一致，🟢#5）。
4. **请求进行中用户修改筛选条件**：请求体已在点击时刻组装快照，不受后续控件变化影响（与 S1 V4 L103「入参快照」口径一致：点击时刻的筛选 = 产物内容）。
5. **warning 场景**：信息性提示，不弹阻塞确认、不提供取消（用户锁定决策 + S1 V4 2.4.7）。

7. **「重置」「查询数据」逻辑不在本任务范围**（🟢#8）：两按钮现状为静态占位（L152、L156-158），重置/查询逻辑属列表查询改造任务，本方案不实现、不假设其行为。导出始终读取点击时刻的筛选控件值——若用户未重置即导出，将携带当前筛选值，符合「按当前筛选条件全量导出」的锁定决策，不视为缺陷。
