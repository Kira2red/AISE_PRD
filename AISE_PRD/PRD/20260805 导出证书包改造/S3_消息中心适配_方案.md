## 1. 背景

「导出证书包」改造后，16_学生证书管理页「导出数据」按钮走异步链路：任务创建后进入消息中心「导出记录」Tab 展示与下载（S1 方案 V4 2.4.2 步骤 6、附录 A）。本方案负责 19_消息中心「导出记录」Tab 的适配：数据源由硬编码 mock 改为任务接口，补齐 failed 状态样式与下载/重试真实交互，其余状态沿用现状样式。

用户已锁定决策（本方案不得违反）：
1. 导出范围：按当前筛选条件全量导出（跨页）
2. PDF 只打包已签发；Excel 保留全量行；zip 附「缺证书说明.txt」
3. 按钮保持「导出数据」原名；走异步链路（消息中心下载 zip）
4. 无硬件依赖、无外部系统集成

### 3.5 下载按钮：真实下载 + 错误码提示（改造）

- success 行「下载文件」点击调用 `GET /api/admin/export/tasks/{taskId}/download`（实现见 4.2，onclick 传 this：`onclick="downloadTask('${r.taskId}', this)"`，🟡#4 修订）：fetch blob → `URL.createObjectURL` → 临时 a 标签触发下载 → 释放 URL。
- 错误码映射（非 200 时解析响应体 code）：
  - `FILE_NOT_READY` → 「文件生成中，请稍后再试」（兜底：正常前端已禁用按钮不发请求，该码仅在绕过禁用/竞态时出现，对齐 S1 评审遗留 L5）
  - `FILE_NOT_FOUND` → 「文件不存在或已失效，请重新导出」
  - `FILE_EXPIRED` → 「文件已过期，请重新导出」
  - HTTP 403 → 「无权限下载该文件」（仅发起人或管理员可下载）
- 下载中按钮短暂禁用（防重复点击），完成后恢复。

### 3.6 重试按钮：POST retry（新增）

- failed 行「重试」调用 `POST /api/admin/export/tasks/{taskId}/retry`。
- 成功（200）→ Toast「已重新提交导出任务」+ 刷新当前视图（保持分页/关键词，该行变 processing 后轮询接管）。
- 409 → Toast「已达单任务重试上限（3 次），如需再次导出请重新发起」；**不做前端本地记录（🟢#7 修订）**——行按钮禁用完全由服务端返回的 attemptCount>=3 数据驱动渲染，下次列表刷新自然生效。
- 其他失败（403 越权等）→ 对应 Toast。

### 3.7 状态刷新：轮询状态机（🟠#1 两轮修订；第 2 轮：tick 拉取「已加载范围」）

- **状态机：IDLE ⇄ POLLING**。
  - 启动（IDLE→POLLING）：已加载全量行 exportRows（首屏 + 已追加）中存在 processing 行时启动；switchTab 切回「导出记录」时按同一判定立即启动。
  - 停止（POLLING→IDLE）：某次列表响应合并后 exportRows 无 processing 行；或切到「系统通知」Tab（clearInterval）。
  - 运行中：每 5 秒一次刷新 tick（假设值，可配置；与 S1 任务执行时长量级匹配，千级任务分钟级完成）。
- **刷新策略（🟠#1 第 2 轮修订：tick 拉取「已加载范围」，正文与 4.1/4.5 代码同步）**：
  - 每次 tick **不请求「当前页」**，改为拉取「已加载范围」整段：请求 `page=1 & size=已加载行数`（= exportPage × exportSize，封顶 500），一次拉取覆盖首屏与全部已追加页——第 1 页的 processing 行也在响应 rows 中，merge 必然更新，杜绝「第 1 页行永久生成中 + 轮询空转永不停机」。
  - 返回 rows 按 taskId 合并进 exportRows（已存在行更新状态列/操作列、新增行插入、已追加的历史行保留），**合并后按 createdAt 倒序重排（🟢#4，新任务在前）**，随后整体重渲染 tbody 并同步「加载更多」按钮状态。
  - 保持 exportKeyword 不变；不重置 page=1、不清空用户已「加载更多」追加的行；processing 行无论落在第几页，只要已加载即参与启动判定并被刷新（承接第 1 轮修复，本轮将刷新范围从「当前页」扩为「已加载范围」）。
- **竞态防护（请求序号 + AbortController）**：
  - 全局 reqSeq 自增：搜索防抖触发、加载更多、轮询 tick、重试成功刷新、切换 Tab 时均 ++reqSeq；列表请求回调校验 reqSeq 为最新才生效，乱序旧响应直接丢弃。
  - 发起新列表请求前 abort 上一在途请求（AbortController，避免无效带宽与重复渲染）。
  - 轮询与搜索叠加：搜索防抖后发起新请求，旧 tick 响应按 reqSeq 丢弃，以最新请求为准。
- 交互触发汇总：搜索输入（防抖 300ms）→ 重置 keyword/page 并清空 exportRows 重新加载；加载更多 → page+1 追加；重试成功 → 刷新当前视图（merge 更新该行）。
- 轮询 tick 请求失败或业务错误（code!==0）均静默：仅 console 记录、保留当前渲染、下轮重试，不弹 Toast 刷屏（🟡#2）；Toast 仅限 reset 场景（首屏/搜索/切 Tab 加载失败时提示）。
- 不额外提供手动刷新按钮（轮询已覆盖，保持简单）。

## 4. 关键代码示意（第 1 轮 8 条 + 第 2 轮 🟠#1 / 🟡#2 / 🟡#3 / 🟢#4 / 🟢#5 已修订）

### 4.1 列表加载与渲染（轮询状态机 + 竞态防护）

```js
let exportPage = 1, exportSize = 10, exportKeyword = '', exportTimer = null;
const POLL_MAX_ROWS = 500;         // 🟠#1：轮询 tick 单次拉取上限（exportPage×exportSize 封顶）
let exportRows = [];                 // 已加载全量行（首屏 + 追加）：轮询启停判定与合并基准
let reqSeq = 0, listAbort = null;    // 竞态防护：请求序号 + AbortController

async function loadExportTasks(reset = false, pollSilent = false) {
    const seq = ++reqSeq;
    if (listAbort) listAbort.abort();          // 取消上一在途列表请求
    listAbort = new AbortController();
    if (reset) exportRows = [];                // 首屏/搜索/切 Tab：清空重载
    // 🟠#1（第 2 轮）：tick 拉取「已加载范围」——page=1 & size=已加载行数（封顶 POLL_MAX_ROWS），
    // 一次拉取覆盖所有已加载页，第 1 页的 processing 行也在响应 rows 中，merge 必然更新
    const isTick = pollSilent;
    const page = isTick ? 1 : exportPage;
    const size = isTick ? Math.min(Math.max(exportRows.length, exportSize), POLL_MAX_ROWS) : exportSize;
    const url = `/api/admin/export/tasks?page=${page}&size=${size}&keyword=${encodeURIComponent(exportKeyword)}`;
    try {
        const res = await fetch(url, { signal: listAbort.signal });
        const body = await res.json();         // { code:0, data:{ rows, total } }
        if (seq !== reqSeq) return;            // 已被更新的请求覆盖，丢弃乱序响应
        if (body.code !== 0) {                 // 🟡#2：区分 reset 与 tick 场景
            if (isTick) { console.error('[export] 轮询刷新失败 code=', body.code); return; }  // tick：静默，仅 console
            showToast('导出记录加载失败'); return;                                            // reset：可弹 Toast
        }
        const { rows, total } = body.data;
        mergeExportRows(rows);                 // 按 taskId 合并（已存在行更新、新行插入、已追加行保留）
        renderExportRows();                    // 整体重渲染当前已加载视图
        updateLoadMoreBtn(total);
        syncPolling();                         // 基于 exportRows 启动/停止轮询
    } catch (e) {
        if (e.name !== 'AbortError' && seq === reqSeq) { /* 失败静默，下轮重试 */ }
    }
}

function mergeExportRows(rows) {
    const byId = new Map(exportRows.map(r => [r.taskId, r]));
    rows.forEach(r => byId.set(r.taskId, r));  // 已存在行整体覆盖（状态列/操作列随之更新）
    exportRows = [...byId.values()];
    // 🟢#4：合并后按 createdAt 倒序重排（新任务在前），避免 Map 追加破坏列表排序；
    // 契约 createdAt 为 YYYY-MM-DD HH:mm:ss 零填充字符串，字典序即时间序（落地时按实际类型对齐）
    exportRows.sort((a, b) => String(b.createdAt).localeCompare(String(a.createdAt)));
}

function statusBadge(r) {
```

```js
async function downloadTask(taskId, btn) {
    btn.disabled = true;
    try {
        const res = await fetch(`/api/admin/export/tasks/${taskId}/download`);
        if (!res.ok) {
            const body = await res.json().catch(() => ({}));
            const msg = { FILE_NOT_READY: '文件生成中，请稍后再试', FILE_NOT_FOUND: '文件不存在或已失效，请重新导出', FILE_EXPIRED: '文件已过期，请重新导出' }[body.code]
                     || (res.status === 403 ? '无权限下载该文件' : '下载失败，请稍后重试');
            showToast(msg); return;
        }
        const blob = await res.blob();
        const disposition = res.headers.get('Content-Disposition') || '';
        const name = decodeURIComponent((disposition.match(/filename\*=UTF-8''(.+)/) || [])[1] || 'export.zip');
        const url = URL.createObjectURL(blob);
        const a = document.createElement('a');
        a.href = url; a.download = name; document.body.appendChild(a); a.click();
        a.remove(); URL.revokeObjectURL(url);
    } finally { btn.disabled = false; }
}
```

```js
function filterSummary(f) {
    if (!f) return '全量导出';
    const label = { elecCertStatus: '电子证书状态', certStatus: '证书状态', result: '测评结果', moduleIds: '模块', levelIds: '级别', channelIds: '渠道', scoreMin: '分数' };
    const text = { issued: '已签发', pending: '待签发', failed: '签发失败', unconfigured: '未配置',
                   processing: '批改中', completed: '批改完成', publicity: '公示中', making: '制作中', sent: '已寄送',
                   优秀: '优秀', 良好: '良好', 合格: '合格' };
    const parts = [];
    const push = (key, val) => { if (val !== undefined && val !== null && val !== '' && !(Array.isArray(val) && !val.length)) parts.push(`${label[key]}=${val}`); };
    push('moduleIds', f.moduleIds?.join('、'));
    push('levelIds',  f.levelIds?.join('、'));
    push('elecCertStatus', text[f.elecCertStatus] || f.elecCertStatus);
    push('certStatus', text[f.certStatus] || f.certStatus);
    push('result', f.result);
    push('channelIds', f.channelIds?.join('、'));
    // 🟢#8：分数单边取值只展示有值一侧（如「分数=90」），不再输出「分数=~90」
    if (f.scoreMin != null || f.scoreMax != null) {
        const sMin = f.scoreMin != null ? `${f.scoreMin}` : '';
        const sMax = f.scoreMax != null ? `${f.scoreMax}` : '';
        push('scoreMin', (sMin && sMax) ? `${sMin}~${sMax}` : (sMin || sMax));
    }
    push('name', f.name); push('phone', f.phone); push('idCard', f.idCard);
    return parts.join('；') || '全量导出';
}

function summaryText(s) {
    if (!s) return '';
    const base = `${s.totalRows} 行 / ${s.pdfCount} 份`;
    return s.missingCount > 0 ? `${base} / 缺 ${s.missingCount}` : base;
}

function formatFileSize(bytes) {
    if (bytes == null) return '';
    if (bytes < 1024) return `${bytes} B`;
    const units = ['KB', 'MB', 'GB'];
    let v = bytes / 1024, i = 0;
    while (v >= 1024 && i < units.length - 1) { v /= 1024; i++; }
    return `${v.toFixed(1)} ${units[i]}`;
}
```

## 6. 边界处理

### 6.1 列表为空
rows 为空时 tbody 渲染空态占位：居中图标（fa-inbox）+「暂无导出记录」+ 次级文案「发起导出后，任务将在此展示」；**隐藏「加载更多」按钮（🟢#6：与 4.1 代码一致，采用「隐藏」而非置灰改文案）**；不启动轮询。搜索结果为空时文案为「未找到相关导出记录」，同样隐藏加载更多。

### 6.2 processing / expired / 未知状态下载禁用（前端不发请求）
processing 行操作列渲染禁用按钮（沿用 L128-130 形态），**点击不发请求**——对齐 S1 评审遗留 L5（V4 L391）：FILE_NOT_READY 仅作为绕过禁用/竞态时的兜底错误码，前端正常路径永不触发。expired 同理（L239-241 形态）。**未知状态（非四态枚举，如服务端后续新增枚举）操作列渲染同款禁用态、状态列中性灰「未知状态」（🟢#5：不 fallback 到 expired，避免误导用户）**。

### 6.3 keyword 搜索行为（🟡#3 修订）
- **匹配范围：keyword 只匹配 fileName 与 task_type（或 filterSnapshot 内容，以 S1 实现为准）；不与 taskName 匹配**——taskName 契约固定「导出学生证书包」全行相同，匹配无意义。placeholder 相应改为「搜索文件名 / 任务类型」。
- 输入防抖 300ms；每次输入变化重置 page=1 并重新请求（不做服务端实时联想）。
- 搜索与分页叠加：keyword 非空时「加载更多」仍可用（追加查询结果分页）。
- 搜索结果为空：展示空态（文案「未找到相关导出记录」）。
- 清空输入：恢复全量列表（page=1）。
- 轮询叠加：搜索请求与轮询 tick 并发时，以 reqSeq 最新请求为准，旧响应丢弃（见 3.7 竞态防护）。

### 6.4 重试边界
- attemptCount >= 3：重试按钮渲染层禁用 + title「已达重试上限」，不发请求（actionCell 按服务端返回的 attemptCount 判断，🟢#7）。
- 409：Toast 提示「已达单任务重试上限（3 次），如需再次导出请重新发起」；**409 仅限单任务重试上限，不限制新建任务**（S1 V4 L358、2.4.6 L229）；**不做前端本地禁用记录**，下次列表刷新后渲染层按 attemptCount>=3 自然禁用。
- 重试成功：刷新当前视图，该行变 processing，轮询自动接管刷新；请求期间按钮禁用防重复提交。

### 6.5 下载边界
- 下载中按钮禁用（防连点）；失败恢复可点。
- 非 200 时按 code 映射 Toast（3.5）；无法解析 body 时按 HTTP 状态兜底（403 越权 / 其他「下载失败，请稍后重试」）。
- 文件名优先取 `Content-Disposition: filename*=UTF-8''...`（S1 V4 L357），缺失时兜底 `export.zip`。

### 6.6 轮询边界（🟠#1 两轮修订）
- 状态机启停：仅「导出记录」Tab 激活且 exportRows 存在 processing 行时轮询；切走 `clearInterval`；页面隐藏（document.visibilitychange 可选）不额外处理（保持简单）。
- 刷新策略（🟠#1 第 2 轮）：tick 拉取「已加载范围」——请求 page=1 & size=已加载行数（exportPage×exportSize，封顶 500）一次合并，覆盖所有已加载页；保持 exportKeyword；不重置 page=1、不清空已追加行；processing 行无论在第几页，只要已加载即参与启动判定并被刷新（第 1 页行也在响应 rows 中，merge 必然更新，不会永久「生成中」）。
- 竞态防护：reqSeq 丢弃乱序响应 + AbortController 取消在途请求；搜索/加载更多/轮询并发时以最新请求为准。
- 轮询 tick 请求失败或业务错误（code!==0）均静默：仅 console 记录、保留当前渲染、下轮重试，不弹 Toast 刷屏（🟡#2）；Toast 仅限 reset 场景。
- 任务长期 processing（服务端超时置 failed，S1 2.5-15）→ 轮询自然刷出 failed 行与重试按钮，无需前端兜底超时。
