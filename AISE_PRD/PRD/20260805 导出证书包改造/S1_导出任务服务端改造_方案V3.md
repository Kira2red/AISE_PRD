### 2. 方案正文

#### 2.1 背景与目标

（V2 2.1，未变）背景、已锁定决策①全量导出②zip 结构③异步链路、非目标均维持原样。补充约束（用户锁定决策④）：本改造为纯后台管理功能改进，**无硬件依赖、无外部系统集成**。非目标中「分卷 zip」仍为 Could（仅预留，见 2.4.7 的 4GB 联动）。

**背景**：admin 端「16_学生证书管理」页面的「导出数据」按钮当前为纯前端 mock（loading 2s → Toast → 恢复），不产生任何真实文件（出处：`AISE_PRD/AISE_PRD/html/admin/16_学生证书管理.html` L376-409 `exportData()`）。页面表格同时存在两条独立证书链路：实体证书状态（批改中→…→已寄送）与电子证书状态（已签发/待签发/签发失败），电子证书链路已有平台内 PDF 资产（已签发时保存证书编号、PDF 地址、验签地址，出处：`AISE_PRD/AISE_PRD/PRD/20260512 5 月需求/20260512 证书签发流程 prd.md` L72；用户证书对象含 PDF 地址，L51；签发中心可下载 PDF，L834）。

**已锁定决策（用户拍板，直接采用）**
1. 导出范围：按当前筛选条件全量导出（跨页，非仅当前页/勾选行）
2. PDF 只打包「已签发」电子证书；Excel 保留筛选结果全量行（含电子证书状态列，未签发行保留）；zip 内附「缺证书说明.txt」列明未打包学生及原因（可溯源）
3. 按钮保持「导出数据」原名不改文案；仍走异步导出链路（按钮 loading → Toast → 消息中心导出记录 → 下载 zip）
4. 纯后台管理功能改进，无硬件依赖、无外部系统集成（证书 PDF 为平台内已生成资产）

**非目标（V1/V2/V3 不做）**：前端按钮交互改造（S2）、消息中心展示适配（S3）的详细方案（仅输出接口与文件规范约定）；增量导出、定时导出、分卷 zip、压缩选项调优；取消/中止接口（Could 预留）。

#### 2.2 用户故事与用户旅程

（V2 2.2，未变）

- US1（运营/管理员）：按当前筛选条件一键导出「证书包」（Excel + 已签发证书 PDF），用于线下归档、渠道分发、寄送清单核对。【E 级经验判断——导出场景为运营线下作业；按钮与异步链路为现状锁定行为】
- US2（运营/管理员）：在消息中心查看导出任务进度并下载 zip，异步取回大文件不阻塞页面操作。【C 级——消息中心「导出记录」Tab 已存在且已含「导出电子证书包 (PDF)」zip 形态 mock 行（19_消息中心.html L141-148）】
- US3（运营/管理员）：部分证书未打包时，通过 zip 内说明文件快速定位缺失项及原因，跟进补签或人工处理。【用户已拍板锁定（可溯源要求）】

**用户旅程（关键路径）**
1. 进入「16_学生证书管理」→ 设置复合筛选 → 点击「查询数据」核对列表
2. 点击「导出数据」（保持原名）→ 按钮 loading（禁用）→ Toast「正在导出，请稍后在『消息中心』查看下载」→ 按钮恢复
3. 服务端创建导出任务并异步执行（用户无感知等待）
4. 用户进入「19_消息中心」→「导出记录」Tab → 看到「导出学生证书包」任务（生成中/生成成功）
5. 生成成功后点击「下载文件」→ 获得 zip → 解压核对「学生证书列表.xlsx」与「证书PDF/」目录；如有缺证书，查阅「缺证书说明.txt」

#### 2.4 核心流程

##### 2.4.1 触发与入参（修订，回应 #1/#2）

- 触发点：16 页面「导出数据」按钮点击（`exportData()` 改造为调用创建接口，此为 S2 职责；S1 定义接口契约）
- 任务创建时序：点击 → 前端收集筛选控件值 → `POST /api/admin/export/tasks` → 服务端按序执行：
  1. **同步配额预检**：存储配额余量不足 → **直接拒绝创建，不落任务记录**，返回 `code=QUOTA_EXCEEDED` + 提示「存储配额不足，请联系管理员」（与 F12、2.5-14、附录 A 同口径）
  2. **轻量预估**：`预估大小 = 筛选 count × 平均 PDF 大小参数（假设 1.25MB，待实测）`；count 复用列表 COUNT 查询一次，开销可忽略；超阈值生成 warning（见 2.4.7）
  3. 落任务记录（status=processing，入参快照 JSON 全量保存）→ 返回 `{ taskId, status:"processing", warning? }` → 异步队列消费执行
- 入参（filter 对象，与列表查询接口完全同源，避免语义分叉；另含 desensitize 默认 true）：

| 字段 | 类型 | 对应筛选控件 | 枚举/说明 |
|---|---|---|---|
| name | string | 学生姓名 | 模糊 |
| phone | string | 手机号 | 模糊 |
| idCard | string | 身份证号 | 模糊 |
| channelIds | string[] | 渠道（可多选） | 空=全部 |
| certStatus | string | 证书状态（实体） | processing 批改中 / completed 批改完成 / publicity 公示中 / making 制作中 / sent 已寄送（16 页 L108-113） |
| elecCertStatus | string | 电子证书 | issued 已签发 / pending 待签发 / failed 签发失败 / unconfigured 未配置（16 页 L116-122） |
| result | string | 测评结果 | 优秀 / 良好 / 合格（L125-130） |
| scoreMin / scoreMax | number | 分数范围 | 闭区间 |
| moduleIds | string[] | 模块（可多选） | |
| levelIds | string[] | 级别（可多选） | |
| desensitize | boolean | （导出口径） | 默认 true（手机号/身份证脱敏）；明文导出需前端二次确认 |

- 入参快照存 JSON：任务执行期间以快照为准（与 2.5 快照一致性一致），保证「点击时刻的筛选 = 产物内容」

##### 2.4.2 执行流程（服务端异步任务）（修订，回应 #5）

```
队列消费任务
  → 1. 按 filter 快照全量查询学生证书行（游标分页，无页大小上限）
  → 2. 生成 Excel（列规范见 2.4.3；数据 = 步骤 1 全量行）
  → 3. 遍历行：电子证书状态=已签发 且 有 cert_no → 从证书文件存储读 PDF
         - 读取失败/文件缺失 → 该行记入缺证书清单（原因枚举见 2.4.5），继续
         - 未签发/签发失败等 → 该行记入缺证书清单（状态原因），继续
  → 4. 流式打包 zip（结构见 2.4.4；PDF 每批 N 个写入（假设值 N=500，待验证））；
         ★ 每批完成后刷新 updated_at（心跳，回应 #5）——合法大任务不会被悬挂扫描误杀
  → 5. 上传/落盘 zip，更新任务记录：status=success、fileName、fileSize、统计、完成时间
  → 6. 消息中心导出记录 Tab 从任务表读取（S3 负责 UI 消费）
失败（Excel 生成失败 / zip 打包失败 / 存储写入失败 / 超时）
  → 任务置 failed + failReason，可重试（F10）
```

##### 2.4.4 zip 包结构（修订，回应 #6/#8）

```
学生证书包_20260805_共5682人_3200份.zip
├── 学生证书列表.xlsx          （全量行，必含）
├── 缺证书说明.txt             （★恒生成，三种内容形态，见下）
└── 证书PDF/                   （打包 PDF 数为 0 时不生成此目录）
    └── 张小明_CERT202608050001.pdf   （仅已签发且读取成功；文件名=姓名_证书编号）
```

- **「缺证书说明.txt」恒生成**（与锁定决策 2「zip 附缺证书说明.txt」字面一致），三种内容形态：
  - 形态一·全部打包成功（0 缺）：头部统计 + 注明「全部 {N} 行证书均已打包，无缺失」
  - 形态二·筛选结果为空：注明「筛选条件下无数据，无需导出」
  - 形态三·存在未打包行：逐行列明缺失明细（序号/姓名/证书编号/电子证书状态/原因）
- **ZIP64**：Excel/zip 库选型必须支持 ZIP64（单 zip 可超 4GB，规避 zip32 上限）；此为硬性选型条件（2.7 同步）
- zip 文件名规范：`学生证书包_{yyyyMMdd}_{共{总行数}人}_{{打包PDF数}份}.zip`
  - 命名先例参考：消息中心 mock 已有 `certs_batch_1002_final.zip`（19 页 L147）形态；本规范加入日期与统计【依据：C 级参考 + 默认假设】
  - 文件名字符集：UTF-8；姓名中的非法文件名字符（`/ \ : * ? " < > |`）统一替换为 `_`
- 不生成空目录：当打包 PDF 数为 0 时，zip 内无「证书PDF/」目录
- 单个学生多行（多证书实例）时每行独立 PDF，文件名以 cert_no 唯一区分（规避同名冲突）

##### 2.4.5 缺证书说明.txt 内容结构（修订，回应 #4）

```
学生证书包缺证书说明
导出任务：{taskId}
导出时间：{yyyy-MM-dd HH:mm:ss}
筛选条件摘要：{如：模块=Python,一级；电子证书状态=全部}
结果总行数：5682
已打包证书数：3200
未打包行数：2482

序号	学生姓名	证书编号	电子证书状态	未打包原因
1	李小红	-	待签发	电子证书未签发
2	赵小梅	-	签发失败	电子证书签发失败
3	张三		CERT202608050099	已签发	证书PDF文件缺失（存储异常）
```

- **原因映射层统一说明（回应 #4）**：elecCertStatus 对外枚举 issued/pending/failed/unconfigured 中，等待成绩/生成中/待签发为 **pending 大类的内部子状态**（页面文案），映射层统一归 pending 大类。
- 原因枚举（机器可读 code + 展示文案，同时落库以便统计）：

| code | 文案 | 触发条件 |
|---|---|---|
| NOT_ISSUED | 电子证书未签发 | 状态 ∈ **pending 大类（含内部子状态：等待成绩/生成中/待签发）** |
| ISSUE_FAILED | 电子证书签发失败 | 状态 = 签发失败（证书 PRD L73 保存失败原因） |
| PDF_MISSING | 证书PDF文件缺失（存储异常） | 已签发但存储无对应文件 |
| PDF_CORRUPT | 证书PDF文件损坏/读取失败 | 已签发但读取/校验失败 |
| CERT_NO_MISSING | 证书编号缺失，无法定位PDF | 已签发但 cert_no 为空（数据异常） |
| OTHER | 其他 | 兜底 |

##### 2.4.6 导出记录与下载（修订，回应 #7）

（V2 2.4.6 存储模型、状态流转、下载接口、Range 断点续传，未变）以下两项修订：
- `attempt_count` 字段语义：**已重试次数（首次执行不计入，初始 0）**，上限 3 次重试
- 重试：仅 failed 可重试；attempt_count < 3 允许 retry（自增 1）；attempt_count 达 3 后第 4 次重试请求返回 409（附录 A 同步）

存储模型（导出任务表 `export_task`，字段建议）：

| 字段 | 说明 |
|---|---|
| id / task_id | 任务 ID（如 ET20260805001） |
| task_type | 固定 `student_cert_package`（预留其他导出类型） |
| filter_snapshot | 筛选条件快照 JSON |
| desensitize | 脱敏开关（默认 true） |
| operator_id / operator_name | 发起人 |
| status | processing / success / failed / expired |
| file_name / file_path / file_size | zip 信息（对象存储 key 或本地路径） |
| summary | { total_rows, pdf_count, missing_count } |
| warning | 信息性提示（预计体积/耗时，如触发大批量提示） |
| attempt_count | 已重试次数（初始 0，上限 3） |
| fail_reason | 失败原因 |
| created_at / finished_at / expire_at / updated_at | 时间戳（updated_at 兼作心跳） |

- 状态流转：`processing → success` / `processing → failed` / `success → expired`（保留期到期）
- 消息中心「导出记录」Tab 数据源即此表（S3 适配）；现有 UI 已覆盖 processing（L123-125「生成中」）、success（L160-162「生成成功」+下载按钮 L165-167）；**failed / expired 展示样式均需 S3 新增**（现状无失败行 mock、无过期行 mock）
- 下载接口：`GET /api/admin/export/tasks/{taskId}/download`，返回 `application/zip` 流 + `Content-Disposition: attachment; filename*=UTF-8''...`；鉴权要求发起人本人或管理员（防越权，见 2.5-12）；下载前校验文件存在性，缺失/过期返回明确错误码（FILE_NOT_FOUND / FILE_EXPIRED）；支持 Range 断点续传（大文件防断）

##### 2.4.7 性能与存储（修订，回应 #1/#2/#3/#6）

- 数量级假设（假设值，待验证）：典型筛选数百~数千行；页面 mock 总量级「共 5,682 条记录」（16 页 L357，仅量级参考）
- 单 PDF 平均大小：未实测 → **P0 上线前实测项**；实测前阈值参数用假设值 **1.25 MB/份**（V2 0.5~2MB 区间中值，标注假设）
- 全签发 5,682 人按假设 ≈ 原始 PDF 约 7 GB；zip 对 PDF 压缩收益有限（PDF 已压缩），预计压缩比 ≈ 0.9~1.0（待验证）
- **ZIP64（回应 #6）**：Excel/zip 库选型硬性要求支持 ZIP64；预估超 4GB 时 warning 文案追加「文件可能超 4GB（ZIP64 已支持）；分卷下载为预留能力（Could）」
- **配额预检（统一口径，回应 #1）**：创建任务时**同步预检**存储配额余量——不足 → **直接拒绝创建、不落任务、返回 QUOTA_EXCEEDED**（提示联系管理员）；通过 → 正常落任务。执行中写入失败仍按任务 failed 处理（真实约束保留）。建议技术评审重估 19 页 L62「1GB 配额」口径（单次全量包即可能 GB 级）
- **信息性提示（替代 V2 软提示，回应 #2/#3）**：
  - 预估算法：`预估大小 = 筛选 count × 平均 PDF 大小参数（假设 1.25MB）`；创建时同步完成（一次 COUNT 查询，无额外统计开销，不与异步设计冲突）
  - 阈值：预估 zip ≥ 2 GB 或证书数 > 10,000（可配置参数，实测后回填）→ 响应带 `warning` 字段（{ estimatedSize, estimatedTime, message }）；**任务照常创建并执行，不阻塞、不拒绝**
  - 前端行为：warning 仅作**信息性展示**（文案如「本次导出预计约 X GB、耗时较长，请稍后在『消息中心』查看下载」，告知已知悉性质），**不弹阻塞确认、不提供取消**；取消/中止接口列入 Could 预留（V3 不做）
- 硬失败仅保留真实约束：创建时配额预检不足（拒绝创建）、PDF 读取系统性故障（连续 N 个失败，N 待定）
- 任务超时 30 分钟（假设值，可配置）；PDF 分批读取 + 流式写 zip（每批 500，假设值）；保留期 7 天（假设值，待确认）
- 存储生命周期：保留期到期 → 逻辑置 expired（立即拒下载）+ 延迟 10 分钟物理删除（消除下载竞态，见 2.5-10）
