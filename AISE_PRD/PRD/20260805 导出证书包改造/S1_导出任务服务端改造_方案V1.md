### 2. 方案正文

#### 2.1 背景与目标

**背景**

admin 端「16_学生证书管理」页面的「导出数据」按钮当前为纯前端 mock（loading 2s → Toast → 恢复），不产生任何真实文件（出处：`AISE_PRD/AISE_PRD/html/admin/16_学生证书管理.html` L376-409 `exportData()`）。页面表格同时存在两条独立证书链路：实体证书状态（批改中→…→已寄送）与电子证书状态（已签发/待签发/签发失败），电子证书链路已有平台内 PDF 资产（已签发时保存证书编号、PDF 地址、验签地址，出处：`AISE_PRD/AISE_PRD/PRD/20260512 5 月需求/20260512 证书签发流程 prd.md` L72；用户证书对象含 PDF 地址，L51；签发中心可下载 PDF，L834）。

**已锁定决策（用户拍板，直接采用）**

1. 导出范围：按当前筛选条件全量导出（跨页，非仅当前页/勾选行）
2. PDF 只打包「已签发」电子证书；Excel 保留筛选结果全量行（含电子证书状态列，未签发行保留）；zip 内附「缺证书说明.txt」列明未打包学生及原因（可溯源）
3. 按钮保持「导出数据」原名不改文案；仍走异步导出链路（按钮 loading → Toast → 消息中心导出记录 → 下载 zip）

**目标**

- 服务端提供完整、可追溯、可重试的异步导出任务能力，产物为「学生证书包」zip
- 任意筛选结果、任意状态组合下行为确定（S4 穷举兜底）
- 导出记录在消息中心「导出记录」Tab 完整呈现并可下载

**非目标（V1 不做）**

- 前端按钮交互改造（S2）、消息中心展示适配（S3）的详细方案（仅输出接口与文件规范约定）
- 增量导出、定时导出、分卷 zip、压缩选项调优

#### 2.2 用户故事与用户旅程

**用户故事**

- US1（运营/管理员）：作为运营人员，我想在学生证书管理页按当前筛选条件一键导出「证书包」（Excel + 已签发证书 PDF），以便线下归档、向渠道分发、与寄送清单核对。【依据：E 级经验判断——导出场景为运营线下作业；按钮与异步链路为现状锁定行为，无需价值论证】
- US2（运营/管理员）：作为运营人员，我想在消息中心查看导出任务进度并下载 zip，以便异步取回大文件而不阻塞页面操作。【依据：C 级竞品/现状参考——消息中心「导出记录」Tab 已存在且已含「导出电子证书包 (PDF)」zip 形态的 mock 行（`19_消息中心.html` L141-148，文件名 `certs_batch_1002_final.zip`、45.2 MB、下载按钮），本次为将其落地为真实服务】
- US3（运营/管理员）：作为运营人员，当部分证书未打包时，我想通过 zip 内说明文件快速定位缺失项及原因，以便跟进补签或人工处理。【依据：用户已拍板锁定（可溯源要求），无需价值论证】

**用户旅程（关键路径）**

1. 进入「16_学生证书管理」→ 设置复合筛选（姓名/手机/身份证/渠道/实体证书状态/电子证书状态/结果/分数范围/模块/级别）→ 点击「查询数据」核对列表
2. 点击「导出数据」（保持原名）→ 按钮 loading（禁用）→ Toast「正在导出，请稍后在『消息中心』查看下载」→ 按钮恢复
3. 服务端创建导出任务并异步执行（用户无感知等待）
4. 用户进入「19_消息中心」→「导出记录」Tab → 看到「导出学生证书包」任务（生成中/生成成功）
5. 生成成功后点击「下载文件」→ 获得 zip → 解压核对「学生证书列表.xlsx」与「证书PDF/」目录；如有缺证书，查阅「缺证书说明.txt」

#### 2.4 核心流程

##### 2.4.1 触发与入参

- 触发点：16 页面「导出数据」按钮点击（`exportData()` 改造为调用创建接口，此为 S2 职责；S1 定义接口契约）
- 任务创建时机：点击 → 前端收集当前筛选区控件值 → `POST /api/admin/export/tasks` → 服务端落一条任务记录（状态 processing，入参快照 JSON 全量保存）→ 返回 taskId → 异步队列消费执行
- 入参（filter 对象，字段与列表查询接口完全同源，避免语义分叉）：

| 字段 | 类型 | 对应筛选控件（出处：16 页面 L84-148） | 说明 |
|---|---|---|---|
| name | string | 学生姓名 | 模糊 |
| phone | string | 手机号 | 模糊 |
| idCard | string | 身份证号 | 模糊 |
| channelIds | string[] | 渠道（名称/编号，可多选） | 空=全部 |
| entityCertStatus | string | 证书状态（实体） | 批改中/批改完成/公示中/制作中/已寄送 |
| elecCertStatus | string | 电子证书 | issued/pending/failed/unconfigured |
| result | string | 测评结果 | 优秀/良好/合格 |
| scoreMin / scoreMax | number | 分数范围 | 闭区间 |
| moduleIds | string[] | 模块（可多选） | |
| levelIds | string[] | 级别（可多选） | |

- 入参快照存 JSON：任务执行期间以快照为准（与 2.5 快照一致性一致），保证「点击时刻的筛选 = 产物内容」

##### 2.4.2 执行流程（服务端异步任务）

```
队列消费任务
  → 1. 按 filter 快照全量查询学生证书行（游标分页，无页大小上限）
  → 2. 生成 Excel（列规范见 2.4.3；数据 = 步骤 1 全量行）
  → 3. 遍历行：电子证书状态=已签发 且 有 cert_no → 从证书文件存储读 PDF
         - 读取失败/文件缺失 → 该行记入缺证书清单（原因枚举见 2.4.5），继续
         - 未签发/签发失败等 → 该行记入缺证书清单（原因=状态原因），继续
  → 4. 流式打包 zip（结构见 2.4.4；PDF 每批 N 个（假设值 N=500，待验证）写入，控制内存峰值）
  → 5. 上传/落盘 zip，更新任务记录：status=success、fileName、fileSize、统计、完成时间
  → 6. 消息中心导出记录 Tab 即从任务表读取（无需单独通知；如需轮询/推送由 S3 决定）
失败（Excel 生成失败 / zip 打包失败 / 存储写入失败 / 超时）
  → 任务置 failed + failReason，可重试（F10）
```

##### 2.4.4 zip 包结构

```
学生证书包_20260805_共5682人_3200份.zip
├── 学生证书列表.xlsx          （全量行，必含）
├── 缺证书说明.txt             （仅当存在未打包行时生成；全部打包则不生成）
└── 证书PDF/
    └── 张小明_CERT202608050001.pdf   （仅已签发且读取成功的证书；文件名=姓名_证书编号）
```

- zip 文件名规范：`学生证书包_{yyyyMMdd}_{共{总行数}人}_{{打包PDF数}份}.zip`
  - 命名先例参考：消息中心 mock 已有 `certs_batch_1002_final.zip`（L147）形态，但该命名不含统计信息；本规范加入日期与统计，便于运营按文件直接识别批次规模。【依据：C 级参考 + 默认假设】
  - 文件名字符集：UTF-8；姓名中的非法文件名字符（`/ \ : * ? " < > |`）统一替换为 `_`
- 不生成空目录：当打包 PDF 数为 0 时，zip 内无「证书PDF/」目录
- 单个学生多行（多证书实例）时每行独立 PDF，文件名以 cert_no 唯一区分（规避同名冲突，见 2.5-4）

##### 2.4.5 缺证书说明.txt 内容结构

```
学生证书包缺证书说明
导出任务：{taskId}
导出时间：{yyyy-MM-dd HH:mm:ss}
筛选条件摘要：{如：模块=Python,一级；电子证书状态=全部}
结果总行数：5682
已打包证书数：3200
未打包行数：2482

序号	学生姓名	证书编号	电子证书状态	未打包原因
1	李小红	-	待签发	电子证书未签发
2	赵小梅	-	签发失败	电子证书签发失败
3	张三		CERT202608050099	已签发	证书PDF文件缺失（存储异常）
```

- 原因枚举（机器可读 code + 展示文案，同时落库以便统计）：

| code | 文案 | 触发条件 |
|---|---|---|
| NOT_ISSUED | 电子证书未签发 | 状态 ∈ 等待成绩/生成中/待签发 |
| ISSUE_FAILED | 电子证书签发失败 | 状态 = 签发失败（PRD L73 保存失败原因） |
| PDF_MISSING | 证书PDF文件缺失（存储异常） | 已签发但存储无对应文件 |
| PDF_CORRUPT | 证书PDF文件损坏/读取失败 | 已签发但读取/校验失败 |
| CERT_NO_MISSING | 证书编号缺失，无法定位PDF | 已签发但 cert_no 为空（数据异常） |
| OTHER | 其他 | 兜底 |

##### 2.4.6 导出记录与下载

- 存储模型（导出任务表 `export_task`，字段建议）：

| 字段 | 说明 |
|---|---|
| id / task_id | 任务 ID（如 ET20260805001） |
| task_type | 固定 `student_cert_package`（预留其他导出类型） |
| filter_snapshot | 筛选条件快照 JSON |
| operator_id / operator_name | 发起人 |
| status | processing / success / failed / expired |
| file_name / file_path / file_size | zip 信息（对象存储 key 或本地路径） |
| summary | { total_rows, pdf_count, missing_count } |
| fail_reason | 失败原因 |
| created_at / finished_at / expire_at | 时间戳 |

- 状态流转：`processing → success` / `processing → failed` / `success → expired`（保留期到期）
- 消息中心「导出记录」Tab 数据源即此表（S3 适配）；现有 UI 已覆盖 processing（L123-125「生成中」）、success（L160-162「生成成功」+下载按钮 L165-167）、expired（L234-236「文件已过期」+「不可下载」L239-241）；failed 展示样式需 S3 新增（现状无失败行 mock）
- 下载接口：`GET /api/admin/export/tasks/{taskId}/download`，返回 `application/zip` 流 + `Content-Disposition: attachment; filename*=UTF-8''...`；鉴权要求发起人本人或管理员（防越权，见 2.5-12）

##### 2.4.7 性能与存储

- 数量级假设（标注为假设值，待验证）：典型筛选结果数百~数千行；页面 mock 展示总量级「共 5,682 条记录」（`16_学生证书管理.html` L357，仅作量级参考）
- 单 PDF 大小假设：0.5~2 MB（含模板底图+电子章，待验证）。全签发 5,682 人 ≈ 2.8~11 GB 原始 PDF；zip 对 PDF 压缩收益有限（PDF 已压缩），预计压缩比 ≈ 0.9~1.0（待验证）
- 阈值与超时（默认假设，待确认）：
  - 预估 zip ≥ 2 GB 或打包证书数 > 10,000 时，任务直接失败并提示「数据量过大，请缩小筛选范围后重试」（规避 zip64/浏览器下载/存储压力；分卷为 V1 之后 Could）
  - 任务超时上限 30 分钟，超时置 failed 可重试
  - PDF 分批读取+流式写 zip（每批 500 个，假设值），控制内存峰值
- 存储生命周期：
  - 导出文件保留期建议 7 天（假设值，待确认）；到期定时清理存储 + 状态置 expired，消息中心显示「文件已过期/不可下载」（该 UI 形态已存在，L208-243）
  - 导出文件纳入消息中心存储占用统计（现状展示「当前存储占用：124MB / 1GB」，`19_消息中心.html` L62）；超配额（假设：达 80% 预警、95% 拒绝新导出任务，待确认）时新任务直接失败并提示
- 失败重试：failed 任务可重试（F10），重试 = 同一 taskId 重新入队全流程执行，覆盖旧的失败产物（如有）

#### 2.5 边界与异常场景（穷举，S4）

| # | 场景 | 行为定义 | 说明/依据 |
|---|---|---|---|
| 1 | 筛选结果为空（0 行） | 任务仍创建并成功；zip 内仅「学生证书列表.xlsx」（含表头）+「缺证书说明.txt」（注明「筛选结果为空，无数据需导出」）；统计 0 人 0 份；消息中心正常展示 | 保持异步链路一致与可溯源，不引入前端分支【E 级经验判断】；前端亦可提示但以服务端为准 |
| 2 | 全部学生未签发（0 份 PDF） | zip 含 Excel 全量行 + 缺证书说明.txt（逐行列明状态原因）；不生成空的「证书PDF/」目录；任务 success | 已锁定决策 2（Excel 全量行保留） |
| 3 | 已签发但 PDF 文件缺失/损坏 | 该行跳过打包，记入缺证书说明.txt（PDF_MISSING / PDF_CORRUPT）；任务仍 success（行级降级，不因单行失败毁掉整包）；统计 missing_count>0 | 保证部分成功可用；「缺证书说明」保证可溯源（已锁定） |
| 4 | 同名学生 | 证书编号系统唯一（system.certNo，PRD L596），PDF 文件名含 cert_no（`姓名_证书编号.pdf`）规避冲突；Excel 行与 PDF 通过 cert_no 一一对应 | |
| 5 | 导出过程中数据变化（新签发/状态变更） | 快照一致性：任务以创建时刻的 filter 快照 + 执行时一次全量查询结果为准；执行期间新签发/新变更不追加入包 | 取舍说明：保证 zip 内 Excel 与 PDF 清单自洽（同一查询结果派生），代价是产物可能落后于最新数据；运营如需最新可重新导出 |
| 6 | 单个学生多张证书（多模块/级别/测评实例） | 表格行粒度 = 用户证书行（用户×证书实例，PRD L51 模型「用户证书 关联用户+证书实例」）；每行独立 cert_no、独立 PDF；Excel 行与 PDF 1:1；同一学生多行 PDF 以 cert_no 区分 | 页面 mock 一人一行（L185-224）仅为演示，真实模型支持一用户多证书 |
| 7 | 超大批量（万人级） | 阈值拦截：预估 zip ≥ 2 GB 或证书数 > 10,000 → 任务失败并提示缩小范围（见 2.4.7）；阈值内分批流式打包 | 分卷 zip 为 Could（V1 不做） |

| 12 | 越权下载/访问他人任务 | 下载与重试接口鉴权：仅任务发起人或管理员可操作；他人访问返回 403 | 安全边界 |
| 13 | 中文/特殊字符文件名 | 姓名非法字符替换为 `_`；zip 内文件名 UTF-8 编码（Windows 解压兼容性待验证）；zip 下载文件名 UTF-8 编码头 | |

#### 2.7 风险与依赖

**依赖**

- 证书 PDF 资产可用性：依赖签发链路正确落库「证书编号 + PDF 地址」（PRD L72）且文件存储可读——这是本功能的数据前提【已核实现状】
- 服务端技术栈与异步队列：与 AISE 现有后端一致（待验证——仓库为 PRD/HTML 原型，无后端代码）
- Excel 生成、zip 流式写入的库选型（待验证）
- 文件存储形态（本地磁盘/对象存储）与配额（待验证）
- 「成绩发布后自动触发生成证书」的触发源：PRD 明文为「开发者调用证书申请 API」（L68-69），成绩发布自动触发生成未见 PRD 原文，需实现侧确认实际触发方式（影响「已签发」数据的来源完整性，但不影响导出逻辑本身）【待验证】

**风险**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 大 zip（GB 级）生成慢、下载易中断 | 体验差、任务超时 | 阈值拦截 + 流式写入 + 超时重试（2.4.7） |
| 存储膨胀（多人多次导出） | 配额耗尽 | 7 天保留期 + 配额预检（F9/F12） |
| PDF 资产与库记录不一致（孤儿/缺失） | 缺证书行增多 | 缺证书说明兜底 + 建议后续增加存储巡检告警（V1 后可选项） |
| 队列积压导致「生成中」长时间悬挂 | 用户困惑 | 超时机制 + 失败重试 |
| Windows 解压中文名乱码 | 运营侧可用性 | UTF-8 编码 + 文件名规范（2.5-13，兼容性待验证） |
