# AISE 全量页面影响分析

基于 AISE 现有 86 个页面，逐端逐页评估新需求的影响范围，输出精确到页面级的变更清单。

## 工作流

```
1. 读取平台能力梳理文档（Functional_Specs/AISE&爱测评平台能力梳理.md）
2. 读取新需求/讨论结论
3. 逐端（admin/user/exam/iceping/org_admin/issuance）逐页对照
4. 对「可能受影响」的页面，读对应 HTML demo 确认实际交互
5. 输出三列矩阵
```

## 校验步骤

1. 对每个标记为"改造"的页面，**必须**读到对应的 HTML demo 文件（如 `html/admin/14_活动证书管理.html`）
2. 确认现有 DOM 结构、筛选项、表格列、按钮与改造描述是否匹配
3. 如果 HTML demo 显示改造范围比预判更大或更小，**修正输出**并说明原因
4. 对每个标记为"新增"的页面，检查是否与现有页面功能重叠（如果重叠，考虑改为改造）

## 约束

- **必须读 HTML demo 确认**，不可仅凭页面名称推断。
- 页面状态机（如旧实体证书流程 vs 新电子证书流程）要区分清楚，判断是并存还是替换。
- 签发中心是独立平台，页面不与 admin 端合并编号。
- 分析结果应可直接用于后续 PRD 章节编号和 HTML 文件创建。
