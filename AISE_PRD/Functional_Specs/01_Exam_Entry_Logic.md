# 考试进入逻辑规范

## 1. 概述
本文档定义了学生从考试列表或仪表盘进入考试的逻辑。涵盖了“进入考试”按钮的 UI 状态以及防止提交后再次进入的后端拦截逻辑。

## 2. UI 状态

### 2.1. 提交前 (默认)
- **按钮文案**: `进入考试`
- **按钮状态**: 可用 (Enabled)
- **动作**: 导航至环境检测页面或直接进入考试界面。

### 2.2. 提交后
一旦学生成功提交了试卷：
- **按钮文案**: `已交卷`
- **按钮状态**: **禁用** (置灰)
- **动作**: 无。用户无法点击该按钮。

## 3. 拦截逻辑 (后端/前端校验)

为了解决 UI 可能状态滞后（例如用户在另一个标签页提交了考试，或者页面未刷新）的情况：

### 3.1. 校验检查
当用户点击“进入考试”时：
1.  **前端**: 检查本地状态（如果可用）。
2.  **后端请求**: 发送请求以初始化考试进入流程（或检查资格）。
3.  **服务器验证**: 服务器验证该学生针对此特定考试的提交状态。

### 3.2. 处理“已提交”或“归档”状态
如果服务器返回考试状态为 `submitted` (已提交) 或 `archived` (已归档)：
- **阻止导航**: **不要**跳转到考试环境或答题页面。
- **反馈**: 显示 Toast 或模态框提示：“未知错误”或“您已提交该考试。”（具体错误文案由 UI/UX 定义，但逻辑是必须阻止）。
- **UI 更新**: 自动刷新列表或更新按钮状态为“已交卷”（禁用），以反映当前状态。
