## 大模型（真实调用，与 Hermes 同款）

- 配置读取：环境变量 `GLM_API_KEY`，缺省自动读 `~/.hermes/.env`
- 文本模型 `glm-5.3-flash`（预审判分 / 画像分析 / 问答），图片作品走 `glm-4.5v` 视觉模型
- 端点 `GLM_BASE` 默认 `https://open.bigmodel.cn/api/coding/paas/v4`，可用环境变量覆盖
- 未配置 key 时预审置「预审失败」，人工可直接终审（PRD 的降级口径），问答会报错提示

## 演示链路

1. 学员端上传作品（代码/图片/PDF，类型自动识别，≤10MB）→ 状态「审核中」
2. 后台异步真实调用大模型预审：准入结论 + 理由 + 能力标签（强制清洗：剔除格式词/作品名，≤4 个）+ 100 分制得分 + 评语 + 理解摘要
3. 教研员端审核工作台：预审队列 → 作品原文预览 → 确认通过 / 修改后通过 / 驳回（必填原因），全部留痕
4. 通过后人才卡特长标签动态更新；画像分析报告（学员端点「生成/重新生成」）综合 AISE 测评记录、逐题作答、知识点掌握与入库作品评价生成
5. 问答助手：学员只答本人数据；教研员可问全库。越界请求（写作文/出卷/闲聊）、隐私打探、学员互查一律拦截，话术以「该问题超出人才库服务范围。」开头

### 0. 总览：哪些内容是 AI 生成，哪些不是

| 页面内容 | 来源 | 说明 |
|----------|------|------|
| 作品预审（结论/理由/标签/得分/评语/理解摘要） | **AI 实时生成** | 上传后异步调用，glm-5.3-flash / 图片走 glm-4.5v |
| 画像分析报告（总体评价 + 5 段分区点评 + 优劣势 + 建议） | **AI 实时生成** | 「生成/重新生成」按钮触发；种子里的李小明报告是**真实生成的快照**（generatedAt 2026-11-10） |
| 问答助手全部回答与拦截话术 | **AI 实时生成** | 流式 SSE，学员端/教研员端同一契约 |
| 整体数据分析 6 段 AI 点评 | **AI 实时生成 + 缓存** | 首次进某渠道约 15-20 秒生成，按聚合数据 md5 指纹缓存于 `analytics_cache.json`（重置演示数据不丢） |
| 人才卡：标签 / 雷达 / 测评成绩 / 活动 / 荣誉 | 静态种子数据 | 演示假数据；接真实数据后来自测评系统与审核留痕（标签在作品通过时由审核动作合并写入，非 AI 直写） |
| 报告页指标卡 / 进度条 / 雷达 / 环形图 / 时间线 | 数据驱动渲染 | 值来自 AISE 测评与作品库，非 AI 文字 |
| 归档作品（种子中 6 份）的得分/评语/标签 | 静态假数据 | 模拟「已审完」状态；真实链路中这些字段由预审+终审产生 |

### 1. 作品预审智能体

- **触发**：作品上传后 / 教研员点「重新预审」。函数 `server.ai_review_work(work)`。
- **系统提示词**（`server.py` 常量 `REVIEW_SYSTEM`，原文）：

> 你是人工智能人才库的作品审核智能体，审核对象是中小学生的作品。请只输出 JSON（不要其他文字），字段：{"conclusion":"通过或驳回","reason":"一句话理由","tags":["标签1","标签2"],"score":0到100整数,"comment":"两句话评语","understanding":"对作品内容的理解摘要"}。tags 必须是人工智能教育方向的能力标签（如：程序设计、生成式人工智能、算法思维、创意设计、逻辑思维、数据思维、计算思维、问题解决），禁止使用文件格式（如PDF、PNG）、作品名称或文件名。评分锚点：60分=基本完成但质量一般；80分=完整且质量良好；90分以上=完整且有亮点创意。内容过于简单、残缺、明显敷衍的建议驳回。评语面向学生与家长，语气友好具体。

- **输入构造**：按作品类型差异化——图片转 base64 走视觉模型并附「分析这幅图片作品」指令；PDF 抽正文（解析失败则只给名称描述）；代码截前 8000 字符。
- **输出契约**：`{conclusion(通过|驳回), reason, tags(1-4个), score(0-100), comment, understanding}`。
- **代码侧后处理**：`extract_json` 容忍 ``` 包裹；score 钳制 0-100；标签清洗（BAD_TAG_WORDS 黑名单剔除格式词/作品名/文件名词，合并去重截断 4 个）。
- **降级**：模型调用失败 → aiStatus=failed，人工可直接终审。

### 2. 画像分析智能体

- **触发**：学员端「生成/重新生成」；教研员 `POST /api/admin/report/generate {studentId}`。函数 `server.ai_generate_report(stu, data)`。
- **系统提示词**（`REPORT_SYSTEM`，原文）：

> 你是人工智能人才库的画像分析智能体，分析对象是中小学生。基于给定数据生成个人画像分析，只输出 JSON：{"summary":"120字内的总体评价，概括整体水平与最突出的特点","examComment":"考试成绩表现的一句话小结","knowledgeComment":"知识点掌握情况的一句话小结，点名最薄弱项","radarComment":"四个能力维度表现的一句话小结","errorComment":"错误归因的一句话小结，按错误类型给改进方向","workComment":"入库作品表现的一句话小结","strengths":["优势1"],"weaknesses":["短板1"],"suggestions":["建议1（附练习方向）","建议2"]}。各 comment 控制在 60 字内、面向家长的具体表述，不写空话。成长建议原则：优先补齐关键短板，难度递进，定期巩固，每条建议附可执行的练习方向；不含培训课程推销。语言面向小学生与家长，友好易懂。

- **输入构造**：学员的 AISE 考试（含逐题）、知识点掌握（含错误类型）、能力雷达、入库作品（得分/标签/评语）、成长活动，序列化为结构化文本。
- **输出契约**：6 个文字字段 + 3 个列表；max_tokens=3000。
- **页面映射**：summary→Hero 顶栏；5 个 comment→各数据区块「✦ AI 点评」条；suggestions→「下一阶段建议」编号卡。

### 3. 问答智能体（非流式契约 / 流式契约两版）

- **触发**：问答页发送。学员端 `own_only=True`（附加规则 `QA_OWN_ONLY`：只答本人数据，问他人/全库一律 refuse）。
- **流式系统提示词**（`QA_STREAM_TMPL`，原文，规则部分与非流式 `QA_SYSTEM_TMPL` 一致，仅输出格式不同）：

> 你是人工智能人才库的问答助手，服务对象是中小学生及其家长与教研员。你只允许基于【人才库数据】回答问题，数据如下：【人才库数据】{context}
>
> 规则：1. 只回答与人才库数据相关的问题（学员的测评成绩、逐题作答、知识点掌握情况、作品评价、成长画像、简历材料）。数据中没有的信息要如实说明人才库暂无相关记录，禁止编造。2. 与人才库无关的请求（写作文、写代码、做题、闲聊、时事新闻等一切代办或创作类请求）一律拒绝。3. 打探他人隐私（住址、联系方式、身份证号等）或要求生成不当内容的请求一律拒绝。4. 拒绝时第一行输出 [SCOPE:refuse]，正文以「该问题超出人才库服务范围。」开头，随后一句话说明可提问的范围（测评成绩、知识点掌握、作品评价、成长建议）。5. 回答精炼友好（200字内），适合小学生与家长阅读。
>
> 输出格式（严格遵守）：第一行输出且仅输出 [SCOPE:answer] 或 [SCOPE:refuse]，随后另起一行直接输出回答正文。不要 JSON，不要代码块，不要任何额外说明。

- **QA_OWN_ONLY 附加规则**（学员端拼入 {extra}，原文）：

> 6. 【最重要】你只允许回答当前登录学员本人的数据。任何询问其他学员、全库统计、学员名单的问题，一律按无关请求拒绝。

- **非流式契约**（`/api/qa`，老链路，仍作为流式失败兜底）：输出 JSON `{"scope":"answer或refuse","answer":"..."}`；解析失败自动加大 max_tokens 重试；scope=answer 但内容为空再重试一次，仍空则给固定口径「人才库中暂时没有能回答这个问题的记录。」
- **流式链路**（`/api/qa/stream`）：SSE 推送 `{t:'scope'|'delta'|'done'}`；开头不符合 [SCOPE:*] 约定自动降级老链路。
- **context 构造**：`build_student_context(stu, data, brief)`——brief 模式（学员多于 2 人时教研员端）逐题明细省略、保留知识点行。

### 4. 整体数据分析点评智能体

- **触发**：分析页加载/切渠道时前端调 `POST /api/admin/analytics/ai-comment {channel}`。函数 `server.ai_analytics_comment(out)`。
- **系统提示词**（`ANALYTICS_AI_TMPL`，原文）：

> 你是人工智能人才库的数据分析智能体，面向教研员解读渠道学员的整体数据看板。基于给定聚合数据，只输出 JSON：{"summary":"80字内的整体解读（覆盖规模、水平、突出特点）","channelComment":"渠道对比的一句话解读","knowledgeComment":"知识点掌握的一句话解读，点名最薄弱的知识点","radarComment":"能力维度均值的一句话解读","errorComment":"错误归因的一句话解读，给教学改进方向","tagComment":"作品特长标签分布的一句话解读"}。各字段 60 字内，客观具体、有洞察（如对比、归因、可执行建议），不写空话，不推销课程。

- **输入构造**：`compute_analytics(data, channel)` 的聚合结果（总量/渠道对比/知识点/能力均值/错误归因/标签/评级）序列化为 JSON。
- **缓存**：`_analytics_fp` 对聚合数据取 md5 指纹，命中 `analytics_cache.json` 直接返回；数据变化自动失效重生成。生成失败前端显示「生成失败，可稍后重试」。

### 5. 接真实数据的改造点

1. **输入侧**：`seed_data.py` 的 students/works/reports 替换为测评系统与作品库的真实记录（字段契约见各 compute 函数与 `build_student_context`）；`data.json` 仅是运行时存储，可换 DB。
2. **报告快照**：种子中李小明报告为真实生成快照；接真实数据后删掉 `data['reports']` 预置项，让报告按需生成。
3. **归档作品**：种子里归档作品的 ai 字段是假数据；真实链路中它们由预审+终审流程产生，无需预置。
4. **提示词即契约**：四个系统提示词都在 `server.py` 顶部常量区（REVIEW_SYSTEM / REPORT_SYSTEM / QA_SYSTEM_TMPL + QA_STREAM_TMPL + QA_OWN_ONLY / ANALYTICS_AI_TMPL），调整口径改常量即可，页面文案无需动。
5. **回归**：改提示词后跑 `python3 tests/test_prompts.py` 确认格式与效果不回退。
